# bn254-pairing-inversion: (6,2) STNFS on a twisted base field: expected work 2^88.309529378 units

Track bn254-pairing-inversion. Input: z = g^x in GT (g = e(P0, Q0), the profile's generator), x uniform in 0..r-1; output P in G1, Q in G2 with e(P, Q) = z. The score unit is C = 20,000 scalar AArch64 instruction equivalents (a borrowed normalisation unit:
every BN254 operation below is charged in instructions). No advice, smaller targets or amortization are used. Analytic, exploratory claim.

## Claim

W is all classical work of one attack on one full-production target. Under the stated hypotheses the attack succeeds with probability at least 0.39 over uniform challenges and fresh coins (under H5 as modeled an opened run succeeds with probability at least 0.998296; the run gate opens at most a share 0.390666 of runs), and

    E[W] <= 1 + (K/2^64) 2^89.665522899 < 2^88.309529378 units (C=20,000 instructions), K = 7206510081926327593.

Run gate: before any other work the attack reads one fresh 64-bit coin u and opens the run only when u < K = 7206510081926327593, the least integer with (K/2^64) x 0.998296 >= 0.39 (evidence.py checks in exact rationals that K - 1 fails). A closed run is a failure and costs 1 unit. In an opened run both individual logarithms run under one combined phase meter t = 2^112 units: when the logarithm phase reaches t the run aborts as failure. The work spent in that phase is min(D, t), with D the uncapped two-log work, so its expectation is at most E[D] <= 2^86.490355 units by the DESCENT.md recurrence (hypothesis H5), and the ledger charges that. Both the work and the success (section 7) of an opened run rest on H5 as modeled; no allowance factor is added or claimed. The other rows are expected upper bounds under the stated hypotheses and include failed trials and abort work.

The split phase alone has an interruptible budget of 2^112 units; both individual logarithms share the 2^112-unit phase meter above. The split is deterministic (section 8, no ECM and no retry loop): before the prime-tree build and before each wave, reserve and charge that step's whole finite worst-case formula at its actual size; if the reservation would pass the split budget, abort as failure. The 128-bit remaining-budget debit and branch require at most 128 scalar instructions per invocation, charged per reservation; the ledger also doubles the whole listing bill for debit and control, including the aborting check. The field-map, collection, exact smoothness checks, linear algebra and output retain their explicit finite loops and existing cost models; their measured averages are not used as worst-case reservations.

Writing E_split for the split row, a reservation (each below 2^84 instructions) is refused only after more than 2^112 - 2^84/C units of split work, so Markov charges split abort at most E_split/(2^112 - 2^84/C). A partial or unverified output is failure.

## 1. Wrapper

1. Check z (canonical encoding, z != 0, z^r = 1). If z = 1 return (P0, infinity) (allowed exactly when z = 1).
2. Draw s uniform in 1..r-1 and t uniform in 0..r-1; g' = g^s, z' = z g^t (g = e(P0, Q0), the profile's generator). g' is uniform on GT minus
   {1} and z' uniform on GT, independent: the core's input law, whatever z is.
3. Map g' and z' into the core's tower (field-map.md).
4. Run the core on (g', z') under its meter and node counter (any failure is a failure): l = log_g'(z') mod r. Then x = s l - t mod r.
5. Q = [x]Q0 on the twist over F_p2 (left-to-right double-and-add, Jacobian coordinates, mixed additions, one inversion; ledger row "output": at most 2^26.05 instructions, ledger16.g2_output_bound with loose four-limb prices: F_p product <= 4,096, addition <= 256). Check e(P0, Q) = z (one pairing; a mismatch is a failure) and return (P0, Q). P0 is the public generator and Q = [x]Q0 lies in G2 because Q0 does.

GT has prime order r, so z = g^x for a unique x mod r and z' = g'^l with l = (x + t)/s. The field isomorphism preserves z' = g'^l; the final
check rejects any wrong output. One relation and linear-algebra phase serves both logarithms (section 6). Steps 1-3 and the pairing check of step 5 (validation, two GT exponentiations, one pairing, the field map of field-map.md, randomness) are charged in the wrapper row: at most 2^68 instructions; the scalar multiplication has its own row.

## 5. Main-phase success

Region and polynomials are coin- and challenge-independent, so the relation set and filtered matrix are fixed. H-R (rank M = N, rank [M|S] = N + 6, kernel the virtual-log line with nonzero map part) and H-X (rank C_d = N with the seven Schirokauer columns fixed in the start block, O_e injective on V, at the charged d = ceil(D/n) + 1 + ceil(D/(128n)), e = ceil(D/m) + 1 + ceil(D/(128m)) on the actual sparse support) are declared premises (RANK-BRIDGE.md); they do not follow from relation counts, class numbers or map injectivity. Given them, the sampled X and Z entries (low 64 bits of independent 128-bit draws) fail with probability at most 4Ncap/2^64, Ncap = ceil(4 NU U') (one joint Schwartz-Zippel grid, RANK-BRIDGE.md (c)). The kernel vector is certified (A(w, c) = 0, c != 0) before use; this detects, but does not bound, a failure of the premises. Purged logs are reconstructed and unresolved low-occurrence ideals are handled in descent.

## 6. Individual logarithms

DESCENT.md and finalmodel4.py specify the fixed62-type production plan, original amortized node sieves and independent single-cell boot.
