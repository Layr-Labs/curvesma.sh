Loop audit -- bn254-pairing-inversion rho-tower-pi-v1
Written 2026-11-12 for the resubmission after rejection of submission d887db59 (bn254-pairing-inversion #1).

The claim is a per-run work cap, so every loop in the algorithm must have a
bound that holds for every run.  This file lists each loop in proof.md, its trip
count and why that trip count is data-independent.  "Run" = one execution of the
algorithm; there is one trial, one table, one salt, no restart, no retry, no
distinguished-point search and no distinguished-point store.

No loop in the algorithm has a data-dependent trip count.  The only
data-dependent decisions are the carry/borrow/comparison arms inside fp_add,
fp_sub, fp_mul and scalar_add_r.  They select which instruction sequence runs,
never how many times a loop runs, and they are covered by the measured
worst-case step sweep in evidence/worstcase-sweep.txt (32 production table
entries x 22 operand patterns, maximum charged).

The sampler is the only place where the algorithm can stop early.  Its cap is
K = 64 attempts per scalar; if any of the 66 calls exhausts the cap the run
aborts and reports failure.  The abort probability (union bound) is
66*(1-r/2^256)^64 <= 2^-13.30, which is charged against the success bound
(0.8559 - 2^-13.30 > 0.85), and the abort path has spent at most the sampler's
capped cost, so the per-run work cap also holds on that path.
