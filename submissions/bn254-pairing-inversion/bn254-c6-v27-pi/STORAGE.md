# STORAGE.md: Direct Live Score Nodes, 1-Hop 16 KiB Link Pages and the < 2^{100} B Storage Bound

Where the Band 1, Lower Band 2 and Lattice Band 2 data lives, how it moves and what moves cost. This replaces the v23b design (passive Storage Nodes S[s_id], linked page chains, a single serialized consumer C_0, the K_pass = 4096 fallback). Every node is a flat 64-bit scalar machine with < 2^64 B of RAM, addressed by unit-cost ldr/str/ldp/stp/staddh under COST_MODEL.md. Every cross-node byte goes through an explicit 1-hop 16 KiB link page copied by scalar ldp/stp (2,048 ldp/stp + 12 loop/setup = 2,060 instructions per page = 1.007 <= 1.05 Ir per 8 B word, as for v23b's L -> C and S -> C links). Figures are printed by model_bn254_v6.py (geometry) and checked by audit_bn_cm.py (ram_ok).

## 1. Node Types and Memory

| Node | Count | Holds | RAM (log2 B) |
|---|---:|---|---:|
| Emitter E_0 | 1 | a_tab (284 * 2^{50} 8 B entries, 2^{61.150} B), b_tab (560 * 2^{51} 8 B entries, 2^{63.130} B), 2^{36} 16 KiB staging slots at a 32 KiB stride and 2^{36} link pages link_E_to_C[s], write pointers, E_a+ build arrays (`32 \|E_a+\|` B), LUT4 table (1,048,584 B) | <= 63.457 (emitter_log2) |
| Score Nodes C[s] | N_sc = 2^{36} | live uint16_t score rows of the sub-bands assigned to s (<= average + one sub-band), 2^{36} incoming list link pages, 1 incoming emitter link page, the 2^{50} B sink (counted on every node), the init_a[] copy source and the a(ai) vectors Stage B reads (`18 \|E_a+\|` B), the 1.5 MB Stage-B batch | <= 62.417 (score_node_log2) |
| List Nodes L[k] | N_list = 2^{36} | Band 1 / Lower Band 2 lists of their primes (2^{60} B pool), 1-prime build scratch (2^{52.535} B, incl. ai_of_chord[] and piece descriptors of all four shells), 2^{36} outgoing link pages link_L_to_C[k][s] (2^{50} B), the sub-band to (s, row_block) map (8 B per sub-band) | <= 60.014 (list_node_log2; model 60.0095) |

Score rows. Each b-vector of E_{12} owns one row. Rows are grouped in sub-bands of W = 64 consecutive b_0 values on one (b_1, ..., b_5) chord (sb = b_0 >> 6, an arithmetic shift, so negative b_0 nest correctly: checked at b_0 in {-64, -63, -1, 0, 1, 63, 64, 559}). All rows of a sub-band share one stride 2^{k_s} bytes, k_s = max(35, ceil(log2(2 * cap))), so a sub-band is 64 * 2^{k_s} contiguous bytes aligned to 2^{35}-byte blocks, allocated whole. A deterministic greedy rule gives each next sub-band to the least-loaded Score Node, so every node holds at most the average plus one sub-band (64 * 2^{50} B). b_tab[b] stores `(row_block << 36) | s`, row_block = offset >> 35 (at most 2^{27.415} blocks per node, so the word fits 28 + 36 = 64 bits). b outside E_b maps to b_tab = 0, the dummy sink: blocks [0, 2^{15}) of C[0] (`2^{50} B > 2 |E_a+|`), disjoint from every real row (real rows start at block 2^{15}); sink writes are never read.

Index sets, out-of-domain lookups and row capacity. With x = (a_3, -a_4, a_5) and s_x = x_0 + x_1 + x_2, the canonical a lie in the closed cone K_a = {s_x >= 0, x_0 >= x_1, x_0 >= x_2}. E_a+ = K_a cap Z^6 cap {0 < Q(a) <= 1 + delta}, delta = 0.005, is ranked 1, 2, ... by (Q(a), fixed tie order) (ai); ranks up to `|E_a|` are the real a-set Q(a) <= 1. Band 1, Lower Band 2 and the lattice emitter all index this one ranked set; list entries carry the shell-local index ai - base_sh < 2^{47} (mask M47) and each bucket header's row base includes 2 base_sh. a_packed is a dense box index below 284 * 2^{50} (every coordinate of a clipped chord stays in the box; E_a+ fits it with `max |a_i| = (416.6, 387.7, 362.7, 276.5, 276.5, 276.5)`). a_tab[a_packed] = 2 ai for a in E_a+ and 0 elsewhere (a = 0, non-canonical or out-of-range patterns, Q(a) > 1 + delta); such a record writes cell 0 of its own row, the *trap*, which no list writes (ai = 0 is the ll null link), init_a[0] = 0, and the scan masks (1 op per row). Every accepted leaf has Q(a) + Q(b) <= 1 + eps_or with eps_or <= 0.0023389 <= delta / 2 (KERNELS.md §1.3, Theorem B), so Q(a) <= u_sb + eps_or with u_sb = max_{b in sb} (1 - Q(b)). Band 1 applies a row's hits up to the next prefix checkpoint, at most `D_B1 = ceil(ceil(|E_a| / 4) / 512) <= 2^{37.274}` cells past the row's logical end N_a(b); Lower Band 2 writes stop at namax <= N_a(u_sb). So every row of a sub-band gets the exact count

cap(sb) = #{a in E_a+ : Q(a) <= u_sb + delta} + D_B1 + 16

(one binary search per sub-band at b_tab build, inside the 50 V_b build charge), and every write of every tier for a b in E_b lands at a cell index < cap of its own row (records for b outside E_b go to the sink). Logical cells are [1, N_a(b)]; cells N_a(b) < ai < cap are the guard region: they may collect over-radius, checkpoint-overshoot or out-of-group writes and wrap, and are never used as scores, because a survivor with ai > N_a(b) is dropped by one compare before Stage B (KERNELS.md §1.4). v25_verify.py check 8 runs stor_bound.py and fd_bounds.py and asserts eps_or <= delta / 2 (row_capacity_guard_errs = 0).

## 2. Data Movement and Charges

Link machine model (declared, as v23b's link pages). Nodes are separate processors with private RAM. For every (producer, consumer) pair the schedule uses, one 16 KiB page of dual-ported memory is part of both processors' physical memory and is mapped at a fixed address in each (link_E_to_C[s] at a fixed offset (s << 14) of E_0's link window and at one fixed address in C[s]; link_L_to_C[k][s] likewise). It is the only inter-node data path (no network or DMA): remote delivery is exactly the producer's scalar stores into that page (charged per 8 B word below), and destination selection is the address arithmetic on s that the producer already performs (inside the charged emit and bucket-header operations). Signalling uses two doorbell registers per link page, one per direction, in the style of an Arm Message Handling Unit: a memory-mapped register whose write raises an interrupt request at the link's other processor only (one doorbell per link and direction, so no target addressing and no broadcast; SEV is not used). A processor with nothing to do executes wfi and is halted, executing no instructions, until its interrupt arrives. Producer side of a handoff: 2 header stores, 1 store to the doorbell, wfi; on the return interrupt (exception entry is taken by hardware): mrs ICC_IAR1_EL1 (acknowledge), msr ICC_EOIR1_EL1 (end of interrupt), eret to the resume point, pointer reset: 8 instructions. Consumer side: on its interrupt, mrs ICC_IAR1_EL1, 2 header loads and a branch into the apply loop (records charged separately); after the page, 1 store to the producer's doorbell, msr ICC_EOIR1_EL1, wfi: 8 instructions (+ eret when resumed). Both are within the <= 20 instructions per side charged below.

0. Execution schedule and page handoff. The nodes run one deterministic program under a static serial schedule: one node executes at a time, an idle node executes nothing, and since the score counts instructions, not wall-clock time, this costs nothing extra. A link page moves only at a *handoff*: a producer (E_0 or L[k]) that has filled a page (or ends a band or stream with a partial page) writes the page header (record count, log p weight) and passes control and the page address to the Score Node C[s] owning the page, which applies the whole page and returns control; the producer resets its pointer and continues. So the producer can overwrite slot and link page with no ownership or completion flag, and C[s] never polls or searches for pages. A handoff costs <= 20 instructions for the producer (two header stores, pointer reset, control transfer and return) and <= 20 for the consumer (header load, loop setup, return), charged: Lattice Band 2 pages in C_LAT_EMIT (2,060 + 20 Ir per 2,046 records <= 1.017) and C_LAT_APPLY (20 / 2,046 inside the 1.80); list pages in the 1.05 Ir per 8 B entry ((2,060 + 20 + 20) / 2,048 = 1.0254 <= 1.05); every partial page at 4,130 Ir in misc.
1. One-time score initialisation. Before any apply, each C[s] copies the init_a[] pattern (init_a[0] = 0 for the trap cell) into cells [0, L_g] (scan: [1, L_g]) of the 8 rows of each scan group, L_g the group's longest logical row, with the pass-2 instructions of v23b's scan8 (16 x (2 ldp + 8 stp) per 1,024 cells; pricing, group overhead and survivor drop in KERNELS.md §1.4). In v26 pass 2 runs once, before the row's first apply, not after the scan; the scan (pass 1) is read-only over the same cells, cell 0 masked (1 op per row), all inside C_SCAN_G8 = 549/1024 (scan_zero = 0.854 Ir/cell). Cells beyond L_g are never initialised or scanned. v25_verify.py checks read-only ORR survivor detection on 8 rows against a reference (init_scan8_readonly_errs = 0).
2. Lattice Band 2 emission (E_0 -> link_E_to_C[s] -> C[s]). Per accepted leaf E_0 forms the 8 B record rec = (row_block << 35) + (ai << 1) (the cell's byte offset in C[s]) from a_tab[a_packed] and b_tab[b_packed] and appends it to slot s (KERNELS.md §1.3, 11 ops). Slot s starts at base + (s << 15) + 16; after 2,046 records the write pointer reaches offset 16,384, bit 14 becomes 1 and tbnz x_wp, #14 branches to the flush: one 16 KiB ldp/stp copy into link_E_to_C[s] (2,060 Ir) plus the handoff (<= 20 Ir), 2,080 Ir per 2,046 records <= 1.017 Ir per record inside C_LAT_EMIT, then a pointer reset to +16. For records 1..2,045 bit 14 is 0 (tbnz14_single_slot_errs = 0, replayed for s in {0, 1, 17, 2^{36}-1}). The header carries the record count and the band's log p weight. C[s] applies each page directly from the link page (KERNELS.md §1.3: 1.759 Ir per record incl. header <= 1.80 = C_LAT_APPLY). Records are grouped by 16-per-bit log p band (208 bands on [2^{48}, 2^{61}]); at each band end E_0 flushes every non-empty slot: <= 208 * 2^{36} partial pages * 4,130 Ir, in misc.
3. Band 1 and Lower Band 2 streams (L[k] -> link_L_to_C[k][s] -> C[s]). Each L[k] builds its primes' lists locally (KERNELS.md §1.1-1.2) and streams each bucket to the Score Node owning its sub-band; s is fixed per bucket, so there is no per-hit routing. Full pages cost 1.05 Ir per 8 B entry (Band 1 uint32_t delta runs: 0.525 Ir per hit) inside C_HIT_LO and `C_B2_INT_*`. A stream (L[k], C[s], kind) is one continuous sequence of pages: bucket headers (row base, log p weight, delta-run restart) are inline records, +2.05 each inside C_B1_ROW/`C_SB_ENTER_*`, so pages fill across bucket and prime boundaries and only a stream's last page is partial. With at most one partial page per (L[k], C[s]) pair and stream kind, the model charges 8 stream kinds: 8 * 2^{36} * 2^{36} * 4,130 Ir in misc (misc <= 2^{73.366904} u in total).
4. Scan and cofactorisation. After all bands and streams, each C[s] runs the read-only scan8 pass over the logical cells of its rows and hands survivors to Stage B on the same node (KERNELS.md §1.4, §3).
5. Setup broadcasts. Before collection Score Nodes receive init_a[] and the a(ai) vectors (`18 |E_a+|` B), List Nodes the a-tables, ai_of_chord[] and the sub-band map, via link pages at 1.05 Ir per 8 B word. The model charges the Score Node copies as `3 N_sc |E_a+|` Ir in misc (18/8 * 1.05 = 2.37 <= 3 Ir per a per node) and the List Node copies as the 6 * 2^{36} * N_a Ir term of the lists setup (ins_pre: v23b's 4 Ir per a per node for the a-tables plus 2 for ai_of_chord[] and the map), both far below the totals.

There is no passive storage, linked page chain, global page counter or fallback pass: every record is applied when its page arrives, and all row memory is allocated once, before collection.

## 3. Other Single-Worker Working Sets (< 2^{64} B)

1. Band 1 / Lower Band 2 list builders (on L[k]): worst case 1 prime (x4, B_a = 4, N_{a,sh} = 2^{46.189}): <= 2^{52.535} B (b2_build_1p_ram_log2; incl. the ai_of_chord[] and kta_arr[] arrays of the kta kernel); with the shell arena <= 2^{57.690} B (b2_1p_ram_log2).
2. Stage-B P_min = 24 g_rec batched Bernstein SRT (0.17 cap): SP = 64,388 limbs, batch 8,192 8-limb leaves: 1.5 MB.
3. 1-owner 8-vec Z[omega] BW LA (bw = (1024, 48)): <= 2^{59.532} B.
4. 1-owner split batch (SPLIT_Q = 2^{46}, 56 B records): <= 2^{51.808} B.
5. 1-owner boot tree (x_EA = 66.3438, conservative 0.30 cap): <= 2^{63.137} B (v23b's). The boot wave it strips holds at most 2^{44} + 144 kept candidates (filled lattice by lattice until >= 2^{44}; ADAPTIVE.md §1.2), each stored as its vector (6 + 6 coordinates of bit length < 128 / < 160 by the pre-norm gate, 216 B), its |N_g| (< 2^{1974.26} for every gated vector, bt_ng_hi_bits, 247 B) and its lattice's position in the wave (5 B), plus the exponent e of each lattice that contributed a candidate (32 B, at most 2^{44} lattices): <= 2^{44} x 468 + 2^{49} B <= 2^{53.0} B, the same order as v23b's wave of 2^{44} single candidates.

## 4. Total Machine Storage (< 2^{100} B, pointwise) and Sensitivity

- Total (outward, input-independent; stor_bound.py, exact rationals, run by v25_verify.py check 8 and read by the model). Lattice-point counts by cube packing (`#(K cap Z^n) <= Vol(K + [-1/2, 1/2]^n)`; an ellipsoid of radius R needs radius R + h, h the largest cube-corner norm: h/R = 0.00727 on the a side, 0.00548 on the b side); the cone K_a by the overlap count of its six images under +-S^k (they meet only on the four walls, each a rank-5 lattice); active sub-bands by embedding each in 64 Z x Z^5 (incl. the 64-alignment waste at both chord ends); the strides exactly by levels, 2^{k_s} = 2^{35} + sum_{k=36}^{50} 2^{k-1} [k_s >= k], with [k_s >= k] <= [u_sb >= t_k] for the largest grid point t_k with 2 CA(t_k) <= 2^{k-1} (CA a monotone upper bound of cap). Results: `|E_a| <= 2^{48.274}`, `|E_a+| <= 2^{48.296}`, sub-bands <= 2^{46.689}, score rows <= 2^{98.398} B; per Score Node <= 2^{62.417} B < 2^{63}; E_0 <= 2^{63.457} B; L[k] <= 2^{60.014} B; machine total with every node at its provisioned size plus the one-owner LA, split and boot-tree sets (rounded up to 2^{60}, 2^{52}, 2^{64}) <= 2^{98.667} B < 2^{100} (ram_log2). The total sums every set over all phases (setup, collection with all tiers overlapping, scan and Stage B on C[s], one-owner split, LA, descent), so phase overlap does not matter. Row memory is fixed by E_{12} and the capacity rule, not by record counts, so storage_cap_abort = 0.0.
- Replays. v20_lat_b2.py replays the b_tab bit packing and 2^{35}-block addressing at production width and the record paths E_0 -> link_E_to_C -> C[s] and L[k] -> link_L_to_C -> C[s] against a reference score array on scaled parameters (16 Score Nodes, 208 bands, 2,331 pages, 0 errors). It keeps each row as its own array, so it checks record format and page flow, not strides; the stride and capacity layout rests on the bounds above.
- Sensitivity (part="sensitivity"): plain_dickman_rho 2^{84.05044} (exp_run 85.408891); conservative_lat_b2_plus10 (C_LAT_LEAF + 10 Ir) 2^{84.455107} (85.813558); conservative_srt_030_cap (g-SRT cap 0.30 vs 0.17) 2^{84.223348} (85.581799); de_bruijn_tighter_cap (cap_scale = 0.80) 2^{84.187852} (85.546303); flat_shared_arena_ref (Band-1 hit at 2.65 Ir) 2^{84.177673} (85.536125).
