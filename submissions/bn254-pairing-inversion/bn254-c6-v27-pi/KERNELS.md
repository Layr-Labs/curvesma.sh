# KERNELS.md: Scalar ARMv8.1-A Integer Kernels with Disclosed FEAT_LSE STADDH

All inner loops use scalar general-purpose-register ARMv8.1-A integer instructions (-march=armv8.1-a -mgeneral-regs-only, simd = 0; no NEON/SVE, DC ZVA, fp64, TABM or external C/Callgrind measurements; complete opcode count, verified in audit_bn_cm.py), plus the disclosed FEAT_LSE atomic halfword add STADDH Ws, [Xn] (32-bit alias of LDADDH Ws, WZR, [Xn]; scalar registers; base-register [Xn] addressing only, no [Xn, Xm, lsl #1]), priced at 1 scalar instruction = 1 / 20,000 units under COST_MODEL.md. Every score cell satisfies `init_a[ai] + sum_{p | N_g} floor(16*log2(p)) <= 32,768 + 16*529.15 = 41,234 < 65,536` (also on the SWAR coordinate box), so uint16_t accumulation never wraps in a logical cell 1 <= ai <= N_a(b) (guard and trap cells and the dummy sink collect unrelated writes and may wrap; they are never used as scores), and STADDH is bit-identical to ldrh; add; strh (staddh_16b_semantic_errs = 0 on 4,096 inputs).
