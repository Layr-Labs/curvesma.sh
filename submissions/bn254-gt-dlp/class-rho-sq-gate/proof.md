# bn254-gt-dlp: gated distinguished-point rho on Frobenius classes with a squaring branch

Submitted score: **time_log2 = 123.459421** (exact rational 123459421/1000000).

**The score is an expectation, not an every-run bound.** It is the expected total work over uniform
challenges and the algorithm's fresh coins, the same probability space in which the rules measure
success. One fresh 64-bit coin decides before any other work whether the run opens.
- A closed run costs 64 instructions and counts as a failure.
- An opened run costs 2^124.810812 units in expectation.
- On every run the work is at most 2^133.287917 units, enforced by counters (section 4).

Success probability is at least 0.39 over uniform x and fresh algorithm coins, closed runs
included as failures, under the disclosed heuristics H1-H3 (section 6). Peak memory is at most
2^57.000001 bytes in one address space with 64-bit pointers. Preprocessing 2^23.478998 units,
included. No advice, nothing amortised, no production-size run.

This is a generic square-root method with explicit scalar AArch64 accounting.
It is not a finite-field sieve attack and is not a security estimate.
Notation: p, r, g are the protected modulus, group order and generator;
C = 20,000; N = (r-1)/12; lambda = p mod r; R = 2^14; N' = 4RN/(3R - 1).

## 1. Facts used (all checked by `experiment.py`, mode `algebra`)

- p and r are prime, p = 7 (mod 12), and p has order exactly 12 modulo r. So
  lambda is a primitive 12th root of unity mod r and lambda^6 = -1.
- On GT the Frobenius sigma(y) = y^p acts as y -> y^lambda. It has order 12 and
  sigma^6 is inversion. Every y != 1 has a class {sigma^k(y)} of exactly 12
  elements (a fixed point would need lambda^k = 1 with 0 < k < 12). There are
  N = (r-1)/12 classes.
- Tower: Fp2 = Fp[u]/(u^2+1), xi = 9+u, Fp6 = Fp2[v]/(v^3-xi),
  Fp12 = Fp6[w]/(w^2-v), so y = sum_{k<6} e_k w^k with e_k in Fp2. The pinned
  basis maps to it bijectively: e_k = (c_k + 9 c_{k+6}) + c_{k+6} u.
- sigma(y) = sum conj(e_k) gamma^k w^k with gamma = xi^((p-1)/6) = d + e u in Fp2.
  zeta = xi^((p^2-1)/6) lies in Fp and satisfies zeta^2 - zeta + 1 = 0.
- **Squaring.** sigma(y^2) = sigma(y)^2, so squaring maps classes to classes. GT has odd
  order r, so squaring is a bijection of GT and therefore permutes the classes. GT lies in
  the cyclotomic subgroup, where the Granger-Scott formula computes y^2 (`machine.md`).
- **Order of 2.** r - 1 = 2^28 3^2 13 29 983 11003 237073 405928799 1670836401704629
  13818364434197438864469338081. The order of 2 mod r follows from this factorisation, and
  2^t lies in the order-12 group generated by lambda only if t is a multiple of a number
  above 2^243.7263.

**Class keys.** Write e_1 = a + b u and B = a d + b e. Then the real part of the
w^1 coefficient of sigma^k(y) is

    V_{2j} = a zeta^j,   V_{2j+1} = B zeta^j   (j = 0..5).

Proof: sigma(y) has w^1 coefficient conj(e_1) gamma, whose real part is B;
sigma^2 multiplies that coefficient by gamma^(1+p) = zeta, and induction gives
the rest. Since zeta^3 = -1, zeta^2 = zeta - 1, zeta^4 = -zeta and
zeta^5 = 1 - zeta, all twelve values come from **4 multiplications**
(a d, b e, a zeta, B zeta) and 9 additions or negations. They also satisfy
V_k(sigma(y)) = V_{k+1}(y) (indices mod 12).

**Selector.** Values are compared as their stored Montgomery residues (a
bijection of Fp, so the 12-element multiset is still a class invariant). If the
minimum is attained once, K(y) is that value and k*(y) its index; otherwise y has
a **tie**. Then K is constant on a class and k*(sigma^j y) = k*(y) - j. So
c(y) = sigma^{k*(y)}(y) is the same element for every member of the class: its
canonical representative.

## 2. Algorithm

Parameters: R = 2^14 table indices, window w = 24, A = 8 probes, distinguished
bits b = 87, one branch bit, trail cap L_cap = 2^94 slots. Run caps: M_cap walk slots
(section 4), ST_max = 2^50 trail starts, D_max = 2^50 reports, REC_max = 16 recoveries.

0. **Gate.** Before any other work, read one 64-bit word u of fresh coins. If u >= K, stop and
   return no answer; this costs 64 instructions and is a failure. Otherwise the run is **opened**
   and continues with step 1.

K = 7229537559736918267

   K is the least integer with (K/2^64) x 1043455/1048576 >= 0.39; the experiment checks K and K - 1
   in exact integers. K/2^64 = 0.391915 (rounded up).
1. **Input.** Decode z and check z != 0 and z^r = 1. If z = 1, output x = 0.
2. **Table.** For h < R draw uniform scalars u_h, v_h from the algorithm's ordinary fresh independent coins (64 bits per load, one RNDR with its status branch, 16 instructions per 64-bit word everywhere) (254-bit draws of 4 words, rejection,
   at most 128 draws each) and set T_h = g^{u_h} z^{v_h}. Store
   TW[h][k] = sigma^{-k}(T_h) and EX[h][k] = (lambda^{-k} u_h, lambda^{-k} v_h)
   mod r for k < 12.
3. **Hash.** Read two 64-bit words of fresh coins as salts s1, s2. khash(K, s) is the splitmix64 finalizer chained
   over the four words of K starting from s. Word w1 = khash(K, s1) gives the index
   h(K) = w1 mod 2^14. K is **distinguished** when bits 14..63 of w1 are zero and the
   low 37 bits of w2 = khash(K, s2) are zero (87 bits). Bit 63 of w2 is the **branch bit**
   b(K): the class of K is a squaring class when it is 1.
4. **Trails** (run one after another). Draw (alpha, beta) uniform mod r from fresh coins, as in step 2, and set
   y = g^alpha z^beta. On a tie, drop the trail. Otherwise put the window = (K(y)).
   Then repeat:
   - If K(y) is distinguished, **report** it (step 5) and end the trail. If the trail
     has used L_cap slots, end it without a report.
   - For a = 0..7: if a = 0 and b(K) = 1, compute y' = y^2 by the cyclotomic squaring with
     increment (alpha, beta) (one squaring slot); otherwise compute
     y' = y * TW[(h(K)+a) mod R][k*(y)] with increment EX[same entry] (one multiplying slot).
     - On a tie at y', end the trail.
     - If the hash word w1 = khash(K(y'), s1) equals one of the 24 hash words stored in
       the window, reject this probe. Equal keys give equal hash words, so every true
       window repeat is caught; a 64-bit hash collision adds a spurious rejection with
       probability at most 24 x 2^-64 per slot (H2), which is counted in nu.
     - Otherwise accept: add the increment to (alpha, beta) mod r (a squaring doubles
       them), set y = y' and append K(y') to the window (keep the last 24).

     If all 8 probes are rejected, end the trail.
5. **Report and recovery.** Set (alpha_c, beta_c) = lambda^{k*}(alpha, beta) mod r.
   These are the exponents of the canonical representative c(y). Look K up in an
   ordered store keyed by the full 4-word K.
   - If K is absent, insert (K, alpha_c, beta_c).
   - If K is present with (alpha', beta') and beta' != beta_c, set
     x = (alpha_c - alpha')/(beta' - beta_c) mod r and check g^x = z on all 12
     coefficients. If the check holds, output x and stop.
   - Otherwise continue.
6. **Stopping.** Trails follow one another until step 5 outputs x. There is no step budget.
   The run stops without an answer, a failure, as soon as one counter reaches its cap: M_cap
   walk slots (tested in every slot), ST_max trail starts, D_max reports or REC_max recoveries.
   No restart or amplification is performed.

**Invariant.** y = g^alpha z^beta throughout, because
sigma^{-k}(T_h) = T_h^{lambda^{-k}} and y^2 = g^{2 alpha} z^{2 beta}. Also c(y) = g^{alpha_c} z^{beta_c}.

**The walk is on classes.** Let c = c(y) and k = k*(y), so y = sigma^{-k}(c). Then
y' = sigma^{-k}(c * T_h), and the class of y' is the class of c * T_h. That class
depends only on the class of y and the index used. A squaring gives y^2 = sigma^{-k}(c^2), in
the class of c^2. So whenever the first probe is accepted, the next class is
F(C) = class(c(C)^2) for a squaring class and F(C) = class(c(C) * T_{h(K(C))}) otherwise, a
function of the current class C alone (K, h and b are functions of the class). A later probe is used only when F(C) is among the last 24
classes of the trail (section 7).

**Correctness.** Suppose two reports have equal K and come from the same class.
Then their canonical representatives are the same element, so
alpha_c + x beta_c = alpha' + x beta' (mod r), which gives the formula in step 5.
Every output is checked against z, so a false key match (equal K, different
classes) only costs a recovery and can never produce a wrong answer.

## 3. What happens after two trails meet

Suppose a later trail reaches a class C already visited by an earlier trail (a **meeting**). That
earlier trail ended (trails are sequential), normally with a report. From C both
trails apply F, except when a window rejection happens in one of them and not the
other. The windows hold different older keys for at most 24 further steps, so the
trails stay together unless such a rejection occurs in that stretch. The
later trail then reaches the earlier trail's distinguished class, the store finds
the key, and recovery outputs x.

**Degeneracy.** Given the true x, the walk depends on each start only through
alpha_0 + x beta_0, and on the table only through u_h + x v_h. Given those
values, each start's beta_0 is still uniform, because (alpha_0, beta_0) ->
(alpha_0 + x beta_0, beta_0) is a bijection. Along a trail, beta_c = lambda^{k*} (2^t beta_0 + c)
with t the number of squarings and c fixed by the path, an affine map of beta_0 with invertible
slope. So beta_c of the later trail is uniform and independent of beta', and beta' = beta_c has
probability exactly 1/r.

**A meeting that does not end the run.** Each row bounds the probability that a meeting fails to
produce the output. The run then simply continues to the next meeting, so these events cost time,
never correctness, and they are part of what H1 measures (section 6).

| | Cause | Bound |
| --- | --- | ---: |
| M1 | the earlier trail reached L_cap without a distinguished class ((1-2^-87)^(2^94) <= e^-128, H2), or the later trail is cut: its length is its own part before the meeting plus the earlier trail's remaining path, so it exceeds L_cap = 2^94 only if one part exceeds 2^93 (2 e^-64) | 2^-91 |
| M2 | a window rejection in one trail within 24 steps after the meeting: <= 2 x 24 x nu, nu <= 1.0002/(12R) + 24/N + 24 x 2^-64 (section 7) | 2.5e-4 |
| M3 | one of the two trails is caught by an undetected trap (2^94 x 2^-163.5 = 2^-69.5) or loses all 8 probes (2^94 x nu^8 <= 2^-46.6) | 2^-45 |
| M4 | a tie in either trail: at most 2^95 states at the H3 rate | 2^-100 |
| M5 | beta' = beta_c (exact, 1/r); or a stored key from a different class shadows the true one. Two classes have equal keys with probability at most 144/p, and equal keys have equal hash words, so the pair matters only when that one key is distinguished (2^-87, H2). Over all pairs of the at most M_cap classes of a run: (M_cap^2/2) x (144/p) x 2^-87 | 2^-67 |

Together below 3e-4 per meeting.

## 4. Work ledger

The unit is 20,000 scalar AArch64 instructions. No operation is priced at one
unit. Instruction counts come from `machine.md`:
- Fp12 product: 13,843 executed instructions.
- Cyclotomic squaring: 5,238 executed instructions.
- Selector: 1,067 executed instructions.
- Per-slot glue (branch choice, hashing, window test, table addressing, exponent update, counters,
  control): 366 executed instructions, the same on every path through a slot.

So a multiplying slot costs 15,276 instructions and a squaring slot 6,671. Every slot is charged
the squaring price, and every multiplying slot also pays the surcharge 13,843 - 5,238 = 8,605.

  expected number of walk slots of an opened run.

    class's branch bit is 0. That bit is exactly uniform over the salt s2 (khash is a bijection of the salt
    for a fixed key) and, by H2, independent of everything the run did before reaching the class. Whether
    the run reaches a given slot is decided by that earlier history. So half of these slots multiply in
    expectation (Wald's identity): at most E_slots/2.

    (section 3), so fewer than 2 trails meet an earlier one in expectation; a trail meets itself with
    probability below 2^-76 (H1: length squared over 2N) or enters a trap with probability below 2^-69
    (section 7), over 2^38.68 trails in expectation. The allowance is 2^96 slots, and every one of
    them is priced as a multiplying slot.

## 5. Success probability

**An opened run fails only by reaching a cap**, because it otherwise continues until it outputs x, and
every output is checked. The probability that it reaches a cap:

| | Cap | Bound |
| --- | --- | ---: |
| F1 | M_cap walk slots. By H1 the expected number of slots is at most E_slots, and M_cap = 2^8 E_slots (Markov's inequality) | 2^-8 |
| F2 | 2^50 trail starts or 2^50 reports. A new class is distinguished with probability 2^-87 (H2), so the expected number of reports is at most E_slots/2^87 + 8 = 2^38.68; each trail ends with at most one report, a tie, 8 rejections or the trail cap, so the same figure bounds the expected trail starts. Markov's inequality for both caps gives 2^-10.32 | 2^-10 |
| F3 | everything else: a scalar draw fails 128 times (at most 2^52 draws, each 0.2439^128 < 2^-260); 16 recoveries without an output (that needs a false key match, below 2^-67 for the whole run by M5); the two salts are equal (2^-64, which changes the distinguished rate) | 2^-20 |

So an opened run succeeds with probability at least 1 - 2^-8 - 2^-10 - 2^-20 = 1043455/1048576.
The gate coin is independent of the run, so the algorithm succeeds with probability at least
(K/2^64) x 1043455/1048576 >= 0.39. A closed run is a failure and is counted as one.

The cap is the only way an opened run fails, and a run that reaches no meeting stops at the cap: this is
event F1 and is inside the 2^-8. No part of the argument assumes that a cap is reached rarely for any
other reason.

The identity input returns 0 directly in an opened run. For z != 1 the walk depends on z only through
the uniform u_h + x v_h, so the bounds hold for every z, not only for uniform z.

## 6. Heuristics, support and limits

**H1 (mean stopping time).** An opened run that is never capped outputs x after at most
(11/10) sqrt(pi N'/2) walk slots in expectation.
- *Where it is used:* the two walk rows of the expectation column, and F1.
- *Why sqrt(pi N'/2).* A random map on N' points produces its first repeated point after sqrt(pi N'/2)
  new points in expectation. The run then needs the later trail's remaining path to the distinguished
  class, about 2^87 slots against 2^125, and meetings that fail (below 3e-4 each).
- *Why N'.* Two distinct classes can have the same image only if at least one of them
  multiplies, because squaring permutes the classes. Each class squares with probability
  s = 1/2. So two classes have the same image with probability about
  (1 - s^2 - (1 - s)^2/R)/N: the term (1 - s)^2/R removes every same-index pair, and
  N' = N/(3/4 - 1/(4R)). This is the usual loss of mixed walks against adding walks, priced here.
- *Why 11/10.* The toy runs below measure the stopping time of the complete algorithm directly: the
  pooled mean is 1.0508 times sqrt(pi N'/2) with standard error 0.0086. The allowance 1.10 is that mean
  plus more than 5 standard errors; the experiment checks this. The toy figure contains the toy's
  larger overheads: its distinguished rate is 1/64, so the path from a meeting to the distinguished
  class is about 1.5% of a run, against 2^-38 of a run in production.
- *Limit.* It is measured at N' near 2^23 and used at N' = 2^250.4. If the true mean were larger by a
  factor f, the expected work would grow by f and F1 would become f 2^-8.
- *Context only, not a premise:* adding walks are studied in Teske, Math. Comp. 70 (2001) 809-825.

**H2 (hash fields and twists).** For distinct classes, the index, the 87
distinguished bits, the branch bit and the twist increment k*(c T_h) mod 12 behave as
independent uniform values, also given the run's earlier history. It is used for the expected
multiplying slots, the expected reports, trail lengths, nu and the trap sums.
- Each branch bit is exactly uniform over the salt.
- The twist increment is exactly uniform for a uniform GT element, because
  sigma(y) is uniform and shifts k* by one. Its independence from the index is the
  heuristic.

**H3 (ties).** A tie needs e_1 of the state to satisfy one of 8 linear conditions:
a = 0, B = 0, or B = zeta^t a for t = 0..5.
- A uniform element of Fp12 meets them with probability at most 8/p, but GT is a
  subgroup, so a rate of at most 2^-195 per state is assumed, not proved.
- It is used only in M4 and F2, with a margin above 2^90. Ties end the trail. They never
  produce output.

**Toy evidence** (`toy_offline.json`, and mode `toy` of `experiment.py`, which runs `toyrho.py`). The same
`ClassRho` code runs the whole algorithm, to its output, in two families of BN-shaped fields. Both
have q = 7 (mod 12), xi = a0 + u neither a square nor a cube in Fq2, and a prime
r' with q of order 12 mod r'.
- **BN family:** q = p(-41) = 99,286,339 and r' = r(-41) = 99,276,253 from the BN
  polynomials, so q is close to r' as in production. xi_toy = 1+u.
- **Generic family:** r' = 67,108,933 with q = 17,600,215,022,347, so q is much
  larger than r'. xi_toy = 2+u.

**What the toy shares with production.** The selector, the window of 24, the 8
probes, the squaring branch (bit 63 of the second hash word, probe 0 only), the
canonical-exponent recovery with its check, the hash function, the stopping rule (run until
the output or the slot cap) and the trail cap ratio L_cap = 128/theta.

**What differs, stated so the scope is clear:**
- (a) R, the distinguished density (6 bits), and the field sizes.
- (b) Keys are ordered as plain residues, not Montgomery residues. Both orders are
  bijections of Fq, so both give class invariants.
- (c) The distinguished test reads the 6 bits of hash word 1 just above the index
  bits. Production reads 50 bits of word 1 and 37 of word 2. The branch bit comes from
  word 2 in both.
- (d) The store is a hash map keyed by the full key, not a red-black tree.
- (e) The toy window compares full keys; production compares 64-bit hash words of the
  keys. They differ only on a 64-bit hash collision (at most 24 x 2^-64 per slot).
- (f) The toy squares with the dense product y * y. It has the same value as the
  cyclotomic squaring on GT, which the kernel test checks.
- (g) The toy has no gate and no start, report or recovery caps. Its slot cap is 64 sqrt(N'),
  not 2^8 times the mean allowance; no run reached it.

Seeds were fixed before the runs (instance i of table size R uses seed 2 x 10^7 + 1000 i + R), and

  largest run used less than 7 times the model mean; the production cap is at 2^8 times the allowance.
- *Branch balance.* The squaring share of all slots is within 0.001 of 1/2 in every row. The ledger
  charges the multiplying half plus the allowances of section 4.
- *Rejections* are below the printed bound nu (section 7, at each toy's R and N) in every
  row. With squaring, only two consecutive multiplying steps can form a 2-cycle.
- *Trail starts per slot* match the toy's distinguished rate 1/64, as H2 predicts for the report count.
- *Limits:* the runs support H1 and H2 only at toy scale. Extrapolation to N' =
  2^250.4 is the heuristic itself.

## 7. Deterministic cycles and the window

Write x_n = log_g(y_n) and m_h = log_g(T_h) = u_h + x v_h, which are uniform and
independent. A step gives x_{n+1} = x_n + lambda^{-k_n} m_{h_n}. A return to the
class of x_t after l accepted steps means

    lambda^s x_t = x_t + sum_h P_h(lambda) m_h,   P_h = sum over steps using h of zeta12^{-k_i}.

With the squaring branch a squaring step gives x_{n+1} = 2 x_n. If the l steps contain t >= 1
squarings, the return condition reads (lambda^s - 2^t) x_t = sum_h P_h(lambda) m_h. Here
each P_h collects the uses of h, each scaled by 2 to the number of later squarings, and
lambda^s - 2^t is nonzero mod r: t <= l < 2^94, far below 2^243.7263 (section 1). So the
return is either one linear condition with a nonzero coefficient on uniform values
(probability 1/r, covered by H1), or, if every P_h vanishes, it forces x_t = 0, the
identity, which is excluded. **A deterministic trap therefore contains no squaring step**:
every trap below is a run of multiplying steps, and the analysis of the plain walk applies
to it unchanged. We drop the extra factor (1/2)^l, the chance that l consecutive classes all
multiply, which only helps. The cases for multiplying steps:
- **A random coincidence.** If some P_h(lambda) != 0 mod r, the return is one linear
  condition on uniform independent m_h: probability 1/r per pattern. H1 covers it.
- **A deterministic trap.** If all P_h(lambda) = 0, the return happens whatever the
  m_h are. If moreover s != 0, then x_t = 0, which is the identity and is excluded.

**From mod r to Z[zeta12].** Map Z[zeta12] -> Z/r by zeta12 -> lambda. The kernel is
a prime of norm r. Each P_h is a sum of at most l roots of unity, so every complex
embedding has absolute value at most l, and |Norm(P_h)| <= l^4. A nonzero P_h in the
kernel therefore needs l^4 >= r, that is l >= 2^63.399. So for l < 2^63 a trap needs
P_h = 0 in Z[zeta12] for every h used. A single root of unity is not zero, so **every
index in a trap is used at least twice**.

**Trap probability.** Let a trap of length l use d distinct indices (d <= l/2). Under
H2 the indices fall in a fixed set of d values with probability (d/R)^l. For each
index, the twist at its last use is a fresh uniform shift, so the sum over that index
vanishes with probability at most 1/12. Hence

    E(l) = sum_{d=1}^{min(l/2,R)} C(R,d) (d/R)^l 12^-d

bounds the probability that a trap of length l starts at a given step.
- E(2) = 1/(12R). This is the two-cycle: same index twice with twists 6 apart.
- sum_{l=3..24} E(l) = 1.02e-4 x E(2).
- sum_{l=25..512} E(l) = 2^-163.54.
- For l > 512: C(R,d) <= (eR/d)^d gives each term at most (e/12)^d (d/R)^(l-d)
  <= 2^-(l/2) when d <= R/2. Terms with d > R/2 are at most (e/12)^(R/2) < 2^-17000.
  So E(l) <= (l/2) 2^-(l/2) + l 2^-17000. The first part sums to below 2^-246; the second,
  summed over all lengths below 2^63, stays below 2^126 x 2^-17000.
- Patterns of length 63 bits or more are longer than a trail (L_cap = 2^94 slots bounds every trail, and such a trail is a capped trail).

**How the window handles traps.**
- *Up to 24 steps:* closed within 24 steps, the trap is caught by the window and
  escaped by the next probe.
- *Per-step rejection rate:* nu <= sum_{l=2..24} E(l) + 24/N + 24 x 2^-64 <= 1.0002/(12R) + 24/N + 24 x 2^-64.
- *Longer traps:* a trapped trail uses at most L_cap slots, all inside the slot cap. A trap
  of length 25 to 2^63 starts at a given step with probability at most 2^-163.5 (the sums
  above), so at most 2^94 x 2^-163.5 = 2^-69.5 per trail (M3). A trapped trail ends at the trail
  cap; its slots are counted by the run slot counter like all others.

## 8. Evidence and reproduction

`experiment.py` (standard library) is the one declared experiment.
- **kernels:** generates the priced programs, executes them, checks them against
  big-integer arithmetic (the cyclotomic squaring against the dense square on GT
  elements) and prints the counts used above. The glue runs on the multiplying and the
  squaring path, across the carries of its counters and on both sides of both caps.
- **algebra:** checks section 1 on the pinned constants. That covers the step's class
  invariance, the squaring step's class invariance, the factorisation of r - 1 and the
  order of 2 mod r.
- **ledger:** recomputes every integer in section 4, E_slots, M_cap, K (and that K - 1 fails),
  the failure budget, the score and the trap sums.
- **stated_figures** (every mode): reads `submission.json`, this file and `machine.md`, and checks
  that the claim score equals the computed score, that every figure and table row above appears as
  computed, and that the pooled toy mean plus 5 standard errors is within the allowance of H1. Any
  stated-figure or kernel mismatch makes the experiment exit with status 1.
- **toy:** runs the algorithm to its output in the BN-family toy
  q = p(-15), r' = r(-15), with 8 to 48 instances (48 initially) and R in {16, 64}. It prints the
  mean number of slots at the stop over the model mean, with its standard error. At 48 instances
  that standard error is about 0.07, so one run does not test the allowance. The decisive statistics
  are the offline runs of the table above.

Offline, the table above was produced with the same `ClassRho` code. A small driver
called toyrho.py's `bn_toy` or `find_toy` and `ClassRho.run` with the seeds stated in
`toy_offline.json`, which holds the slot count of every instance.

**Limitations.**
- The score is an expectation. An opened run costs more than the score: 2^124.810812 units in
  expectation and up to 2^133.287917 units.
- The success bound and the expectation are heuristic (H1-H3).
- The instruction counts are executed counts of generated straight-line programs on an
  interpreter, not timings.
- Nothing runs at production size.
- Finite-field sieve methods are expected to be cheaper and are not used here.
