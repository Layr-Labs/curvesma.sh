### 8.1 The enumeration in integers (`pt_orb`, `pt_geo`, `pt_rows`, `pt_e3`, `pt_cands`)

An orbit is an LLL-reduced basis `b_0..b_11` of `Lambda_p`; `Q(x) = sum_k E_k`, `E_k = r_k (x_k - c_k)^2`, `r_k = d[k+1]/d[k]`, `c_k = -sum_{j>k} mu_{jk} x_j`. The PT functions take an orbit `(p, B, d, lam, T)`, i.e. the Bareiss integers `d[0] = 1`, `d[k+1] = det Gram(b_0..b_k)`, `lam[j][k] = d[k+1] mu_{jk}` (`j > k`) returned by `bareiss_lll_12d` (`ret_dl`) for the orbits of the HT replay, and `T = 112,218,575,642,218` (`T12_prod = round(1764 * 568.83^2 * 196608)`). `E = {x != 0 : Q(x) <= T, the first nonzero coordinate of x (from index 11 down) positive}` is the ball of the unchanged tree, one of `x` and `-x` (the half-space entry of `KERNELS.md` §1.3). With `>>` floor shift, `//` floor division, `Q32 = 2^32` (`pt_orb`, as in the HT-replay loop of `v20_lat_b2.py`):

    MU[j][k] = (lam[j][k] << 32) // d[k+1]      EK[k] = min(2^64-1, (d[k+1] << 64) // (d[k] T))
    GW[k] = ceil(2^38 d[k] T / d[k+1])          CV[k] = isqrt(ceil(d[k] T / d[k+1])) + 1 + sum_{j>k} ceil(CV[j]/2)
    K_k = 1 + sum_{j>k} CV[j]                   en_k(D) = (((max(D - K_k, 0) >> 13)^2 EK[k]) >> 64)
    Lam(M) = isqrt(M << 52) + 1                 (Direct Q12 table, entry M-1)

A *level-3 node* is a prefix `x_{>=3}` accepted by levels `11..3`; it hands down `C2 = -sum_{j>=3} MU[j][2] x_j`, `c1b`, `c0b` (same sums with `MU[j][1]`, `MU[j][0]`) and `rem3 = 2^38 - sum_{j>=3} en_j(.)` (`pt_node_data`; `//@seg handoff3a/b/c`).

*E3 list* (`pt_e3`; `//@seg e3_*`). `cell3 = (C2 >> 22) & 1023`, `bin3 = rem3 >> 26` (`<= 4096`), `top3 = ((bin3+1) << 26) - 1` (`2^38` if `bin3 = 4096`), `[pa, pb] = [cell3 << 22, ((cell3+1) << 22) - 1]`, `dm(j) = dist(j << 32, [pa, pb])`, `s(j) = en_2(dm(j))`. `J3 = {j in [-120, 120] : s(j) <= top3}` (an interval, asserted), `binp(j) = min((top3 - s(j)) >> 28, 1023)`; list `jlo, binp(jlo) << 8, ...`, sentinel `2^31`, at index `cell3 << 13 | bin3` (`1024 x 4097` entries).

*Candidates* (`pt_cands`; `//@seg node_L2`). `s2 = C2 >> 32`, `j = jlo + i`: `x2 = s2 + j`, `C1 = c1b - MU[2][1] x2`, `c0 = c0b - MU[2][0] x2`, `s1 = C1 >> 32`, `d0 = c0 - MU[1][0] s1`, `t0 = d0 >> 32`, `f1 = (C1 >> 24) & 255`, `f0 = (d0 >> 24) & 255`; directory index `f1 << 18 | binp << 8 | f0` (`2^26` entries).

*Patch rows of a key* (`pt_geo`, `pt_rows`; `//@seg pair_*`, `gen_neg`, `gen_pos`, `rows_*`). `top = ((binp+1) << 28) - 1` (`2^38` if `binp = 1023`), `[p1a, p1b] = [f1 << 24, ((f1+1) << 24) - 1]`; for `y` from `0` downwards and from `1` upwards until `rem < 0`: `dmin(y) = dist(y << 32, [p1a, p1b])`, `rem(y) = top - en_1(dmin(y))`, `W(y) = Lam(((rem(y) GW[0]) >> 64) + 1)`, `blo(y) = -MU[1][0] y - K_0 - W(y) + 2^32 - 1`, `bhi(y) = -MU[1][0] y + K_0 + W(y) - 1 + 2^24`, `lo(y) = (blo(y) + (f0 << 24)) >> 32`, `hi(y) = (bhi(y) + (f0 << 24)) >> 32`; the row exists if `lo <= hi`. `N(node) = {(x2, s1 + y, t0 + q) : j in J3, row y of the key of j, lo(y) <= q <= hi(y)}`, each triple once. The mod-3 wheel `BAD(v mod 3)` acts on `N` as on the old leaves. Row and chain encodings, the tails and the builders are in `KERNELS.md` §5.

### 8.2 Completeness (Theorem A), overshoot (Theorem B), the certificate `pt_cert`

Checks (integers): **C1** `2 |lam[j][k]| <= d[k+1]` (`j > k`: `|mu| <= 1/2`, `|MU| <= 2^31`); **C2** `2^39 <= EK[k] < 2^64 - 1` and `0 < d[k+1] < d[k] T`, `k = 0, 1, 2` (`a_k = r_k/T < 1`, `EK[k]` unclamped); **C3** `en_1(120 Q32 + 1) > 2^38` and `en_2(120 Q32 + 1) > 2^38`. **Interface hypothesis IH** (the package's own bound for its fixed-point levels): for every prefix accepted by levels `11..3`, `sum_{k=3}^{11} (2^38 E_k/T - en_k)/2^38 <= D1`. ### 8.3 Fallback orbits

An orbit with `ok = False`, a failing `orbit_check` (`GX[1] <= 3972`, `EK[1], EK[2] >= 2^39`, `GW[0] < 2^63`: the windows of the mod-3 tables) or a certificate excess above the gate runs the unchanged tree: segment prices `FP_CL`, the unchanged leaf price, no build. It pays the certificate and `orbit_check`; the build is charged to every orbit (8.4). No table is built before either test: `pt_cert` runs before `pt_orbit_build`, whose first segment is `orbit_check`, and a failing gate returns after 7 ops without calling any builder (part `pt`, key `drivers/gate_fail`). **Charge.** `c_lat_use = C_LAT_LEAF + PT_FB_EXC` (`compute_ledger`) on every leaf, `PT_FB_EXC = 0.022`, `C_LAT_LEAF = 8.220`, i.e. `8.2420` per leaf. The pool stores for every draw the price `x` of its leaves under the tables (all 4096 draws run the tables), `C_LAT_LEAF` bounds the production-weighted mean of `x` (8.4), and an orbit that falls back (a failing certificate, certificate gate or `orbit_check`) costs `P_old(o)`, the price of the unchanged tree, instead of `x(o)`. So the production-weighted mean price per leaf is at most `C_LAT_LEAF + F`, `F = E[(P_old - x)^+ 1_fail]` over all leaves (`1_fail`: the orbit falls back), and `PT_FB_EXC` bounds `F`. Let `e(o)` be the extended failure variable of the stored table: the certificate excess, set to 255 (above every gate) when `C1..C3` or `orbit_check` fail. Then `1_fail = 1[e > G]` for the design gate `G = 0.35 %`, hence `1_fail <= 1[e > G_S]` for the stress gate `G_S = 0.3 %`, and `F <= F_S = E[(P_old - x)^+ 1[e > G_S]]`. None of the 4096 stored draws has `e > G`, but 7 have `e > G_S`: their `P_old` has the weighted mean 14.324 (largest 15.062), their `x` lies in 8.845 .. 10.127. The pool's estimator on `(P_old - x)^+ 1[e > G_S]` gives `F_S` = 0.00613 +- 0.00234; estimate + 3.78 SE `= 0.01498`; as a diagnostic margin, the estimate times the Poisson upper-limit factor of 7 events (3.353) `= 0.02054`; `PT_FB_EXC = 0.022` is at least both (`1.07x`). A calibration over 16 stored runs of the same kind as H-PT (b), not an algorithmic guarantee; the other gates, the mutants and the checks: `KERNELS.md` §5.6.

## 10. KNAP: Boot-Root Children Priced by the Gate Knapsack (No New Premise)

**Setting.** A boot root (`boot = [185, 80, 11, 1]`, `ea = [3, 1225]`) is a kept boot-lattice vector that is *usable*; the miniature `joint_ea_mini_audit` (`boot_dp.py`) applies the test. **(G)** Its rough part `cof` (the product, with multiplicity, of its prime factors above `2^{x_EA}`, `x_EA = 62.9375`) is `<= 2^{tau}`, `tau = 1225` (the early abort of `ADAPTIVE.md` §1.2, before ECM and any descent, which the survivor count, the ECM price and the usable mass of `evaluate_descent` already assume, `ADAPTIVE.md` §5); all its prime factors are `<= 2^{185}`; it has `<= 11` prime factors in `(2^{59}, 2^{n_A}]`, `n_A = 164` (A children), and `<= 1` in `(2^{n_A}, 2^{185}]` (B child). **(R)** A child of size `s` in the row `[b_lo, b_hi)` of `plan59` (side `g`; its 31 rows tile `[59, 215)`, `rows_tile_ok`) costs that row's values, unchanged: expected work `W` (with its subtree), Boole failure bound `PHI`, slots `CC`. **(A)** Works add and failure bounds add (union bound, no independence).

**Pricing.** Before, each of the `12` children was charged the worst row below its size cap (kept as `w_dag_one_wc`, `phi_dag_one_wc`, `c_det_one_wc`, `e_runs_per_log_wc`; caps `11 x 164 + 185 = 1989` bits against `tau = 1225`). Now `w_dag_one`, `phi_dag_one`, `c_det_one` are `min(M_V, worst row)`, rounded outward, for `V = W, PHI, CC` separately. `M_V` is the maximum of `sum V[r_i]` over all multisets of `<= 11` rows with `b_lo < n_A` (A) and `<= 1` row overlapping `(n_A, 185)` (B) for which the lower row ends `floor(b_lo)` (B: `floor(max(b_lo, n_A))`) of the rows with `b_lo >= x_EA` sum to `<= tau`; rows with `b_lo < x_EA` are free (their children are stripped with the small primes first), and rounding down only enlarges the set. `boot_gate_knapsack` computes `M_V` by an exact integer DP and returns an argmax; no monotonicity of `V` in the size is used (the row values are not monotone). Values and argmax rows: `ADAPTIVE.md` §5.

**Validity (deterministic).** (i) Every descending root has a configuration in the set `C` of (G). (ii) Each child size lies in one row, so the child costs `<= W[r]`, fails with probability `<= PHI[r]` and takes `CC[r]` slots (R). (iii) The feasible set of the DP contains the row assignment of every `c` in `C` (counts `<= 11` / `<= 1`; A rows `b_lo < n_A`; B rows overlap `(n_A, 185)`; every child above `x_EA` is charged `floor(b_lo) <=` its size, every child below `x_EA` nothing, and the sizes above `x_EA` sum to `log2 cof <= tau`), so `M_V >= V(c)` for every admissible root. (iv) With `wM = w_dag_one`, `phiM = phi_dag_one`: given its configuration a run fails with probability `<= sum PHI <= phiM` (Boole) and its descent costs `<= wM`; the runs are i.i.d. and `N`, the number of runs until success, is a stopping time, so Wald gives `E[N] <= 1/(1 - phiM)` and the expected work `<= tree + E[N] (trial/prob + over + wM)`, the evaluated formula. The bounds use the separate maxima `wM`, `phiM`; a joint maximum of the work and the failure bound of one configuration is not used. Used: (G), (R), (A); the previous pricing used (R), (A) and the child counts of (G), and the budget `tau` of (G) is the early abort that the model already used. **Not used:** monotonicity of the row values, independence of the children, any distribution of the children's sizes (a Mertens-type premise would be a new probabilistic premise). **Scope:** KNAP prices the children of the boot root, its prime factors above `2^{59}` (a child below `x_EA` uses none of the budget `tau`, the rough part `cof` of (G) being the product of the prime factors above `x_EA`; every child is priced by its row).
