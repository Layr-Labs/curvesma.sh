# STORAGE.md: Direct Live Score Nodes, 1-Hop 16 KiB Link Pages and the < 2^{100} B Storage Bound

Where the Band 1, Lower Band 2 and Lattice Band 2 data lives, how it moves and what moves cost. Every node is a flat 64-bit scalar machine with < 2^64 B of RAM, addressed by unit-cost ldr/str/ldp/stp/staddh/ldadd under COST_MODEL.md. Every cross-node byte goes through an explicit 1-hop 16 KiB link page copied by scalar ldp/stp (2,048 ldp/stp + 12 loop/setup = 2,060 instructions per page = 1.007 <= 1.05 Ir per 8 B word, as for v23b's L -> C and S -> C links), or, for Band 1 and Lattice Band 2, written directly into the link page by the producer's counted stores (KERNELS.md §1.1, §1.3). Figures are printed by model_bn254_v6.py (geometry) and checked by audit_bn_cm.py (ram_ok).

Score rows (truncated E_{12}: Q(a) <= 17/20, Q(b) <= 17/20, B_a = 2, BLK = 38). Each canonical b-vector with 0 < Q(b) <= 17/20 owns one row. Rows are grouped in sub-bands of W = 64 consecutive b_0 values on one (b_1, ..., b_5) chord (sb = b_0 >> 6, an arithmetic shift, so negative b_0 nest correctly: checked at b_0 in {-64, -63, -1, 0, 1, 63, 64, 559}). All rows of a sub-band share one stride 2^{k_s} bytes, k_s = max(38, ceil(log2(2 * cap))), so a sub-band is 64 * 2^{k_s} contiguous bytes aligned to 2^{38}-byte blocks, allocated whole. A deterministic greedy rule gives each next sub-band to the least-loaded Score Node, so every node holds at most the average plus one sub-band (64 * 2^{49} B). b_tab[b] stores `(s << 29) | row_block`, row_block = offset >> 38: 35-bit s in bits [63:29] ([0, 2^{35})), **bits [28:26] identically 0** because row_block < 2^{26} (blocks <= 2^{25.3921} < 2^{26}, cs_blocks_max = 44,031,851 < 67,108,864; max record byte address ((blocks - 1) << 38) + 2|E_a+| + 2 < 2^{64}). Having bits [28:26] = 000 lets E_0 compute `&ptrs[s] = x17 + 8*s` in a single shifted-register add `add x8, x17, x3, lsr #26` and `rec = (row_block << 38) + 2*ai` in a single `add x7, x0, x3, lsl #38` (KERNELS.md §1.3). b outside E_b (including Q(b) > 17/20) maps to b_tab = 0, the dummy sink: blocks [0, 2^{12}) of C[0] (`2^{50} B > 2 |E_a+|`), disjoint from every real row (real rows on C[0] start at block 2^{12}); sink writes are never read.

Index sets, out-of-domain lookups and row capacity. With x = (a_3, -a_4, a_5) and s_x = x_0 + x_1 + x_2, the canonical a lie in the closed cone K_a = {s_x >= 0, x_0 >= x_1, x_0 >= x_2}. E_a+ = K_a cap Z^6 cap {0 < Q(a) <= 17/20 + delta}, delta = 0.005, is ranked 1, 2, ... by (Q(a), fixed tie order) (ai); ranks up to `|E_a|` are the real a-set Q(a) <= 17/20. Band 1, Lower Band 2 and the lattice emitter all index this one ranked set. On E_0, `a_tab` uses exact mixed-radix linear packing over the full `E_{12} + delta` box (`|a_i| <= (416, 387, 362, 276, 276, 276)`, `prod_Ma = 79,151,674,016,786,875 < 2^{56.136}`), storing `a_tab[pack_a(a)] = ((2*ai) << 26) | k(a)` (`k in {0, 1, 2}` for `S a != a`, `k = 3` for the rank-2 fixed subspace `S a = a`) for all 6 orbit images of `E_a+` and `0` elsewhere (`a = 0` or `Q(a) > 17/20 + delta`, which writes trap cell `0` of its own row). `B_TAB[0..3]` uses 4 planes at stride `2^{59}` entries over the full `E_{12} + delta` b-box (`|b_i| <= (553, 514, 481, 367, 367, 367)`, `prod_Mb = 435,563,320,543,855,875 < 2^{58.596} < 2^{59}`), storing `b_tab[canon_sign(S^k b)]` on planes `k in {0, 1, 2}`, `b_tab[canon_S_sign(b)]` on plane `k = 3`, and `0` (C[0] dummy sink) for `b = 0` or `Q(b) > 17/20`. Every accepted lattice leaf has Q(a) + Q(b) <= 1 + eps_or with eps_or <= 0.0023389 <= delta / 2 (KERNELS.md §1.3, Theorem B), so any leaf hitting a real a in E_a+ and real b in sb has Q(a) <= min(17/20, u_sb) + eps_or with u_sb = max_{b in sb} (1 - Q(b)). Band 1 applies a row's hits up to the next prefix checkpoint, at most `D_B1 = ceil(ceil(|E_a| / 2) / 256) <= 2^{38.578}` cells past the row's logical end N_a(b); Lower Band 2 writes stop at namax <= N_a(min(17/20, u_sb)). So every row of a sub-band gets the exact count

cap(sb) = #{a in E_a+ : Q(a) <= min(17/20, u_sb) + delta} + D_B1 + 16

(one binary search per sub-band at b_tab build, inside the 50 V_b build charge), and every write of every tier for a b in E_b lands at a cell index < cap of its own row (records for b outside E_b go to the sink). Logical cells are [1, N_a(b)]; cells N_a(b) < ai < cap are the guard region: they may collect over-radius, checkpoint-overshoot or out-of-group writes and wrap, and are never used as scores, because a survivor with ai > N_a(b) is dropped by one compare before Stage B (KERNELS.md §1.4). v25_verify.py check 8 runs stor_bound.py and fd_bounds.py and asserts eps_or <= delta / 2 (row_capacity_guard_errs = 0).

## 2. Data Movement and Charges

Link machine model (declared, as v23b's link pages). Nodes are separate processors with private RAM. For every (producer, consumer) pair the schedule uses, one 16 KiB page of dual-ported memory is part of both processors' physical memory and is mapped at a fixed address in each (link_E_to_C[s] occupies the exact 16,384 B interval `[base + (s << 15) + 8, base + (s << 15) + 16392)` inside each 32 KiB stride of E_0's link window, with `base` 32 KiB-aligned, so bit 14 of the write pointer is 0 across records 0..2,044 at offsets `24..16376` and 1 on record 2,045 at offset `16384`, and at one fixed address in C[s]; link_L_to_C[k][s] likewise). It is the only inter-node data path (no network or DMA): remote delivery is exactly the producer's scalar stores into that page (charged per 8 B word below), and destination selection is the address arithmetic on s that the producer already performs (inside the charged emit and bucket-header operations). Signalling uses two doorbell registers per link page, one per direction, in the style of an Arm Message Handling Unit: a memory-mapped register whose write raises an interrupt request at the link's other processor only (one doorbell per link and direction, so no target addressing and no broadcast; SEV is not used). A processor with nothing to do executes wfi and is halted, executing no instructions, until its interrupt arrives. Producer side of a handoff: 2 header stores, 1 store to the doorbell, wfi; on the return interrupt (exception entry is taken by hardware): mrs ICC_IAR1_EL1 (acknowledge), msr ICC_EOIR1_EL1 (end of interrupt), eret to the resume point, pointer reset: 8 instructions. Consumer side: on its interrupt, mrs ICC_IAR1_EL1, 2 header loads and a branch into the apply loop (records charged separately); after the page, 1 store to the producer's doorbell, msr ICC_EOIR1_EL1, wfi: 8 instructions (+ eret when resumed). Both are within the <= 20 instructions per side charged below.

0. Execution schedule and page handoff. The nodes run one deterministic program under a static serial schedule: one node executes at a time, an idle node executes nothing, and since the score counts instructions, not wall-clock time, this costs nothing extra. A link page moves only at a *handoff*: a producer (E_0 or L[k]) that has filled a page (or ends a band or stream with a partial page) writes the page header (record count, log p weight) and passes control and the page address to the Score Node C[s] owning the page, which applies the whole page and returns control; the producer resets its pointer and continues. So the producer can write directly into the link page with no separate staging buffer and no ownership or completion flag, and C[s] never polls or searches for pages. A handoff costs <= 20 instructions for the producer and <= 20 for the consumer, charged: Lattice Band 2 pages in C_LAT_EMIT ((8 flush + 2 cold stub + 20 handoff) / 2,046 = 0.014663 <= 0.015 Ir/kept record, matching Band 1's direct-to-link-page delivery) and C_LAT_APPLY ((11 page + 3 exit + 20 handoff) / 2,046 + 386/256 = 1.52443 <= 1.55 Ir/kept record); list pages in the 1.05 Ir per 8 B entry ((2,060 + 20 + 20) / 2,048 = 1.0254 <= 1.05); every partial page at 4,130 Ir in misc.
1. One-time score initialisation. Before any apply, each C[s] copies the init_a[] pattern (init_a[0] = 0 for the trap cell) into cells [0, L_g] (scan: [1, L_g]) of the 8 rows of each scan group, L_g the group's longest logical row, with the pass-2 instructions of v23b's scan8 (16 x (2 ldp + 8 stp) per 1,024 cells; pricing, group overhead and survivor drop in KERNELS.md §1.4). Pass 2 runs once, before the row's first apply, not after the scan; the scan (pass 1) is read-only over the same cells, cell 0 masked (1 op per row), all inside C_SCAN_G8 = 549/1024 (scan_zero = 0.851 Ir/cell). Cells beyond L_g are never initialised or scanned. v25_verify.py checks read-only ORR survivor detection on 8 rows against a reference (init_scan8_readonly_errs = 0).
2. Lattice Band 2 emission (E_0 -> link_E_to_C[s] -> C[s]). Per kept 3-primitive leaf E_0 loads `x0 = a_tab[pack_a] = ((2*ai) << 26) | k`, forms the 4-plane index `x6 = (k << 59) | pack_b` via `extr x6, x0, x5, #5`, loads `x3 = B_TAB[k][pack_b] = (s << 29) | row_block`, forms `&ptrs[s] = x17 + 8*s` via `add x8, x17, x3, lsr #26` (exact because bits [28:26] of B_TAB are 000 with BLK = 38 and row_block < 2^{26}) and `rec = (row_block << 38) | (2*ai)` via `extr x7, x3, x0, #26`, atomically fetches and post-increments `ptrs[s]` by `x1 = #8` via ARMv8.1-A FEAT_LSE `ldadd x1, x9, [x8]`, stores `str x7, [x9]` directly into `link_E_to_C[s]`, and tests `tbnz x9, #14, .Lfl_*` (KERNELS.md §1.3, 10 ops; 8 ops on final leaf falling into `.Lk0_back`; exact same direct-to-link-page model as Band 1 under the serial wfi handoff, zero separate stage_buf[s] and zero 16 KiB copy). `link_E_to_C[s]` starts at `page_start = base + (s << 15) + 8` (`16,384 B` exact: 16 B header at `[page_start, page_start + 16)` followed by 2,046 records at `[page_start + 16, page_start + 16384)`). `emit_direct_flush` (`kernels_v31.s //@seg emit_direct_flush`, 8 ops, preserving `x1 = #8`): `(8 + 2 + 20) / 2,046 = 0.014663 <= 0.015` Ir/kept record inside C_LAT_EMIT. C[s] applies each page directly from `link_E_to_C[s]` via x128-unrolled `lat_apply_page` / `lat_apply` (`kernels_v31.s`: `386/256 + (11 + 3 + 20)/2,046 = 1.52443 <= 1.55 = C_LAT_APPLY` Ir/kept record). Both the 10-op `EXTR+LDADD` emit + flush (2,100 records across all 4 planes `k in {0, 1, 2, 3}`, `s in {0, 1, 2^{35}-1}`, `row_block` up to `2^{26}-1`) and the x128 apply are executed instruction by instruction by `v25_verify.py lat_apply_e2e` (`emit9_e2e_ok = True`, `ok = True`, 0 errors). Records are grouped by 16-per-bit log p band (248 bands on `[2^{45.5}, 2^{61.0}]`); at each band end E_0 flushes every non-empty link page: <= 248 * 2^{35} partial pages * 4,130 Ir, in misc.
3. Band 1 and Lower Band 2 streams (L[k] -> link_L_to_C[k][s] -> C[s]). Each L[k] builds its primes' lists locally (KERNELS.md §1.1-1.2) and streams to the Score Node owning each row's sub-band. Band 1 (KERNELS.md §1.1, executed by v25_verify.py check 2): the List Node writes each hit as the 8 B record `(row_block << 38) + 2 ai` straight into `link_L_to_C[k][s]`; these stores are the delivery, inside the 2.03125 Ir per entry of C_HIT_LO. It keeps one page per destination stream (16 B of state per s, switched at sub-band starts by b1_switch), hands a page off once it holds >= 1,918 records, with a header of record count and the prime's log p weight, and at the end of each prime hands off each stream's partial page: at most 2^{35} per prime, 4,130 Ir each in misc (`n_1 * 2^{35} * 4,130` Ir for the n_1 Band-1 primes). C[s] applies a Band-1 page from its header alone: it needs no row base, because each record is its cell's address. Lower Band 2 (as in v27): s is fixed per bucket, so there is no per-hit routing; full pages cost 1.05 Ir per 8 B entry inside `C_B2_INT_*`; bucket headers (row base, log p weight) are inline records, +2.05 each inside `C_SB_ENTER_*`, so pages fill across bucket and prime boundaries and only a stream's last page is partial. With at most one partial page per (L[k], C[s]) pair and stream kind, the model charges 8 stream kinds, `8 * 2^{36} * 2^{35} * 4,130` Ir, plus Band 1's per-prime partial pages, in misc (`misc <= 2^{72.512798}` u in total).
4. Scan and cofactorisation. After all bands and streams, each C[s] runs the read-only scan8 pass over the logical cells of its rows and hands survivors to Stage B on the same node (KERNELS.md §1.4, §3).
5. Setup broadcasts. Before collection Score Nodes receive `init_a[]` and the `a(ai)` vectors (`18 |E_a+|` B), List Nodes the a-tables, `ai_of_chord[]`, `z_tab[]` (1 B per a), the sub-band map and Band 1's per-b descriptors, sub-band flags and line records, via link pages at 1.05 Ir per 8 B word. The model charges the Score Node copies as `3 N_sc |E_a+|` Ir in misc and the List Node copies as `6.4 * N_list * N_a` Ir in the lists setup (`ins_pre`) plus `2^{36} * (4.4 |E_b| + 8.4 * lines)` Ir for the descriptors and `128 |E_b|` Ir to build the descriptors once; all far below the totals.

There is no passive storage, linked page chain, global page counter or fallback pass: every record is applied when its page arrives, and all row memory is allocated once, before collection.
