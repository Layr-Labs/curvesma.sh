## 1. Measured side-output kernel: 929 instructions per lane, worst path, with explicit fixed-call row

The side-output function side_lanes(args, n) (measure/side_lanes.S) keeps the interface of the k16 kernel: args[i] = {out, P, T, inv}; it writes the fully reduced x' of P-T to out+0, y' to out+48 and the parity key (limbs 1..3 of whichever of y' and p-y' is even, a38cb931) to out+96; args[n] = {NULL, NULL} ends the lane loop. Inputs: x1, y1, x2, y2 canonical Montgomery residues (P is a kernel output, a restart root or a strand start; T a gap-table entry), y2 != 0 (G1 has odd prime order), inv = 1/(x2-x1) canonical from the batched inversion. Each gap-table entry stores v2 = p - x2 at T+96 and n2 = p - y2 at T+144 (192-byte entries; +21 instructions per entry in the gap-table step, TABLE_BK 48 <= 50; re-walk rebuild 2000+50; memory GMAX x 192; the hoisted stride register holds 192). Base-point and strand-start entries get v and n inside their scalar-multiplication charge (SM = 8192000 instructions per point, about four times a double-and-add).

Arithmetic (unchanged formulas). R = 2^384, p/R < 0.1016; the word-serial Montgomery product returns S = (ab + qp)/R < ab/R + p before its final conditional subtraction, which the kernel omits. blst f7a88067's __mul_mont_384 (twice), __sqr_384 and __mul_by_1_mont_384 are inlined with n0 pinned in x18, the modulus in x5..x10 and the 768-bit square in registers. Steps: t = y1 + y2 < 2p; mu = S(t, inv) < 1.21p; V = S(mu^2) < 1.15p; X = V + v2 - x1 in (-p, 2.15p) reduced to x' by a sign branch or one or two borrow-checked subtractions; w = x' + v2 in (0, 2p); z = S(w, mu) < 1.25p; y' = mu(x' - x2) + y2 = mu(x' - x1) - y1 (the line through P and -T has slope -mu and mu(x2 - x1) = y1 + y2), i.e. D = z - n2 in (-p, 1.25p), reduced by one branch and stored with the key block (tbz, at most four borrow instructions, stp, str: 7 worst path, audited by key_check.py on both emitted copies). The code after the x' reduction is emitted twice, so no x' path jumps through shared code.

Derivation (measure/derive_k929.py). The shipped file is produced byte for byte from the measured 971 listing of 99e03e91/fd385c98 (SHA-256 ba448d6b7d1623febeae2c4b9b9e7f343232e1651639d1c3cc5cde9e709f355a, the file of its Callgrind record; asserted by the script) by two text transforms, every edit asserted by count:

K1, value-bound carry deletion (-37). Lemma: in a word-serial Montgomery product with a < 2p and any 384-bit b, the accumulator before round j satisfies acc_j < a + p, and every pre-shift sum acc_j + a b_j + q_j p is below 2^64 (a + p). Induction: acc_0 = 0; if acc_j <= a + p - 1 then acc_j + a b_j + q_j p <= (a + p - 1) + (2^64 - 1)(a + p) = 2^64 (a + p) - 1, so acc_{j+1} < a + p. With a + p < 3p < 2^383, every pre-shift sum is below 2^447 and every shifted accumulator below 2^383; every partial sum the listing holds inside a round is a sub-sum of nonnegative terms of the pre-shift sum. So word 7 of every partial sum and word 6 of every shifted accumulator are zero. The 971 listing used this for the final round only; K1 applies it to rounds 0..4 of all three product copies (first product, both copies of the second), deleting the carry words adc x17,xzr,xzr; adc x17,x17,xzr; adc x4,{x17|xzr},xzr; adc x25,x4,xzr (18 per product), and turning the next round's first read of the zero word 6, adcs x25,x25,xzr, into adc x25,xzr,xzr (same count; its carry-out fed only a deleted word, and the following instruction sets the flags again). Both products satisfy a < 2p: t = y1 + y2 <= 2p - 2 and w = x' + v2 <= 2p - 1. In the square, mu < 1.21p < 2^381, so the cross sum sum_{i<j} mu_i mu_j 2^(64(i+j)) is below 2^701 and doubling words 1..10 never carries into word 11: adc x1,xzr,xzr is deleted and adc x16,x16,x1 reads xzr (-1).

K2, paired b-word loads (-5). After K1, x17 holds only the current b word inside each product. In the first product x29 is dead from the lane head to the P/T reload (the square uses it as scratch; the epilogue restores it), so b = inv loads as ldp x17,x29 pairs and rounds 1, 3, 5 read x29 (6 ldr -> 3 ldp, -3). In the second product x2 (out) is unused inside the product, so b = mu loads as ldp x17,x2 pairs from the frame and out is reloaded once after the product in each continuation copy (6 ldr -> 3 ldp + 1 ldr, -2). The transform asserts that the partner register appears nowhere else in its product.

Instruction counts per lane (static, from the shipped file; 971 listing in brackets): first product 295 [316], square 91 [92], square reduction 150 [150], second product 296 [316], driver worst path 97 [97]; total 929 [971].
