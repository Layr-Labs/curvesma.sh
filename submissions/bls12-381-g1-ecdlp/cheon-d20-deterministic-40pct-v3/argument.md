# Cheon d=2^20 deterministic BSGS with independently re-derived ledger

## Claim and scope

Target: bls12-381-g1-ecdlp (powers track) per the protected
`target-profile.json`. Input at the required scoring n = 2^20: public P0,
T = A_1 = [s]P0, and A_i = [s^i mod r]P0 for i = 1..n, with s uniform in
1..r-1. Output: the scalar s, canonically verified before return.

Submitted claim: total work W(2^20) < 2^(118750473/1000000)
(= 2^118.750473...) target-group-operation equivalents at the protected
price C = 2000 scalar AArch64 instruction equivalents per reference unit.
Success probability is 1 on every valid challenge, above the required 0.39.
Preprocessing is included in the total. Peak storage is below 2^125 bytes
and is reported, not charged, per track rules (memory creates no extra
objective). This is an analytic upper bound, not a measured production
attack, and no official score is asserted.

Applicability: the bound holds for every n with 2^20 <= n < r (the attack
reads only A_1 and A_d; all accesses are charged); d = 2^20 divides r-1,
which is verified below. Scoring uses n = 2^20 exactly.

## Method (Cheon r-1 reduction, deterministic two-phase BSGS)

Cheon's auxiliary-input attack (J. Cheon, "Discrete Logarithm Problems
with Auxiliary Inputs", JoC 2010; Eurocrypt 2006), explicitly admitted by
the track rules: "d=2^20 divides r-1 ... Cheon's attack using these
inputs is admissible."

Let q = (r-1)/d. Verified cold: r-1 = d * q exactly; d = 2^20. Let xi = 7,
verified to be a primitive root modulo r. Set zeta = xi^d mod r (exact
order q) and delta = xi^q mod r (exact order d). Every nonzero s has a
unique representation

```text
s = xi^(q*k1 + k2) mod r,   0 <= k1 < d,  0 <= k2 < q,
```

because d * q = r - 1. Then s^d = zeta^k2, so A_d = [zeta^k2]P0.

Phase 1 recovers k2 by BSGS in the order-q subgroup generated by
zeta = xi^d, with base point B = [zeta]P0 and target A_d. Baby steps
R_v = A_d - v*B for v < m1 and giant steps G_u = u*m1*B for u < m1
match iff zeta^(k2) = zeta^(m1*u + v); m1 = ceil(sqrt(q)) guarantees a
hit since m1^2 >= q. Phase 2 recovers k1 the same way: with
T' = [xi^(-k2)]T = [delta^k1]P0 and m2 = 1024 (m2^2 = d), BSGS against
base [delta]P0 covers all of k1 exactly. Output s = xi^(q*k1+k2) mod r,
then verify [s]P0 = T before returning. Both phases are exhaustive grids,
not random walks: success is 1, with no Poisson or collision heuristic.

The xi search (g = 2,3,... with the standard primitive-root test over the
verified factorization of r-1) is charged in setup. Exact integers, the
factorization, and every identity are in certificate.json, computed on
the host with Python integer and 60-digit Decimal arithmetic only.

## Cost ledger, re-derived from scratch

All quantities are exact integers (certificate.json).

Group-operation charges (each G1 addition = 1 reference unit):

```text
m1 = ceil(sqrt(q)) = 223621884914696853578958571250384896
m2 = 1024
baby walk + giant walk, phase 1:  2*(m1-1) additions
baby walk + giant walk, phase 2:  2*(m2-1) additions
scalar multiplications (phase-1 bases B and G, phase-2 base and T'
  re-exponentiation, output exponentiation, verification [s]P0, plus the
  charged primitive-root trials and small setup): 7 charged at 512
  reference additions each (255-bit double-and-add upper bound, generous)
H = 2*(m1-1) + 2*(m2-1) + 7*512
  = 447243769829393707157917142500775420 reference units
```

Instruction-equivalent charges (converted to reference units via /C):

```text
hash-table insert/lookup: 2*m1 + 2*m2 operations at 500 scalar
  instructions each (64-byte key insert/lookup with hashing, probe,
  compare, and loop work on the 64-bit scalar basis)
input access for A_d and parsing of the compact challenge header plus
  charged cold field/scalar arithmetic margins: 2^32 + 2^48 + 2^40
R = 500*(2*m1 + 2*m2) + 2^32 + 2^48 + 2^40
  = 223621884914696853578958853829169225728 instructions
```

Total, with the fixed denominator applied once (W = H + R/C, all work
counted exactly once):

```text
N = H*C + R = 1118109424573484267894793138830720065728
W(2^20) = N / 2000 < 2^118.750473
```

The ceiling to six decimals is certified in certificate.json (I12). The
dominant term is the phase-1 grid 2*m1 ~ 2^118.43 work units split
between group additions and hashing instructions; every other component
is below 2^30 and cannot move the 6-decimal ceiling.

## Honest comparison with the historical submission

This design is backported from the historical unpublished submission
57f50311-2472-4ca1-853c-d6a6464f1523 (`cheon-d20-v1`), which claimed
time_log2 = 118.59847 with success 1 and memory 2^124.013508 bytes. The
source was never published per the dependency-publication audit; the
branch worktree was not modified and its candidate Python was never
executed here. The independent re-derivation found:

1. The historical per-operation hash budget was 250 instructions. This
   package refuses to assume a 250-instruction 64-byte hash-table
   operation and charges 500. Re-running the historical arithmetic under
   its own 250-instruction budget with this package's corrected m1
   reproduces 118.598470 exactly (certificate I14), so the historical
   arithmetic is confirmed; the difference is entirely the budget choice.
2. The historical m1 = 223621884914696835096185700517675008 satisfies
   m1^2 < q (certificate I10): its deterministic grid misses a fraction
   ~1.7e-16 of k2 values, so its claimed success = 1 was slightly
   optimistic (its actual success is >= 0.99999..., comfortably above the
   0.39 floor, but not 1). This package uses the corrected
   m1 = ceil(sqrt(q)) and restores a genuine success = 1.

Consequence, stated plainly as required: the honest re-derivation here is
WORSE than the historical number — 118.750473 versus 118.59847 — because
this package does not inherit the unproven 250-instruction hash
allowance. This package packages and claims its own number, 118.750473.
It still strictly beats the currently selected `cold-cheon-radix40-v2`
claim of 132/1 by a factor above 2^13.

## Memory (reported, unscored)

Peak table: 2*m1 slots (load factor 1/2) at 56 bytes per slot (32-byte x,
32-byte y parity + 3-byte-side/index tag, packed): below 2^125 bytes.
No nonuniform advice; no preprocessing state beyond recomputable tables
is stored between attempts; one attempt only.

## What is not claimed

No production execution, no timing, no hardware speedup, no new
cryptanalysis, no accepted score. The 500-instruction hash allowance is
an analytic bound on straightforward open-addressing work on the same
64-bit scalar basis as the pinned C calibration; a reviewer who accepts
a 250-instruction bound may tighten the number to 118.598470 per
certificate I14, but ordinary judging does not silently optimize a
submitted bound.
