# Streamed signed BSGS on BLS12-381 G1 with batch affine conversion

This candidate claims the conservative upper bound **time_log2 = 1372154/10000 = 137.2154** for the score point n = 2^20 = 1048576, in the protected target-group-operation equivalents, with **success_probability > 1/2** (exactly (COV-1)/(r-1), defined below), **memory_log2_bytes = 145**, **preprocessing_log2 = 1372154/10000**, and **nonuniform_advice_log2_bytes = 0**. Zero advice bytes are used. These are submitted analytic bounds, not an executed production attack. The fixed normalization for this track is **C = 2000 scalar AArch64 instruction equivalents** per target-group equivalent. All arithmetic, communication and control work is charged through scalar 64-bit instructions; no reference group operation is additionally charged.

The streamed signed BSGS design and ledger structure are credited, as design provenance only, to the public secp256k1 submission `f888bb9e-1cc3-4be1-bb0a-734722d78885`. This document re-derives every field price, record size, coverage count and ledger term for the BLS12-381 G1 profile and stands alone; no prior acceptance, score or cross-submission comparison is relied upon.

## Use of the auxiliary powers

The attack uses **only** the target T = [s]P0 = A_1, supplied as the input field T. It reads none of A_1, ..., A_n beyond that point, uses no Cheon-type step, and needs no number-theoretic condition on n or r. The rules allow a subset of the powers, including this one. The work function is

```
W(n) = T_instr(n) / 2000,
T_instr(n) = 2^40 + 2^15*n + (m+h)*1585152,     m = 2^126, h = 2^127,
```

valid for every integer n with 1 <= n < r. The term 2^15*n is a deliberate over-charge: the attack accesses T directly and does not scan the powers array, but 2^15 instructions per supplied power are charged anyway so that an implementation that locates T by walking the serialized input is still covered (a canonical point encoding has two 96-character coefficients plus fixed punctuation, so 2^15 covers more than 64 instructions per byte). The published score is the bound on log2(W(2^20)).

## Target and algorithm

Use exactly the protected BLS12-381 G1 field, subgroup order and generator:

```
p  = 1a0111ea397fe69a4b1ba7b6434bacd764774b84f38512bf6730d2a0f6b0f6241eabfffeb153ffffb9feffffffffaaab   (381 bits)
r  = 73eda753299d7d483339d80809a1d80553bda402fffe5bfeffffffff00000001                                   (255 bits)
E1 : y^2 = x^3 + 4 over F_p,   P = P0 the profile generator of order r
```

The challenge samples s uniformly from 1..r-1 and gives T = [s]P. Write Q = T. Set

```
m = 2^126,  h = 2^127,  d = 2m - 1 = 2^127 - 1,  B = 4096,  D = -[d]P.
```

Decode Q canonically, check the curve equation and the subgroup condition [r]Q = O (the G1 cofactor is large, so this check is required). Compute D with charged scalar multiplication. Construct two lists:

- baby records `(jP, j)`, for 0 <= j < m;
- giant records `(Q + iD, i)`, for 0 <= i < h.

Each sequence is generated by complete mixed Jacobian addition by its fixed affine increment, P or D. Collect B successive projective points, convert the block to affine with the exact batch-inversion procedure below, and write one record to each numbered leaf of the sequence's storage tree. Both m and h are divisible by B. The last update of a sequence may be performed and discarded; it is included in the budget.

A record has 24 64-bit words, 192 bytes: one infinity tag, six canonical x limbs, six canonical y limbs, four scalar/index limbs and seven padding words. A finite point's key is `(1, x)` with x the canonical standard-form integer in [0, p); infinity's key is `(0, 0)` with zero coordinate words. The key therefore has seven words. The index is carried unchanged. No square roots, hashing or recovery of omitted coordinates are used.

Each tree lazily merges its leaves into a nondecreasing key stream. The central engine intersects the two sorted streams. It caches one head from each stream; if one key is smaller, it discards only that head and asks its stream for the next record. If keys are equal, it uses the two full y coordinates to identify

```
Q + iD = jP       or       Q + iD = -jP,
```

forms `a = id + j mod r` or `a = id - j mod r`, verifies [a]P = Q, and outputs a as the canonical 32-byte scalar. If both keys are infinity, j = 0 and a = id mod r. Exhausting either stream without a match returns failure. At most one final scalar verification is needed, because an equal key necessarily supplies a correct equality or negated equality (two points of E1 with the same x are equal or opposite). A y disagreement with both choices is an implementation error, not a probabilistic event.

## Exact success and ties

Baby keys are distinct. If jP = kP then j = k in the stated range. If jP = -kP then j + k is a multiple of r; since 0 <= j+k <= 2m-2 < r, this happens only for j = k = 0, the single infinity record. Thus no baby key is duplicated.

Giant keys can repeat, and the algorithm does not assume otherwise. Internal merge nodes break equal-key ties by emitting the left child's head first, marking only that head consumed; the other head remains cached and is emitted later unless the search has already succeeded. No record is lost. At the central intersection, equal keys immediately provide a valid cross-list match, so repeated giant keys neither reduce success nor require more than one verification. If the heads differ, advancing only the smaller head is the exact sorted-list intersection rule and cannot discard a possible match.

For fixed i, an equal key exists exactly for the scalar residues

```
[id-(m-1), id+(m-1)] modulo r.
```

Successive integer intervals are adjacent and disjoint because d = 2m-1. Their union is the integer interval from -(m-1) through (h-1)d+(m-1), with precisely COV = h*d members. COV < r, so reduction modulo r is injective on this interval, including its wrap through zero. The interval contains 0, which is not a possible challenge scalar, so exactly COV - 1 of the r - 1 equally likely values of s are recovered. Exact arithmetic gives

```
COV            = 28948022309329048855892746252171976963147354982949671778132708698262398304256
2(COV-1)-(r-1) = 5460169443531907232337751996157988088604157465371705733661758696586215423998 > 0
```

so the success probability is (COV-1)/(r-1) > 1/2 >= 0.39 (numerically about 0.55207). The construction is deterministic; no coins, trials, restarts or amplification are used. It deliberately fails outside the covered set, and no claim is made that s is drawn from a restricted interval.

The index arithmetic is small: i, j < 2^127 fit two limbs, d < 2^127, and id+j < 2^255 fits four limbs. The greatest positive reconstructed integer is (h-1)d+(m-1) = COV - m < r. A negative value can occur only for i = 0 and is corrected by adding r. All of this is in the fixed reserve below.

## Field arithmetic with 64-bit limbs

p has 381 bits, so field elements use six 64-bit limbs; a seventh limb holds carries. Inside the generation and normalization kernels, elements are kept in Montgomery representation x~ = x*R mod p with R = 2^384, always canonical in [0, p). The map x -> x~ is a bijection of [0, p) that commutes with addition, subtraction and negation, and x~ = 0 exactly when x = 0, so all zero tests and branch decisions below are unchanged. Records are converted back to standard form before they are written (charged below), so every key is the standard canonical x.

Modular addition or subtraction costs at most **A = 512** instructions: six seven-limb passes at eight instructions per limb (336) plus sixteen control instructions is 352. Small multiples 2, 3 and 8 are formed with these charged additions.

A Montgomery multiplication (CIOS, six limbs) costs at most **M = 2^14 = 16384** instructions. It performs 36 operand limb products, 6 products for the per-round quotient digit, and 36 products of that digit with the limbs of p: 78 MUL/UMULH limb products. Budgeting 128 instructions per limb product for the multiplication pair, loads, stores and carry propagation gives 9984; another 1024 cover setup, the final conditional subtraction of p and output, for 11008 <= M. Since p < R/4, the reduction output before the conditional subtraction is below 2p, so one subtraction makes it canonical. Squaring uses this same bound, and so does conversion out of Montgomery form (a Montgomery multiplication by 1).

For nonzero z, Fermat exponentiation z^(p-2) by binary square-and-multiply over the 381-bit exponent costs at most 762 multiplications, 64 control instructions per exponent bit and 4096 fixed instructions: 12513088 <= **I = 2^24** instructions. This is an analytic instruction bound, not a measured assembly result.

## Complete projective generation

Represent a finite point by `(X:Y:Z)` with x = X/Z^2 and y = Y/Z^3; infinity is Z = 0. For mixed addition of `(X:Y:Z)` and a finite fixed affine point `(u,v)`, first handle Z = 0 by returning `(u:v:1)`. Otherwise compute

```
ZZ = Z^2
U2 = u*ZZ
S2 = v*Z*ZZ
H  = U2-X
q  = S2-Y
```

If H = 0 and q != 0, return infinity. If H = q = 0, use the doubling procedure below. Otherwise

```
HH  = H^2
HHH = H*HH
V   = X*HH
X3  = q^2-HHH-2*V
Y3  = q*(V-X3)-Y*HHH
Z3  = Z*H
```

For doubling, return infinity if Z = 0 or Y = 0; otherwise use the a = 0 formulas

```
AA = X^2
BB = Y^2
CC = BB^2
DD = 2*((X+BB)^2-AA-CC)
EE = 3*AA
FF = EE^2
X3 = FF-2*DD
Y3 = EE*(DD-X3)-8*CC
Z3 = 2*Y*Z
```

These are the `madd-2004-hmv` mixed-addition and `dbl-2009-l` doubling formulas from the Explicit-Formulas Database for Jacobian coordinates with a = 0 (https://www.hyperelliptic.org/EFD/g1p/auto-shortw-jacobian-0.html), with the exceptional branches specified here. The curve constant b = 4 does not enter them. The ordinary mixed branch uses eleven field multiplications or squares; the doubling branch uses at most the four initial ones plus seven. Each branch, including zero tests, copies, index bookkeeping, storing the current point in the block, additions and negations, fits

```
JAC = 16*M + 32*A + 4096 = 282624 instructions.
```

P and D are nonidentity points of the order-r subgroup (d is nonzero modulo the prime r), so the y = 0 doubling branch is never reached by a valid point; it is kept as a defensive branch. P, D and the giant start Q are converted into Montgomery form once, inside the fixed reserve.

## Exact block normalization

For each block of B = 4096 projective points, set z_k = Z_k when Z_k != 0 and z_k = 1 otherwise, keeping the zero-Z flags. Form prefix products, invert the final (nonzero) product once, and traverse backward: the running inverse times the preceding prefix gives z_k^(-1), and the running inverse times z_k prepares the next step. That is at most B prefix and 2B reverse multiplications.

For each nonzero Z, compute Z^(-2), X*Z^(-2), Z^(-3) and Y*Z^(-3) (four multiplications), then convert x and y out of Montgomery form (two multiplications). For zero Z, emit the infinity record; substituting 1 ensures there is never a zero inversion. The block costs at most

```
B*JAC + 9*B*M + 4096*B + I
```

instructions; the 4096 per point covers flags, prefix-array transfers, backward counters, record construction and normalization control. Since I/B = 4096, this is 438272 instructions per point, strictly below the adopted allowance **E = 2^19**. There are no partial blocks. Point blocks, original Z values, prefixes, flags and one staging record use less than 2 MiB and fit the separate 2^24-byte reserve; normalized records are written to their leaves during the reverse pass.

## Distributed storage and initialization

Use two complete binary trees: the baby tree with m = 2^126 leaves and depth 126, and the giant tree with h = 2^127 leaves and depth 127. They have (2m-1) + (2h-1) < 2(m+h) nodes in total. A node is a scalar processor with at most 64 KiB local code, state, buffers and records. It has local 64-bit pointers and three local word-transfer ports, to its parent and children; leaves ignore child ports. A destination index of at most 127 bits is routed one bit per level when writing leaves. The engine has a port to each root. Node state includes two cached 192-byte child heads, flags, scratch and routing metadata, well within 64 KiB. One data request is served at a time along a dependency path, and processors suspend for events instead of spinning. All work of all processors is counted.

The trees are not a free global address space. For each node, allow up to 8192 word clears at eight instructions each, up to 8192 word image copies or transfers at sixteen instructions each (sender and receiver charged), and 2^15 instructions for port and path metadata, counters, startup acknowledgements and initialization control:

```
8192*8 + 8192*16 + 2^15 = 229376 < INIT = 2^18.
```

All initialization is bounded by 2(m+h)*INIT. Root code preparation is in the fixed reserve.

To write one 192-byte record, allow a 28-word command/data packet (four command/address words) over every edge of its request and acknowledgement route. With depth at most 127 there are at most 256 aggregate edge crossings. Per crossing, sixteen instructions per word cover both endpoint loads/stores, port transfers and addressing, and another 64 cover control: 256*(28*16+64) = 131072 = 2^17 instructions. **U = 2^18** adds another 2^17 for root and leaf work, packet setup and acknowledgements. Every baby and giant record is written exactly once and charged U.

## Lazy sorting streams, including end markers

A leaf answers its first NEXT request with its single record and its next with END, which it remembers. An internal node keeps one head slot per child, marked EMPTY, RECORD or END, initially EMPTY. To answer NEXT it fills EMPTY slots by issuing NEXT to those children. If both are END it returns END; if exactly one is END it emits the other's record; otherwise it compares keys and emits the smaller, the left one on equality. Only the emitted head becomes EMPTY, and refilling is deferred to the next parent request. A parent that receives END never asks that child again.

By induction on the tree, every record of a subtree is emitted exactly once, in nondecreasing key order, and cached heads remain available across equal keys. The engine may abort after a match; its work is bounded by a complete drain of both streams.

For a tree with n_T leaves and depth L_T, let n_e be the leaves below child edge e. On a complete drain that edge carries n_e record responses, at most one END and at most n_e + 1 NEXT requests. Each leaf has L_T ancestors, so sum_e n_e = n_T*L_T, there are 2n_T - 2 child edges, and sum_e (n_e+1) < n_T*(L_T+2). A NEXT packet has at most four words and a record or END response at most 28 words. At sixteen instructions per word for both endpoints and 64 control instructions per packet, a request/response pair costs (4*16+64) + (28*16+64) = 640 instructions. Another 512 per pair cover the seven-limb key comparison (x compared from its most significant limb), copying a 24-word head (24 loads and 24 stores), state updates and local control. A further 4096 per record cover the root's interaction with the engine, leaf finalization and the root END event. With L_T <= 127, a complete stream costs at most

```
n_T * [1152*(L_T+2) + 4096] <= n_T * 152704 < n_T * S,   S = 2^18.
```

Both streams together cost at most (m+h)*S. The central intersection makes at most m+h head-consumption iterations, each at most 8192 instructions for key comparison, index and state movement and control, so it is bounded by (m+h)*2^13. NEXT transfers were counted in the stream budget and are not charged again.

## Fixed work, memory and total bound

The fixed 2^40-instruction reserve covers decoding T and rejecting malformed input, the curve and [r]Q checks, computing D = -[d]P, Montgomery constants and conversions, the engine's code and constants, scalar reconstruction at a match, one independent [a]P verification, canonical output and cleanup. A complete affine addition with explicit infinity, opposite-point, doubling and y = 0 branches fits 2^25 instructions using the inversion bound above; a binary scalar multiplication by a scalar below 2^255 needs at most 510 such additions, under 2^34 instructions, and the few fixed scalar multiplications fit well within 2^40. All input-dependent giant construction, sorting and intersection work is in the variable ledger, not in this reserve.

With INIT = S = 2^18, E = 2^19, U = 2^18 and m + h = 3*2^126, the complete worst-case instruction budget at n = 2^20 is

```
T = 2^40
    + 2^15*n                       # input access over-charge

    + (m+h)*(E+U+4096)             # generation, normalization and writes
    + (m+h)*S                      # both complete sorted streams
    + (m+h)*2^13                   # central intersection
  = 2^40 + 2^15*n + (m+h)*1585152.
```

The computation metric is T/2000 target-group-operation equivalents. Its logarithm is approximately 137.21536797. The submitted rational upper bound 1372154/10000 = 137.2154 is justified without floating point by the exact integer inequality

```
T^10000 < 2000^10000 * 2^1372154,
```

while the same inequality with 2^1372153 fails, so 137.2154 is the bound rounded up at four decimals.

Preprocessing (storage and code setup, baby generation, and any baby-stream work done before inspecting Q) is a subset of the fully charged attack, so preprocessing_log2 = 1372154/10000 holds with the same complete bound. Nothing is amortized over other targets.

Peak storage is strictly below

There is no retained randomness or nonuniform advice. Public profile constants and algorithm-design effort are the only excluded work. Physical resources of this scale are unavailable; the claim is a finite analytic accounting construction, not a practical attack.

## Evidence and limitations

Heuristic assumptions: **none**. There is no random-walk mixing assumption, random oracle, birthday approximation, ideal hash table, empirical success extrapolation or uncharged table. Success is an exact count; time and memory are worst-case bounds, not expectations. The cost claims are analytic scalar-instruction bounds rather than measurements; the distributed word-transfer machine and its instruction allowances are explicit, reviewable parts of the construction rather than a free parallel speedup.

`experiment.py` checks bounded instances: exhaustive toy groups for the stream merge, signed intersection, ties and exact coverage; the Jacobian formulas and zero-safe batch normalization on the production BLS12-381 G1 field against an independent affine oracle; small-bound recovery and planned failures on production G1 points; and the exact integer ledger, coverage and score inequality above. Small experiments are evidence only at their executed scope; they are not production complexity proofs.
