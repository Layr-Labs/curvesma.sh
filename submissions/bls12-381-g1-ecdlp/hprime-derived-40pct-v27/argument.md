## 2. keymod = 2^50 is derived, and it is a walk field, not a key modulus (flaw 4)

The class key is 168 bits (`keymod.KEY_BITS`); the even representative fixes one bit, so the
key image is 167 bits. **2^50 is the walk-offset width**: `ceil(log2(N/nb)) = ceil(49.650348)
= 50`, and the position index is `pool_slot(66 bits) || walk_offset(50 bits)`, which fits the
128-bit index field with 12 bits spare. `derive_v27.py::keymod` computes this integer and
asserts the field arithmetic.

Why 50 is the *right* effective modulus for the success law: the pair correction at nw is
`(nw-1)/nw^2`. At nw = 2^50 that is `2^-50.000000`, which sits `42.018` bits below the
measured band `0.003955 = 2^-7.982`. One further walk bit doubles the records row (+1 bit of
W) and buys less than `2^-50` of success, so 50 bits exhausts the correction at this
precision. Fixture consistency (`keymod.fixture_consistency`, machine rows): the census big
fixture is `nb=1024, nw=64, records/side=65536 = nb*nw`; the small fixture is
`64*64=4096`; the direct-v25 series is `172*1`, `86*2`, `43*4` — all `nb*nw` exactly. The
production instantiation follows the same rule at `2^66 * 2^49.65`.

## 3. kappa: an occupancy identity plus a measured residual, charged at 1.0166 (flaw 2)

The v25 inequality `sum_k N(k)^2 <= 6m` stays retracted. `derive_v27.py::kappa.check_row`
recomputes `m^2/D = 2^302.714179`, `6m = 2^237.442052`, ratio `2^65.272127 > 1` and asserts
the premise is false. **C-S is a lower bound on the collision sum: it refutes the withdrawn
upper bound and says nothing about kappa above 1.** No monotonicity is claimed, and the v26
sentence that carried the anchor's m by hand (`9 - 18.4138`) is gone.

What replaces it is the occupancy identity, which is exact for a uniform key map:

    E[sum_k N(k)^2] = D*((m/D)^2 + m/D)   =>   kappa = D*sum_k (N(k)/m)^2 = 1 + D/m.

At production `D/m = 2^-67.857089`, so the uniform term is `1 + 3.6e-21`. The census measures
the deviation from uniformity directly: 16 dense rows (`predicted >= 4096`), ratio
observed/predicted. The envelope top is `1.016602`; the residual after removing each row's
Poisson scale (`max(0, kappa-1-2/sqrt(predicted))`) is **0.000000**, and the largest
standardised excess over all 16 rows is `1.999 < 2`. So no clustering is detectable above
counting noise at any anchor.

Charged kappa is therefore `1.016602` (`= 1 + D/m + envelope_top + residual_max`), replacing
the hand slack `1.231`. Pricing kappa linearly, `E_bad = 2^64.324424` (was `2^64.6005`), and
the `2^84` candidate cap keeps `19.68` bits of headroom: **no ledger row moves**.
