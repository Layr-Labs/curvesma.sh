## 1. Problem and reduction

Given T = [s]P0 and A_i = [s^i]P0 for i = 1..n, n >= 2^20, recover s. Let d = 2^20. Since v_2(r-1) = 32, d | r-1 and 6d | r-1. H = {x^d : x in F_r^*} has order m = (r-1)/d, log2 m = 234.857089. z = s^d is uniform in H and A_d = [z]P0 is an input. Only T, A_1 and A_d are read, so the same W applies to every n >= 2^20.

Lemma 1 (recovery of s from z). Twenty successive square roots in F_r (Tonelli-Shanks, each a few hundred F_r multiplications) give one t with t^d = z. Then s = t * zeta for one of the 2^20 d-th roots of unity zeta = g^k, g a fixed primitive 2^20-th root. Write k = i + 2^10 j: compute the 2^10 points [t g^i]P0 and the 2^10 points [g^(-2^10 j)]A_1 (2^11 scalar multiplications, 2^23 units), sort the first list by x and look each point of the second up in it. Charged at 2^24 units in the ledger.

Lemma 2 (mu6 in H). The group mu6 = {+-1, +-omega, +-omega^2} of sixth roots of unity lies in H because 6d | r-1 (asserted by the script). On this j = 0 curve [omega](x, y) = (beta x, y) and [-1](x, y) = (x, -y), so the six points [u]X, u in mu6, share the unordered pair {y, p-y}.

## 2. Algorithm A

H-primes. A prime q is an H-prime if q^m = 1 mod r. The walk list W is the set of H-primes w_0 < w_1 < ... above 2^39, taken in order until L = 2^51.6397 of them are listed (last element about 2^77.4; H2). Base H-primes a lie in (2^80, 2^99), 2^64 for the baby side and 2^64 disjoint ones for the giant side. Every scalar x = a w is below 2^178 < r, so x is a well-defined element of H and (a, w) is recovered from x by unique factorisation.

Chains. Chain a holds X_j = [a w_j]Q, with Q = P0 on the baby side and Q = A_d on the giant side. X_{j+1} = X_j + [a g_j]Q where g_j = w_{j+1} - w_j is even and at most 2^33 (H2'); the table G_a[g/2] = [a g]Q has 2^32 affine entries (96 bytes each, 2^38.6 bytes) and is built by repeated addition of [2a]Q in 2^16 strands. Each strand starts with one scalar multiplication; strand 0 starts at k = 2 (entry k = 1, the point [2a]Q itself, is the one extra scalar multiplication in the ledger), so the first addition of every strand is [2ka]Q + [2a]Q with k >= 2. The chain itself runs as 2^16 lockstep segments of 2^35.66 steps (segment starts by scalar multiplication), so each round is 2^16 independent incomplete affine additions sharing one Montgomery inversion. That is exactly the reference operation (batched 6M).

Lemma 3 (no degenerate addition). X_j = +-[a g_j]Q would need w_j = +-g_j in H, impossible since w_j > 2^39 > g_j > 0 and w_j is prime. So no doubling or point at infinity occurs in the chains or the table strands (table strands add [2a]Q to [2ka]Q with 2 <= k < 2^32: equality would need k = +-1 mod r, false). The toy builds its small tables by scalar multiplication, so it exercises the chain half of this lemma only; it asserts a non-zero denominator at every batched step.

Key. The record for X = (x, y) is (key, id): key = bits 1..192 of the even one of y and p - y (192 bits), id = 64-bit chain index. 32 bytes. By Lemma 2 the six points [u]X have the same key.

Lemma 4 (distinct ratios). Baby point [a w]P0 equals [u][a' w']A_d = [u a' w' z]P0 for some u in mu6 iff z = a w / (u a' w') in F_r; an equal key means exactly this for one of the six u. As fractions of integers, the N^2 ratios a w / (a' w') are pairwise distinct except on the diagonal w = w' (fraction 1/L = 2^-51.64 of pairs), by unique factorisation with a, a' in disjoint sets. Their images in H, and the six mu6 multiples of each, can coincide; Lemma 4 only rules out the trivial repeats. That the 6 N^2 (1 - 2^-51.64) candidates cover z like independent uniform elements of H is heuristic H1, and the success 1 - e^(-K) rests on it (toy: 0.4025 at 400 trials and 0.3895 at 2000 against 0.3935 predicted, Section 6).

Order of the sides. The whole baby side runs first: every baby record is generated, routed and inserted before any giant chain starts, and a giant record is only ever compared against a complete table. The 2^20 generating nodes each run one chain at a time (2^44 baby chains each, then 2^44 giant chains each), holding one gap table at a time, which is the 2^39.17 B generating-node figure.

Routing. 2^84 owner nodes, node index = key bits 0..83, read as three 28-bit fields (t, u, v). Each generating node scatters records into 2^28 send blocks of 16 records (512 B) by t; a full block is posted to the hop-1 relay for t, which is owner node (t, 0, 0). That node re-scatters the records it receives by u into its own 2^28 send blocks and posts full blocks to the hop-2 relay for (t, u), owner node (t, u, 1), which re-scatters by v and posts to the owner (t, u, v). Every node has one send array of 2^28 blocks and three receive FIFOs, one per hop, and the relay work is executed at the relay and charged per record (listing in Section 4). Three hops, each a data-independent copy of 32 bytes plus addressing, posting and polling. Within an owner node, baby records are inserted into a direct-mapped head array of 2^33 8-byte slots indexed by key bits 84..116, chained through a pool of 2^33 32-byte records (capacity 2.57 x the mean 2^31.64). The node index and the head slot are implied by where a record sits, so a pool record stores key bits 117..191 (75 bits), the 64-bit chain id and a 33-bit link to the next pool record, the rest spare; a head slot is a 33-bit pointer to the first pool record and a 7-bit count. A head slot holds at most 64 baby records; a 65th makes the node report fail. Giant records are not stored: a giant record reads its head slot and compares its 75 remaining key bits with each pooled record on the chain (8 instructions per comparison: load 24 bytes, compare, branch, pointer advance, and a decrement of the node's comparison counter). Equal key gives a candidate record (key, id, id'): the full 192-bit key, reassembled from the node index, the slot and the stored bits, and both chain ids, 40 bytes, appended to the node's candidate list of 2^16 slots. A 2^16 + 1st candidate makes the node report fail.

Per-pair verification. After the giant side, every owner node reports its candidate count through the status tree below; if the total exceeds 2^44 the run outputs fail. Otherwise each 40-byte candidate is copied into one 512-byte block for each of the two generating nodes g(id) and g(id'), where g(id) is the top 20 bits of the chain id, posted and polled (charged 128 instructions per candidate). Each generating node has a candidate receive area of 2^24 slots x 40 B; a 2^24 + 1st candidate makes it report fail. Then each of the two chains is re-walked once, linearly, from its start to its end by the generating node that owns it (its gap table rebuilt, its strands and segments restarted, all charged as in the table), and at every step the key of the point is extracted and compared with the retained key: the 47 instructions of walk overhead from the baby listing plus 32 (parity select and key extraction 23, compare 8, position bookkeeping 1), 2079 per step with the addition. The positions whose key equals the retained key are kept, at most 4 per chain; a fifth makes the run output fail. g(id') sends its kept values a' w' to g(id) as one 168-byte block (40 B header plus 4 x 32 B; copy, post and poll charged at 256 instructions). g(id) now holds at most 4 values a w and at most 4 values a' w', so at most 16 pairs, and for each pair the six z = a w / (u a' w') are tested by [z]P0 = A_d: at most 96 scalar multiplications per candidate, all at g(id). On a hit g(id) runs Lemma 1 and writes s into its status record. Nothing is ever compared against the whole other chain, so the re-walk is O(L) per chain, never L^2. A wrong candidate never produces a wrong answer. Charged in full for every candidate up to the cap (Section 3).

Node overflow and caps, all enforced locally. An owner node fails if it receives more than 2^33 baby records, if any head slot exceeds 64 records, if its candidate list exceeds 2^16, or if its comparison counter, preset to cap_node = 1.01 x 2^114.279 / 2^84 = 2^30.294, reaches zero; a generating node fails if its candidate receive area exceeds 2^24; a node that fails stops and the run outputs fail. The global candidate cap is 2^44 (checked from the per-node counts before any re-walk), and a re-walk fails if one chain carries the retained key at more than 4 steps. The work charged is the maximum: every record, 2^84 x cap_node comparisons, every candidate up to the cap with the full 96-multiplication recovery.

Status collection. Every node keeps a 48-byte status record (fail flag, baby count, giant count, candidate count, and s if found). It is collected three times, after the baby side, after the giant side and after recovery, through a fan-in-256 tree over all 2^84 + 2^20 + 2^30 nodes (depth 11): a node posts its record, or the combined record of its 256 children, to its parent. Charged at 2^12 instructions per node per pass in the ledger.

## 3. Sizes, caps and success

N = L 2^64 with L the least integer such that 6 N^2 >= 0.5025 m: L = 2^51.6397, N = 2^115.6397, K = 6 N^2 / m = 0.502500. Under H1 the probability that z is among the 6 N^2 (1 - 2^-51.64) distinct candidates is 1 - exp(-K) = 0.3950.

Comparisons. 2^117 head slots in total, load lambda = N / 2^117 = 0.389 per slot. The giant side makes sum over slots of (baby count x giant count) comparisons, mean N^2 / 2^117 = 2^114.279, per node 2^30.279 against the node cap 2^30.294 (1.01 x). Three per-node tails under H3, each already multiplied by the number of nodes or slots: (i) a head slot with more than 64 baby records, Poisson(0.389) tail at 65, 2^-273 over all 2^117 slots; (ii) a node's baby or giant count more than 2^-10 (0.098 %) off its mean, Chernoff, 2^-1449 over all nodes (both counts within 2^-10 puts the conditional mean at most (1 + 2^-10)^2 - 1 < 0.196 % above the nominal, and 0.196 % + 0.8 % < 1 %); (iii) given (i) and (ii), the node's comparisons are a sum of its giant records' independent slot draws, each a baby count in [0, 64] with second moment lambda + lambda^2 (the ledger takes 4 x this), so Bernstein with M = 64 and deviation 0.8 % of the mean gives 2^-10417 over all nodes. Every tail in this document is rounded towards the larger probability. The 1 % cap is therefore essentially never reached and the charge 2^84 x cap_node = 1.01 x 2^114.279 is a bound on the total.

False matches. Pairs with equal 192-bit key but different mu6 orbit: mean N^2 / 2^192 = 2^39.28, cap 2^44, Chebyshev tail below 2^-47.6 under H3. True matches: under H1 their number is Poisson with mean K = 0.5025; I budget 2^20 of them inside the same cap, a budget exceeded with probability below 2^-20499797. Per node the candidate count is Poisson with mean (2^39.28 + 2^20) / 2^84 = 2^-44.7, so the chance that any of the 2^84 nodes exceeds its 2^16 candidate slots is below 2^-2930730. Per generating node the forwarded candidates have mean 2 (2^39.28 + 2^20) / 2^20 = 2^20.28 against a 2^24-slot receive area; the chance that any of the 2^20 generating nodes exceeds it is below 2^-40054095.

Re-walk key repeats. Under H3 a chain of L steps carries some key twice with probability about L^2 / 2^193 = 2^-89.7, and carries one key at more than 4 steps with probability below L^5 / (5! 2^768); over all 2^65 chains that is below 2^-451. Both are far inside the 2^-40 budget below. The step with the retained key is found by the linear re-walk because the key is a function of the point and the chain is deterministic from its start.

Node overflow. Mean 2^31.64 baby records per node, capacity 2^33 (2.57 x). Under the binomial form of H3 the Chernoff bound per node is 2^-(3.3 x 10^9); times 2^84 nodes it is still astronomically small. I budget 2^-20 for modelling error.

Gaps. The expected number of gaps above 2^33 among L consecutive H-primes with mean gap 2^25.75 is 2^-167 (exponential gaps, H2'); a larger gap is split into two table steps and the ledger reserves 2^69 units for 16 such splits per chain, a bound the list construction checks. 

Success claimed: 0.3950 - 2^-20 - 2^-40 > 0.392. The 2^-40 covers every cap and re-walk tail above (each is below 2^-47); the 2^-20 is the modelling budget for node overflow. The 0.0030 gap between predicted and claimed is the H1-error budget; the claim keeps 0.002 over the required 0.39.

## 4. Instruction listing per record (AArch64 scalar, on top of the 2000-instruction reference addition)

Baby record (listed 143): gap stream read and pointer advance 5; gap stream transport from the storage nodes (4 bytes per step, blocked) 3; table address 2; operand loads and stores for the addition beyond the reference's own 18; batch-inversion prefix and suffix product loads and stores 6; lane control and loop 8; flow control and counters 5; parity select and key extraction 23; scatter at 3 hops (block index, slot, bounds, 12 per hop) 36; post and poll of full blocks amortised over 16 records at 3 hops 9; transport copy of 32 bytes at 3 hops (4 ldp/stp pairs plus addressing, 6 per hop) 18; insert (head load, slot count check, link write, record store, head update) 10.

Giant record (listed 139): the same without insert, plus lookup fixed cost 6 (head load, chain pointer test, end). Comparisons are charged separately at 8 each up to the node cap. The hop items are executed at the generating node, the two relays and the owner; all are charged per record wherever they run. The first seven items (gap stream through flow control, 47 instructions) are the walk overhead, and the same 47 are charged on every gap-table addition and every re-walk step.

Charged: 180 per record on both sides, 37 above the listed baby count (1.26 x), as a margin for items I did not list.

## 6. Heuristics

H1 (coverage). The 6 N^2 (1 - 2^-51.64) distinct rationals a w / (u a' w') behave like independent uniform elements of H for the purpose of hitting z. Support: Lemma 4 removes the trivial repeats (equal fractions), nothing more, and the toy below, whose measured success agrees with 1 - exp(-K') within 0.4 standard errors in both runs, where K' carries the toy-scale diagonal loss (the toy's own prediction is 0.3935, not 0.3950, because its diagonal is 1/25 of the pairs rather than 2^-51.64). The toy cannot separate 0.3950 from 0.39: the standard error is 0.024 at 400 trials and 0.011 at 2000. The production success figure rests on H1, not on the toy.

H2 / H2' (H-prime density and gaps). A fraction 1/2^20 of the primes near q are H-primes; the L-th H-prime above 2^39 is below 2^78 (ledger estimate 2^77.4), the base range (2^80, 2^99) holds more than 4 x 2^65 of them, and consecutive gaps are exponential with mean 2^20 ln q, so a gap above 2^33 among the L listed has expectation 2^-167. Both are checked by the computation that builds the lists. Sanity on this r: 402 of the 6542 primes below 2^16 are 16th powers (expected 408.9) and 27 are 256th powers (expected 25.6).

H3 (key bits). The 192-bit keys of the 2N records behave like independent uniform strings across mu6 orbits: node and slot occupancies are binomial and cross-orbit key equality has probability 2^-192. Support: the toy bins truncated keys into 32 pseudo-nodes x 16 heads and the chi-square statistic matches its expectation (31.32 against 31, standard error 0.42).

## 7. Evidence (`evidence.py`, standard library, about 3 s)

`ledger`: every number above from exact integers, the assertions d | r-1, 6d | r-1, mu6 in H, the node memory sums and the exact memory inequality, the per-slot, per-node, candidate and re-walk tails and the H2 sanity count.

`ec`: Algorithm A end to end on the j = 0 curve y^2 = x^3 + 3 over F_207670579 of prime order r = 207671809 (d = 128, m = 1622436): H-primes from a sieve, 15 chains x 25 steps per side (K = 0.5201), gap tables, batched affine walks asserting no zero denominator, 16-bit parity key binned into 32 pseudo-nodes x 16 heads, comparisons and false matches counted, each candidate kept as (key, id, id'), one linear re-walk of each of its two chains collecting the steps whose key equals the retained key (at least one asserted; more than 4 on either side counts the trial as a miss, reported as `rewalk_cap_fails`), the six z tested against A_d for every pair of kept steps, then 7 square roots and the root-of-unity scan. The toy never compares one chain against the other. It is not the production procedure at small size, and these are the differences: the comparison, slot, candidate, pool and 2^44 caps are not enforced, the counts are compared with the model instead; the re-walk cap is enforced and counted as a failure; all 15 chains of a side advance in lockstep instead of 2^16 segments of one chain; the re-walk uses the stored small table with complete affine additions and one inversion per step; Lemma 1 scans the 128 roots of unity linearly in batches of 16 instead of a sort and lookup; it is one process, so nothing is routed, posted or polled; candidates are processed in the order found, duplicates included. 400 trials, seed 2026 (the hosted input): success 0.4025 against 0.3935 predicted with the toy diagonal loss (z = +0.37); comparisons 276.2 per run against 274.7 expected; false matches 2.2 against 2.146; true matches 0.51 per run against K = 0.52; re-walk cap failures 0; every recovered s correct. 2000 trials, same seed, run locally (about 15 seconds): success 0.3895 against 0.3935 (z = -0.37, standard error 0.011); comparisons 275.4; false matches 2.104; chi-square 31.17 against 31 (standard error 0.18); re-walk cap failures 0; every recovered s correct.

## 8. Limitations and what was not done

Analytic bound, no full-size run. The instruction counts are itemised, not measured on hardware; the cluster model is the one stated in the cost accounting above, mine and not a rule of the challenge. H1 and H3 are validated only at toy scale. Memory is exponential as in any BSGS-form Cheon attack. This revision keeps the accepted 0a45ddb2 package byte for byte in algorithm, walks, routing, matching, keys, caps, charges and toy procedure and moves only the coverage parameter, K = 0.52 to 0.5025; every size, cap, tail and ledger row derived from N is recomputed by the script, and success (claimed 0.392) keeps a 0.0030 H1-error budget, with 0.002 over the required 0.39. The preprocessing figure is upward-rounded and integer-asserted, answering the round-to-nearest accounting fault. K below the accepted package's stated 0.51 search boundary is claimed here because that boundary was its authors' stopping choice, not a proved barrier; K = 0.50 with its 0.0005 margin over 0.39 is searched and not claimed. Other negative results inherited from that package (two-for-one P+Q / P-Q, x-only or projective steps, rho inside H, two routing hops, records under 32 bytes), not claimed.
