## 1. Measured side-output kernel: 971 instructions per lane, worst path, with explicit fixed-call row

The side-output function side_lanes(args, n) (measure/side_lanes.S) replaces the k6 body of the file base. Its interface is the base's: args[i] = {out, P, T, inv}; it writes the fully reduced x' of P-T to out+0, y' to out+48 and the parity key (limbs 1..3 of whichever of y' and p-y' is even, a38cb931) to out+96; args[n] = {NULL, NULL} ends the lane loop. Points, keys, routing, candidates and success events are therefore those of the base. Inputs: x1, y1, x2, y2 canonical Montgomery residues (P is a kernel output, a canonical restart root (s15) or a strand start; T a gap-table entry), y2 != 0 (G1 has odd prime order, so no point has y = 0), inv = 1/(x2-x1) canonical from the batched inversion, as in the base. Each gap-table entry additionally stores v2 = p - x2 at T+96 and n2 = p - y2 at T+144, so entries are 192 bytes; building one costs 21 more instructions (3 ldp of p, 2 subs + 10 sbcs, 6 stp), charged in the gap-table step (TABLE_BK 27 -> 48, asserted <= 50) and in the re-walk rebuild (2000+32 -> 2000+50); the memory term uses GMAX x 192 and the hoisted stride register holds 192 instead of 96 (no instruction change). Base-point and strand-start entries get v and n inside their scalar-multiplication charge (SM = 8192000 instructions per point, about four times a double-and-add; 21 instructions sit inside that slack).

Arithmetic. R = 2^384, p/R < 0.1016. The word-serial Montgomery product returns S = (ab + qp)/R < ab/R + p before its final conditional subtraction, which the kernel omits; each round's accumulator stays below a + p < 3p < R, so the round-1 zero word and the round-6 top-carry chain of blst's bodies are provably zero and deleted. The kernel inlines blst f7a88067's __mul_mont_384 (twice), __sqr_384 and __mul_by_1_mont_384 with n0 pinned in x18, the modulus in x5..x10 for the whole lane and the 768-bit square kept in registers. Steps: t = y1 + y2 < 2p; mu = S(t, inv) < 2p x p/R + p < 1.21p; V = S(mu^2) < 1.47p^2/R + p < 1.15p; X = V + v2 - x1 in (-p, 2.15p) is x' mod p and is reduced by a sign branch (add p once) or one or two borrow-checked subtractions, then stored; w = x' + v2 in (0, 2p) is x' - x2 mod p; z = S(w, mu) < 2p x 1.21p/R + p < 1.25p; y' = mu(x' - x2) + y2 (the line through P and -T has slope -mu and mu(x2 - x1) = y1 + y2, so this equals mu(x' - x1) - y1), i.e. D = z - n2 in (-p, 1.25p), reduced by one branch (add p once, or subtract p at most once), then stored with the key block (tbz, at most four borrow instructions, stp, str: 7 worst path, audited by key_check.py on both emitted copies). The code after the x' reduction (second product, y', key, loop tail) is emitted twice, so no x' path jumps through shared code.
