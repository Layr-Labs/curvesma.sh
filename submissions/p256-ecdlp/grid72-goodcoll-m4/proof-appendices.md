# Appendix: FRACTION_LABEL.md
# Fraction labels and point-only cell bounds

## 1. Exact label and computed key

For x in[0,p) let T(x)=floor(2^192*x/p), monotone in x; a value of T is taken by at most2^64 values of x (p<2^256). The backward kernel flip_bwd computes L with L-T(x(Z)) in[-21,12] for the emitted point Z (proof.md section3: the truncation deficits of TP1 and TP2, two exact floors T(x(X)), T(x(Y)) and one final floor), whatever the representatives of w and N1 or the batch's other leaves. The record key is floor(L/2^17), 175 bits: K2 holds bits[128,192), the routing digits bits[28,100), and the masked K3 bits[100,128) and[17,36) (plus eight repeated d2 bits). So every key a point can receive lies in K(Z)={floor((T(x(Z))+e)/2^17): -21<=e<=12}, at most two consecutive values, a fixed function of x(Z): both points of a class share it. Labels are fractions of the true residue, so no representation filter, noncanonical band or exceptional label exists.

## 2. Label-error set

If T mod2^17 lies in[21,2^17-12), K(Z) is the single value floor(T/2^17) and both records of any collision in that class carry it. Otherwise (the33 bad residues) the collision may be missed. At most33*2^175 values of T are bad, so at most33*2^239 values of x and2*33*2^239 points; with at most two negation partners, a cross-node pair is both a collision and bad with probability at most4*33*2^239/(r-1)^2. proof.md section6 charges Gamma times this, union-charged before any capacity or survival conditioning; no independence is assumed.

## 3. Single-cell bounds

Fix f key bits at positions B in[17,192), with lowest fixed position a. Widening by the error range adds at most33 values of T to each run of2^a consecutive values, so at most2^(192-f)(1+33*2^-a) values of T, hence2^(256-f)(1+33*2^-a) values of x and twice as many points can produce a computed key with those bits. For a uniform nonidentity point: KB(175)=(2+66*2^-17)*2^81/(r-1) for the full key (a=17), and coefficient2*(1+33*2^-28)=2+66*2^-28 for every pattern with a>=28 (the72-bit home in the pair-load term h, the130-bit hash cell and the136-bit K2 cell).

Interval lemma (d1, fraction bits[64,100); d2, bits[28,64); home, bits[28,100)). For one contiguous block[a,b), bits[a,b) of T(x) equal floor(2^(b-a)*f) with f=frac(2^(192-b)*x/p), so the cell is {x: u=2^(192-b)*x mod p in I}, I an interval of length p/2^(b-a) (widened by33*p/2^b at each end). As u->x is a bijection, its point count is the sum over u in I of1+chi(G(u)) with G(u)=g(2^(b-192)u), g(x)=x^3-3x+b nonsingular, not a square and without roots (no point has y=0). Expanding the interval's indicator in the p additive characters of Z/p (normalized Fourier L1 norm at most2+ln p) and applying the mixed character bound to each frequency (Todd Cochrane, Exponential sums modulo prime powers, Acta Arithmetica101.2(2002), equation(1.2): a nonzero additive frequency of degree1 with the cubic character term gives3sqrt(p); Hasse gives2sqrt(p) at frequency zero) bounds the character sum by3sqrt(p)(2+ln p)<2^138 (ln p<180, sqrt(p)<2^128). The cells have about2^220 (d1, d2) and2^184 (home) points, so KB(36)=(513/512)*2^220/(r-1) and KBH=(513/512)*2^184/(r-1) hold with room.

## 4. Pair loads and dependence

For a fixed opposite point P', K(P') has at most two keys, so a free point whose possible keys can match P' on175 bits lies in a union of at most two fixed cells: M=2*KB(175). Home and relay factors use the single-cell bounds. With rho=(r/(r-1))^4 the shared-generator and same-chain cases are those of proof.md section6, h=rho*(S^2*KB72*M+(4S+20)*M), g=2*rho*n0*S*M, v=18*rho*((S/SIDE)*S*KB36*M+(4S+20)*M). A good witness (section2 of this appendix) carries its single key, so its intruder rate is rho*(S+18)*KB(175) without another factor2 (proof.md section6: S+12 for the other and reserved leaves, plus the three fixed non-witness pairs of the witness incidences). Slot and home-array indicators remain fixed point predicates, so the covariance argument applies unchanged. False partial or full matches are members of these envelopes; caps and verification account for them, and no adjacency-subset claim is used.

# Appendix: RECEIVER_PROTOCOL.md

# Grouped home-array receiver machine

An abstract scalar AArch64 instruction-work construction, not a network-throughput claim. Every processor's instructions and all delivery and in-flight work are charged. routing_check.py executes route.s (receive, h2s, h2done, zero16384) on the true layout; the counts below are the ones it asserts.

## 1. Contexts, channels and the blocking-port convention

Each node has its main scalar context and one dedicated, resident scalar receiver context sharing the node's coherent private memory; no per-packet software dispatcher invokes it. Its code and register parameters are fixed before hop2 begins and persist across all groups. Both contexts' work is charged. Final-cursor, barrier and phase4 messages keep the addressed delivery handler; hop1 follows BLOCK_PROTOCOL.md; hop2 payloads use a separate fixed row-payload port bound to the receiver window, which control messages cannot enter (a fixed channel distinction, not content classification). The extra context, stack, 64-byte packet window, DONE cell in its own 4096-byte granule and port state need less than 8KiB per node, inside the fixed-region reservation.

Blocking-port convention (a machine premise, proof.md section4): a sender's ST64B waits while its bounded port/window cannot accept another message; the receiver's LD64B waits until a complete packet is atomically published; a waiting instruction counts once, never as a poll. Arbitration is fair and backpressured; there is one bounded receiver window, no hidden software queue and no context-switch loop. The single LD64B reads all eight packet words in one single-copy-atomic access and only then releases the window; publication and the blocking load have acquire ordering.

## 2. Receiver body, counts and DONE completion

Resident inputs: packet address, head-address register x12 (bits61..63 set, bits0..2 clear), record cursor x10 and limit x11, candidate-list cursor and end, list-end cell, DONE-cell address, done count, sender count and the constant1. The body reads the packet by one LD64B and branches on bit63 of the destination word (TBNZ): DONE markers set bit63, h2s masks data destinations to bits0..35. x10 holds the pointer of the last written record (record_base-16 initially) and x11 the last admissible pointer record_base+16+32*(CAP_H-1); a record is accepted iff x10<x11 (unsigned), so exactly CAP_H records fit, and a full-array drop stores nothing. Accepted records are prepended to their hash chain and walked as in proof-tails.md Section12 receiver; the walk runs after the window release, on this node's own memory only.

Counts (charged per potential record, including records dropped earlier): accepted path12 before its walk; walk4 per visit and7 more per K3' match (a listing replaces the pointer test); full-array drop5, charged at12. A DONE marker increments the done count and compares with the sender count: non-final6, final9 (one STP of the list cursor and record cursor to the list-end cell, STLR of1 to the DONE cell, count reset). The callable test's RET has the price of the resident branch back to the blocking load.

Completion: the receiver is strictly sequential, so consuming a sender's DONE marker implies every earlier packet from that sender is fully processed, and reaching the sender count implies every stream is. The main context waits on the DONE cell with LDAXR/CMP/B.EQ/WFE (4 per group), loads the published list end (1) and resets the cell (1); the release STLR orders every record, head, next-word and list store before the flag. These sit in group_fixed. Startup, resident registers and a final idle blocking receive are inside the charged2^20 per-node control allowance.

## 3. Phases, progress and per-group work

Per group (proof.md section15): block windows and cursor tables are initialized (BLOCK_PROTOCOL.md), full and partial blocks and final cursors are emitted, drained and barriered; then h2s streams the local slots through the row-payload port and h2done publishes one DONE marker to every row destination, empty ones included. Destination d2 is extracted before BFI replaces w3 bits0..35 by the source column j.

Progress: the receiver never sends a payload or waits on main-context work while processing a packet. It performs finite local work (a walk visits at most CAP_H records of its own node), and its single STLR targets its own DONE cell, which never blocks. Fair execution therefore drains finite sender workloads even if main contexts block on their ports. Every sender publishes exactly one DONE marker per destination per group, so the count reaches the sender count exactly when all streams are processed and no receiver hangs. Home record arrays, cursors, heads, next words and the candidate list persist through all groups; hop1 slots are reused only after the barrier following the group's hop2 drain; resolution of a group's candidates starts only after that barrier.

Per-group counts: h2s costs1 per group plus, per source slot of n records,7 if n=0 and otherwise22+8P+5L+2floor(P/32) with P=floor((n-1)/2), L=(n-1) mod2, at most19+129n/32 (the H2S row is129/32 per record); h2done costs2+4*SIDE. The full per-group fixed sum is1236*SIDE+27 per node (BLOCK_PROTOCOL.md), PHI-weighted over the1600 planned groups.

## 4. Addresses

Fixed memory is[0,2^52), with the DONE granule and receiver state allocated explicitly. Per-group hop1 slots, the32*CAP_H-byte home record array (ending below7*2^61) and the2^58 head words at[7*2^61,2^64) are disjoint increasing regions. flip_ledger.py and fixed_layout.py check the record end, the head base, the fixed reservation, positive cap gaps and the attempted hop1 cursor bound. routing_check.py runs sixteen nodes and two executed groups of three planned with filter-free high raw labels and slot, home-array and list caps against independent reference contents and counts. These finite tests establish the stated finite behavior and counts, not a physical asynchronous implementation; the protocol and all ideal-machine assumptions remain explicit review obligations.

# Appendix: RESOLUTION_PROTOCOL.md

# Explicit bounded resolution routing

No count exchange, sender-side sorting, offset reply, per-destination list or undisclosed allocator is used. resolution_check.py executes phase4.s on 21 capped cases, six actual P-256 recoveries, partial replies, maximum home tags and nine output-tree configurations; its printed counts are the ones charged here.

## 1. Record formats

Candidate list entries are two record pointers (16 bytes), capped at CAND_CAP=2^25 per home; the source cap is REQ_CAP=2^25 and the relay allocation RELAY_CAP=2^34 records. A64-byte request is rawmetadata0, rawmetadata1, home_i|(cid<<36), home_j|(endpoint<<36),0,K3',0,0; K3' is loaded from the record pointer-8. Raw metadata holds source_i36+Ylo28 and source_j36+Xpair9+Yhi19; the source recovers the sign and X low bit (proof.md section20). The seven reply payloads are Xx,Xy,Yx,Yy,a,b,c+us and an eighth chunk carries the recovered sign. Reply tags put cid at bit36 of one word and endpoint at bit36, chunk at bit37 of the other; source and home destination masks are2^36-1. The cid field has28 bits, so every cid below CAND_CAP=2^25 fits; the finite test exercises the field maximum2^28-1.

## 2. Four phases and buffers

`make_requests` runs once per group over that group's new candidates only, the list entries between the previous and the newly published list end (proof-tails.md Section12 receiver), and writes two requests per candidate (19 per candidate plus3) into the separate128*CAND_CAP-byte request-output region (room for2*CAND_CAP requests; fixed_layout.py). Each candidate therefore produces its two requests exactly once over the run. (1) Request hop1: home (h_r,h_c) to relay (g_r,h_c) by word0's low36 bits, appended to the64*RELAY_CAP region. (2) Request hop2: after drain and barrier each relay scans its records once and sends to source (g_r,g_c) by word1, appended to the64*REQ_CAP region. (3) Reply hop1: after drain, each source processes its accepted requests sequentially, gathers the seven values, builds eight tagged replies in a512-byte temporary and sends them to relay (h_r,g_c), whose dead phase-1 region is reused with a fresh cursor. (4) Reply hop2: after drain, each relay sends each reply once to home (h_r,h_c), stored at a direct index. Every phase ends with all sender ports drained and a global barrier before a receiving buffer is read or reused. The append receiver reserves64 bytes by LDADD and either stores all eight words or rolls the cursor back, so the first CAP records in arrival order are kept and excess records drop individually.

## 3. Reply association and completeness

The home stores chunk ch of endpoint side of candidate j at reply_base+64*((2*j+side)*8+ch), injective on valid tags, so no two legitimate writes collide. All16*CAND_CAP flag words are zeroed before any request; only reply records set them; after the final barrier `complete` checks all16 flags of a candidate before its payload is used, so any missing request or chunk drops the candidate. The home reconstructs both leaves from X, Y and the source-recovered signs, rejects identity leaves, tests equality up to negation, performs at most one scalar inversion and one verification of [x]P=Q, and otherwise rejects. The source keeps its X entries (x, y, a_j), b and every chain's (c,s); for a request it decodes round rho and lane k, so the chain is (rho div L, k) and u=rho mod L, forms c+u*s mod r and regenerates Y=[c+u*s]P by cold generation.

## 4. Executed counts and source service

Per record or call, executed by resolution_check.py: send64 14 per record plus2; append64 13 accepted,7 dropped; home64 16; clear_flags 3 per flag plus2; complete at most67 per candidate; make_requests 19 per candidate plus3; gather224 31 per served request; build_replies 84 per request. Lifetime request count. The candidate list is cumulative with cap CAND_CAP per home over the whole run, so the run creates at most2*N*CAND_CAP requests, and a source serves only requests delivered to it. REQ_CAP is a per-group source buffer: its cursor is reset for each group's phase2, it caps the requests stored and answered in one group, and it is not used to bound lifetime work. Source service needs at most64 for decoding indices and locating X, a, b and the chain coins,31 gathering,84 replies and256 for argument setup and loop state: 435, below the1024 per-request allowance. With one256-step modular product and addition (36928+64<2^16), one generator item (23441408) and the2^22 recovery charge of proof.md section20, flip_ledger.py charges NODES*2*CAND_CAP*(1024+23441408+2^16+2^22) (source_service): the lifetime maximum, whether or not requests occur.

## 5. Complete phase-4 work bound

Per phase every input record is visited once by send64; the sender (14), receiving path (at most16) and two in-flight updates total at most32, charged256 per record, which also covers per-call fixed costs and tag moves. Per phase of each executed group each node gets a fixed2^37 allocation covering request creation (19*CAND_CAP+3), flag initialization (48*CAND_CAP+2), completeness checks (67*CAND_CAP), cursor resets and context work: 134*CAND_CAP<2^37. # Appendix: BLOCK_PROTOCOL.md

## Fixed windows, complete delivery and progress

Each sender has one header port and a fixed4096-byte payload window per destination d at payload_base+8192*d+32 (8192-byte stride from an8192-byte-aligned base; the upper4096 bytes are padding, so bit12 of a slot address is set exactly on the128th slot). A header is (destination, destination slot address, fixed payload-window address,128); the emitted address is always that destination's allocated window, not an arbitrary remote-pointer service. Source windows lie below2^51 and destination slots start at2^51+2^56+32, so the ranges do not alias.

The completing header store waits until its transaction is completely copied and acknowledged, not merely enqueued. The destination's dedicated scalar context is fairly scheduled with resident parameters: it reads a complete header, copies128 records (slots1 and128 by LDP/STP, slots2..127 as63 LD64B/ST64B pairs) and issues one STLR1 to its fixed device ACK endpoint; the ACK consumes the single current transaction and no new transaction replaces the mapping before it. The sender may reuse the payload after ACK. There is one bounded window per receiver and one outstanding header per sender; arbitration is fair and backpressured; the receiver never waits on other work before acknowledging, so finite workloads drain even when producers block. Phase drains and barriers precede any window or cursor reuse.

## Emission, partial blocks and prefix preservation

block.s initializes local cursors to window starts and remote cursors to each sender's slot base. Each record is two STPs; one TBZ on bit12 detects the128th slot, where the local cursor resets,4096 remote bytes are reserved and the block is published only if within the slot; a full but dropped block still pays the flush. At group end block_finish publishes one padded full block if the remainder is nonzero and room remains, then sends the clamped valid cursor min(remote+remainder,slot_end). CAP_PG=1441792=128*11264 is divisible by128, so every admitted block lies wholly within its slot and the valid cursor excludes padding: in sender order the slot holds exactly the first min(number_emitted,CAP_PG) records. Record words are unchanged, so the capacity, intruder, pair-load and success bounds apply without a new distributional assumption.
