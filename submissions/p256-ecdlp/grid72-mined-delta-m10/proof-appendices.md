# Appendix: FRACTION_LABEL.md
# Fraction labels and point-only cell bounds

## 1. Exact label and computed key

For x in[0,p) let T(x)=floor(2^192*x/p), monotone in x; a value of T is taken by at most2^64 values of x (p<2^256). The backward kernel flip_bwd computes L with L-T(x(Z)) in[-21,12] for the emitted point Z (proof.md section3: the truncation deficits of TP1 and TP2, two exact floors T(x(X)), T(x(Y)) and one final floor), whatever the representatives of w and N1 or the batch's other leaves. The record key is floor(L/2^17), 175 bits: K2 holds bits[128,192), the routing digits bits[28,100), and the masked K3 bits[100,128) and[17,36) (plus eight repeated d2 bits). So every key a point can receive lies in K(Z)={floor((T(x(Z))+e)/2^17): -21<=e<=12}, at most two consecutive values, a fixed function of x(Z): both points of a class share it. Labels are fractions of the true residue, so no representation filter, noncanonical band or exceptional label exists.

## 2. Label-error set

If T mod2^17 lies in[21,2^17-12), K(Z) is the single value floor(T/2^17) and both records of any collision in that class carry it. Otherwise (the33 bad residues) the collision may be missed. At most33*2^175 values of T are bad, so at most33*2^239 values of x and2*33*2^239 points; with at most two negation partners, a cross-node pair is both a collision and bad with probability at most4*33*2^239/(r-1)^2. proof.md section6 charges Gamma times this, union-charged before any capacity or survival conditioning; no independence is assumed.

## 3. Single-cell bounds

Fix f key bits at positions B in[17,192), with lowest fixed position a. Widening by the error range adds at most33 values of T to each run of2^a consecutive values, so at most2^(192-f)(1+33*2^-a) values of T, hence2^(256-f)(1+33*2^-a) values of x and twice as many points can produce a computed key with those bits. For a uniform nonidentity point: KB(175)=(2+66*2^-17)*2^81/(r-1) for the full key (a=17), and coefficient2*(1+33*2^-28)=2+66*2^-28 for every pattern with a>=28 (the72-bit home in the pair-load term h, the130-bit hash cell and the136-bit K2 cell).

Interval lemma (d1, fraction bits[64,100); d2, bits[28,64); home, bits[28,100)). For one contiguous block[a,b), bits[a,b) of T(x) equal floor(2^(b-a)*f) with f=frac(2^(192-b)*x/p), so the cell is {x: u=2^(192-b)*x mod p in I}, I an interval of length p/2^(b-a) (widened by33*p/2^b at each end). As u->x is a bijection, its point count is the sum over u in I of1+chi(G(u)) with G(u)=g(2^(b-192)u), g(x)=x^3-3x+b nonsingular, not a square and without roots (no point has y=0). Expanding the interval's indicator in the p additive characters of Z/p (normalized Fourier L1 norm at most2+ln p) and applying the mixed character bound to each frequency (Todd Cochrane, Exponential sums modulo prime powers, Acta Arithmetica101.2(2002), equation(1.2): a nonzero additive frequency of degree1 with the cubic character term gives3sqrt(p); Hasse gives2sqrt(p) at frequency zero) bounds the character sum by3sqrt(p)(2+ln p)<2^138 (ln p<180, sqrt(p)<2^128). The cells have about2^220 (d1, d2) and2^184 (home) points, so KB(36)=(513/512)*2^220/(r-1) and KBH=(513/512)*2^184/(r-1) hold with room.

## 4. Pair loads and dependence

For a fixed opposite point P', K(P') has at most two keys, so a free point whose possible keys can match P' on175 bits lies in a union of at most two fixed cells: M=2*KB(175). Home and relay factors use the single-cell bounds. With rho=(r/(r-1))^4 the fixed-leaf, witness-chain and same-Y cases are those of proof.md section6: pair counts of free leaves h=rho*S^2*KB72*M, g=rho*n0*S*M, v=rho*(S/SIDE)*S*KB36*M, and e_o for pairs with a fixed or witness-chain leaf. A good witness (section2 of this appendix) carries its single key, so its intruder rate is rho*(S+FIXED*F2)*KB(175) without another factor2 (proof.md section6). Slot and home-array indicators remain fixed point predicates, so the covariance argument applies unchanged. False partial or full matches are members of these envelopes; caps and verification account for them, and no adjacency-subset claim is used.

# Appendix: RECEIVER_PROTOCOL.md

# Grouped home-array receiver machine

Every processor's instructions and all delivery and in-flight work are charged. routing_check.py executes route.s (h2b, h2fin, rblk, zero16384) on the true layout; the counts below are the ones it asserts.

## 1. Contexts, channels and the blocking-port convention

Each node has its main scalar context and one dedicated, resident scalar receiver context sharing the node's coherent private memory; no per-block software dispatcher invokes it. Its code and register parameters are fixed before hop2 begins and persist across all groups. Both contexts' work is charged. Final-cursor, barrier and phase4 messages keep the addressed delivery handler; hop1 follows BLOCK_PROTOCOL.md; hop2 uses the same block transaction on a separate fixed row port bound to the receiver context: a header names the sender's fixed window for that destination and a count, and control messages cannot enter that port (a fixed channel distinction, not content classification). The extra context, stack, header window, DONE cell in its own4096-byte granule and port state need less than8KiB per node, inside the fixed-region reservation.

Blocking-port convention (a machine premise, proof.md section4, as in BLOCK_PROTOCOL.md): the sender's completing header store waits until its block is completely copied, joined and acknowledged, not merely enqueued; the receiver's header load waits until a complete header is published; a waiting instruction counts once, never as a poll. There is one outstanding header per sender and one bounded port per receiver; arbitration is fair and backpressured, with no hidden software queue and no context-switch loop. The header is an address of the sender's own allocated window, never an arbitrary remote pointer, and the sender reuses the window only after the ACK.

## 2. Receiver body, counts and DONE completion

Resident inputs: header address, head-address register x12 (bits61..63 set, bits0..2 clear), record cursor x10 and array end x11, entry cursor x14, the constant C, candidate-list cursor and end, list-end cell, DONE-cell address, done count and sender count. Body, walk and counts are proof-tails.md Section12: 6 per record and27 per full block, at most6c+35 for a block of c records,4 per visit,7 per K2 hit, at most18 per full-key match. A block is kept or dropped whole; the room test leaves one slot for the hole, so the witness's block is stored unless fewer than129 slots remain, and the array loses at most one slot per final block (CAP_H's G*SIDE term, proof.md section6).

Completion: the receiver is strictly sequential, so consuming a sender's DONE block implies every earlier block from that sender is fully processed, and reaching the sender count implies every stream is. The main context waits on the DONE cell with LDAXR/CMP/B.EQ/WFE (4 per group), loads the published list end (1) and resets the cell (1); the release STLR orders every record, head, entry and list store before the flag. These sit in group_fixed. Startup, resident registers and a final idle blocking load are inside the charged2^20 per-node control allowance.

## 3. Phases, progress and per-group work

Per group (proof.md section15): block windows and cursor tables are initialized (BLOCK_PROTOCOL.md), hop1's full and partial blocks and final cursors are emitted, drained and barriered; then h2b sorts the local slots into the hop2 windows, one per row destination d at W2+8192*d+32 with a cursor table on a2^39-aligned base. Per record: BFI of d (w3 bits0..35) into the cursor address, LDADD of32, BFI of the source column j into w3, two STP, and TBZ on bit12 of the slot address, which is set exactly on the128th slot; there h2flush resets the cursor and publishes the header (8, and2 in flight). h2fin then publishes for every row destination its remaining0..127 records with the DONE flag and resets the cursor (11 per destination, and2 in flight), empty destinations included.

Progress: the receiver never sends a payload or waits on main-context work while processing a block. It performs finite local work (a walk visits at most CAP_H records of its own node), and its STLRs target the ACK endpoint of the block being processed and its own DONE cell, which never block. Fair execution therefore drains finite sender workloads even if main contexts block on their ports. Every sender publishes exactly one DONE block per destination per group, so the count reaches the sender count exactly when all streams are processed and no receiver hangs. Home record arrays, cursors, heads, entries and the candidate list persist through all groups; hop1 slots and hop2 windows are reused only after the barrier following the group's hop2 drain; resolution of a group's candidates starts only after that barrier.

Per-group counts: h2b costs4 per group plus, per source slot of n records,7 if n=0 and otherwise25+14P+8L+2floor(P/32) with P=floor((n-1)/2), L=(n-1) mod2, at most19+(7+1/32)n, plus8 per full block (the H2S row is7+1/32+10/128 per record); h2fin costs2+11*SIDE. The full per-group fixed sum is1277*SIDE+28 per node (BLOCK_PROTOCOL.md), PHI-weighted over the1600 planned groups.

## 4. Addresses

Fixed memory is[0,2^52), with the DONE granule and receiver state allocated explicitly. Per-group hop1 slots, the32*CAP_H-byte home record array, its16*CAP_H-byte next array (ending below7*2^61) and the2^58 head words at[7*2^61,2^64) are disjoint increasing regions. flip_ledger.py and fixed_layout.py check the array ends, the head base, the fixed reservation, positive cap gaps and the attempted hop1 cursor bound. routing_check.py runs sixteen nodes and two executed groups of three planned (toy K2 below2^6 except top bits, so distinct K2 share chains and K2 hits occur; planted cross-group and same-node same-key pairs; full arrays and lists; odd, empty and full blocks) against independent reference contents and counts: finite behavior and counts, not a physical asynchronous implementation.

# Appendix: RESOLUTION_PROTOCOL.md

# Explicit bounded resolution routing

No count exchange, sender-side sorting, offset reply, per-destination list or undisclosed allocator is used. resolution_check.py executes phase4.s on 21 capped cases, six actual P-256 recoveries, partial replies, maximum home tags and nine output-tree configurations; its printed counts are the ones charged here.

## 1. Record formats

Candidate list entries are two record pointers (16 bytes), capped at CAND_CAP=2^27 per home; the source cap is REQ_CAP=2^29 and the relay allocation RELAY_CAP=2^34 records. A64-byte request is rawmetadata0, rawmetadata1, home_i|(cid<<36), home_j|(endpoint<<36),0,K3',0,0; K3' is loaded from the record pointer-8. Raw metadata holds source_i36+Ylo28 and source_j36+Xpair9+Yhi19; the source recovers the sign and X low bit (proof.md section20). The seven reply payloads are Xx,Xy,Yx,Yy,a,b,c+us and an eighth chunk carries the recovered sign. Reply tags put cid at bit36 of one word and endpoint at bit36, chunk at bit37 of the other; source and home destination masks are2^36-1. The cid field has28 bits, so every cid below CAND_CAP=2^27 fits; the finite test exercises the field maximum2^28-1.

## 2. Four phases and buffers

`make_requests` runs once per group over that group's new candidates only, the list entries between the previous and the newly published list end (proof-tails.md Section12 receiver), and writes two requests per candidate (23 per candidate plus3) into the separate128*CAND_CAP-byte request-output region (room for2*CAND_CAP requests; fixed_layout.py). Each candidate therefore produces its two requests exactly once over the run. (1) Request hop1: home (h_r,h_c) to relay (g_r,h_c) by word0's low36 bits, appended to the64*RELAY_CAP region. (2) Request hop2: after drain and barrier each relay scans its records once and sends to source (g_r,g_c) by word1, appended to the64*REQ_CAP region. (3) Reply hop1: after drain, each source processes its accepted requests sequentially, gathers the seven values, builds eight tagged replies in a512-byte temporary and sends them to relay (h_r,g_c), whose dead phase-1 region is reused with a fresh cursor. (4) Reply hop2: after drain, each relay sends each reply once to home (h_r,h_c), stored at a direct index. Every phase ends with all sender ports drained and a global barrier before a receiving buffer is read or reused. The append receiver reserves64 bytes by LDADD and either stores all eight words or rolls the cursor back, so the first CAP records in arrival order are kept and excess records drop individually.

## 3. Reply association and completeness

The home stores chunk ch of endpoint side of candidate j at reply_base+64*((2*j+side)*8+ch), injective on valid tags, so no two legitimate writes collide. All16*CAND_CAP flag words are zeroed before any request; only reply records set them; after the final barrier `complete` checks all16 flags of a candidate before its payload is used, so any missing request or chunk drops the candidate. The home reconstructs both leaves from X, Y and the source-recovered signs, rejects identity leaves, tests equality up to negation, performs at most one scalar inversion and one verification of [x]P=Q, and otherwise rejects. The source keeps its X entries (x, y, the public a_j), b, R_g and every chain's (c,s); for a request it decodes round rho and lane k, so the chain is (rho div L, k) and u=rho mod L, forms c+u*s mod r and regenerates Y=R_g+[c+u*s]P by cold generation.

REQ_CAP is a per-group source buffer: its cursor is reset for each group's phase2, it caps the requests stored and answered in one group, and it is not used to bound lifetime work. # Appendix: BLOCK_PROTOCOL.md

## Fixed windows, complete delivery and progress

Each sender has one header port and a fixed4096-byte payload window per destination d at payload_base+8192*d+32 (8192-byte stride from an8192-byte-aligned base; the upper4096 bytes are padding, so bit12 of a slot address is set exactly on the128th slot). Source windows lie below2^51 and destination slots start at2^51+2^56+32, so the ranges do not alias.

The completing header store waits until its transaction is completely copied and acknowledged, not merely enqueued. The destination's dedicated scalar context is fairly scheduled with resident parameters: it reads a complete header, copies128 records (slots1 and128 by LDP/STP, slots2..127 as63 LD64B/ST64B pairs) and issues one STLR1 to its fixed device ACK endpoint; the ACK consumes the single current transaction and no new transaction replaces the mapping before it. The sender may reuse the payload after ACK. There is one bounded window per receiver and one outstanding header per sender; arbitration is fair and backpressured; the receiver never waits on other work before acknowledging, so finite workloads drain even when producers block. Phase drains and barriers precede any window or cursor reuse.
