# bls12-381-miller-inversion: bounded 32-adding Pollard rho

## Exact scope

This submission claims ONLY the protected bls12-381-miller-inversion task. It is a standard low-memory discrete-log attack with an explicitly heuristic runtime-success claim, not a new attack or practical break. The claimed success probability is at least 0.39 under the supported finite random-walk heuristic H below. All output correctness checks and the worst-case instruction cap are unconditional; only the probability of reaching a useful collision within the cap is heuristic. The submitted log2 upper bound is 159/1 in the protected classical-group-work-v2 units (C=20000). No formal production probability theorem or actual full-size solve is claimed.

## Track reduction and output

Compute G=e(P0,Q0) using the pinned reduced pairing. Set T=y^((p^12-1)/r), where y is the raw Miller target. Run rho in the multiplicative prime-order subgroup GT, recovering a with G^a=T. Return affine P=[a]P0 only after checking the EXACT raw M(P)=y using the pinned quotient, with no final exponentiation in this final check. Because the honestly generated y=M([a0]P0) final-exponentiates to G^a0, and G has order r, successful DLOG recovery yields a=a0 modulo r. Thus the final raw check passes. T=1 gives a=0 and P=infinity. The independently generated powers secret is not assumed to equal a.

## Fully specified walk

Write the prime-order group's operation additively in this section; in GT replace addition by multiplication and [a]G by G^a. Let the unknown target logarithm be x, so T=[x]G. Use canonical element encodings: for curve points a one-byte infinity tag followed by fixed-width big-endian x,y field coefficients (zero-filled at infinity); for GT the twelve fixed-width big-endian 48-byte coefficients in profile order. Use affine curve coordinates, never noncanonical projective representatives, for hashing or equality.

Run at most EIGHT independent attempts. In each attempt draw a fresh uniform 32-byte hash seed, 32 pairs (u_j,v_j), and initial coefficients a,b, all uniform in 0..r-1. A scalar draw uses a fresh uniform 256-bit string, accepts it if less than r, retries up to 64 times, and aborts this attempt if all draws fail. This bounded rejection sampler costs work even on rejected draws. Build D_j=[u_j]G+[v_j]T by binary scalar multiplication; this preprocessing is paid from scratch for each attempt. Set X=[a]G+[b]T. All arithmetic on coefficients is modulo r. Every walk state has the invariant X=[a]G+[b]T.

A step on (X,a,b) computes j=SHA256(seed || encode(X))[0] & 31, then returns (X+D_j,a+u_j,b+v_j). SHA256 is the standard scalar FIPS algorithm, not a random-oracle instruction or uncharged lookup. The 32-entry table is retained for this attempt. The seed is constant within an attempt so the step is a deterministic function of the group element; a new independent seed/table/start are used on restart.

Use Floyd's cycle algorithm: slow=fast=initial; for at most N=2^132 iterations, replace slow by step(slow), fast by step(step(fast)), then compare the exact canonical group elements. On equality, set denominator=b_slow-b_fast mod r. If zero, abandon this attempt as fruitless and restart. Otherwise compute

    candidate = (a_fast-a_slow) * denominator^(-1) mod r.

Verify [candidate]G=T and the track-specific output conditions above. If verification succeeds return the output; otherwise restart. After eight unsuccessful attempts return failure. Check the identity target before setting up the walks. All cap, comparison, failed verification, restart, and scalar inversion work is charged. No exponentially large table or nonuniform advice is used.

If denominator is nonzero, the invariant and order r imply candidate=x mod r exactly. Thus no incorrect output can pass the verification. Identity and valid nonzero targets are both covered as appropriate for this track.

## Heuristic H and success accounting

H is the following quantitative engineering assumption for this exact 32-adding walk, canonical encoding and seeded SHA256 partition: averaged over uniform production targets and fresh attempt coins, a fresh attempt has at least 0.10 probability of producing a nonfruitless verified collision within 16*sqrt(r) Floyd iterations, and this lower bound continues to hold conditional on the previous failed attempts. This explicitly includes coefficient nondegeneracy, not just a group collision. It is an extrapolation, not a theorem about SHA256. A pathological target-dependent walk family or correlations across restarts could invalidate H and therefore the claimed success probability.

The protected r is less than 2^256, so 16*sqrt(r)<=2^132. Conditional on H and successful scalar sampling, eight attempts succeed with probability at least 1-0.9^8=0.56953279. Since r>2^254, a 256-bit scalar draw accepts with probability greater than 1/4. There are at most 8*66=528 coefficient draws; a union bound on exhausting 64 rejection trials is less than 528*(3/4)^64 < 0.000006. Subtracting this from 0.56953279 still exceeds 0.39 by a wide margin. Hash-seed draws are fixed length and need no rejection. No extra confidence estimate is substituted for algorithmic probability.

Why H is plausible: the algorithm follows the standard many-partition r-adding construction, avoiding reliance on Pollard's original three-way walk. Teske's work studies this distinction and supports using many-partition adding walks for random-like behavior. In the ideal uniform random-mapping model, a first repeat occurs on the square-root scale; Floyd detection costs a constant-factor number of iterations. A budget of 16*sqrt(r) and a per-attempt success floor of 0.10 are deliberately conservative relative to that model. The precise transfer to SHA256 and these production groups remains the stated heuristic, including nonfruitless collisions and restart robustness.

Supporting literature: Edlyn Teske, On random walks for Pollard's rho method, Mathematics of Computation 70 (2001), 809-825, DOI 10.1090/S0025-5718-00-01213-8; Waterloo's report record: https://uwaterloo.ca/combinatorics-and-optimization/research/combinatorics-and-optimization-technical-reports/technical-reports-1998 . Kim, Montenegro, Peres and Tetali, A Birthday Paradox for Markov chains with an optimal bound for collision in the Pollard Rho algorithm for discrete logarithm, https://arxiv.org/abs/0712.0220 . The latter proves square-root-order collision results in a random-oracle partition model, not a finite 0.10 guarantee for our SHA256 implementation. Neither paper is claimed to prove H exactly.

## Finite experiment and its limits

experiment.py implements the same 32-adding invariant, seeded SHA256 partition, Floyd detection, fruitless restart and collision equation in additive prime-order groups of orders 1019, 10007, 65537 and 1000003. Fixed deterministic test seeds make results reproducible; production uses fresh random coins, not Python's test RNG. The toy loop cap is 16*isqrt(order)+16, a rounding of the same square-root-scale allowance, with eight attempts. It checks output against the known toy scalar. At 64 trials per order, the isolated local run recovered all 256 targets, with zero fruitless restarts and zero capped attempts. Maximum step counts (three steps per Floyd iteration) were 243, 777, 1806 and 10359; means were 104.203125, 317.953125, 781.640625 and 3135.328125 respectively. These are toy step counts, not timings or instruction counts.

The experiment was run in an unprivileged, read-only Docker container with no network, dropped capabilities and bounded memory/CPU/process count, using Python image sha256:a6e34c598f2467ed0e9a8d349809fcd8b5c603269512df273a0bb1784edc11b1. The model-specific production curve/GT encoding is NOT tested by this scalar-group experiment. It provides implementation sanity evidence and finite random-walk observations only. It does not establish production probability, cryptanalytic novelty, or cost constants. The hosted reviewer can rerun the declared experiment and should assess this limitation explicitly.

## Concrete base-field and point arithmetic

Use 64-bit scalar AArch64 instructions and fixed arrays of seven 64-bit limbs for all base-field arithmetic. The protected field modulus has at most 381 bits; the seventh limb accommodates carry for addition. Canonical residues are always reduced. An addition computes a+b with carry and conditionally subtracts p. Subtraction computes a-b and conditionally adds p on borrow. Comparisons inspect the limbs from most significant to least. Load/store, carry, branch and address work are included: reserve 128 instructions per limb per pass and four seven-limb passes plus 512 fixed instructions. Thus one addition/subtraction/comparison/copy costs at most A=2^12 instructions. This is generous for straight scalar loads, ADDS/ADCS, SUBS/SBCS, comparisons, selections and branches; it is not a unit-cost wide-integer assumption.

Multiplication is bit-serial double-and-add modulo p: t=0,v=a; for bits j=0..380 of b, conditionally t=addmod(t,v), then v=addmod(v,v). Include leading zero bits. At most 762 modular additions, 381 bit tests and loop overhead, plus setup/copy, fit M=2^24 instructions (762*4096 is less than 2^22). Squaring is a multiplication. For nonzero a, inversion is binary powering a^(p-2), at most 762 multiplications and less than 2^20 instructions of bit scanning, setup and control; I=2^35 bounds it. This uses Fermat's theorem for the protected prime p, not an inversion oracle.

For affine point arithmetic maintain an infinity flag. For R+G: if R is infinity, copy G; if the x coordinates agree and the y coordinates sum to zero, return infinity; otherwise the equal-point branch uses slope (3*x_R^2)/(2*y_R), and the unequal-x branch uses (y_G-y_R)/(x_G-x_R). Then x_new=slope^2-x_R-x_G and y_new=slope*(x_R-x_new)-y_R (in doubling x_G=x_R). On the nonexceptional branches the denominator is nonzero. The protected G1 curve has a=0. These are the standard chord/tangent group law. Charge one I, 32 M and 32 A plus 2^20 overhead, below 2^36 per addition. This includes testing every exceptional branch. Exact point comparison and scalar increment use fixed arrays; no scalar exceeds 256 bits. Output is canonical hex or null for infinity.


## Extension arithmetic and exact evaluation

For this track, kernels.md provides the exact formulas and schedule; this paragraph prices them under the CURRENT 64-bit model, replacing the older repository baseline's word convention.

In Fp2, u^2=-1 and (a+bu)(c+du)=(ac-bd)+(ad+bc)u. In Fp12, w^12=2*w^6-2. Multiply dense degree-11 polynomials using 144 base products and 144 accumulation additions. Reduce terms of degrees 22 down to 12: for coefficient c at degree d add 2c at degree d-6 and subtract 2c at degree d-12. At most 44 additional modular additions suffice, including formation of 2c. All intermediate coefficients are reduced. Fp12 multiplication therefore costs at most 144M+188A+2^20 < E=2^34. Fp2 multiplication, extension addition/subtraction, coefficient movement and comparisons also cost less than E. The 2^20 reserve includes loops, pointer arithmetic and movement of arrays of at most 23*7 limbs; no array has an exponential address.

Each projective point operation, twist, cast, or rational line call in kernels.md uses fewer than 64 extension arithmetic calls and fewer than 2^20 other scalar instructions; allocate 128E for each. A Miller substep uses fewer than eight such calls, including accumulator updates and control, so allocate 1024E. There are fewer than 128 substeps. Allocate another 1024E for initialization, validation of the fixed generators/current point, decoding constants, and the final quotient multiplication. This subtotal is below 2^52 instructions. Denominator inversion is binary powering in Fp12 by p^12-2; reduced pairing additionally powers by (p^12-1)/r. Each exponent has at most 4572 bits and costs at most 9144E plus 2^24 overhead, less than 2^48. Even BOTH exponentiations, loop subtotal and wrapper fit below 2^53. Raw Miller omits the final exponentiation. Infinity returns one immediately.

Exponent construction is charged, not an oracle: represent integers up to p^12 in 73 64-bit limbs, compute twelve successive bit-serial integer products by p, then ordinary binary long division by r. Reserve 512 instructions per limb per bit for carry, loads/stores, comparisons and control. Product stages total at most 12*381*73*512 < 2^28; division at most 4572*73*512 < 2^28. A 2^32 budget includes decoding constants and both exponent constructions. This can be done once on the cold input. Registers, arrays and all routines fit well within the memory bound below.



## Complete scalar instruction ledger

The coefficient field modulo prime r uses the same conservative seven-limb arithmetic (r<2^256). Every coefficient add costs at most A=2^12; inverse at most 2^35. Scalar generation draws are charged up to 2^20 instructions per 256-bit string, including bit generation, copying, comparison and branching; fewer than 2^16 such draws occur. For hashing a production element with the 32-byte seed, the message fits within eleven SHA256 blocks (curve encodings are shorter). Each block has 64 compression rounds plus message scheduling using ordinary 32-bit rotates/shifts, Boolean logic and additions, loads/stores and loop work. Fewer than 4096 scalar instructions per round plus 2^20 fixed copy/encoding overhead fits 2^24 instructions per hash. All table accesses use ordinary small addresses and are charged.

A curve walk step costs less than 2^37 scalar instructions: one affine addition (<2^36), hashing (<2^24), two coefficient additions, record loads/stores, control and exact comparison reserve. A GT step costs less than 2^35: one Fp12 product (<2^34), the same hashing/coefficient work and movement. These are analytic instruction-equivalent bounds, not Python interpreter timings. Use the applicable bound S=2^35 for THIS track.

At most 8*3*2^132 < 2^137 walk steps are executed. Setup, all 32-entry tables on eight restarts, scalar sampling, target conversion, final checks, failures and output fit an additional 2^64 instructions: table building takes fewer than 2^19 group operations (two scalar multiplications of at most 512 operations each, 32 entries and initial state, eight attempts); even the point bound gives less than 2^55 instructions, and constant target conversions/verification, where applicable, fit the remaining reserve. Charge every failed attempt, no expected-runtime discount. No precomputed table is reused between targets.

For every 1<=n<r, compact input scanning costs at most 2^20*(n+1) scalar instructions: fewer than 1024 bytes per point, up to 1024 instructions per byte, with a streaming parser discarding unused powers. Their generation is excluded as specified by the profile; all processing performed is charged. No full-array validation is needed for honestly generated auxiliary powers. Let L(n)=(2^137*S+2^64+2^20*(n+1))/C, with H_reference=0 and C=20000. This is a total-work upper bound for the whole stated n range, with no divisor assumptions. At n=2^20, L(n)<2^159. Submit W(n)=2^159 + (2^20/C)*max(0,n-2^20), which dominates L(n) and has log2(W(2^20))=159 exactly. Cold preprocessing is bounded by (2^64+2^20*(n+1))/C and is included, not amortized.

Peak working memory is at most 2^24 bytes for code, constants, all 32 entries, seed, states, input buffers and arithmetic scratch. Each entry holds at most twelve seven-limb coefficients and two four-limb scalars, below 1024 bytes; 32 entries use below 32768 bytes. Fewer than 4096 field slots, 65536 bytes of counters/buffers and 2^20 bytes of fixed loop code/stack/constants fit well below the bound. Iterative Floyd detection retains only two states and fixed scratch, no path history. Nonuniform advice is zero bytes. Including external compact input storage, memory is at most 2^24+1024(n+1) bytes on the BLS tracks (n=2^20 gives less than 2^31); for this statement on secp use n=0 merely as a storage-count convention, with no auxiliary-input claim.
