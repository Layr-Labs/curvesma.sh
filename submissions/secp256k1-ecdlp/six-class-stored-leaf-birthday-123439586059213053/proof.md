## 2. The algorithm
### 2.1 Machine
2^72 nodes (i, j), 0 <= i, j < 2^36, each with a main processor and one delivery processor per message kind (dlv, hop-1 arrival h2s, hop-2 arrival dlvh), scalar AArch64: base set, FEAT_RNG, FEAT_LSE, DC ZVA (DCZID_EL0.BS = 6, a 256-byte block as on Fujitsu A64FX; DZP = 0, DZE = 1) on Normal memory, FEAT_LS64 (EnALS = 1). **Premises:** one 64-bit flat address space per processor, with shared node backing and the processor-qualified receive aperture below, the LS64 locations, the DC ZVA block size. The ledger counts every processor's executed instructions (one step each), all executed data movement, and each message's delivery and in-flight count; storage is reported separately; fixed address decode/wiring is part of the machine design, not an oracle.
**Address decode and finite messages.** The main processor sees the whole beta reservation, including [LINK, 2^64) (LINK = 2^64 - 2^14), as shared Normal backing; each of the three delivery processors sees its own read-only Device receive aperture there and the same node backing below LINK, under the output-port store decode: a static per-initiator map, the same at every node for the whole run, with no page-table switch, relocation, table copy, advice or computed lookup. Main never reads an aperture; delivery never looks up beta, whose backing stays live.
An aperture exposes only the finite message being delivered (a six-word record, or four header words and 4k payload words; k = 256, at most 8224 bytes), not a zero-filled window; reads stay within it and writes to it are forbidden. Unused final-block slots are real stale payload, never consulted past the count or final cursor. A delivery processor retains one message until its handler completes, another waiting at its sender's port; a completing port store waits for its receiver, which performs the listed loads and stores, and the message is released. DSB waits for all such acknowledgements; h2s can wait only on dlvh, which writes backing and never sends: bounded backpressure keeps the dependency order and all-in-flight completion, with no sorting or routing oracle. The two instructions per message price the completion counters; payload accesses, forwarding and receiver work are executed schedules. Three receive latches (3*2^14 bytes), their state and four register states fit a 2^16-byte node reserve in peak storage; decode constants are static and target-independent. An optional 128-instruction initialization (four contexts, <= 32 each) fits the NODE_INIT slack (checked). No other per-message instructions are assumed.
- **Ports and links.** A port's 48-byte message block (destination word, address, four data words; the STP to +32 completes it) sends one record. Record blocks, one per destination d at PB + 2^14 d (PB = 2^50 column, 2^51 row), hold a header (destination word, address, byte count; at hop 2, p at +24) and k = 256 slots at +32n; the header's STP after the count word completes a k-record message, written by delivery code at its address (hop-1 column blocks go to the destination's h2s). Links keep no state but the message in flight.
- **LS64 (premise).** `LD64B`/ST64B Xt, [Xn] move Xt..Xt+7 in one 64-byte access: t even, <= 22, no offset, Xn 64-byte aligned. Supported locations are IMPLEMENTATION DEFINED; here the link windows (Device), R2, pair entries, Y-records, β and X tables (Normal Non-cacheable, with LSE atomics: bwd's fixup STADD hits a Y-record), nowhere else; R2 starts at 32 mod 64 so slot pairs of a block and of its R2 copy are both 64-byte aligned. `a64.py` asserts on every access Xt even and <= 22, an LD64B base outside Xt..Xt+7, alignment and the run's regions; machine.py ls64_checks ships a failing input per case and dlvh, h2s mutants, `isa_checks` branch reach (TBZ 8191 ahead loads; 8192, B.LO 2^18 rejected) and DC ZVA (aligned Normal runs; misaligned, Device rejected).
- **Delivery is charged** as executed `route.s`: dlv 6 per one-record message, h2s (every hop-1 block), dlvh (4). Each runs as a loop on its delivery processor, its first window load waiting for a complete message; h2s then loads p from the node word at 2^48 - 168, written by the main processor for group g after group g - 1's last barrier's DSB (at set-up for g = 1).
- **Completion and barriers.** A port counts messages in flight (charged 2 each); DSB completes once the node's stores are written and its ports' counts are zero, and nodes run it before a barrier. **No deadlock:** a main processor's completing store waits only for a delivery processor, h2s's row-port stores only for dlvh, which writes memory and never waits on a port. Barriers are a combining tree of epoch writes; a wait is an LDAXR/WFE loop that only a store into the awaited word wakes (this machine's event register).
### 2.2 Leaves and records
Node g draws uniform `b_g`, `a_j` (j < 1024) in [0, r) and, per batch k < q1 = 536870880 (w2 keeps k mod 2^28, section 4 recovers bit 28), c_k, t_k, s_k in [1, r), ρ_k in [1, p) (t_k, s_k are batch coins; S alone is the leaf total). It stores R_g = [b_g]Q, the permanent X_j = R_g + [a_j]P and per batch C_k, T_k, S_k = [c_k]P, [t_k]P, [s_k]P; the batch's points are Y_(m,n) = [c_k + m t_k + n s_k]P (m < 8192, n < 4), point number u = 8192n + m. Incidence l = 1024u + j < q2 = 2^25 pairs X_j with Y_u; its leaves are the x-coordinates of φ^t(X_j) + s Y_u, t in {0, 1, 2}, s = ±1: n0 = 6 q1 q2 per node, S = 2^72 n0 (log2 S approximately 128.584962) in an opened run. As φ = [λ], such a leaf is [μ]P + [ν]Q, μ = λ^t a_j + s(c_k + m t_k + n s_k), ν = λ^t b_g. A point Z ≠ O has class {±Z, ±φ(Z), ±φ²(Z)}; its x-coordinates {x, βx, β²x} have canonical member `v* = min(x, βx mod p, β²x mod p)` and its **label** is `(T(v*), T(βv* mod p))` (3.3). A record is [K2, K3, w2, w3]: K2, K3 from the two parts' words (3.3), w2 = i | k<<36 (i the source's row; the 64-bit shift keeps k mod 2^28), w3 = d2 | 2<<36 | l<<39, bits 36..63 complemented (5, ~l) on a j = 1 leaf (3.2): w3 gives l, neither s nor t (signless, soispoke's `KEY_W3`). d1, d2 are bits 28..63 of the parts' L words; a record's source at its home is (w2 mod 2^36, j), j its arrival slot's index.
### 2.3 Phases
Pair slots hold cap_p = 2^22 - 2^17 32-byte records (a multiple of k): at hop 1 a node in row i writes only into slot i of R1 at each node of its column, at hop 2 one in column j only into slot j of R2 at each node of its row. Each port has **LC** (next slot of d's record block; init3) and **RC** (sender's cursor in its pair slot at d; tinit) tables of 2^36 entries, the column port's LC at address 0 and the row port's at 2^39 (d's entry is also a destination word for d).
- **0. Preprocessing:** program delivery, node state, coins, the 1024 permanent X's (affine store), the X tables (tblx), pair-entry X words, rows of β, LC/RC tables, hash-head zeroing (zero16384), hash-read cursors (init3), β tables (tbld), E3 = 2^64 - 1 (tinit); then Q is broadcast and R_g generated.
- **1-5. Groups** g = 1..780 of contiguous batches ending at `688296*g` (6.6), the loop first testing the latched stop flag, barriers between all phases. Per batch: C_k, T_k, S_k by the generator, ygen, fwd, fe_inv, bwd, keys. **Hops:** under per-group caps cap_pg = 2^20 - 2^11, keys emits each record into d1's column block, sent after slot k to (d1, j) at its RC cursor or dropped if that cursor is at or past the slot end (4); h2s forwards each record through the row port to (own row, d2) by the same rule into cumulative R2 slots; fin sends final blocks and writes final cursors (E1, E2[j] by group parity); dlvh copies each row block into R2 and joins its unjoined records (at or past the slot's previous final cursor F; list cap 2^35). **Resolution** (four count-exchange sub-phases; drops at 2^33 requests per source, 2^40 records per relay): a home sends two requests per new candidate to sources (g_r, g_c) via relay (g_r, h_c), replies of <= 8 records return via (h_r, g_c). The home decodes each record's k (4) and a request carries it; the source reads X_j's affine point from its permanent store (5) and batch k's coins, **regenerates** `Y_u` by the generator and copies the scalars (REQ_SERVE = 2^10 + GEN_MUL, 7); old groups serve identically. As w3 gives neither s nor t, the home forms each record's six possible leaves [μ]P + [ν]Q, tests the 36 pairs in fixed order for a unit u with L' = uL and, with the first having ν' - uν ≠ 0, outputs x = (uμ - μ')/(ν' - uν) mod r after checking [x]P = Q. **Stop:** a resolved x latches a stop flag, broadcast over 2 hops; all halt after the barrier outputting it (W_g).
**Barriers** <= 13265 (4 pre, 17 per group, 1 output; 13265 charged).
### 2.4 Run gate
Before anything else one coordinator reads a fresh 64-bit RNDR word u (a coin independent of the challenge and of every other coin) and compares it with K = 7203334947470835147 (MOVZ and three MOVK, CMP, a branch). If u < K it starts the run of 2.3 by broadcasting Q (2.3's first message; a node does nothing before it); otherwise it halts and outputs nothing, and no other processor executes an instruction. `certificate.py` charges GATE = 2^7 on every run (64 for the coin, at most 8 more itemized). K is the least integer with (K/2^64) lo_run >= 0.39 (6.7), so K/2^64 approximately 0.3904935700. A closed gate is a failure and its cost is charged; nothing is amortized. **Caps** (fixups, pair slots, candidates, requests, relay records, coin retries) bound the worst case on every run; walks are uncapped; the E-ledger (7) averages group-granular work and the candidate and fixup counts.
## 3. Leaf kernels (kernels/leaf.s; ygen in kernels/secp_fe.s)
### 3.1 One batch
A batch is one (c_k, t_k, s_k): its 2^15 Y points against the 1024 permanent X's, q2 = 2^25 incidences l = 1024u + j, walked up by fwd and down by bwd, keys through 512-byte **pair entries** (entry l at SB + 512 l, SB a multiple of 2^35). With a = x(X_j), b = x(Y_u), A_j = y(X_j)², B = y(Y_u)², D = B - A_j = b³ - a³, incidences (j even, j + 1) of a point form a **pair** with e = D_j D_(j+1). fwd stores e and acc_(i-1) in the pair's odd entry and forms acc_i = acc_(i-1) e, acc_(-1) = ρ_k; fe_inv gives R = 1/acc_(H-1), H = q2/2; bwd, i = H-1..0, sets inv_e = R acc_(i-1), R <- R e, splits inv_e into 1/D_j, 1/D_(j+1) and per incidence (inv = 1/D) forms u², v² (u = 1/(y_Y + y_X), v = 1/(y_Y - y_X)) and twelve **fractions**, two of each **component** α' = Ew, β'' = Fw, γ = Gw (3.3), E = b⁴ + 2a³b, F = a⁴ + 2ab³, G = 3a²b², w = u² (s = +1) or v² (s = -1). For t = 0, 1, 2 the leaves, like the components never formed, are
    x(φ^t(X) + sY) = (α' - b) + β^t (β'' - a) + β^(2t) γ   (mod p).
**Why.** With β³ = 1, (b - β^t a) Q_t = D, Q_t = b² + β^t ab + β^(2t) a², so the slope of φ^t(X) ± Y is Q_t u (s = +, u = 1/(y_Y + y_X)) or -Q_t v (s = -, v = 1/(y_Y - y_X)); its square less the two x-coordinates is Q_t² w - β^t a - b, and Q_t² = E + β^t F + β^(2t) G. D ≠ 0 unless Y = ±φ^t(X) (3.4).
**Lookups (PX, W7).** A value v has seven **windows** v_k = floor(v/2^(o_k)) mod 2^(w_k), w_k = 37 (k < 4), 36, o_k = 0, 37, 74, 111, 148, 184, 220, so v = Σ v_k 2^(o_k). X pair p = (X_j, X_(j+1)), j = 2p, owns 2^49 bytes at TB0 + 2^49 p. Its **pair tables** (2^46-byte slots; row t at +512t, window k's line at +64k, lines 0-3 built for t < 2^37, 4-6 for t < 2^36) hold two canonical entries (c t 2^(o_k) + add [k = 0]) mod p a line: PE, PF, PG (slots 0, 1, 2) [X_j's | X_(j+1)'s] with (c, add) = (2a³, 0), (2a, a⁴), (a², 0); for even p σ's (slot 3) pair p's and pair p + 1's, c = -(A + A'), add = AA' - 7(A + A') (A = A_j, A' = A_(j+1)); P1_j, P1_(j+1) (slots 4, 5) [2A_j | 2y_X] of one X. The single table δ (slot 6, 2^45 bytes, c = A' - A) has row t at +256t, slot k at +32k (k < 4 to 2^37 rows, 4-6 to 2^36; slot 7 zero). The 2816 pair and 512 δ tables, 3·2^56 bytes, are built by tblx, twice a table (lines 0-3, 4-6; δ 0-1, 2-3; `route.s`: one ST64B per line, 25 + 26(L - 1) + 22Ln for L lines of n rows), exact on canonical inputs (`x_tables`). P1 and C1BS take window k by EXTR or LSR of v's limbs and BFI at bit 9 (δ: 8) of line k's base; E, F, G and σ use ygen's offsets. A **lookup of v** adds the entries at row v_k, window k, a sum of canonical values congruent to c v + add; one LD64B fetches a line, in PE, PF, PG and σ for two X's (or X pairs) seeing the same Y (**PX**, soispoke's joint-2X lookups), in P1_j both of X_j's constants. With a base term (b⁴, B², a running value) a sum has <= eight terms below 2^256: AC4F/AC4 keep it exactly as low + c 2^256, c <= 8, and **LF** folds Z mod 2^256 + c C0, adding C0 once more if that carries (3.4).
**fwd, per two pairs (PFWD2, 272).** With B = b³ + 7, e = B² - (A + A')B + AA' = B² - (A + A') b³ + (AA' - 7(A + A')). Pairs 2q, 2q + 1 share Y: EFWD2 loads B² (a Y-record word) once, starts both sums at it (one by three-operand ADDS) and adds σ's lines of b³'s windows (one LD64B serves both e's), two LFs; ST64B stores (e, acc_(i-1)) of pair 2q and four STPs pair 2q + 1's; P1X, P1XB form `acc_i`, acc_(i+1) (rows of acc by SHX, e's limbs as multipliers, FDX).

### 3.2 Key pass, emit and counts
keys walks entries downwards, a sign at a time, loading its six fractions and forming its three leaves' W0, W1 by 26 word sums (mod 2^64). Each leaf's KEY index j comes from the H words F0 of W0, F1 of W1 and σ = F0 + F1 mod 2^64: if F0 >= F1 it goes to block JH, where j = 2 if F1 + σ carries, else 1; otherwise j = 2 if F0 + σ carries, else 0. The j = 0 path emits (W0, W1); JH and JT form `S` (the L words' sum) and N' = ~(W0 + W1) = (~σ, ~S); JH emits (W1, N'), JT (N', W0). The **emit** (7 instructions) takes d1 from the L word of the pair's first fraction, the slot by LDADD of 32 on d1's LC entry, K2 by BFXIL, K3 = the second part's H word (**emit 7**) and w3 = d2' + x18, x18 = (entry + 128) << 30 = 2<<36 | l<<39 once per incidence (complemented on j = 1: 2 -> 5). **Key paths.** The exact index is uniform on {0, 1, 2} for a leaf other than O, and a leaf takes JH or JT (2 more instructions, S and MVN; the sign's B is charged always) only if its exact index is 1 or 2 or it lies in W (3.3), probability <= 2/3 + 2 d_wj; this work is E-priced in 6.6 like the walks, the worst case charges every leaf (7). Executed keys: 133.5 per incidence. bwd and keys end each pass with a test of bit 34 of the entry pointer, clear at every entry and set one entry below the block (`loop_ends_on_bit_34`, with the 156 emit TBZs on bit 13).
### 3.3 The class label (truncated fraction products, the index, the paths)
For v in [0, p) let T(v) = floor(2^128 v/p), with **words** H(v) = T(v) >> 64 = floor(2^64 v/p) and L(v) = T(v) mod 2^64 = H(2^64 v mod p); for a leaf value x let v_m = β^m x mod p, `v* = min v_m` (index j = argmin; β^m x has index j - m and the same label); H_m(c) = H(β^m c mod p), likewise `L_m`.
**Truncated products (TFP4S, CHAIN).** For a stored E, F or G c = (a0, a1, a2, a3) below 2^256 and a multiplier M below 2^256 (limbs `M_k`), let z = cM mod p, h_i, l_i = hi, lo(a_i C0). One carry chain gives U = [l2, l3, a0, a1] + [h1, h2, h3, 0] mod 2^256 = (u, t, s, v) (words 0..3); the rows are R_0 = c, R_1 = c 2^64, R_2 = U, R_3 = (l1, u, t, s), R_4 = R_3 2^64 (mod 2^256). ### 3.4 Arithmetic sites
**Steps that can lose a carry.** A product on the rows of a weak b (below 2^256) uses B_0 = b, B_(k+1) = SHX(B_k); the rows of an X constant, y_Y and β, and every lookup entry, are tabled exactly. RF and RA sum Z < 2^322 exactly; a fold (FDX) keeps (Z mod 2^256) + floor(Z/2^256) C0 mod 2^256; SQ13 forms a weak square L + H C0 exactly and F5 folds it alike. Only SHX's last ADCS and the final ADC of FDX and F5 drop a carry (CHAIN's final ADC too, harmless: 3.3's ε_2); without one each returns a value below 2^256 congruent to the exact one:
- **row shift** of B = (b0, b1, b2, b3): lost iff (B mod 2^192) + floor(b3 C0/2^64) >= 2^192, needing B mod 2^192 > 2^192 - 2^33: at most 2^97 rows.
- **fold** of Z < 2^322: lost iff t >= 2^256, needing Z mod p = t - p in [C0, 2^66 C0).
- **square fold**: lost iff its sum is at least 2^256, needing the true square in [C0, C0² + 2C0).
A fold returns a value >= p only when the true value is below C0: as a multiplier it is still its value mod p (3.3 holds for every multiplier below 2^256); a row-shifted value (acc, R) so stored has its low 192 bits above 2^192 - 2^33, in its first row shift's charged bad set. **Lookup folds are exact:** a sum is low + c 2^256, c <= 8; LF adds c C0, takes the carry out of limb 0 by branch (LF3) and, on a carry past 2^256, adds C0 once more (which cannot carry again): below 2^256, congruent, bit-identical to the full chain; BLK6 likewise. **FS in C1BS** has canonical operands: exact. **In P1 they do not:** M (an LF) and N (a fold) are below 2^256 and congruent to their true values but may be >= p (only when the true value is below C0), so FS(M, N) is wrong (by C0 mod p) iff N > M + p (needing N >= p + 1 and M < C0) and FADDW(M, N) iff M + N >= 2^257 - C0 (needing M and N both >= p + 1): defects of bad set C0 at N (`fs_weak_operands`, `faddw_weak_operands`). Every other operation is exact on its inputs (RF, RA; the truncated products; corrections and sums; KEY; the emit; tblx; `fe_mul_f`, `fe_sqr_f` and so fe_inv, exact below 2^256); the generator, ygen, table constants, Y-record and pair-entry words, corrections, the resolver and [x]P = Q run on these with each coordinate brought below p before use: no sites (no point has x = 0: 7 is not a square mod p).
**Distribution (marginals).** The other points of a batch fix Y_u (all share c_k, t_k, s_k), so the bound uses marginals: given the X's, Y_u is uniform on G \ {O} up to one point (c_k uniform), and a value of x_Y comes from at most 2 points, of y_Y at most 3. A site's true operand is a function of one incidence's point (`D`, 1/D: 6 points per value; w = 1/D², M = (D + 2A)/D², L = 2y_X w: 12, two D per value; N = 2y_X y_Y/D²: 12, y_Y a root of a quartic; u², v², βu², βv²: 6; E, F, G: 8; `e`, `inv_e`: 12) or a running product: acc starts at ρ_k uniform on `F_p^*`, so acc_i = ρ_k Π e is uniform on `F_p^*` while no e = 0, as are R = 1/acc and R' = 1/acc_(i-1) (1 point per value); acc_(-1) = ρ_k, not 1: no exemptions at l = 0. A run fails at a site with probability at most runs × bad values × points over r - 1. Degenerate cases: X_j = O (1/r per X, a whole-run row) and D = 0, i.e. Y_u = ±φ^t(X_j) (at most 6/(r-1) per incidence), which zeroes an e and so acc (`d_zero_batch`); ygen fails only on a zero denominator, YGEN_DEF = 2(M - 1 + M(N - 1))/r (C + mT = ±2^k T in a start level, Y(m, n-1) = ±S in a step); two points of a batch may coincide or be negatives (L_Y²/(r - 1)), which 6.1-6.4's distinctness excludes. The first site of a batch whose predicate holds has exact operands, so a batch has a defect with probability at most d_batch = D_SITES + 6 q2/(r - 1) + YGEN_DEF + L_Y²/(r - 1) < 2^-126.99 (`D_BATCH`; 6.4).
**Rare carries by branch.** In SHX the carry out of the first ADDS, in FDX, F5 the carry into limb 2, in FS the borrow of its C0 subtraction, in FADDW, BLK6, LF the carry out of limb 0 are rare. Each macro branches over its **fixup** (B.LO; B.HS for FS) unless that carry or borrow occurred; the fixup is the rest of the inline chain and STADD x4, [sp]. Where the branch is taken the skipped instructions would add or subtract 0, so every register equals the inline chain's on every input; only the flags differ, and every path from the join sets them before reading or returns (`flags_dead_at_every_join`). A fixup adds 3 instructions (SHX, FDX, F5), 4 (FS, FADDW) or 6 (BLK6, LF) and C0 to the word at [sp] (fwd's frame; bwd's Y-record word); each call returns it in x0, at most 19 q2 C0 < 2^63 (2^61.248). The driver adds x0/C0 to the node's count N and starts a batch only while N <= 2^62 - 19 q2 (per pair 9 SHX, 6 FDX, 2 F5, 3 FS, 2 FADDW, 16 BLK-type), so N <= 2^62 on every run (R_worst: `6*2^62` per node); section 7's E-row charges 6 per expected fixup, q1(E_FIX + 19 q2 d_batch) per node.
**How often.** A fixup needs a word in a small set. SHX: the shifted row's low word above 2^64 - C0 (C0 2^192 rows). FDX: output low 128 bits below F C0 <= (2^66 + 1) C0, rest nonzero (F_w = (2^66 + 1) 2^128 C0 words). F5: output low 128 bits below 2^65 (2^193 words). FS: output low word at least 2^64 - C0; FADDW: below C0 (C0 2^192 words each). BLK6: the window sum (below 6p, t = sum >> 256 <= 5) has low 64 bits >= 2^64 - t C0: at most 15 C0 2^192 sums, each fixing u² (v²) mod p (two words): 30 C0 2^192 words. LF: low 64 bits >= 2^64 - c C0: at most Σ_(c<=8) c C0 2^192 = 36 C0 2^192 sums, each fixing the residue of the folded value (the sum is congruent to it, for canonical or weak lookup operands alike): 36 C0 2^192 values (`FIX_LF`), with the output's points per value. While no site of the batch up to this one has deviated, the row or output is a word below 2^256 congruent to the site's operand value (times 2^(64k) for the k-th row), which determines it; so a site takes its fixup with probability at most its set's size times its points over r - 1. The 16 rows of `FIXUPS` and 10 of `SITES` are these sets and bad sets times the per-pair macro counts above (H = q2/2 pairs) and the points per value above (in `FIXUPS` inv_e and R' share 12, FS and FADDW of u², v² take 6, M, L, N, w 12; in `SITES` N, w and the M, N weak operands 12). Summed (`E_FIX`), the expected number of fixups before a batch's first deviation, hence of a batch without a defect, is at most `E_FIX`; over a node's batches q1 E_FIX < 2^33.36 (2^33.316).
**The meter row.** A node stops early only if N exceeds 2^62 - 19 q2 at the start of a batch; with no batch defect N is the clean count, so by Markov this has probability at most q1 E_FIX/(2^62 - 19 q2) + q1 d_batch < 2^-28.64 (`d_f`, 2^-28.684; a node-local row, 6.4).
## 4. Transport and grouping (kernels/route.s and the emit)
Per record, executed (charged): hop 1 emit 7 + flush 9/256 = 7.03515625 (7.04296875); hop 2 h2s 6 + (flush 9 + dlvh copy 531)/256 + 8/256 = 8.140625 (8.1484375); join 4; total 19.17578125 (19.19140625); walks (4.5 per visit), K2 verifications and listings are E-rows.
Each executed count is its loop's instruction list in `route.s` or `leaf.s`, the charged count 2 more per message per hop (in flight). A destination's full blocks number at most its records over k, cumulatively (prefix sums dominated, PHI decreasing); a dropped block costs 7 or 9, so 542 per k records bounds hop 2's row blocks. **Blocks and cursors.** Emit and h2s take a slot by LDADD of 32 on the LC entry (the absolute slot address, so bit 13 marks slot k: one TBZ, checked). The **flush** resets the LC entry to slot 1 and advances the RC cursor by 32k (LDADD) returning c; the block is sent if c is below the sender's slot end, else dropped (a hop-2 cursor stays at most its slot end; a hop-1 cursor passes it only by the node's own leaves, < 2^63.43, checked); fin sends the L records left if L > 0 and c is below end, and writes min(c + 32L, end). **Keep lemma.** Cursors start at the slot base and move by 32k per block, `cap_p` is a multiple of k, so c and end are congruent mod 32k and c below end gives c + 32k <= end: a block is kept or dropped whole, and the records kept, their slot order and the final cursor match sending each record alone at its own cursor. A final block's k - L slots after its L records hold older records or none: at hop 1 the handler stops at count L; at hop 2 they land at or past the final cursor, where every later read stops, and the next group's first full block to d rewrites [c, c + 32L) with the same L records (below F). Also at cap_pg (a multiple of k, checked). **Hash table and join.** 2^58 head words at 2^61 and a packed next-array at 2^62 (16 bytes per R2 slot: next address, K2); bucket K2 mod 2^58, so same-key records meet without ordering. A hop-2 sender writes into header word 3 the address p of F, its slot's final cursor at the destination after the previous group; dlvh copies all k slots into R2 and joins exactly the records in [max(F, c), c + count). Within a group a sender's blocks to d cover disjoint ranges at or past F in any arrival order; across groups the barrier orders them and the only repeats (the previous final block's L records) come first, below F; so every record is joined once, and stale slots are copied, never joined. Heads and next fields hold entry addresses E = (A>>1) + C (never 0); costs: join 4 per record, walk 4.5 per visit, K2 check 5, listing 5, dlvh's copy `DLVHB`, `DLVHS` (certificate.py).
**Chains, no sorting.** A home's records share d1, d2; records with equal compared bits (K2 and K3's bits 44..63, 156 with the home's d1, d2) land in one bucket and form one arrival-order chain, each member linked on every run (walks are uncapped) to its most recent same-key predecessor. A class's records form one connected chain unless an **intruder**, a record with the same 156 compared bits not carrying the class's label, arrives between two members (6.4, 6.6); listed pairs of different classes are rejected by the resolver and charged by 6.4 through KB(156). With members u_i Z and Q coefficients ν_i, a pair is useless iff ν_i/u_i = ν_j/u_j, an equivalence relation, so a chain with a useful pair has a useful chain edge.
**Epoch cursors (bit 28 of k).** w2 holds kf = k mod 2^28. Let F_g[j] be slot j's final cursor at a home after group g: RC cursors only grow, fin writes F_g = min(c + 32L, end) without moving RC, and an unsent block's records stay in its LC block, so F_g is nondecreasing; a record is joined once, in its batch's group g, inside [F_(g-1), F_g) (above). E3 (a word per slot) is 2^64 - 1 from set-up (tinit); at group 391's start ecopy copies into it the table group 390's fin wrote (group 391 reads F from it). With q = 688296, B = 390 q = 268435440 <= 2^28 and q1 - 2^28 = 268435424 < B, so k = kf + 2^28 [a >= E3[j] and kf < B] is exact: groups <= 390 have k = kf < B; later ones have k >= B, with kf = k >= B below 2^28, else kf = k - 2^28 < B.
