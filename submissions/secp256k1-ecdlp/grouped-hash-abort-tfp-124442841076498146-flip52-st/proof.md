## 1. Overview

On secp256k1 (`y^2 = x^3 + 7` over `F_p`, `p = 2^256 - 2^32 - 977`, group `G` of prime order `r`, `phi(x, y) = (beta x, y) = [lambda](x, y)`), six leaves `x(phi^t(X) +- Y)` (`t = 0, 1, 2`) are labelled per pair from one batched inverse of `D = y_Y^2 - y_X^2` via Fourier components `(Ew - b) + beta^t(Fw - a) + beta^(2t) Gw` without forming the curve points (Galbraith, Wang and Zhang, ePrint 2015/605). Records travel in two bulk-synchronous hops from `2^68` generators through `2^42` relays to `2^83` homes, joining arrival-order hash chains whose 170-bit label collisions yield `x` mod `r`.

## 2. The algorithm and 52-bit-VA machine

### 2.1 Machine, addressing, ordering and completion

Three roles of nodes, each with one main processor and one delivery processor per incoming message kind, execute scalar AArch64 instructions (`C = 1000` instructions per target-group-operation unit, `COST_MODEL.md`):
- **Generators** `g < 2^68`: permanent X setup, streamed Y-chain batches (`yround`, `fwd`, `fe_inv`, `bwd`, `keys`), hop-1 sends to relay `d1`, phase-4 request serving.
- **Relays** `d1 < 2^42`: hop-1 arrival `h2s` from the link window, hop-2 row blocks to home `(d1, d2)`, phase-4 forwarding.
- **Homes** `(d1, d2)` with `d2 < 2^41` (`2^83` homes): one cumulative `R2` slot of `CAP_H` records, fused copy-and-join `dlvh`, candidate resolution.

Architectural extensions and premises, all scalar (no SIMD/SVE):
- **52-bit virtual addresses (`FEAT_LVA`, TBI off) and 56-bit physical addresses (`FEAT_D128`).** Under Arm DDI0487 D8 (`AArch64.VAIsOutOfRange` with `T0SZ = T1SZ = 12`, TBI = 0), a virtual address is valid iff bits `[63:52]` are all `0` (`TTBR0`: `[0, 2^52)`) or all `1` (`TTBR1`: `[2^64 - 2^52, 2^64)`). Every node's memory map (§5, checked in `certificate.py`) fits inside these two `2^52`-byte halves, so standard scalar loads/stores address every byte in one instruction; `a64.py` asserts `va52()` on every memory access. Under VMSAv9-128 (`FEAT_D128`, `TCR2_EL1.D128 = 1`, 64 KB granule, `PARange = 0b0111`), each processor maps its valid VAs 1-to-1 onto physical addresses below `2^56` (max per-node storage is `2^52.8644` B on a generator, `< 2^56` B).
- **Base-ISA `DC ZVA` (`DCZID_EL0.BS = 6`, `DZP = 0`, `SCTLR_EL1.DZE = 1`).** Zeroes one 256-byte aligned cacheable Normal-memory block per instruction (implemented in Fujitsu A64FX; `a64.py` asserts 256-byte alignment and non-device memory).
- **`FEAT_LS64` (`LD64B`/`ST64B`, `SCTLR_EL1.EnALS = 1`).** `LD64B Xt, [Xn]` and `ST64B Xt, [Xn]` move 64-byte aligned blocks into/from `Xt..Xt+7` (`t` even, `t <= 22`, `[Xn]` base only, and for `LD64B` architectural register disjointness `n not in {t..t+7}` per DDI0487 C6.2.155; `a64.py` asserts all four rules, and `machine.py` tests mutants for each). Supported locations are `IMPLEMENTATION DEFINED`: here the link windows (Device, `LD64B` only), home `R2` (Normal Non-cacheable, `LD64B`/`ST64B`), a generator's pair entries (`2^34` B, Normal Non-cacheable, `ST64B` of `bwd`'s fraction lines), and a generator's read-only X-tables `[2^48, 2^51)` and beta tables `[2^64 - 2^51, 2^64)` (Normal Non-cacheable, `LD64B` only).
- **Links, store-release ordering and `DMB ISH`.** A link is a stateless point-to-point interconnect from a sender's port buffer to a receiver's window (`0xc000` in the delivery processor's mapping). At a generator, hop-1 block `d1` (`1,024` B, `k1 = 16` slots at `+32..+543`, header `[dest 8*d1, bytes, msg_cnt, 0]` at `+0..+31`) is completed by `STLUR`/`STLR` to `+0`. At a relay, hop-2 row block `d2` (`2,048` B at `2^64 - 2^52 + 2048*d2`, `k2 = 32` slots, header `[2^44 + 8*d2, cursor c, bytes, p]`) is completed by `STLUR` to `+0`, and a 48-byte one-record message (`2^48 - 128`) by `STLUR` to `+40`. The link (an Inner Shareable observer) acquires the completing store, reads the payload words, and only then completes the store; the sender executes `DMB ISH` before reusing or clearing any buffer (`FLUSH` 10, `FIN_DEST` 15, `FINH_DEST` 16, phase-4 senders `reqh/fwdq/sendr/fwdr`; `machine.py` defers payload reads to the next `DMB ISH` and rejects any pending message at `RET`).
- **Implemented completion and two-wave barriers (no `DSB` premise).**
  1. *Hop 1 -> Relay:* `FLUSH` increments block `d1`'s message counter (`header +16`); `fin1` sends every relay `d1` a final block (`0 <= n < 16` records) carrying total messages `m = blocks + 1 < 2^49`. Relay `d1`'s `h2s` (sole writer) maintains a 128-bit register accumulator `D = x14:x13 = 2^126 + (arrived finals' m) - (arrived messages)` and missing-finals count `x5:x15` (initialized to `2^68` by `h2s0`). Each final adds `m` and decrements `x5:x15` (`FIN_CNT = 6`), the last final subtracting `2^126` (`+1`); every message subtracts `1` and tests `D == 0` (`RCV1 = 4`). Since `|finals' m - messages| <= 2^68 * 2^49 = 2^117 < 2^126`, `D` never wraps or hits `0` until all `2^68` finals and every sent message have arrived, whereupon `h2s` store-releases group index `g` to `DONE` (`2^48 - 4096`) and re-arms (`H2S_DONE = 5`); main waits once (`EXPECT = 8`).
  2. *Hop 2 -> Home:* Every `dlv` and `dlvh` ends with `STADDL x28, [x29]` (`x28 = 1`, release-ordered after its stores, into dedicated 2 KB granules `CNTE = 2^48 - 6144` and `CNT = 2^48 - 8192`). Home main waits for `CNTE` to include the fixed barrier releases plus relay `d1`'s `E2` cursor message (reading `F`), then waits for `CNT` to reach `T_(g-1) + ceil((F - c_0)/(32 * 32))` (`EXPECTH = 16`).
  3. *Two-wave barriers:* Over the spanning tree `home (d1, d2) -> relay d1`, `generator g -> relay (g mod 2^42)`, `relay d (d > 0) -> generator d -> relay 0` (up-wave arrival after local completion, down-wave release; `LDAXR, CMP, B.EQ, WFE` with `CNTKCTL_EL1.EVNTEN = 0`, `8` instructions per wait; charged `2^11` per node, `> 7x` itemized `95` average). Wait graph is strictly acyclic (`generator -> relay h2s -> home dlvh -> memory`).
- **Coins (`FEAT_RNG`).** `MRS Xt, RNDR` draws fresh uniform 64-bit algorithm coins (`64` instructions per 256-bit scalar).

### 2.2 Flipped-grid leaves, labels and records

Generator `g` draws `b_g` and `a_0..a_255` in `[0, r)`, storing `R_g = [b_g]Q` and `X_j = R_g + [a_j]P` (`0 <= j < 256`), and for batches `k = 1..q1` (`q1 = 2327370190`) draws `c_k in [0, r)`, `s_k in [1, r)`, `rho_k in [1, p)`, streaming `Y_(k, u) = [c_k + delta_u s_k]P` (`0 <= u < 2^17`). Pair `l` (`0 <= l < 2^25`) of batch `k` pairs `Y_(k, l >> 8)` with `X_(l & 255)`, producing six leaves `x(phi^t(X_(l & 255)) + s * Y_(k, l >> 8))` = `[m]P + [n]Q` with `m = lambda^t a_(l & 255) + s(c_k + delta_(l >> 8) s_k)` and `n = lambda^t b_g`.

For `Z != O`, its order-6 class `{+-Z, +-phi(Z), +-phi^2(Z)}` has canonical x-coordinate `v* = min(x, beta x mod p, beta^2 x mod p)` and **106-bit label parts** `(comp(v*), comp(beta v* mod p))`, `comp(v) = floor(2^106 v / p) = T(v) >> 22`. A 32-byte record `[K2, K3, w2, w3]` carries:
- `K2`, `K3`: top 64 bits of the first and second parts;
- `w2`: low 64 bits of `g`;
- `w3 = (g >> 64) | (k << 4) | (code << 36) | (l' << 39)` (`4 + 32 + 3 + 25 = 64` bits, since `g < 2^68`, `q1 < 2^32`, `l < 2^25`), with `(code, l') = (2, l)` for `s = +1` and `(4, (l - 1) mod 2^25)` for `s = -1`.

Routing and hash digits: **relay** `d1` = low 42 bits of part 1 (bits `22..63` of fraction 1's low word), **home** `d2 = K2 mod 2^41`, **hash key** `K3` (bucket `K3 mod 2^47`), and **verified bits** `d4 = K2 >> 41` (`23` bits): a listed pair matches on `42 + 41 + 64 + 23 = 170` label bits.

### 2.3 Phases

0. **Preprocessing (`E_PRE <= 2^116.0470` units, charged in full):** program delivery (`<= 2^17` B), node state, all scalar coins `(3 q1 + 257)` per generator (`c_k, s_k, rho_k` drawn upfront or per group, charged unconditionally here), `256` permanent `X_j` points with `40`-slot descriptors (`GEN_MULX + XSETUP`), `1,280` unified 8×32-bit X-tables (`tbld`), permanent X words in the `2^25` pair entries (`ENTRY_X`), `7`-slot 43-bit beta tables (`tbld`), LC/RC tables (`init3`, `tinit`), home hash-head zeroing (`zero16384` over `2^47` words), home read cursors (`init3`), `Q` broadcast, and `R_g = [b_g]Q`.
1-5. **Groups `g = 1..160`** (`q_g` Y-chains per generator, `sum q_g = q1`), separated by two-wave barriers:
   - *Leaf + Hop 1:* `yround` generates `q_g` chains of `2^17` Y-records in sets of `YB = 256` chains; per batch `k`, `fwd`, `fe_inv`, `bwd`, and `keys` emit records into hop-1 blocks (`k1 = 16`), flushed on full and finished by `fin1`.
   - *Hop 2 & Grouping:* Relays run `h2s` on arriving blocks into cumulative home slots (`CAP_H = 86586540687360 ≈ 2^46.2992`, `k2 = 32`) and `fin` at completion; homes run `dlvh` to copy blocks into `R2` (`LD64B`/`ST64B`) and hash-join `[max(F, c), c + count)` (`CAND_CAP = 2^19`).
   - *Resolution & Stop:* Over two-way links (`reqh -> dlvq -> fwdq -> dlvq -> sendr -> dlvq -> fwdr -> dlv`, each hop `<= 32 <= 40` instructions), generator `g` serves each request (`cap 2^34`) by reading permanent `X_(l & 255)` and regenerating `Y_(k, l >> 8) = [c_k + chain_n(l >> 8) s_k]P` from its stored chain scalars (`REQ_SERVE = 2^10 + GEN_MUL = 646,434` charged on all `2^34` cap entries). The home tests the `3 x 3 = 9` twist pairs for `L' = u L` with `n' != u n`, checks `[x]P = Q`, and latches/broadcasts the stop flag (`5` instructions per node per group).

## 3. Leaf and Y-chain kernels (`kernels/leaf.s`, `kernels/secp_fe.s`)

### 3.1 Flipped batch, unified 8×32-bit `LD64B` tables, C1b, C2 and C4a

For `X_j = (a_j, y_(X_j))` (`A_j = y_(X_j)^2 mod p`) and `Y = (b, y_Y)` (`B = y_Y^2 mod p`), `D = B - A_j ≡ b^3 - a_j^3 (mod p)`, `u = 1/(y_Y + y_X) = (y_Y - y_X)/D`, `v = 1/(y_Y - y_X) = (y_Y + y_X)/D`, `w = u^2` or `v^2`, and `E = b^4 + 2 a^3 b`, `F = a^4 + 2 a b^3`, `G = 3 a^2 b^2` give `x(phi^t(X) + sY) ≡ (Ew - b) + beta^t(Fw - a) + beta^(2t)(Gw) (mod p)`.

- **Unified 256-byte slot-interleaved X-tables (`tbld`).** Every per-X and per-X-pair table has `2^32` rows of `256` bytes (`2^40` B = `1 TiB`, `2^40`-aligned in `[2^48, 2^51)`): slot `k` (`0 <= k < 8`) of row `t` (`0 <= t < 2^32`) at `base + 256*t + 32*k` holds `(c * t * 2^(32k) + add_0 * 1[k=0]) mod p`, built by `route.s` `tbld` (`4 + 8*10 + 20 * 2^35` instructions per table). Each X `j` has four `1 TiB` tables (`2a_j^3`; `2a_j` with `add_0 = a_j^4`; `a_j^2`; `y_(X_j)`), and each X-pair `(X_(2j), X_(2j+1))` has two `1 TiB` tables (`-(A_1 + A_2)` with `add_0 = (A_1 A_2 - 7(A_1 + A_2)) mod p`; and `A_2 - A_1`), totaling `5` tables (`5 TiB`) per X = `1,280 TiB = 2^50.3219` B per generator. Even/odd slot pairs `(2i, 2i+1)` lie in one 64-byte aligned line `base + 256*t + 64*i`, read in one `LD64B`.
- **C1b X-pair partial fractions (`fwd` `C1FWD8`, `bwd` `W2SE8 + C1BSPLIT8`).** For `(X_1, X_2) = (X_(2j), X_(2j+1))`, `e_j = D_1 D_2 = B^2 - sigma B + pi` (`sigma = A_1 + A_2`, `pi = A_1 A_2`). Since `B ≡ (b^3 mod p) + 7 (mod p)` identically for every curve point `Y`, `e_j ≡ B^2 + (-sigma)*(b^3 mod p) + (pi - 7*sigma) (mod p)`, so `C1FWD8` reuses the Y-record's 8 pre-shifted `b^3 mod p` offsets (`LKP8`, `68` instructions) plus `4` stores and `P1X` (`84` instructions, seeded at `acc_(-1) = rho_k`): `156` instructions per 2 incidences (`78.0` per incidence). Because no `STP` can advance `x3` by the full `1024`-byte pair entry (imm7 reaches `504`), `C1FWD8` leaves `x3` `264` bytes short and `C1FWD8B` starts there (pre-index `#264`), and `fwd` adds `1024` after each `C1FWD8B`: `fwd_count(q2) = 9 + 78*q2 + 12*(q2//32) + (q2//256) + 3*(q2%32)/2` (the tail copy adds `264` instead). In `bwd`, `W2SE8` (`159` instructions) forms `inv_e = R_j * acc_(j-1)` and stores `R_(j-1) = R_j * e_j`; `C1BSPLIT8` (`165` instructions) forms `D_2 = B - A_2` (`FS`), `1/D_1 = D_2 * inv_e` (spilled at `E_(2j+1) + 0`), and `1/D_2 = 1/D_1 + (A_2 - A_1) * inv_e` via `BFI8G` (`8` 32-bit windows inserted by `BFI #8, #32`, `7` `LD64B x14, [x22]` loads, folded in `9` terms `< 2^256`): `324` instructions per 2 incidences (`162.0` per incidence, plus `2` `LDP` tails).
- **C2 split `u, v` (`C2UV8`, `158` instructions).** Multiplies `inv` by the 4 canonical per-Y rows `y_Y * 2^(64k) mod p` (`[sp, #112..239]`) to get `A < 2^256` (`78`), looks up `L = inv * y_X < 2^256` via `BFI8G` (`ld64b x18, [x26]`, `64`), and forms `u = FS(A, L)`, `v = FADDW(A, L)` (`16`).
- **C4a `LD64B` beta lookups (`PAIRB6`, `95` instructions).** Beta tables at `0xfff8<<48` (`[2^64 - 2^51, 2^64)` in `TTBR1`, 7 slots `0, 1, 3, 2, 4, 5` with window 3 duplicated at slot 6 so bit 128 of `w` selects slot 2 or 6 via `LSL #7`) use `LD64B x12, [x10]` on windows `1..5` from bases `B, B|64, B|128` (`3 + 2*46 = 95`).
- **`LKE8, LKFF8, LKG8` + `TFP4G`/`TFP4B` + `TOUTL` (`1138.0` body per incidence).** After `PAIRB6`, `(x0, x2, x1)` spill once to `[sp, #464..487]` (`2` instructions), freeing `x1` for the table base and `(x0, x2)` for `4` `LDP` offset loads per lookup (`LK8` + `LKF8`: `70` for `E` with `b^4`, `63` each for `F, G`, reloading `x0, x2, x1` in `LKF8` and outputting `c` directly into `(x5, x6, x9, x10)` for `TFP4G` with zero `MOV`s; `x11` is the row temp). The four accumulators `(s, f)` are `x12..x19` in line order, `(u², v², βu², βv²)` in `TFP4G` and `(v², u², βv², βu²)` in `TFP4B` (the same `TROWG` with its limb columns swapped), so after `TFINC`/`TFINS` one `ADD x11, x3, #o` and one `ST64B x12, [x11]` store a component: `α'` at `+64` and `γ` at `+256` (`TFP4G`), `β''` at `+128` (`TFP4B`); 6 fewer per incidence than four `STP`s per component. `bwd` keeps `x3` `512` bytes below the entry address (one `SUB` at entry), so every `x3` offset in `W2SE8`, `C1BSPLIT8`, `C2UV8`, `TOUTL` and `LK8` lies in `-512..472` and each half-body steps `x3` by a post-index `LDP ..., #-512` (so `bwd` returns `x3` 512 bytes lower than the old code did; no caller reads it, as `keys` sets its own `x3`). Two `BWDP` bodies (`4` incidences) run per `ADD x0, x3, #512; TST x0, #0x1fe00; B.NE`, switching Y-records (`sub sp, sp, #512`, `6` instructions) every `256` incidences until `TST x0, #0x3fffe0000` hits `0`: `bwd_count(q2) = 12 + (4555/4)*q2 + 6*(ceil(q2/256) - 1)`.

### 3.2 Exact-carry key pass and 5-instruction emit (`keys`)

`keys` loads each sign's six 128-bit fractions (`6` `LDP`s), computes `W_0(t), W_1(t)` (`t = 0, 1, 2`) in `13` two-word sums/differences (`26` instructions; `gamma` shifted `LSL #3`) plus `ADD x18, x14, x3, LSL #30` (`1`), and for each leaf computes `S = W0_lo + W1_lo` and **exact** `sigma = (W0 + W1) >> 64 mod 2^64` via `ADDS x12, w0l, w1l; ADC x15, w0h, w1h`. Inline `j = 0` (`CMP, B.HS kh; CMN w0h, x15; B.HS kt`) emits `(W0, W1)` in `5` instructions (`AND x15, x1, w0l, LSR #19` for `8*d1` at LC table `0`; `LDADD x4, x16, [x15]`; `STP K2, K3`; `STP x17, x18`; `TBZ x16, #9`; on slot 16 `FLUSH` resets LC, increments block count, `STLUR`s `+0` and executes `DMB ISH`, `7` instructions). Because `sigma` already carries `W0_lo + W1_lo`, `N' = ~(W0 + W1) = (~sigma, ~S)` needs **only one `MVN`** of `x15` on `JHB` (`j = 1`, where `d1` reads `W1_lo`) and on `JTB` (`j = 2`, where `BIC x15, x1, x12, LSR #19` complements `S` into `8*d1` directly!). With the C2/C3 continuation tree, `JPATH = 1` per `j in {1, 2}` leaf and `SJOIN = 1` per sign: `KEY_INC = 132.5`, `KEY_FIX = 4`.

### 3.3 Truncated fraction labels (106-bit parts)

Identical to `va52`: `T(v) = floor(2^128 v / p)`, `TR0`/`TRK` estimate `T(cM mod p)` with error `[0, 64]` (`[-1, 64]` with `-T` correction), leaf errors lie in `[-132, 194], [-132, 194], [-389, 264]` (`1,305` boundary residues in `2^22`, `d_lab < 2^-10.65`; widening `654`, lattice box factor `< 1 + 1/3000` at 106-bit parts), and exact-carry `sigma` removes the `[0, 1]` carry error from KEY's tie comparisons so `W` (`23 * 2^192` values, `d_wj < 2^-58.47`, `0` mismatches outside `W` on `26,000` random/near-tie checks) remains a strict superset of wrong-index inputs.

### 3.4 Error sites and metered rare-carry fixups

Every lookup fold (`LKP8`, `C1BSPLIT8`, `C2UV8`, `PAIRB6`, `LKE8`, `LKFF8`, `LKG8`) sums `M <= 9` operands `< 2^256` (`S < 9 * 2^256`, `t = S >> 256 <= 8`): `(S mod 2^256) + t*C0 < 2^256 + 8*C0`, and if that carries past `2^256`, adding `C0` once yields `< 9*C0 < p`, **exact on every input (`0` defect sites)**. Its fixup fires iff `S mod 2^128 >= 2^128 - t*C0`: at most `36 * C0 * 2^128` (`M = 9`), `28 * C0 * 2^128` (`M = 8`), or `30 * C0 * 2^128` (`PAIRB6`) sums/words.

In `C2UV8`, `A = FDX(inv * y_Y)` and `L = LKF(inv * y_X)` lie in `[0, 2^256) = [0, p + C0)`.
- `FS(A, L)` (`u = A - L`, `+ p` on borrow) deviates iff `A - L + p < 0`, which since `A >= 0` and `L <= p + C0 - 1` forces `-p - C0 + 1 <= A - L <= -p - 1`, hence `u mod p = (A - L) + 2p in [p - C0 + 1, p - 1]`: **at most `C0 - 1 < C0` residues of `u mod p`**, each coming from at most `3` points `Y` (`u = 1/(y_Y + y_X)` fixes `y_Y`).
- `FADDW(A, L)` (`v = A + L`, `- p` on carry) deviates iff `A + L >= 2^256 + p = 2p + C0`, which since `A, L <= p + C0 - 1` forces `v mod p = (A + L) - 2p in [C0, 2*C0 - 2]`: **at most `C0 - 1 < C0` residues of `v mod p`**, multiplicity `3` points `Y`. (And on clean `FADDW` runs where `v < 2^256` has low word `< C0`, `v < p` strictly since every `[p, 2^256)` integer has limbs `1..3` all ones and limb `0 >= 2^64 - C0`, so `v` determines `v mod p` 1-to-1!)
