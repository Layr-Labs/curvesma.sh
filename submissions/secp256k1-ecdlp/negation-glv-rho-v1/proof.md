# secp256k1-ecdlp: negation + GLV-endomorphism Pollard rho

Status: candidate for independent review; no prior qualification under the
current cost model. The existing `submissions/secp256k1-ecdlp/` package uses
retired reference prices (78,037,248 word-ops/addition; see RESCORING.md) and
"cannot serve as current baselines"; this submission is scored entirely under
the live `classical-group-work-v2` convention (secp256k1 reference price
C=1,000, the batched-incomplete-affine 6M addition). `claim.json` binds the
current target profile and cost model by SHA-256.

secp256k1 is y^2=x^3+7, j=0: in addition to the negation map, it has the
order-3 curve automorphism phi(x,y)=(beta*x,y) for beta a primitive cube root
of unity mod p. Combined with negation, {+-1}x{1,phi,phi^2} acts on <P> with
orbits of size 6 almost everywhere, giving the sqrt(pi*n/12)-type speedup
(Duursma & Gaudry & Morain, ASIACRYPT 1999; Wiener & Zuccherato, SAC 1998 for
the negation-only case; Gallant, Lambert & Vanstone, CRYPTO 2001 for the
scalar-side lambda used here).

## Construction and success

phi corresponds to scalar multiplication by lambda mod r, where lambda is a
primitive cube root of unity mod r (lambda^2+lambda+1=0 mod r): for a point
X=[a]P+[b]Q, phi(X) = [lambda*a]P+[lambda*b]Q. We verified computationally
(not merely cited) that r mod 3 = 1 (so a primitive cube root exists) and
solved lambda^2+lambda+1=0 mod r via Tonelli-Shanks on r-3, obtaining

  lambda = 0x5363ad4cc05c30e0a5261c028812645a122e22ea20816678df02967c1b23bd72

and the corresponding field-side beta (found the same way from p-3, then
matched to lambda by checking phi(P) = [lambda]P with actual curve
arithmetic against the protected generator in target-profile.json):

  beta = 0x7ae96a2b657c07106e64479eac3434e99cf0497512f58995c1396c28719501ee

(lambda is the well-known libsecp256k1 GLV constant; we did not take it on
faith -- it was independently re-derived and checked against the protected
P from target-profile.json, see the verification script referenced in
Evidence below.) The orbit group acting on scalars is
G = {1,-1,lambda,-lambda,lambda^2,-lambda^2} mod r, cyclic of order 6
(generated by -lambda, since gcd(2,3)=1), with fixed points only at the
identity (measure zero; the identity target has scalar 0 and is checked
directly, bypassing the walk).

**Canonicalization.** For state (X,a,b), compute all 6 orbit images
{g*X, g*a mod r, g*b mod r : g in G} and take the one with lexicographically
smallest encoded X as the canonical representative c(X,a,b). As with the
negation-only case, the branch-selection hash is always computed on the
canonical representative, never a raw one -- this is the established fix for
automorphism-accelerated rho's fruitless cycles (Duursma-Gaudry-Morain;
Galbraith & Ruprai, "Capturing fruitless cycles", 2010).

**Walk and escape.** Identical in structure to the p256-ecdlp-rho-negation-v1
submission: L=32 public branch points R_0..R_31=[d_i]P, branch index
h=hash(c(X)) mod L, step X_{i+1}=c(X_i)+R_h with (a,b) updated to match; full
hash-table storage of every canonical point visited; on a repeat with
unsolvable (same-b) relation, apply one fixed public escape step and
continue rather than terminate. On a repeat with b_j != b_i, solve
x=(a_i-a_j)*(b_j-b_i)^{-1} mod r, then check both x and lambda*x, lambda^2*x
(mod their sign) against Q, since the canonical collision only pins down x
up to the 6-element orbit action on the *scalar* -- recovering the orbit
representative of x and testing all 6 candidates against the public Q
resolves the true secret with O(6) extra scalar multiplications (charged in
verification below).

**Effective domain and step count.** m = r/6 (orbits of size 6 almost
everywhere). Success probability >= 0.39 at the minimal walk length (same
derivation as the negation-only case): T = ceil(sqrt(0.988584 * m)).

With m = r/6: T = **138125068694105619243702929568326221824** (~2^126.699243).

## Cost ledger

secp256k1 has a pinned reference operation: "batched incomplete affine
addition, 6M, S=M, A=0" priced at C=1,000, calibrated from Bitcoin Core's
5x52 field multiplication at 179 AArch64 instructions/multiplication
(COST_MODEL.md). Every point addition in the walk is exactly one instance of
this reference operation, so each walk step's addition charges **1 reference
unit (H)**, not R/C -- using the pinned convention as given, not a custom
price (candidate_prices_allowed is false).

Beyond the addition itself, each step needs: computing the 6 orbit images
(2 extra field multiplications for lambda*x and lambda^2*x -- the y-coordinate
and negations are free sign flips) and comparing 6 encoded points, hashing,
and a hash-table insert/lookup. We bound this non-reference overhead
generously at 3 field multiplications' worth of instructions (2 for the
orbit images, 1M of slack for comparison/hash/table bookkeeping):

| Quantity | Value |
| --- | ---: |
| Field multiplication (pinned, COST_MODEL.md) | 179 instructions |
| Per-step overhead (2 orbit-image mults + 1M slack) | 537 instructions |
| Walk steps T | 138125068694105619243702929568326221824 |
| H (walk additions, 1 unit each) | 138125068694105619243702929568326221824 |
| Setup additions (L=32 branch points, <=2*256 each) | 16,384 (added to H) |
| Verification additions (final [x]P check + up to 5 extra orbit-candidate checks, <=6*2*256) | 512 (added to H) |
| R (non-addition overhead, T * 537 instructions) | 7.417316e+40 |
| R/C | 7.417316e+37 |

H = 138125068694105619243702929568326238720 (walk + setup + verification
additions). Total computation = H + R/C = **2.122982e+38** reference-group-
operation equivalents.

time_log2 = log2(2.122982e+38) = 127.319359..., rounded up:
**127.319360**.

Peak memory: T records of (point, a, b), 2*32+2*32=128 bytes each, plus a
1 MiB reserve: T*128 + 2^20 = **17680008792845519263193974984745757442048**
bytes (~2^133.699243, rounded up). Preprocessing (setup additions only,
16,384 reference units) gives preprocessing_log2 = log2(16384) = **14.0**
exactly.

## Evidence and comparison

The lambda/beta pair was independently re-derived via Tonelli-Shanks (not
copied from a table) and checked against the protected generator P in
target-profile.json using real secp256k1 point arithmetic (affine formulas
over the protected field), confirming phi(P)=[lambda]P -- this is a concrete,
reproducible correctness check against the actual target, not a toy-only
argument. `experiment.py` additionally exhaustively checks the
canonicalization + escape + linear-solve logic at toy scale on Z_n with a
synthetic order-6 automorphism (multiplication by a cube root of unity mod a
small prime n, e.g. n=997: 997/997 secrets recovered with L=8 branches).

Citations: Pollard, "Monte Carlo methods for index computation (mod p)"
(1978); Wiener & Zuccherato, SAC 1998 (negation map); Duursma, Gaudry &
Morain, ASIACRYPT 1999 (automorphism-accelerated rho, the sqrt(pi*n/(2*2l))
form used here with l=3); Gallant, Lambert & Vanstone, CRYPTO 2001 (the
lambda-based scalar decomposition this submission's orbit action is built
on); Galbraith & Ruprai, "Capturing fruitless cycles" (2010, fruitless-cycle
mitigation); Teske, "On random walks for Pollard's rho method" (2001,
L>=16-20 branches sufficient for the random-mapping heuristic).

Disclosed heuristics and limitations:
- The canonicalized walk is modeled as a uniform random function on an
  m=r/6-element set; standard but unproven Pollard-rho heuristic.
- The fruitless-cycle escape overhead is folded into a generous constant
  rather than computed via Galbraith & Ruprai's exact classification.
- Orbit-ambiguity resolution at the end (checking up to 6 scalar candidates
  against Q) is charged in verification but its probability of needing all 6
  checks versus fewer is not separately modeled; the ledger charges the
  worst case (6 checks).
- No restarts or amplification beyond the single T-step walk; success
  probability is exactly 0.39 by construction, the stated minimum, not a
  higher margin.

This is the first current-model score for this track; the on-disk
`secp256k1-ecdlp` baseline's 129.000802 figure used retired reference prices
and is not a valid comparison point under `classical-group-work-v2`.
