# secp256k1-ecdlp: Pollard's rho with distinguished points

Status: ready for exploratory review. This is a classical generic attack accounting, not a practical break.

## Construction

Let n = r be the prime order of the subgroup generated by P. Input Q = [x]P.

Use a partition of the group into L=16 sets based on a simple hash of the x-coordinate (e.g., lowest 4 bits after canonicalization). Precompute L random points R_j = [a_j]P + [b_j]Q for random a_j, b_j.

Perform random walks: start from a random X0 = [c0]P + [d0]Q. At each step, add the corresponding R_j based on the partition of the current point, and update the coefficients mod n.

To detect collisions, use distinguished points: a point is distinguished if its x-coordinate has trailing zeros (e.g., 20 bits zero), with density θ ≈ 2^{-20}. Store distinguished points with their coefficients in a hash table. On collision of two distinguished points from different walks (or same with different coeffs), solve for x.

Use the negation map: when possible, replace a point by its negative if it has smaller x-coordinate, reducing the search space by factor sqrt(2).

Run enough independent walks / steps so that the probability of finding a useful collision is at least 0.39. Amplify by independent restarts if needed; all work is charged.

## Cost accounting

Reference unit C = 1000 for a batched incomplete affine point addition (6M convention).

Each walk step is one point addition, charged as 1 reference operation, plus scalar additions/modulos for the two coefficients (a, b), each of which is a few word operations (<< 1000 instructions for 256-bit).

With batching of inversions across multiple concurrent walks (Montgomery simultaneous inversion), the amortized field cost per addition matches the 6M + small A reference.

Distinguished point density θ = 2^{-20}: expected steps between distinguished points ~2^20. Storage for ~2^{20} or so points is feasible; peak memory bounded by 2^40 bytes (points + coefficients + overhead).

Expected group operations for collision: approximately sqrt(π n / 2) / sqrt(2) ≈ 2^{128.0} with negation map (standard analysis; see literature). 

To achieve success probability >=0.39, we charge a total of 2^{128.5} reference operations. This covers the expected number plus a constant factor for the tail of the distribution, failed walks, verification (scalar mult to check [x]P == Q, charged fully), randomness generation, sorting/lookup of the DP table, and amplification. Preprocessing for the R_j is O(L) and negligible.

Total computation T = 2^{128.5} target-group-operation equivalents. log2(T) = 128.5.

Memory: peak ~2^{40} bytes for the DP table and walk state. Preprocessing ~2^{10}. Advice: 0.

## Heuristics

- The walk behaves like a random function on the group (or quotient by negation). Supported by extensive literature on Pollard rho for ECDLP and small-scale experiments matching the birthday bound.
- Distinguished point collisions correctly identify group collisions with high probability when density is not too high.
- Negation map can be applied without introducing excessive short cycles (standard techniques exist to handle residual cycles).

Limitations: Analytic bound; no full-size execution. The constant factors are conservative. Small experiments confirm correctness on toy groups only.

## Success

Over uniform challenges and fresh coins, the probability that the charged work finds the discrete log is at least 0.39 by the birthday paradox analysis and amplification. Verification ensures correctness on success.

All work (preprocessing, trials, failures, transfers, verification, output) is included. No free oracles.
