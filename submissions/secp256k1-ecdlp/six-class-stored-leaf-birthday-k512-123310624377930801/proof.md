## 2. The algorithm
### 2.1 Machine
2^64 generator nodes (i, j) (i < 2^36, j < 2^28), each also relay (i, j), and 2^72 homes (d1, d2) (d1, d2 < 2^36), each with a main processor and a delivery processor per message kind it receives (dlv; h2s at relays, dlvh at homes), scalar AArch64: base set, FEAT_RNG, FEAT_LSE, DC ZVA (DCZID_EL0.BS=9, a 2 KB block) on Normal memory, FEAT_LS64. **Premises:** one 64-bit flat address space per processor (an analytical convention: only section 5's regions backed, as PEAK counts, plus the receive aperture below, which holds no storage of its own; no other address used; any load or store one counted instruction), with shared node backing and the processor-qualified receive aperture below, the LS64 locations, the DC ZVA block size. The ledger counts every processor's executed instructions and data movement and each message's delivery and in-flight count; storage is reported apart.
DCZID_EL0.BS is "Log2 of the block size in words"; "The maximum size supported is 2KB, indicated by value 0b1001" and the field is IMPLEMENTATION DEFINED (Arm DDI0601, DCZID_EL0). BS=9 fixes 2048 bytes, without claiming a shipping core. The scalar instruction count charges each bounded architectural DC ZVA, each pointer ADD and all control. zero16384 uses 64 ZVA+ADD pairs, SUBS and B.NE: 130 per pass, plus RET. Main heads start at 2^61; Phase 0 heads start at 0x101800000000 under section 5's 2^35-rounded layout; both are 2048-byte aligned.

**Address decode and finite messages.** A main processor sees [LINK, 2^64) (LINK = 2^64 - 2^15; at a generator node, the β tables' top) as shared Normal backing; each delivery processor sees its own read-only Device receive aperture there and the same backing below LINK, by a static per-initiator map, the same at every node for the whole run (no page-table switch, relocation, table copy, advice or computed lookup). Main never reads an aperture; delivery never looks up beta. An aperture exposes only the finite message being delivered (a six-word record, or four header words and 4k payload words; k=512, at most 16416 bytes); reads stay within it and writes to it are forbidden. Unused final-block slots are real stale payload, never consulted past the count or final cursor. A message stays in its sender's block, which the receiver's aperture maps (no link, port or queue holds a copy; the receiver's executed loads are the transfer), and the sender stalls at its completing store until the receiver's handler returns, so no block is rewritten in flight; other senders wait at their ports. machine.py's Port copies a block at that store and its receiver runs after the sender: a replay of this order, as a handler reads only its aperture and own node, and no sender reads, before the barrier, what a handler writes. The barrier's count wait covers all such acknowledgements; h2s can wait only on dlvh, which never sends: bounded backpressure, no routing oracle. Twelve instructions per message price the completion counters and the wake passes they cause; payload accesses, forwarding and receiver work are executed code. Three receive windows (3*2^15 bytes) and their state fit a 2^17-byte reserve. No other per-message instructions are assumed.
- **Ports and links.** A port's 48-byte message block (destination word, address, four data words; the STP to +32 completes it) sends one record. Record blocks, one per destination d at PB + 2^15 d (PB=2^51 column, 2^52 row), hold a header (destination word, address, byte count; at hop 2, p at +24) and k=512 slots at +32n; the header's STP completes a k-record message. A full block: slot 1, 255 pairs (a 64-pair body run 3 times by MOV, SUBS, B.NE: +7; 63 inline), slot k; h2s's aperture address is MOVN, MOVK (+1 a message).
- **LS64 (premise).** LD64B/ST64B Xt, [Xn|SP] move Xt..Xt+7 in one 64-byte access: t even, <= 22, no offset, Xn 64-byte aligned. Supported locations are IMPLEMENTATION DEFINED; here the link windows (Device), R2, pair entries ((e, acc), the E, F, G lines, P1B's base block, the α', β'', γ component lines), Y-records (YLS rows and private scratch line; no ST64B), β and X tables (Normal Non-cacheable, with LSE atomics: bwd's fixup STADD hits a scratch line), nowhere else; R2 starts at 32 mod 64 so slot pairs of a block and of its R2 copy are both aligned. a64.py asserts this on every access; machine.py's ls64_checks, isa_checks ship failing inputs.
- **Delivery is charged** as executed route.s: dlv 6 per one-record message, h2s (every hop-1 block), dlvh (4). Each runs as a loop, its first window load waiting for a complete message; h2s then loads p from the node word at 2^48 - 168, written for group g after group g - 1's last DSB.
- **Completion and barriers.** A port counts its messages in flight in a count word (charged 12 each, wakes included): up at its completing store, down when the destination's delivery write completes (a hop-1 block's when its h2s run, forwards included, returns). Before a barrier each processor runs DSB (its own accesses only) and main waits until both ports' counts read zero; barriers are a combining tree of epoch writes. Each wait is an LDAXR/WFE loop on a word alone in its exclusive granule (5 barrier and 2 count words, 2048 bytes apart); with the event stream off, interrupts masked and no SEV, only stores into that word wake it, one pass (5) each: an epoch word takes one store, a count word two per message (up, down), their passes charged with the message; one stale-event pass is charged per wait: 232 itemized, inside the 2^10 barrier allowance.
### 2.2 Leaves and records
Generator g holds its class's public X_j = [s_j]P (Phase 0, 2.3; j < 1024), draws uniform b_g in [0, r) and, per batch k < q1=159003867000, c_k, t_k, s_k in [1, r), ρ_k in [1, p) (S alone is the leaf total). It stores R_g = [b_g]Q, the X_j and per batch C_k = R_g + [c_k]P (the generator's accumulator starts at R_g), T_k, S_k = [t_k]P, [s_k]P; the batch's points are Y_(m,n) = C_k + [m t_k + n s_k]P (m < 8192, n < 4), point number u = 8192n + m. Incidence l = 1024u + j < q2=2^25 pairs X_j with Y_u; its leaves are the x-coordinates of φ^t(X_j) + s Y_u, t in {0, 1, 2}, s=±1: n0=6 q1 q2 per generator, S=2^64 n0 in an opened run. As φ = [λ], such a leaf is [μ]P + [ν]Q, μ=λ^t s_j + s(c_k + m t_k + n s_k), ν=s b_g. A point Z ≠ O has class {±Z, ±φ(Z), ±φ²(Z)}, canonical x-coordinate `v* = min(x, βx mod p, β²x mod p)` and label `(T(v*), T(βv* mod p))` (3.3). A record is [K2, K3, w2, w3]: K2, K3 from the two parts' words (3.3), w2=i | k<<36 (i the source's row; the 64-bit shift keeps k mod 2^28), w3=d2 | 2<<36 | l<<39, bits 36..63 complemented (5, ~l) on a j=1 leaf (3.2): w3 gives l, neither s nor t (signless, soispoke's KEY_W3). d1, d2 are bits 28..63 of the parts' L words; a record's source at its home is (w2 mod 2^36, j), j its arrival slot's index.
### 2.3 Phases
**Routes.** Hop 1 takes a record from generator (i, j) to relay (d1, j), counted in the sender's per-group slot i there (cap_pg = 2^28 - 2^19 records; its cursor is a byte count from 0 each group: h2s never reads a hop-1 address word); hop 2 from relay (d1, j) to home (d1, d2), into slot j of the home's R2 (cumulative, cap_p = 2^30 - 512 32-byte records); both caps are multiples of k. A generator node's two ports have LC (next slot of d's record block; init3) and RC (sender's cursor in its slot at d; tinit) tables of 2^36 entries, the column port's (hop 1) LC at address 0 and the row port's (hop 2) at 2^39 (d's entry is also a destination word for d).
- **0. Preprocessing:** after the gate opens, the coordinator binary-powers β=2^((p-1)/3) mod p and λ=3^((r-1)/3) mod r, checks [λ]P=(βx_P,y_P) or aborts, patches computed β into ygen's K words and sets λ in resolver data before program delivery. The powers give exactly the constants checked in experiment.py. Exponents need 254 squares and 138/122 multiplies; charge 256 each at SQRX/MULX, 512 mod-r products including a root check, and 2 GEN_MUL. Each mod-r product scans 256 bits: acc <- 2acc, then acc <- acc+masked operand. Each operation has inputs < r, so one conditional subtraction suffices. Retain the bit-256 carry; subtract r on four limbs, then SBCS on that carry selects the reduced result. Double: 4 adds+carry+4 subtracts+carry subtraction+4 selects = 14; masked add adds shift+mask+4 AND=20; loop/limb reload <= 3; charge 48 per bit. Keep exponentiation state in fixed scratch; <=32 setup/save/load/return instructions per product, 4096 exponent-control, 96 exact-division, 64 modulus-load, 256 install and 256 compare instructions total < 2^16. Thus 256(MULX+SQRX)+512·256·48+2 GEN_MUL+2^16 < 2^23. Charge once in aggregate node set-up slack, not per node; then program delivery, node state, coins (RNDR with range rejection; any coin's second failed draw, the candidates' too, sets the node's flag: abort), LC/RC tables, then **Phase 0** (success.md 6.0). (a) Each generator draws 5*2^38 candidates [s]P (s by RNDR, stored by index) and sends A=y^2 in a 64-byte record (A mod 2^220, its row i, the index: 297 bits) over the two hops to the home (A's bits 220..255, 184..219), into 2^16-record slots (at the relay; in R2); a record reaching a full slot is dropped and sets that generator's flag. (b) **Dictionary, no hash.** A home has 2^34 zeroed head words indexed by h=A's bits 150..183 and a link word per R2 record slot (4's next-array, written before read). Inserting a record in arrival order, the home follows head h's chain through <= 48 earlier records (a 49th: flag), comparing A mod 2^184: equal A sets the flag; an equal cell (A >> 102) with |A' - A| < 2^63 appends the pair, lower A first, to the home's list of <= 64 (a 65th: flag); then the record's link takes the old head, the head its address. A head is 2^48 whole cells: an insert visits every earlier record of its head, so each oriented close pair in a cell is listed once in any arrival order. (c) After a barrier a home sets its flag if a record lies in two of its pairs and sends each pair (lower A, both records' sources (i, j, index)), and every node a set flag, to the collector, home (0, 0) (a home's through relays (h_r, 0), (0, 0)), which keeps <= 2^20 entries (one more: flag). After three barriers the collector aborts (an abort word is broadcast; no output, no padding) on any flag or with < 2^14 entries; else it merge-sorts them by lower A (order (home, cell, A_lo); 20 passes), keeps ranks q < 2^14, fetches their 2^15 scalars from the sources (request and reply, two hops each) and broadcasts this pool. (d) Generator (i, j) takes class c=j mod 4096=(u, w)=(c mod 128, c div 128): with q = 128a + b, (a, b) in GF(128)^2, the 512 pairs on the lines b=u a + v, v = 4w..4w + 3; a pair gives slots (lower A, upper A). Every step has a hard count (MINE_REC, MINE_NODE). Then Phase 0's cursors are reset, the 1024 permanent X's (affine store), X tables (tblx), pair-entry X words, rows of β, hash-head zeroing (zero16384), hash-read cursors (init3), β tables (tbld); then Q is broadcast and R_g generated.
- **1-5. Groups** g=1..1023 of contiguous batches ending at `155429000*g`, testing the latched stop flag first, barriers between phases. Per batch: C_k, T_k, S_k by the generator, ygen, fwd, fe_inv, bwd, keys. **Hops:** keys emits each record into d1's column block, sent after slot k to relay (d1, j) at its RC cursor or dropped past the slot end (4); h2s there forwards it through the row port to home (d1, d2), slot j; fin sends final blocks and writes final cursors (hop 1: E1 at the relay; hop 2: F_g[j], entry g of the home's cursor history); dlvh copies each row block into R2 and joins its unjoined records (at or past the previous final cursor F; list cap 2^36). **Resolution** (four count-exchange sub-phases; per-run caps: each source's served-request count, each relay's record count and each home's list cursor persist across groups and are never reset; drops at 2^42 requests per source, 2^50 records per relay; a group sends requests only for its new candidates, exchanging only its new entries): home (h_r, h_c) sends two requests per new candidate to its sources (i, j) via relay (h_r, j), and replies of <= 8 records return the same way. A request carries the record's decoded k (4); the source regenerates Y_u = R_g + [c_k + m t_k + n s_k]P from its stored coins and returns it with X_j, s_j, the scalars and b_g (REQ_SERVE = 2^10 + GEN_MUL, 7). As w3 gives neither s nor t, the home forms each record's six possible leaves [μ]P + [ν]Q (μ=λ^t s_j + s(c_k + m t_k + n s_k), ν=s b_g), tests the 36 pairs in fixed order for a unit u with L'=uL and, with the first having ν' - uν ≠ 0, outputs x = (uμ - μ')/(ν' - uν) mod r after checking [x]P=Q (experiment resolver; a same-generator pair with u=s'/s has ν' - uν = 0). **Stop:** a resolved x latches a stop flag, broadcast to every node; all halt after the barrier outputting it (W_g).
**Barriers** <= 17396 (4 pre, 17 per group, 1 output; 17396 charged).
### 2.4 Run gate
First one coordinator reads a fresh 64-bit RNDR word u (independent of the challenge and every other coin) and compares it with K = 7195457757823579591 (MOVZ, three MOVK, CMP, a branch). If u < K it starts the run of 2.3 (Phase 0 first); otherwise it halts and outputs nothing, and no other processor executes an instruction. certificate.py charges GATE=2^7 on every run; K is least (success.md 6.7). A closed gate is a failure, its cost charged; nothing is amortized. **Caps** (fixups, pair slots, candidates, requests, relay records, coin retries, Phase 0's slots, chains, lists and collector) bound the worst case; walks are uncapped; the E-ledger (7) averages group work and the candidate and fixup counts.
## 3. Leaf kernels (kernels/leaf.s; ygen in kernels/secp_fe.s)
### 3.1 One batch
A batch is one (c_k, t_k, s_k): its 2^15 Y points against the 1024 X's, q2=2^25 incidences l = 1024u + j, walked up by fwd and down by bwd, keys through 512-byte pair entries (entry l at SB + 512 l). With a=x(X_j), b=x(Y_u), A_j=y(X_j)², B=y(Y_u)², D = B - A_j = b³ - a³, incidences (j even, j + 1) of a point form a pair with e=D_j D_(j+1). fwd stores e and acc_(i-1) and forms acc_i=acc_(i-1) e, acc_(-1)=ρ_k; fe_inv gives R=1/acc_(H-1), H=q2/2; bwd, i=H-1..0, sets inv_e=R acc_(i-1), R <- R e, splits inv_e into 1/D_j, 1/D_(j+1) and per incidence (inv = 1/D) forms u², v² (u = 1/(y_Y + y_X), v = 1/(y_Y - y_X)) and twelve fractions, two of each component α'=Ew, β''=Fw, γ=Gw (3.3), E = b⁴ + 2a³b, F = a⁴ + 2ab³, G=3a²b², w=u² (s=+1) or v² (s=-1). For t=0, 1, 2 the leaves are
    x(φ^t(X) + sY) = (α' - b) + β^t (β'' - a) + β^(2t) γ   (mod p).
**Why.** With β³=1, (b - β^t a) Q_t=D, Q_t = b² + β^t ab + β^(2t) a², so φ^t(X) ± Y has slope Q_t u or -Q_t v; its square less the two x-coordinates is Q_t² w - β^t a - b, and Q_t² = E + β^t F + β^(2t) G. D ≠ 0 unless Y=±φ^t(X) (3.4).
**Lookups (PX, W6).** A value v has six windows v_k=floor(v/2^(o_k)) mod 2^(w_k), w_k=43, 43, 42, 43, 43, 42, o_k=0, 43, 86, 128, 171, 214. X pair p=(X_j, X_(j+1)), j=2p, owns five 2^52-byte pair tables at B_p + n 2^52, B_p = TB0 + 5·2^52 p (row t at +512t, window k's line at +64k, for t < 2^(w_k)), of two canonical entries (c t 2^(o_k) + add [k=0]) mod p a line: PF, PG (n=1, 2) [X_j's | X_(j+1)'s], (c, add)=(2a, a⁴), (a², 0); n=0: for odd p PE [X_j's | X_(j-2)'s], (2a³, 0) (EQUAD), for even p σ of pairs p and p + 1, c = -(A + A'), add = AA' - 7(A + A') (A=A_j, A'=A_(j+1)); P1_j, P1_(j+1) (n=3, 4) [2A_j | 2y_X]. ### 3.2 Key pass, emit and counts
keys walks entries downwards, a sign at a time, forming its three leaves' W0, W1 by 26 word sums (mod 2^64): per incidence one LD64B each of the α' and β'' lines and four LDPs of γ (24 word registers; the slot end and LR on the stack, the flush's 32k by MOV). ### 3.3 The class label (truncated fraction products, the index, the paths)
For v in [0, p) let T(v)=floor(2^128 v/p), words H(v)=T(v) >> 64=floor(2^64 v/p) and L(v)=T(v) mod 2^64=H(2^64 v mod p); for a leaf value x let v_m=β^m x mod p, `v* = min v_m` (index j = argmin; β^m x has index j - m and the same label); H_m(c)=H(β^m c mod p), likewise L_m.
**Truncated products (TFP4S, CHAIN).** For a stored E, F or G c=(a0, a1, a2, a3) below 2^256 and a multiplier M below 2^256 (limbs M_k), let z=cM mod p, h_i, l_i = hi, lo(a_i C0). **Corrections and sums.** A sign's leaves are L_t = α + β^t β' + β^(2t) γ, α = α' - b, β' = β'' - a. bwd adds the words of -T_m(b) to α''s V_m, of -T_m(a) to β'''s (m=0, 1): each word of c - y mod p is c's less y's less {0, 1}. keys takes U_m=V_m, U_2 = -U_0 - U_1 word by word; the values β^m c mod p sum to 0, p or 2p, so H_0 + H_1 + H_2 ≡ -k, k in {0, 1, 2}, and each word of W_m = U_m(α) + U_(m+t)(β') + U_(m+2t)(γ) errs by its terms' errors plus κ in {0, 1, 2}, that of N' = ~(W_0 + W_1) by -(H(v_0) - W_0) - (H(v_1) - W_1) - k + 1. **Mass bound.** Frobenius is π = A + Bω, B=0xe4437ed6010e88286f547fa90abfe4c3, A=0x114ca50f7a8e2f3f657c1108d9d44cfd9: A² - AB + B² = p, Bβ ≡ A - B, (A - B)β ≡ -A (mod p) (checked). So Λ={(v, u): u ≡ βv (mod p)} has the basis (B, A - B), (A - B, -A) of determinant -p; the translates of its half-open parallelogram (area p, widths A and 2A - B) at the points of Λ in a box of integer sides a, b are disjoint and lie in the box widened by A, 2A - B, so it holds <= (a + A)(b + 2A - B)/p of them. Fixing f of the 156 compared bits leaves a union of boxes of word values; widened by the errors, each word value is <= two intervals of v, so <= (1 + 2^-12) 2^(256-f) points of Λ give those bits on each path, whatever index KEY returns: with three paths and two points per x the emitted pair takes given values on f compared bits with probability <= KB(f)=6 2^(256-f)(1 + 2^-12)/(r-1). success.md 6.4 sharpens KB(36), KB(72) for slot loads (KB_R36, KB_H72), 6.6 KB(130) for walk visits (KB_C130).
### 3.4 Arithmetic sites
**Steps that can lose a carry.** A product on the rows of a weak b (below 2^256) uses B_0=b, B_(k+1)=SHX(B_k); rows of X constants, y_Y, β and lookup entries are tabled exactly. RF and RA sum Z < 2^322 exactly; FDX keeps (Z mod 2^256) + floor(Z/2^256) C0 mod 2^256; SQ13 forms a weak square exactly and F5 folds it alike. Only SHX's last ADCS and the final ADC of FDX and F5 drop a carry (CHAIN's too, harmless: 3.3's ε_2); without one each returns a value below 2^256 congruent to the exact one:
- **row shift** of B=(b0, b1, b2, b3): lost iff (B mod 2^192) + floor(b3 C0/2^64) >= 2^192, needing B mod 2^192 > 2^192 - 2^33: at most 2^97 rows.
- **fold** of Z < 2^322: lost iff t >= 2^256, needing Z mod p = t - p in [C0, 2^66 C0).
- **square fold**: lost iff its sum is at least 2^256, needing the true square in [C0, C0² + 2C0).
A fold returns a value >= p only when the true value is below C0: as a multiplier it is still its value mod p (3.3 holds for any multiplier below 2^256); a row-shifted such value (acc, R) has its low 192 bits above 2^192 - 2^33, in its first row shift's charged bad set. **Lookup folds are exact:** a sum is low + c 2^256, c <= 8; LF adds c C0, takes the carry out of limb 0 by branch (LF3) and, on a carry past 2^256, adds C0 once more (which cannot carry again): below 2^256, congruent, bit-identical to the full chain; BLK5 likewise. DF folds low + c 2^256 for low < 2^256 and any c < 2^64: it adds c C0 < 2^97 (two words) and branches on the carry out of limb 1; on a carry past 2^256 the wrapped sum low + c C0 - 2^256 is below c C0, so adding C0 once more leaves it below (c + 1) C0 <= 2^64 C0 < 2^97, with no carry past limb 1: below 2^256, congruent, bit-identical to the full chain. DT (C1BS): 1/D_j + δ inv_e (δ < 2^63, the others below 2^256) is low + c 2^256, c < 2^63 + 2 (delta_fold). EDELTA (EQUAD): with d=2δ_j <= 2^64 - 2, E_j < 2^256 (LF) and b < p, MUL adds lo(d b_k) into limb k of E_j and UMULH hi(d b_k) into limb k + 1, and the top word c collects hi(d b_3) and both chains' carries: E_j + d b = low + c 2^256 exactly, c <= ((2^256 - 1) + (2^64 - 2)(p - 1))/2^256 < 2^64 - 1, folded by DF as above (edelta_fold, d up to 2^64 - 1). FS in C1BS has canonical operands: exact. **In P1 they do not:** M (an LF) and N (a fold) can be >= p (only when the true value is below C0), so FS(M, N) is wrong iff N > M + p (N >= p + 1, M < C0) and FADDW(M, N) iff M + N >= 2^257 - C0: defects of bad set C0 at N (fs_weak_operands, faddw_weak_operands). Every other operation is exact on its inputs (RF, RA, the truncated products, corrections and sums, KEY, the emit, tblx, fe_mul_f, fe_sqr_f, fe_inv); the generator, ygen, table constants, record words, the resolver and [x]P=Q bring each coordinate below p: no sites (no point has x=0: 7 is not a square mod p).
**Distribution (marginals).** The other points of a batch fix Y_u, so the bound uses marginals: Y_u is uniform on G \ {O} up to one point (c_k uniform), and a value of x_Y comes from at most 2 points, of y_Y at most 3. A site's true operand is a function of one incidence's point (points per value: D, 1/D 6; w, M, L, N 12; u², v², βu², βv² 6; E, F, G 8; e, inv_e 12) or a running product (acc_i=ρ_k Π e uniform on `F_p^*` while no e=0, as are R and R': 1 point per value). A run fails at a site with probability <= runs × bad values × points/(r - 1). Degenerate cases: C_k = R_g + [c_k]P = O (1/(r - 1) per batch); D=0, i.e. Y_u=±φ^t(X_j) (at most 6/(r-1) per incidence), which zeroes an e and so acc (d_zero_batch); ygen's zero denominators, YGEN_DEF = 2(M - 1 + M(N - 1))/r; two points of a batch equal or negatives (L_Y²/(r - 1)). The first site of a batch whose predicate holds has exact operands, so a batch has a defect with probability <= d_batch = D_SITES + 6 q2/(r - 1) + YGEN_DEF + (L_Y² + 1)/(r - 1) < 2^-126.99 (D_BATCH; 6.4).
**Rare carries by branch.** In SHX the carry out of the first ADDS, in FDX, F5 the carry into limb 2, in FS the borrow of its C0 subtraction, in FADDW, BLK5, LF the carry out of limb 0, in DF out of limb 1 are rare. Each macro branches over its fixup (B.LO; B.HS for FS) unless that carry or borrow occurred; the fixup is the rest of the inline chain and STADD x4, [sp] ([x3] in bwd). A skipped fixup would add or subtract 0, so every live register equals the inline chain's; only the flags differ, and every path from the join sets them before reading (flags_dead_at_every_join). A fixup adds 3 instructions (SHX, FDX, F5), 4 (FS, FADDW) or 6 (BLK5, LF, DF) and C0 to that word; each call returns it in x0, at most 19 q2 C0 < 2^63. EDELTA's DF too adds C0 per fixup (one STADD), so x0/C0 counts fixups (fixup_words_ok). The driver uses unsigned 64-bit N, adds x0/C0 exactly (UDIV), and starts a batch iff N <= D - 19 q2, D = 2^64 - 2^40. Load the threshold by MOVZ/3 MOVK; use unsigned CMP/B.HI. The two updates cost 2*(2 constant loads + UDIV + LDR/ADD/STR) = 12; a 7-instruction threshold test fits batch set-up (145 + 16 + 7 < 176). Thus N <= D; R_worst charges 6D per generator, section 7 charges 6q1(E_FIX + 19 q2 d_batch).
**How often.** A fixup needs a word in a small set. SHX: the shifted row's low word above 2^64 - C0 (C0 2^192 rows). FDX: output low 128 bits below F C0 <= (2^66 + 1) C0, rest nonzero ((2^66 + 1) 2^128 C0 words). F5: output low 128 bits below 2^65 (2^193 words). FS: output low word at least 2^64 - C0; FADDW: below C0 (C0 2^192 words each). BLK5: the window sum (below 5p, t <= 4) has low 64 bits >= 2^64 - t C0: <= 20 C0 2^192 words. LF: low 64 bits >= 2^64 - c C0: <= Σ_(c<=8) c C0 2^192=36 C0 2^192 values of the folded residue (FIX_LF). DF (1/D_odd): the output's low 128 bits below 2^97: <= 2^225 values (FIX_DF), 6 points per value; EDELTA's DF (E_odd) alike, 8 points per value (E_odd = b⁴ + 2a³b takes a value at <= 4 b, each the x of <= 2 points). While no site of the batch has deviated, the row or output is a word below 2^256 congruent to the operand (times 2^(64k) for row k), which determines it; so a site takes its fixup with probability <= its set's size times its points/(r - 1). The 17 rows of FIXUPS and 10 of SITES are these sets times the per-pair macro counts and points per value. Summed (E_FIX), the expected number of fixups of a batch without a defect is at most E_FIX; over a generator's batches q1 E_FIX < 2^41.4.
**The meter row.** A generator stops early only if N exceeds (2^64 - 2^40) - 19 q2 at the start of a batch; with no batch defect N is the clean count, so by Markov this has probability <= q1 E_FIX/((2^64 - 2^40) - 19 q2) + q1 d_batch < 2^-20.6 (d_f; a generator-local row, 6.4).
## 4. Transport and grouping (kernels/route.s and the emit)
Per record, executed (charged, 12 more per message per hop in flight): hop 1 emit 7 + flush 11/512 = 7.021484375 (7.044921875); hop 2 h2s 6 + (flush 8 + dlvh copy 1050)/512 + 15/512 = 8.095703125 (8.119140625); join 4; total 19.1171875 (19.1640625); full-block fixed work h2s 6k + 15, dlvh 2k + 26, 84/k a record with flushes and in-flight; walks (4 per visit: the chain end falls through to the exit), K2 verifications and listings are E-rows. Each count is its loop's instruction list in route.s or leaf.s. A destination's full blocks are at most its records over k, cumulatively; a dropped block costs 10 or 8, so 1070 per k records bounds hop 2's row blocks. **Blocks and cursors.** Emit and h2s take a slot by LDADD of 32 on the LC entry (the absolute slot address: bit 14 marks slot k, one TBZ). The flush resets the LC entry to slot 1 and advances the RC cursor by 32k (LDADD), returning c; the block is sent if c is below the sender's slot end, else dropped (a hop-1 cursor, a byte count from 0 each group, passes it only by the generator's leaves of the group, < 2^60; a hop-2 drop stores the end back); fin sends the L records left if L > 0 and c < end, and writes min(c + 32L, end). **Keep lemma.** Cursors start at the slot base (0 at hop 1) and move by 32k, cap_p is a multiple of k, so c < end gives c + 32k <= end: a block is kept or dropped whole, and records kept, their order and the final cursor match sending each record alone. A final block's k - L slots after its L records hold older records or none: at hop 1 the handler stops at count L; at hop 2 they land at or past the final cursor, where every later read stops, and the next group's first full block to d rewrites [c, c + 32L) with the same L records. Also at cap_pg. **Hash table and join.** 2^58 head words at 2^61 and a packed next-array at 2^62 (16 bytes per R2 slot: next address, K2); bucket K2 mod 2^58, so same-key records meet without ordering. A hop-2 sender writes into header word 3 the address p of F, its slot's final cursor after the previous group; dlvh copies all k slots into R2 and joins exactly the records in [max(F, c), c + count). Within a group a sender's blocks cover disjoint ranges at or past F in any arrival order; across groups the barrier orders them, repeats coming first, below F: every record is joined once, stale slots never. Heads and next fields hold entry addresses E = (A>>1) + C (never 0); costs: join 4 per record, walk 4 per visit, K2 check 5, listing 5, dlvh's copy DLVHB, DLVHS.
**Chains, no sorting.** Same-key records at a home form one arrival-order chain (walks uncapped); intruders and cross-class listings are charged in success.md 6.4, 6.6. A pair is useless iff ν_i/u_i=ν_j/u_j, an equivalence relation, so a chain with a useful pair has a useful edge.
**Group decode.** w2 holds kf = k mod 2^28. F_g[j], slot j's final cursor at a home after group g (F_0[j] its base, the hash-read cursor), is nondecreasing in g (RC cursors only grow; fin writes min(c + 32L, end) without moving RC), and a record of group g is joined once, inside [F_(g-1)[j], F_g[j]) (above). The home keeps this history: fin's final-cursor message writes F_g[j] to entry g of slot j's 32-byte-stride row, and dlvh reads F_(g-1)[j] there through p. So a record joined at address a is of the least g with a < F_g[j] (binary search, 10 probes), and as q=155429000 < 2^28 its batch is exactly k = q(g - 1) + ((kf - q(g - 1)) mod 2^28), the one k in [q(g - 1), qg) with that kf. The resolver decodes each record (EPOCH_DEC=76); a request carries k.
