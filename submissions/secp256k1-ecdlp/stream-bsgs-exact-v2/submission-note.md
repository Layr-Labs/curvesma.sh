## Result

This is a deterministic, heuristic-free candidate for the unrestricted uniform
full-production secp256k1 target. The submitted bound is

```text
time_log2 = 138.2191  (1382191/10000)
success_probability = 1/2 (deterministic coverage; threshold 0.39)
memory_log2_bytes = 146
preprocessing_log2 = 138.2191 (same conservative bound)
nonuniform advice = 0 bytes
```

The score is `log2(T/1000)` in protected target-group-operation equivalents,
where `C = 1000` scalar AArch64 instructions per reference operation. The exact
integer total is

```text
T = 405594803298275708386680876083793174401646592 instructions
```

and `log2(T/1000) = 138.2190910582461968`. The submitted rational `138.2191` is
an upper bound on this exact logarithm, checked without floating-point rounding
by

```text
T^10000 < 1000^10000 * 2^1382191.
```

Both sides of this comparison were evaluated with exact Python big integers
(1,481,849 bits each). The full construction, coverage proof, ledger and memory
bound are in `proof.md`; the claim stands on that argument alone.

## Construction

Set `m = h = 2^127`, `d = 2m-1`, and `D = -[d]P`. The baby list is
`(jP, j)` for `0 <= j < m`; the giant list is `(Q + iD, i)` for `0 <= i < h`.
Each sequence is generated by complete mixed Jacobian addition by a fixed affine
increment. Blocks of `B = 4096` projective points are converted to affine with a
zero-safe Montgomery prefix/reverse batch inversion; the block cost is at most
`B*JAC + 7*B*M + 4096*B + I`, with `JAC = 16*M+32*A+4096`, `M=4096`,
`A=256`, `I=2^22`.

Each list is stored in a complete binary tree with `m` leaves and depth 127. A
lazy merge tree emits a sorted stream with one cached head per child; equal keys
emit the left head first and consume only that head, so duplicate giant keys are
preserved. The central engine intersects the two sorted streams. An equal key
identifies `Q+iD = jP` or `Q+iD = -jP`; it forms `a = id+j` or `a = id-j mod r`,
verifies `[a]P = Q`, and outputs the canonical scalar. Exhausting a stream
returns failure. Every record, tree edge, NEXT/response packet, comparison and
cached head is charged in the ledger.

### Exact coverage

For fixed `i`, an equal key exists exactly for the residues
`[id-(m-1), id+(m-1)] mod r`. Successive intervals are adjacent and disjoint
because `d = 2m-1`. Their union has exactly

```text
COV = h*d = 57896044618658097711785492504343953926464851149359812787997104700240680714240
```

members, and

```text
2*COV - r = 92138019644721193389046258963199934143 > 0.
```

Hence the covered fraction is `COV/r > 1/2`, above the required `0.39`. The
construction is deterministic; there is no random-walk, collision-rate, cycle,
birthday or hash-table heuristic. It deliberately fails outside the covered
set.

## Assumptions and limitations

There is no statistical success heuristic. The substantive assumptions are the
organizer's field-arithmetic and communication instruction bounds, which are
stated explicitly in `proof.md`: `A=256`, `M=4096`, `I=2^22`, `JAC=16*M+32*A+4096`,
the block-normalization cost, the routed 128-byte record transfer bound and the
tree initialization bound. These are analytical scalar-instruction upper bounds,
not measured processor timings. The distributed word-transfer implementation is
an explicit part of the accounting argument, not a free parallel speedup. The
companion experiment checks bounded instances of the algebra, stream behavior,
ties, batch inversion and the exact integer inequality; it is not a production
execution or a production instruction measurement.
