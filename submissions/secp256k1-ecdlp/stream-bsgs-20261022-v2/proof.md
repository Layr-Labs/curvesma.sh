# Streamed signed BSGS with batch affine conversion

This candidate claims the conservative upper bound **time_log2 = 553/4 = 138.25**, in the protected target-group-operation equivalents, with **success_probability = 1/2**, **memory_log2_bytes = 146**, **preprocessing_log2 = 553/4**, and **nonuniform_advice_log2_bytes = 0**. Zero advice bytes are used. These are submitted analytic bounds, not independently qualified results or an executed production attack. The fixed normalization is **C = 1000 scalar AArch64 instruction equivalents** per target-group equivalent. All arithmetic, communication and control work is charged through scalar 64-bit instructions; no reference group operation is additionally charged.

This is a new add-only successor to `submissions/secp256k1-ecdlp/signed-bsgs-20261022-v1/`. It materially reuses that candidate's signed coverage construction, field-arithmetic bounds and distributed-storage accounting approach. The changes are projective generation with block normalization, two lazy merge trees that produce sorted streams, streaming intersection instead of per-point binary search, and more explicit initialization accounting. The argument below is self-contained. The predecessor is a material submission dependency even if it is not promoted or independently qualified.

## Target and algorithm

Use exactly the protected secp256k1 field, subgroup order, generator, canonical encoding and uniformly sampled full-production challenge Q = [x]P. In particular,

```
p = fffffffffffffffffffffffffffffffffffffffffffffffffffffffefffffc2f
r = fffffffffffffffffffffffffffffffebaaedce6af48a03bbfd25e8cd0364141
```

The public profile is authoritative. No reduced-size challenge, auxiliary powers, scalar interval promise, extra advice or alternative computation price is assumed. Set

```
m = h = 2^127
L = 127
d = 2m - 1
B = 4096
D = -[d]P
```

Validate the canonical input, its curve equation and [r]Q = O. Compute D with charged scalar multiplication. Construct two lists:

- baby records `(jP, j)`, for 0 <= j < m;
- giant records `(Q + iD, i)`, for 0 <= i < h.

Each sequence is generated by complete mixed Jacobian addition by its fixed affine increment, P or D. Collect B successive projective points, convert the block to affine with the exact batch-inversion procedure below, and write one record to each numbered leaf of the sequence's storage tree. Both m and h are divisible by B. The last update of a sequence may be performed and discarded; it is included in the budget.

A record has 16 64-bit words, or 128 bytes: one infinity tag, four canonical x limbs, four canonical y limbs, four scalar/index limbs, and padding. A finite point's key is `(1, x)`; infinity's key is `(0, 0)` with zero coordinate words. The scalar/index is carried unchanged. No square roots, hashing or recovery of omitted coordinates are used.

Each tree lazily merges its leaves into a nondecreasing key stream. The central engine intersects the two sorted streams. It caches one head from each stream; if one key is smaller, it discards only that head and asks its stream for the next record. If keys are equal, it uses the two full y coordinates to identify

```
Q + iD = jP       or       Q + iD = -jP,
```

forms `a = id + j mod r` or `a = id - j mod r`, verifies [a]P = Q, and outputs a as the canonical 32-byte scalar. If both keys are infinity, j = 0 and a = id mod r. Exhausting either stream without a match returns failure. At most one final scalar verification is needed because an equal canonical key necessarily supplies a correct equality or negated equality. A y-coordinate disagreement with both choices is an implementation error, not a probabilistic false positive to be ignored.

## Exact success and ties

Baby keys are distinct. If jP = kP, then j = k in the stated range. If jP = -kP, then j + k is a multiple of r; since 0 <= j+k <= 2m-2 < r, this can only identify the same infinity record. Thus no finite baby key is duplicated.

Giant keys can repeat, and the algorithm does not assume otherwise. Internal merge nodes break equal-key ties by emitting the left child's head first, marking only that head consumed. The other head remains cached and is emitted later unless the search has already succeeded. Consequently no record is lost. At the central intersection, equal keys immediately provide a valid cross-list match; there is no reason to skip an equal-key run. Repeated giant keys therefore do not reduce success or require multiple verifications. If the heads differ, advancing only the smaller head is the usual exact sorted-list intersection rule and cannot discard a possible cross-list match.

For fixed i, an equal key exists exactly for the scalar residues

```
[id-(m-1), id+(m-1)] modulo r.
```

Successive integer intervals are adjacent and disjoint because d = 2m-1. Their union is the integer interval from -(m-1) through (h-1)d+(m-1), with precisely COV = h*d members. COV < r, so reduction modulo r is injective on this interval, including its wrap through zero. Exact arithmetic gives

```
COV = 57896044618658097711785492504343953926464851149359812787997104700240680714240
2*COV-r = 92138019644721193389046258963199934143 > 0.
```

The success probability for the unrestricted uniform x is therefore COV/r > 1/2 >= 0.39. The construction is deterministic; fresh random coins, trials, restarts and amplification are unnecessary. It deliberately fails outside that covered set. No claim is made that the challenge scalar was sampled from a restricted interval.

The index arithmetic is finite and small relative to the table size: m, h, i and j fit 128-bit arrays, d fits 128 bits, and id+j fits 256 bits. The greatest positive reconstructed integer is h*d-m < r. Negative reconstruction can occur only for i = 0 and is corrected by adding r. All comparisons, multi-limb counters and reconstruction work are charged below.

## Field arithmetic with 64-bit limbs

Field operands are canonical four-limb integers. A fifth limb holds carries where necessary. Modular addition or subtraction costs at most A = 256 instructions: six five-limb passes at eight instructions per limb, plus sixteen fixed control instructions, cover loads, stores, carry/borrow propagation, comparison and correction. Small multiples such as 2, 3, 4 and 8 are implemented with these charged additions.

A multiplication costs at most M = 4096 instructions. The eight-limb product uses sixteen limb-pair MUL/UMULH pairs. Budget 128 instructions per partial product for multiplication, loads, stores and fixed carry propagation, totaling 2048. With c = 2^32+977, reduce by the fold `t -> low256(t) + c*high256(t)`. After the first fold the high part is at most c; the second result is below 2^256+c^2. A third fold is below 2^256: if the second result carries, its new value is below c^2+c < 2^65; otherwise it was already below 2^256. Four fixed folds are safe. Each fold uses at most four limb-by-c products and carry accumulation, within 384 instructions. Another 512 instructions cover setup, normalization, one conditional subtraction of p and output. The total is 2048 + 4*384 + 512 = 4096. Squaring uses this same multiplication bound.

For nonzero z, binary exponentiation z^(p-2) costs at most I = 2^22 instructions: at most 512 multiplications, 64 control instructions for each of 256 exponent bits, and fixed setup. This is an analytic instruction bound, not a measured assembly result.

## Complete projective generation

Represent a finite affine point by `(X:Y:Z)` with x = X/Z^2 and y = Y/Z^3. Infinity is Z = 0. All coordinates remain canonical modulo p. For mixed addition of `(X:Y:Z)` and a finite fixed affine point `(u,v)`, first handle Z = 0 by returning `(u:v:1)`. Otherwise compute

```
ZZ = Z^2
U2 = u*ZZ
S2 = v*Z*ZZ
H  = U2-X
q  = S2-Y
```

If H = 0 and q != 0, return infinity. If H = q = 0, use the doubling procedure below. In all other cases compute

```
HH  = H^2
HHH = H*HH
V   = X*HH
X3  = q^2-HHH-2*V
Y3  = q*(V-X3)-Y*HHH
Z3  = Z*H
```

These formulas give exactly the group sum. For doubling, return infinity if Z = 0 or Y = 0; otherwise use the a = 0 formulas

```
AA = X^2
BB = Y^2
CC = BB^2
DD = 2*((X+BB)^2-AA-CC)
EE = 3*AA
FF = EE^2
X3 = FF-2*DD
Y3 = EE*(DD-X3)-8*CC
Z3 = 2*Y*Z
```

The displayed formulas are the `madd-2004-hmv` mixed-addition and `dbl-2009-l` doubling formulas from the [Explicit-Formulas Database, Jacobian coordinates with a = 0](https://www.hyperelliptic.org/EFD/g1p/auto-shortw-jacobian-0.html), with the exceptional-case branches specified here. The ordinary mixed branch uses eleven field multiplications/squares. The exceptional doubling branch uses at most the four initial multiplications plus seven doubling multiplications/squares. Each branch, including canonical zero tests, copies, scalar-index bookkeeping, storing the current point in the block, additions and negations, fits

```
JAC = 16*M + 32*A + 4096 = 77824 instructions.
```

P and D are nonidentity finite points: d is nonzero modulo prime r. The listed finite-increment procedure therefore covers both generated sequences. No probabilistic avoidance of exceptional denominators or points is used.

## Exact block normalization

For each block of B = 4096 projective points, set z_k = Z_k when Z_k != 0 and z_k = 1 otherwise. The zero-Z flags are retained. Form prefix products of all z_k, invert the final nonzero product once, and traverse backward: multiplying the running inverse by the preceding prefix gives z_k^(-1), and multiplying the running inverse by z_k prepares the next step. At most B prefix multiplications and 2B reverse multiplications suffice.

For each nonzero Z, compute Z^(-2), X*Z^(-2), Z^(-3), and Y*Z^(-3), costing four additional multiplications. For zero Z, emit the infinity record; substituting 1 ensures there is never a zero inversion. The entire block costs at most

```
B*JAC + 7*B*M + 4096*B + I
```

instructions. The 4096 instructions per point cover flags, prefix-array transfers, backward counters, canonical record construction and all normalization control. Since I/B = 1024, this is 111616 instructions per point, strictly below the adopted conservative allowance **E = 2^18**. There are no partial blocks at the chosen production m and h. Point-block storage, original Z values, prefixes, flags and a single output staging record use less than 1 MiB; normalized records are written to their numbered leaves immediately during the reverse pass, so no second whole-block output array is retained; the whole central engine, code, scratch and state fit the separate 2^24-byte reserve.

## Distributed storage and initialization

Use two complete binary trees, each with m leaves, depth L = 127 and 2m-1 nodes. There are fewer than 4m nodes total. A node is a scalar processor with at most 64 KiB local code, state, buffers and records. It has only local 64-bit pointers and three local word-transfer ports, for its parent and children; leaves ignore child ports. A 128-bit destination is routed one bit per level when constructing the leaf lists. The engine has a port to each root. Node state includes two cached child-head records, flags, local scratch and routing metadata; it fits the allowance. A single data request is served at a time along a dependency path, and processors suspend for events instead of spinning. All work of all participating processors is counted.

The trees are not a free global address space. Their topology metadata, code distribution, clears and initial state are charged. For each node, allow up to 8192 word clears at eight instructions each and up to 8192 word image copies/transfers at sixteen instructions each, with both sender and receiver charged. These are conservative whole-64-KiB bounds even though actual code and initialized state occupy less. Another 2^15 instructions per node cover port/path metadata, counters, startup acknowledgements and local initialization control. Thus

```
8192*8 + 8192*16 + 2^15 = 229376 < INIT = 2^18
```

suffices per node. All initialization is bounded by 4m*INIT. Root code preparation is in the separate fixed reserve. Fixed programs are not assumed to arrive at the other nodes for free. No node's reserved capacity requires additional unreported retained data or randomness.

To write one 128-byte record, allow a 20-word command/data packet, including four command/address words, over every edge of its request/acknowledgement route. There are at most 256 aggregate edge crossings. Per crossing, sixteen instructions per word cover both endpoint loads/stores, port transfers and addressing; another 64 cover control. The bound is 256*(20*16+64) = 98304 instructions. **U = 2^17** adds more than 32000 instructions for root/leaf work, packet setup and acknowledgements. Every baby and every giant record is written exactly once and charged U. There are no free remote accesses or uncharged table copies.

## Lazy sorting streams, including end markers

A leaf answers its first NEXT request with its single stored record, and its next request with END. Its END flag is then remembered. An internal node keeps one head slot per child, each marked EMPTY, RECORD or END. Initially both slots are EMPTY. To answer NEXT it fills EMPTY slots by issuing NEXT to the respective children. If both are END it returns END. If exactly one is END it emits the other's record. Otherwise it compares the two keys and emits the smaller; equal keys emit the left one. Only the emitted head becomes EMPTY. Refilling is deferred until the next parent request. A parent that receives END remembers it and never requests that child's stream again.

This is recursive merging of singleton streams. Induction on the tree proves that every record in a subtree is emitted exactly once, in nondecreasing key order. Cached unconsumed heads remain available, including across equal keys. The engine can abort immediately after a match. Its actual work is bounded by a complete drain of both streams, so cached lookahead on an aborted run cannot invalidate the budget.

For one tree, let n_e be the number of leaves below child edge e. That edge carries precisely n_e record responses on a complete drain, at most one END response, and at most n_e+1 corresponding NEXT requests. Each leaf has L ancestors, hence

```
sum_e n_e = m*L
number of child edges = 2m-2
sum_e (n_e+1) < m*(L+2).
```

A NEXT packet needs at most four words; a record or END response is conservatively bounded by twenty words. At sixteen instructions per word for BOTH endpoints and 64 control instructions per packet, a request-response pair costs at most

```
(4*16+64) + (20*16+64) = 512 instructions.
```

This includes all physical word transfers, endpoint loads/stores and local message handling. Reserve another 512 instructions per such pair for key comparisons, cached-head selection/copies, state updates and fixed-size local control, beyond those transfer charges. Keys have only five 64-bit words, with x compared from its most significant limb; head records have sixteen. A key comparison uses at most five limb comparisons, while copying a head takes sixteen loads and sixteen stores. Both plus the fixed control fit this allowance. No internal loop scans a subtree or performs a remote array lookup. Child request handling and returning the selected response are already counted at their respective edges.

The central root's NEXT/response interaction and root-local bookkeeping do not add another tree level. A further 4096 instructions per root record cover them, leaf finalization, initial root state and the one root END event. Thus a complete sorted stream costs at most

```
m * [1024*(L+2) + 4096]
= m * 136192
< m * S, where S = 2^18.
```

The slack also covers fixed one-time events for nodes with no prior cached head. END messages are explicitly counted; no zero-cost sentinel oracle is used. Both trees together cost at most 2m*S. The separate central intersection makes fewer than 2m head-consumption iterations, each at most 8192 scalar instructions for key comparison, index/state movement and control. It is therefore bounded by m*2^14. NEXT transfers themselves were counted in the stream budget and are not charged again.

## Fixed work, memory and total bound

The fixed 2^40-instruction reserve covers input parsing and rejection of malformed input, the curve and [r]Q checks, computing D = -[d]P, preparing the engine's fixed code/constants, scalar reconstruction at a match, one independent [a]P verification, canonical output and fixed cleanup/control. For a simple independent implementation, complete affine addition fits 2^23 instructions using the inversion bound above and explicit infinity, opposite-point, doubling and y = 0 branches. Binary scalar multiplication needs at most 512 such additions; the several fixed scalar multiplications fit well within 2^40. No inverse is taken on zero. All input-dependent giant construction, sorting and unsuccessful intersection work is in the variable ledger, not hidden in that reserve.

Let m = 2^127 and INIT = E = S = 2^18, U = 2^17. The complete worst-case scalar instruction budget is

```
T = 2^40
    + 4m*INIT
    + m*(E+U+4096)                 # baby generation, normalization and writes
    + m*(E+U+4096)                 # giant generation, normalization and writes
    + 2m*S                        # both complete sorted streams
    + m*2^14                      # central intersection
  = 2^40 + m*2383872.
```

The extra 4096 per generated record covers outer block counters, leaf addressing and loop work beyond the internal arithmetic and transfer allowances. The exact components are:

The sole computation metric is T/1000 target-group-operation equivalents. Its diagnostic logarithm is approximately 138.2190910582461968. The actual submitted rational upper bound is 553/4, justified without floating-point rounding by the exact integer inequality

```
T^4 < 1000^4 * 2^553.
```

Preprocessing, including storage and code setup, baby generation and any baby-stream work performed before inspecting Q, is a subset of the fully charged attack. The conservative preprocessing bound deliberately uses the same complete T bound, so preprocessing_log2 = 553/4 is justified without omitting D construction or fixed setup. No preprocessing or table construction is amortized over another challenge. Q-dependent work is included once in total work whether or not an implementation schedules it alongside preprocessing.

Peak storage is strictly below

```
4m*2^16 + 2^24
= 44601490397061246283071436545296723028738048 bytes
< 2^146 bytes.
```

This includes code and state of every tree processor, both sets of leaf records, all cached heads and packets, routing metadata, engine code, constants, projective blocks, prefix products, stacks and output. No second set of sorted arrays is allocated. There is no retained randomness or nonuniform advice. Public profile constants and algorithm-design effort are the only excluded work, as permitted by the protected rules. Physical resources of this scale are unavailable; the claim is a finite analytic accounting construction, not a practical attack.

## Evidence and limitations

Heuristic assumptions: **none**. There is no random-walk mixing assumption, random oracle, birthday approximation, ideal hash table, empirical success extrapolation or uncharged precomputed table. The cost claims are analytical scalar-instruction bounds rather than processor timing measurements. The distributed word-transfer implementation and its complete instruction allowance are explicit parts of the construction and remain reviewable assumptions of that accounting argument, rather than free parallel speedup.

The companion experiment specification checks bounded instances of the algebra, stream behavior, ties, batch inversion and integer ledger. Small experiments provide evidence only at their executed scope; they are not production complexity proofs. Candidate files are untrusted evidence and are not executed on the host. The shared llm-verifier isolation, hosted review and emitted results determine qualification. No accepted status or emitted score is inferred from the inequalities in this document.

The predecessor's declared analytic bound was 145; this candidate's declared bound is 138.25, a difference of 6.75 bits in submitted upper bounds. This comparison does not turn either claim into a qualified score, establish novelty, or identify a best-known ECDLP attack. The improvement comes from accounting for locality in merges, batching inversions and tightening an explicit initialization bound. The protected target, six production tracks, one metric, success threshold and reference price are unchanged.
