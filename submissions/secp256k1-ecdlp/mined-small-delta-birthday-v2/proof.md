## 2. The algorithm
### 2.1 Machine
2^72 nodes (i, j), 0 <= i, j < 2^36, each with a main processor and one delivery processor per message kind (dlv, hop-1 h2s, hop-2 dlvh), scalar AArch64: base set, FEAT_RNG, FEAT_LSE, DC ZVA (DCZID_EL0.BS = 6, a 256-byte block as on Fujitsu A64FX) on Normal memory, FEAT_LS64. **Premises:** one 64-bit flat address space per processor, with shared node backing and the processor-qualified receive aperture below, the LS64 locations, the DC ZVA block size. The ledger counts every processor's executed instructions, all executed data movement, and each message's delivery and in-flight count; storage is reported separately.
**Address decode and finite messages.** The main processor sees the whole beta reservation, including [LINK, 2^64) (LINK = 2^64 - 2^14), as shared Normal backing; each delivery processor sees its own read-only Device receive aperture there and the same backing below LINK, by a static per-initiator map, the same at every node for the whole run (no page-table switch, relocation, table copy, advice or computed lookup). Main never reads an aperture; delivery never looks up beta. An aperture exposes only the finite message being delivered (a six-word record, or four header words and 4k payload words; k = 256, at most 8224 bytes); reads stay within it and writes to it are forbidden. Unused final-block slots are real stale payload, never consulted past the count or final cursor. A delivery processor retains one message until its handler completes, another waiting at its sender's port; a completing port store waits for its receiver, and the message is released. DSB waits for all such acknowledgements; h2s can wait only on dlvh, which never sends: bounded backpressure, no routing oracle. Two instructions per message price the completion counters; payload accesses, forwarding and receiver work are executed code. Three receive latches (3*2^14 bytes) and their state fit a 2^16-byte reserve. No other per-message instructions are assumed.
- **Ports and links.** A port's 48-byte message block (destination word, address, four data words; the STP to +32 completes it) sends one record. Record blocks, one per destination d at PB + 2^14 d (PB = 2^50 column, 2^51 row), hold a header (destination word, address, byte count; at hop 2, p at +24) and k = 256 slots at +32n; the header's STP completes a k-record message. Links keep no state but the message in flight.
- **LS64 (premise).** `LD64B`/ST64B Xt, [Xn] move Xt..Xt+7 in one 64-byte access: t even, <= 22, no offset, Xn 64-byte aligned. Supported locations are IMPLEMENTATION DEFINED; here the link windows (Device), R2, pair entries, Y-records, β and X tables (Normal Non-cacheable, with LSE atomics: bwd's fixup STADD hits a Y-record), nowhere else; R2 starts at 32 mod 64 so slot pairs of a block and of its R2 copy are both aligned. `a64.py` asserts this on every access; machine.py's `ls64_checks`, `isa_checks` ship failing inputs.
- **Delivery is charged** as executed `route.s`: dlv 6 per one-record message, h2s (every hop-1 block), dlvh (4). Each runs as a loop, its first window load waiting for a complete message; h2s then loads p from the node word at 2^48 - 168, written for group g after group g - 1's last DSB.
- **Completion and barriers.** A port counts messages in flight (charged 2 each); DSB completes once the node's stores are written and its ports' counts are zero, and nodes run it before a barrier. Barriers are a combining tree of epoch writes (LDAXR/WFE waits).
### 2.2 Leaves and records
Node g holds its class's public X_j = [s_j]P (Phase 0, 2.3; j < 1024), draws uniform `b_g` in [0, r) and, per batch k < q1 = 536870880, c_k, t_k, s_k in [1, r), ρ_k in [1, p) (S alone is the leaf total). It stores R_g = [b_g]Q, the X_j and per batch C_k = R_g + [c_k]P (the generator's accumulator starts at R_g), T_k, S_k = [t_k]P, [s_k]P; the batch's points are Y_(m,n) = C_k + [m t_k + n s_k]P (m < 8192, n < 4), point number u = 8192n + m. Incidence l = 1024u + j < q2 = 2^25 pairs X_j with Y_u; its leaves are the x-coordinates of φ^t(X_j) + s Y_u, t in {0, 1, 2}, s = ±1: n0 = 6 q1 q2 per node, S = 2^72 n0 (log2 S approximately 128.584962) in an opened run. As φ = [λ], such a leaf is [μ]P + [ν]Q, μ = λ^t s_j + s(c_k + m t_k + n s_k), ν = s b_g. A point Z ≠ O has class {±Z, ±φ(Z), ±φ²(Z)}, canonical x-coordinate `v* = min(x, βx mod p, β²x mod p)` and **label** `(T(v*), T(βv* mod p))` (3.3). A record is [K2, K3, w2, w3]: K2, K3 from the two parts' words (3.3), w2 = i | k<<36 (i the source's row; the 64-bit shift keeps k mod 2^28), w3 = d2 | 2<<36 | l<<39, bits 36..63 complemented (5, ~l) on a j = 1 leaf (3.2): w3 gives l, neither s nor t (signless, soispoke's `KEY_W3`). d1, d2 are bits 28..63 of the parts' L words; a record's source at its home is (w2 mod 2^36, j), j its arrival slot's index.
### 2.3 Phases
Pair slots hold cap_p = 2^22 - 2^17 32-byte records (a multiple of k): at hop 1 a node in row i writes only into slot i of R1 at each node of its column, at hop 2 one in column j only into slot j of R2 at each node of its row. Each port has **LC** (next slot of d's record block; init3) and **RC** (sender's cursor in its pair slot at d; tinit) tables of 2^36 entries, the column port's LC at address 0 and the row port's at 2^39 (d's entry is also a destination word for d).
- **0. Preprocessing:** program delivery, node state, coins, LC/RC tables, then **Phase 0** (success.md 6.0). (a) Each node draws 5*2^30 candidates [s]P (s by RNDR, stored by index), computes A = y^2 and sends a 32-byte record (A mod 2^184, its row i, the index: 253 bits) over the two hops to the **home** (A's bits 220..255, bits 184..219), into 2^16-record slots (R1 below the heads; R2); a record reaching a full slot is dropped and sets that node's **flag**. (b) **Dictionary, no hash.** A home has 2^34 zeroed head words indexed by h = A's bits 150..183 and a link word per R2 record slot (section 4's next-array, written before it is read). Inserting a record (arrival order), the home follows head h's chain through at most 48 earlier records (a 49th: flag), comparing all of A mod 2^184 on each: equal A sets the flag; an equal cell (A >> 102) with |A' - A| < 2^63 appends the pair, lower A first, to the home's list of at most 64 (a 65th: flag); then the record's link takes the old head and the head the record's address. A head is 2^48 whole cells, which only lengthen its chain: an insert visits every earlier record of its head, so each oriented close pair in a cell is listed once in any arrival order. (c) After a barrier a home sets its flag if a record lies in two of its pairs and sends each pair (lower A, both records' sources (i, j, index)), and every node a set flag, as messages over two hops to the **collector**, node (0, 0), which keeps at most 2^20 entries (one more: flag). After two barriers the collector **aborts** the run (an abort word is broadcast; no output, no padding) on any flag or with fewer than 2^14 entries; else it merge-sorts them by lower A (the order (home, cell, A_lo); 20 passes), keeps ranks q < 2^14, fetches their 2^15 scalars from the sources (request and reply, two hops each) and broadcasts this pool. (d) A node g takes its class c = g mod 4096 = (u, w) = (c mod 128, c div 128): with q = 128a + b, (a, b) in GF(128)^2, the 512 pairs on the lines b = u a + v, v = 4w..4w + 3; a pair gives slots (lower A, upper A). Every step has a hard count (`MINE_REC`, `MINE_NODE`). Then cursors are reset, the 1024 permanent X's (affine store), X tables (tblx), pair-entry X words, rows of β, hash-head zeroing (zero16384), hash-read cursors (init3), β tables (tbld), E3 = 2^64 - 1 (tinit); then Q is broadcast and R_g generated.
- **1-5. Groups** g = 1..780 of contiguous batches ending at `688296*g`, testing the latched stop flag first, barriers between phases. Per batch: C_k, T_k, S_k by the generator, ygen, fwd, fe_inv, bwd, keys. **Hops:** keys emits each record into d1's column block, sent after slot k to (d1, j) at its RC cursor or dropped past the slot end (per-group cap cap_pg = 2^20 - 2^11; 4); h2s forwards it through the row port to (own row, d2) into cumulative R2 slots; fin sends final blocks and writes final cursors (E1, E2[j] by group parity); dlvh copies each row block into R2 and joins its unjoined records (at or past the previous final cursor F; list cap 2^35). **Resolution** (four count-exchange sub-phases; drops at 2^33 requests per source, 2^40 records per relay): a home sends two requests per new candidate to sources (g_r, g_c) via relay (g_r, h_c), replies of <= 8 records return via (h_r, g_c). A request carries the record's decoded k (4); the source **regenerates** `Y_u` = R_g + [c_k + m t_k + n s_k]P from its stored coins and returns it with X_j, s_j, the scalars and b_g (REQ_SERVE = 2^10 + GEN_MUL, 7). As w3 gives neither s nor t, the home forms each record's six possible leaves [μ]P + [ν]Q (μ = λ^t s_j + s(c_k + m t_k + n s_k), ν = s b_g), tests the 36 pairs in fixed order for a unit u with L' = uL and, with the first having ν' - uν ≠ 0, outputs x = (uμ - μ')/(ν' - uν) mod r after checking [x]P = Q (experiment `resolver`; a same-node pair with u = s'/s has ν' - uν = 0). **Stop:** a resolved x latches a stop flag, broadcast over 2 hops; all halt after the barrier outputting it (W_g).
**Barriers** <= 13265 (4 pre, 17 per group, 1 output; 13265 charged).
### 2.4 Run gate
Before anything else one coordinator reads a fresh 64-bit RNDR word u (independent of the challenge and every other coin) and compares it with K = 7203743419939911301 (MOVZ, three MOVK, CMP, a branch). If u < K it starts the run of 2.3 (Phase 0 first); otherwise it halts and outputs nothing, and no other processor executes an instruction. `certificate.py` charges GATE = 2^7 on every run. K is the least integer with (K/2^64) lo_run >= 0.39 (success.md 6.7), A closed gate is a failure, its cost charged; nothing is amortized. **Caps** (fixups, pair slots, candidates, requests, relay records, coin retries, Phase 0's slots, chains, lists and collector) bound the worst case; walks are uncapped; the E-ledger (7) averages group work and the candidate and fixup counts.
## 3. Leaf kernels (kernels/leaf.s; ygen in kernels/secp_fe.s)
### 3.1 One batch
A batch is one (c_k, t_k, s_k): its 2^15 Y points against the 1024 X's, q2 = 2^25 incidences l = 1024u + j, walked up by fwd and down by bwd, keys through 512-byte **pair entries** (entry l at SB + 512 l). With a = x(X_j), b = x(Y_u), A_j = y(X_j)², B = y(Y_u)², D = B - A_j = b³ - a³, incidences (j even, j + 1) of a point form a **pair** with e = D_j D_(j+1). fwd stores e and acc_(i-1) and forms acc_i = acc_(i-1) e, acc_(-1) = ρ_k; fe_inv gives R = 1/acc_(H-1), H = q2/2; bwd, i = H-1..0, sets inv_e = R acc_(i-1), R <- R e, splits inv_e into 1/D_j, 1/D_(j+1) and per incidence (inv = 1/D) forms u², v² (u = 1/(y_Y + y_X), v = 1/(y_Y - y_X)) and twelve **fractions**, two of each **component** α' = Ew, β'' = Fw, γ = Gw (3.3), E = b⁴ + 2a³b, F = a⁴ + 2ab³, G = 3a²b², w = u² (s = +1) or v² (s = -1). For t = 0, 1, 2 the leaves are
    x(φ^t(X) + sY) = (α' - b) + β^t (β'' - a) + β^(2t) γ   (mod p).
**Why.** With β³ = 1, (b - β^t a) Q_t = D, Q_t = b² + β^t ab + β^(2t) a², so the slope of φ^t(X) ± Y is Q_t u or -Q_t v; its square less the two x-coordinates is Q_t² w - β^t a - b, and Q_t² = E + β^t F + β^(2t) G. D ≠ 0 unless Y = ±φ^t(X) (3.4).
**Lookups (PX, W7).** A value v has seven **windows** v_k = floor(v/2^(o_k)) mod 2^(w_k), w_k = 37 (k < 4), 36, o_k = 0, 37, 74, 111, 148, 184, 220. X pair p = (X_j, X_(j+1)), j = 2p, owns 2^49 bytes at TB0 + 2^49 p: **pair tables** (2^46-byte slots; row t at +512t, window k's line at +64k, lines 0-3 for t < 2^37, 4-6 for t < 2^36) of two canonical entries (c t 2^(o_k) + add [k = 0]) mod p a line: PE, PF, PG (slots 0-2) [X_j's | X_(j+1)'s], (c, add) = (2a³, 0), (2a, a⁴), (a², 0); for even p σ (slot 3) of pairs p and p + 1, c = -(A + A'), add = AA' - 7(A + A') (A = A_j, A' = A_(j+1)); P1_j, P1_(j+1) (slots 4, 5) [2A_j | 2y_X]. The 2816 pair tables, 11·2^54 bytes, are built by tblx, twice a table (lines 0-3, 4-6; one ST64B per line, 25 + 26(L - 1) + 22Ln for L lines of n rows; exact: `x_tables`). P1 takes window k by EXTR or LSR and BFI at bit 9 of line k's base; E, F, G and σ use ygen's offsets. A **lookup of v** adds the entries at row v_k, window k, congruent to c v + add; one LD64B fetches a line, in PE, PF, PG and σ for two X's (or pairs) seeing the same Y (**PX**), in P1_j both of X_j's constants. With a base term a sum has <= eight terms below 2^256: AC4F/AC4 keep it as low + c 2^256, c <= 8, and **LF** folds it (3.4).
**fwd, per two pairs (PFWD2, 272).** With B = b³ + 7, e = B² - (A + A') b³ + (AA' - 7(A + A')). Pairs 2q, 2q + 1 share Y: EFWD2 loads B² once, starts both sums at it and adds σ's lines of b³'s windows (one LD64B serves both), two LFs; ST64B stores (e, acc_(i-1)) of pair 2q and four STPs pair 2q + 1's; P1X, P1XB form acc_i, acc_(i+1) (rows of acc by SHX, FDX).
**bwd, per pair (BWDP, 1887).** **LK2** forms E (b⁴ plus lookups of b in PE), F (b³ in PF), G (3b² in PG) of both incidences and ST64B stores each line [c_j | c_(j+1)] at +448, +64, +256 of the even entry. LD64B of (e, acc_(i-1)); W2S (inv_e = R acc_(i-1), R' = R e; FDX); **C1BS**: D_(j+1) = B - A_(j+1) (FS), 1/D_j = D_(j+1) inv_e (rows of D_(j+1), FDX), 1/D_(j+1) = 1/D_j + δ inv_e (D_j - D_(j+1) = A_(j+1) - A_j = δ, one word in (0, 2^63) at entry +384, Phase 0): **DT**, 4 MUL and 4 UMULH of δ by inv_e's limbs and two carry chains, then the fold **DF**, 22 besides δ's LDR (3.4). Per incidence **INC**: **P1** forms w = inv² (SQ13, F5); one LD64B per window of w in P1_j gives M = inv + 2A w and L = 2y_X w (two LFs); N = y_Y L (y_Y's rows by two LD64B, **YLS**; FDX); u² = M - N (FS), v² = M + N (FADDW), as y_Y² = D + A gives (y_Y ∓ y_X)² w = (D + 2A ∓ 2y_X y_Y)/D² (`p1_identity`). **PAIRB** gives βu², βv²: the six 43-bit windows t_i of u² index β t_i 2^(43i) mod p, slot (0, 1, 3, 2, 4, 5)[i] of row t_i at 2^64 - 2^51 + 256 t_i (window 3 also in slot 6: bit 128, in windows 2 and 3, picks slot 2 or 6: **PAIRB6**), one LD64B each; C0 folds the sum (two BLK6, 91 per incidence). Then E, F, G, each reloaded by two LDPs, with rows from one carry chain (**CHAIN**) and four **truncated products** (TFP4S, 97; 3.3) with the limbs of u², v², βu², βv², corrected word by word and stored. 
**Records** (offsets: `yrecord`, `xwords`). ### 3.2 Key pass, emit and counts
keys walks entries downwards, a sign at a time, forming its three leaves' W0, W1 by 26 word sums (mod 2^64). KEY's index j comes from the H words F0 of W0, F1 of W1 and σ = F0 + F1 mod 2^64: if F0 >= F1 (block JH) j = 2 if F1 + σ carries, else 1; otherwise j = 2 if F0 + σ carries, else 0. The j = 0 path emits (W0, W1); JH and JT form `S` (the L words' sum) and N' = ~(W0 + W1) = (~σ, ~S); JH emits (W1, N'), JT (N', W0). The **emit** (7 instructions) takes d1 from the L word of the pair's first fraction, the slot by LDADD of 32 on d1's LC entry, K2 by BFXIL, K3 = the second part's H word (**emit 7**) and w3 = d2' + x18, x18 = (entry + 128) << 30 = 2<<36 | l<<39 once per incidence (complemented on j = 1: 2 -> 5). **Key paths.** A leaf takes JH or JT (2 more instructions, S and MVN) only if its exact index is 1 or 2 or it lies in W (3.3), probability <= 2/3 + 2 d_wj; E-priced in success.md 6.6, every leaf in the worst case. Executed keys: 133.5 per incidence. bwd and keys end each pass by a test of the entry pointer's bit 34 (`loop_ends_on_bit_34`).
### 3.3 The class label (truncated fraction products, the index, the paths)
For v in [0, p) let T(v) = floor(2^128 v/p), **words** H(v) = T(v) >> 64 = floor(2^64 v/p) and L(v) = T(v) mod 2^64 = H(2^64 v mod p); for a leaf value x let v_m = β^m x mod p, `v* = min v_m` (index j = argmin; β^m x has index j - m and the same label); H_m(c) = H(β^m c mod p), likewise `L_m`.
**Truncated products (TFP4S, CHAIN).** For a stored E, F or G c = (a0, a1, a2, a3) below 2^256 and a multiplier M below 2^256 (limbs `M_k`), let z = cM mod p, h_i, l_i = hi, lo(a_i C0). One carry chain gives U = [l2, l3, a0, a1] + [h1, h2, h3, 0] mod 2^256 = (u, t, s, v); the rows are R_0 = c, R_1 = c 2^64, R_2 = U, R_3 = (l1, u, t, s), R_4 = R_3 2^64 (mod 2^256). As l2 + (h2 + l3)2^64 + (a0 + h3)2^128 + a1 2^192 ≡ c 2^128 and l1 + (h1 + l2)2^64 + (h2 + l3)2^128 + (a0 + h3)2^192 ≡ c 2^192, R_k ≡ c 2^(64k) + ε_k, ε_1 = -a3 C0, ε_2 in {h1, h1 - C0}, ε_3 in {0, -C0}, ε_4 = 2^64 ε_3 - s C0. The **H word** f = Σ_k lo(M_k r_k3) + hi(M_k r_k2) mod 2^64 (r_k2, r_k3: R_k's words 2, 3) sums over R_0..R_3, the **L word** g over R_1..R_4. Z = Σ M_k R_k < 2^322 has floor(Z/2^192) - f in [0, 7] and H(Z mod p) ≡ floor(Z/2^192) + e (mod 2^64), e in {0, 1}; Z ≡ cM + E, |E| < 2^163, moves H by at most one: **H(z) - f is in [-1, 9]**, and likewise (L(z) = H(2^64 z mod p)) **L(z) - g is in [-1, 9]**. M = w gives the words of `cw` (V0), M = βw those of βcw (V1).
**Corrections and sums.** A sign's leaves are L_t = α + β^t β' + β^(2t) γ, α = α' - b, β' = β'' - a. bwd adds the words of -T_m(b) to α''s `V_m`, of -T_m(a) to β'''s (m = 0, 1): each word of c - y mod p is c's less y's less {0, 1}. keys takes U_m = V_m, U_2 = -U_0 - U_1 word by word; the values β^m c mod p sum to 0, p or 2p, so H_0 + H_1 + H_2 ≡ -k, k in {0, 1, 2}, and each word of W_m = U_m(α) + U_(m+t)(β') + U_(m+2t)(γ) errs by its terms' errors plus κ in {0, 1, 2}, that of N' = ~(W_0 + W_1) by -(H(v_0) - W_0) - (H(v_1) - W_1) - k + 1. Over t (certificate.py): H(v_0) - W_0, H(v_1) - W_1 in [-24, 29], H(v_2) - N' in [-59, 48]; L alike.
**The index.** KEY gives j = 2 if min(F0, F1) + σ carries, else 1 if F0 >= F1, else 0. With X_m = 2^64 v_m/p (X_0 + X_1 + X_2 is 2^64 or 2^65), the **window set** W is where (W1) X_0 or X_1 is below 29 or at least 2^64 - 24, (W2) X_2 below 49 or above 2^64 - 61, (W3) |X_0 - X_1| < 54, or (W4) X_0 - X_2 or X_1 - X_2 lies in [-72, 90). a_m = X_m - F_m is in [-24, 30); outside (W1) F_m does not wrap, outside (W2) σ = 2^64 - X_2 - δ, δ = a_0 + a_1 in [-48, 60), so F0 >= F1 iff X_0 - X_1 >= a_0 - a_1 in (-54, 54), and F1 + σ carries iff X_1 - X_2 >= a_1 + δ in [-72, 90): outside W, j = argmin v_m. (W1)-(W4) hold for <= 106, 110, 108, 324 times 2^192 values of x, each of probability <= 2/(r-1): d_wj < 2^-53.66 per leaf.
**The paths.** A leaf of index j emits (W_0, W_1), (W_1, N'), (N', W_0) (j = 0, 1, 2): d1, d2 are bits 28..63 of their L words, K2 the first's H word with bits 0..21 from the second's bits 22..43 (BFXIL), K3 the second's H word. The **compared bits** (K2, d1, d2, K3's bits 44..63) fix exactly 156 bits: each part's H bits 22..63 and L bits 28..63. With the index exact they are the class's unless an error carries a word across a block: the **label-error set** D' is where some H(v_m) mod 2^22 or L(v_m) mod 2^28 lies in [0, hi) ∪ [2^b + lo, 2^b) (b = 22, 28). Outside W and D' a leaf of a batch without a deviation (3.4) emits its class's compared bits; D' has <= 213 2^234 + 213 2^228 values of x: d_lab < 2^-13.24; such classes are not good collisions (success.md 6.1); no leaf is dropped.
**Mass bound.** Frobenius is π = A + Bω, B = 0xe4437ed6010e88286f547fa90abfe4c3, A = 0x114ca50f7a8e2f3f657c1108d9d44cfd9: A² - AB + B² = p, Bβ ≡ A - B, (A - B)β ≡ -A (mod p) (checked). So Λ = {(v, u): u ≡ βv (mod p)} has the basis (B, A - B), (A - B, -A) of determinant -p, and a box of integer sides a, b holds at most (a + A)(b + 2A - B)/p of its points. Fixing f of the 156 compared bits leaves a union of boxes of word values; widened by the errors, each word value is <= two intervals of v, so at most (1 + 2^-13) 2^(256-f) points of Λ give those bits on each path, whatever index KEY returns: with three paths and two points per x the emitted pair takes given values on f compared bits with probability at most KB(f) = 6 2^(256-f)(1 + 2^-13)/(r-1). success.md 6.4 sharpens KB(36), KB(72) for slot loads (`KB_R36`, `KB_H72`), 6.6 KB(130) for walk visits (`KB_C130`).
### 3.4 Arithmetic sites
**Steps that can lose a carry.** A product on the rows of a weak b (below 2^256) uses B_0 = b, B_(k+1) = SHX(B_k); rows of X constants, y_Y, β and lookup entries are tabled exactly. RF and RA sum Z < 2^322 exactly; FDX keeps (Z mod 2^256) + floor(Z/2^256) C0 mod 2^256; SQ13 forms a weak square exactly and F5 folds it alike. Only SHX's last ADCS and the final ADC of FDX and F5 drop a carry (CHAIN's too, harmless: 3.3's ε_2); without one each returns a value below 2^256 congruent to the exact one:
- **row shift** of B = (b0, b1, b2, b3): lost iff (B mod 2^192) + floor(b3 C0/2^64) >= 2^192, needing B mod 2^192 > 2^192 - 2^33: at most 2^97 rows.
- **fold** of Z < 2^322: lost iff t >= 2^256, needing Z mod p = t - p in [C0, 2^66 C0).
- **square fold**: lost iff its sum is at least 2^256, needing the true square in [C0, C0² + 2C0).
A fold returns a value >= p only when the true value is below C0: as a multiplier it is still its value mod p (3.3 holds for every multiplier below 2^256); a row-shifted such value (acc, R) has its low 192 bits above 2^192 - 2^33, in its first row shift's charged bad set. **Lookup folds are exact:** a sum is low + c 2^256, c <= 8; LF adds c C0, takes the carry out of limb 0 by branch (LF3) and, on a carry past 2^256, adds C0 once more (which cannot carry again): below 2^256, congruent, bit-identical to the full chain; BLK6 likewise. **DF** (C1BS): 1/D_j + δ inv_e (δ < 2^63, the other factors below 2^256) is low + c 2^256, c < 2^63 + 2; DF adds c C0 (< 2^96, two words) and branches on the carry out of limb 1; on a carry past 2^256 the wrapped sum is below c C0 < 2^97, so adding C0 once more cannot carry past limb 1: below 2^256, congruent, bit-identical to the full chain (`delta_fold`). **FS in C1BS** has canonical operands: exact. **In P1 they do not:** M (an LF) and N (a fold) may be >= p (only when the true value is below C0), so FS(M, N) is wrong iff N > M + p (N >= p + 1, M < C0) and FADDW(M, N) iff M + N >= 2^257 - C0: defects of bad set C0 at N (`fs_weak_operands`, `faddw_weak_operands`). Every other operation is exact on its inputs (RF, RA, the truncated products, corrections and sums, KEY, the emit, tblx, `fe_mul_f`, `fe_sqr_f`, fe_inv); the generator, ygen, table constants, record words, the resolver and [x]P = Q bring each coordinate below p: no sites (no point has x = 0: 7 is not a square mod p).
**Distribution (marginals).** The other points of a batch fix Y_u, so the bound uses marginals: Y_u is uniform on G \ {O} up to one point (c_k uniform), and a value of x_Y comes from at most 2 points, of y_Y at most 3. A site's true operand is a function of one incidence's point (points per value: `D`, 1/D 6; w, M, L, N 12; u², v², βu², βv² 6; E, F, G 8; `e`, `inv_e` 12) or a running product (acc_i = ρ_k Π e uniform on `F_p^*` while no e = 0, as are R and R': 1 point per value). A run fails at a site with probability at most runs × bad values × points over r - 1. Degenerate cases: C_k = R_g + [c_k]P = O (1/(r - 1) per batch); D = 0, i.e. Y_u = ±φ^t(X_j) (at most 6/(r-1) per incidence), which zeroes an e and so acc (`d_zero_batch`); ygen's zero denominators, YGEN_DEF = 2(M - 1 + M(N - 1))/r; two points of a batch equal or negatives (L_Y²/(r - 1)). The first site of a batch whose predicate holds has exact operands, so a batch has a defect with probability at most d_batch = D_SITES + 6 q2/(r - 1) + YGEN_DEF + (L_Y² + 1)/(r - 1) < 2^-126.99 (`D_BATCH`; 6.4).
**Rare carries by branch.** In SHX the carry out of the first ADDS, in FDX, F5 the carry into limb 2, in FS the borrow of its C0 subtraction, in FADDW, BLK6, LF the carry out of limb 0, in DF out of limb 1 are rare. Each macro branches over its **fixup** (B.LO; B.HS for FS) unless that carry or borrow occurred; the fixup is the rest of the inline chain and STADD x4, [sp]. A skipped fixup would add or subtract 0, so every register equals the inline chain's; only the flags differ, and every path from the join sets them before reading (`flags_dead_at_every_join`). A fixup adds 3 instructions (SHX, FDX, F5), 4 (FS, FADDW) or 6 (BLK6, LF, DF) and C0 to the word at [sp]; each call returns it in x0, at most 19 q2 C0 < 2^63. The driver adds x0/C0 to the node's count N and starts a batch only while N <= 2^62 - 19 q2 (per pair 9 SHX, 6 FDX, 2 F5, 3 FS, 2 FADDW, 16 BLK-type), so N <= 2^62 on every run (R_worst: `6*2^62` per node); section 7's E-row charges 6 per expected fixup, q1(E_FIX + 19 q2 d_batch) per node.
**How often.** A fixup needs a word in a small set. SHX: the shifted row's low word above 2^64 - C0 (C0 2^192 rows). FDX: output low 128 bits below F C0 <= (2^66 + 1) C0, rest nonzero ((2^66 + 1) 2^128 C0 words). F5: output low 128 bits below 2^65 (2^193 words). FS: output low word at least 2^64 - C0; FADDW: below C0 (C0 2^192 words each). BLK6: the window sum (below 6p, t <= 5) has low 64 bits >= 2^64 - t C0: <= 30 C0 2^192 words. LF: low 64 bits >= 2^64 - c C0: <= Σ_(c<=8) c C0 2^192 = 36 C0 2^192 values of the folded residue (`FIX_LF`). DF (1/D_odd): the output's low 128 bits below 2^97: <= 2^225 values (`FIX_DF`), 6 points per value. While no site of the batch has deviated, the row or output is a word below 2^256 congruent to the operand (times 2^(64k) for row k), which determines it; so a site takes its fixup with probability at most its set's size times its points over r - 1. The 16 rows of `FIXUPS` and 10 of `SITES` are these sets times the per-pair macro counts and points per value. Summed (`E_FIX`), the expected number of fixups of a batch without a defect is at most `E_FIX`; over a node's batches q1 E_FIX < 2^33.36 (2^33.257).
**The meter row.** A node stops early only if N exceeds 2^62 - 19 q2 at the start of a batch; with no batch defect N is the clean count, so by Markov this has probability at most q1 E_FIX/(2^62 - 19 q2) + q1 d_batch < 2^-28.64 (`d_f`, 2^-28.743; a node-local row, 6.4).
## 4. Transport and grouping (kernels/route.s and the emit)
Per record, executed (charged, 2 more per message per hop in flight): hop 1 emit 7 + flush 9/256 = 7.03515625 (7.04296875); hop 2 h2s 6 + (flush 9 + dlvh copy 531)/256 + 8/256 = 8.140625 (8.1484375); join 4; total 19.17578125 (19.19140625); walks (4.5 per visit), K2 verifications and listings are E-rows. Each count is its loop's instruction list in `route.s` or `leaf.s`. A destination's full blocks number at most its records over k, cumulatively; a dropped block costs 7 or 9, so 542 per k records bounds hop 2's row blocks. **Blocks and cursors.** Emit and h2s take a slot by LDADD of 32 on the LC entry (the absolute slot address: bit 13 marks slot k, one TBZ). The **flush** resets the LC entry to slot 1 and advances the RC cursor by 32k (LDADD) returning c; the block is sent if c is below the sender's slot end, else dropped (a hop-1 cursor passes it only by the node's own leaves, < 2^63.43); fin sends the L records left if L > 0 and c < end, and writes min(c + 32L, end). **Keep lemma.** Cursors start at the slot base and move by 32k, `cap_p` is a multiple of k, so c < end gives c + 32k <= end: a block is kept or dropped whole, and records kept, their order and the final cursor match sending each record alone. A final block's k - L slots after its L records hold older records or none: at hop 1 the handler stops at count L; at hop 2 they land at or past the final cursor, where every later read stops, and the next group's first full block to d rewrites [c, c + 32L) with the same L records. Also at cap_pg. **Hash table and join.** 2^58 head words at 2^61 and a packed next-array at 2^62 (16 bytes per R2 slot: next address, K2); bucket K2 mod 2^58, so same-key records meet without ordering. A hop-2 sender writes into header word 3 the address p of F, its slot's final cursor after the previous group; dlvh copies all k slots into R2 and joins exactly the records in [max(F, c), c + count). Within a group a sender's blocks cover disjoint ranges at or past F in any arrival order; across groups the barrier orders them and the only repeats come first, below F: every record is joined once, stale slots never. Heads and next fields hold entry addresses E = (A>>1) + C (never 0); costs: join 4 per record, walk 4.5 per visit, K2 check 5, listing 5, dlvh's copy `DLVHB`, `DLVHS`.
**Chains, no sorting.** Same-key records at a home form one arrival-order chain (walks uncapped); intruders and cross-class listings are charged in success.md 6.4, 6.6. A pair is useless iff ν_i/u_i = ν_j/u_j, an equivalence relation, so a chain with a useful pair has a useful edge.
**Epoch cursors (bit 28 of k).** w2 holds kf = k mod 2^28. F_g[j], slot j's final cursor at a home after group g, is nondecreasing (RC cursors only grow, fin writes min(c + 32L, end) without moving RC); a record is joined once, in its batch's group g, inside [F_(g-1), F_g). E3 (a word per slot) is 2^64 - 1 from set-up (tinit); at group 391's start ecopy copies into it the table group 390's fin wrote. So a joined record at address a has a >= E3[j] iff its group exceeds 390. With q = 688296, B = 390 q = 268435440 <= 2^28 and q1 - 2^28 = 268435424 < B, k = kf + 2^28 [a >= E3[j] and kf < B] is exact. The resolver decodes each record (EPOCH_DEC = 24); a request carries k.
