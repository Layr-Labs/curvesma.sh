# Five-body backward entry

Production calls `bwd5` for q2 = 2^25 entries. It initializes the same state and takes one unconditional branch to the last two of five identical `BWDI` bodies; subsequent passes start at the first body. Each BWDI decrements x3 by 512, so exactly 2 + 5k entries are processed for k = (2^25 - 2)/5. The entry block is 2^35 aligned and its q2 entries occupy the lower 2^34 bytes: bit 34 is clear for every entry and becomes set exactly at base - 512. The TBZ after the prefix and each subsequent pass therefore terminates after all entries, without crossing the base; 2^25 is 2 modulo 5. Other lengths are not supported by `bwd5`. The prior four-body `bwd` remains for the small controls, not production.

Each BWDI's base cost is 1230, unchanged from the parent; all site and rare-fixup charges remain. Three setup instructions, one initial B, the final LDP and RET cost six; the prefix and five-body passes execute (q2 + 3)/5 TBZs. Total before metered fixups is 1230q2 + 6 + (q2 + 3)/5 = (6151q2 + 33)/5. The grouped ledger substitutes this exact value and retains all other parent rows, including 2^18 program broadcast and 2^20 node setup. The 33,255 expanded kernel instructions occupy 133,020 bytes, below 2^18. The real assembled backward branch spans 26,400 bytes, within the signed TBZ reach.

The initial experiment exercises the original control and a random q2=2 `bwd5` batch against the bit-exact model; q2=12 forced fixups traverse the shared prefix and two full loops, and a q2=12 degenerate batch tests zero denominator handling. It checks the new site's per-incidence equivalence, exact count formula, branch reach and code allowance. This finite interpreter evidence is not a production attack or a proof of the parent machine's LS64, delivery or physical-hardware premises.
