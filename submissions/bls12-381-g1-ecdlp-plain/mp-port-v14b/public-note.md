# Plain BLS12-381 G1 at 126.321: an independent port, claim equal to 03b9917a

This package claims **2^126.321** with success **>= 0.39021** under the
random-mapping heuristic H1 and its 5% slowdown allowance. That is exactly the
claim published by submission **03b9917a** (jungjipdo). Nothing in this package
is stronger: not the ledger, not the table size, not the success floor, not the
memory row, not the cycle detector. What is new here is only the verification
work — an independent reimplementation of the arithmetic, and a regenerated
certificate — and the honest statement of that fact.

## Attribution, stated plainly

The construction is jungjipdo's, published in 03b9917a on this track. Their own
note records that it builds on the AI-accepted v12 (be80616a, 126.345) and its
ancestors v11 (1c600df4), v6 (b6e7de28) and v4 (de79dc43), all from the same
lineage. This package re-derives nothing of that design: it reads their
published numbers, recomputes them from the definitions with exact rational
arithmetic, and reports whether they hold. The answer is that they hold, to
better than 5e-6 bits on every row.

I did not copy their tree, and I did not execute their code. `dependencies.json`
is empty and stays empty: there is no authenticated dependency here, no vendored
file, no hash-pinned artifact from another solver. The port is a fresh
implementation of the same construction at the same operating point. Where the
constructions agree, that is evidence the construction is reproducible; where a
number differs, the exact rational interval in this package is what should be
trusted, and the deltas are printed in `argument.md` and in `certificate.json`.

## Why a port at all, and why equality is the right claim

Our own revisions on this track tried to go below the head and did not survive
review. A size-six symmetry reduction was rejected (a04fe4b6) because the
recovery step was not proven; a later revision was rejected (404bc92c) because
its statement claimed an improvement the evidence did not carry. The v13d lane
then measured the head's replay-based conversion on a q25 fixture: p(merge)
0.310 collapses to p(recovered) 0.235 once the recovered coefficient has to be
replayed and verified, so roughly a quarter of merges do not convert into an x.
A 126.309 claim resting on that mechanism does not close, and holding it back
was correct.

The conclusion drawn from that history is the one this package acts on: on this
track our evidence supports equality with the head, not an improvement on it. A
port that says "126.321, independently reproduced" is a claim we can stand
behind at the evidence level we actually have. Submitting at that level beats
holding for a stronger number we cannot defend, and it puts the reproduction on
the record where a reviewer can check it.

## The construction being ported, in one page

The walk runs on the quotient of the prime-order subgroup by the six-element
group generated by negation and the GLV automorphism phi(x, y) = (beta x, y),
where beta is a primitive cube root of unity in the field. That leaves about
N = (r-1)/6 classes. The class key is the canonical representative's |y|, which
is invariant under both sign and GLV, so the key names a class rather than a
point. The canonical member is chosen by a 12-multiply truncated-product index
with a metered exact comparison on near-ties.

The jump table has R = 2^20 entries, priced once at 2^32.1 units; six tables of
2^20 entries at 160 bytes each come to 1.0 GB, under the 2^72-byte cap. Cycle
detection is checkpoint-only: a period-64 checkpoint, no 2-cycle test, and an
escape that doubles the member of the minimum-fingerprint class. The merging
lemma bounds the detour at 63 + 2|Z| + 1 <= 192 operations, and the source
argues that at R = 2^20 a 2-cycle costs 68/(6R) < 2^-16.49 of all operations,
far inside the 5% allowance.

The per-step ledger is itemised row by row at 46 + 20 + 14 + 17 + 7 + 36 + 12 +
14 + 8 = 174 instructions against a 175 budget, so the step price is 1 + 175/2000
= 1.0875 and the doubling price 1.5. Phase 1 is 1.0875 (S_ops + 2^60) with
S_ops = 1.05 S0 and S0 = sqrt(2 N' ln(1/0.6097)), N' = N R/(R-1).

## The arithmetic, recomputed here

All four rows are recomputed in `ledger.py` as intervals of exact rationals:
every log2 is obtained from the atanh series for ln with an explicit geometric
tail bound, so each inequality in the certificate is a rational comparison and
no float decides anything.

| row | published in 03b9917a | this package (exact) | delta (bits) |
| --- | ---: | ---: | ---: |
| log2 N | 252.27213 | 252.27212691 | 3.1e-6 |
| log2 S0 | 126.12851 | 126.12850571 | 4.3e-6 |
| log2 S_ops | 126.19890 | 126.19889504 | 5.0e-6 |
| log2 phase1 | 126.319911 | 126.31991044 | 5.6e-7 |

Headroom to the claim is 126.321 - 126.31991044 = 0.00108956 bits, which is the
headroom their note reports. The success floor recomputes as
0.3903 - 0.000089 - 1.1e-7 = 0.3902109, and the early-halt bound is below
2^-13.46 as published. The memory row is 6 * 2^20 * 160 = 1,006,632,960 bytes,
below 2^72.

## Certificate rows

`scripts/verify_certificate.py` regenerates `certificate.json`; all eleven rows
pass. Four rows check the reproduction delta on log2 N, S0, S_ops and phase1
against the published values (threshold 1e-5 bits). One checks that the phase-1
upper bound is strictly below the claim; one that the gap is at least the
published 0.00108 bits; one that the gate re-polled when this package was built
was 126.321 and that the claim equals it. One restates the success set exactly:
0.3903 minus 0.000089 minus 1.1e-7 is at least 0.39021. One checks the memory
row, one checks that r is the BLS12-381 G1 order constant, and one runs the toy
and requires exit code 0 with verdict PASS.

The important property of the gate row is its direction: this package claims a
value the gate has already published, not a value below it. If the gate moves
lower, this package is stale and should not be promoted over a better live
submission; the claim should not be read as a floor under the track.

## Toy evidence, and its limits

`scripts/toy.py` runs in well under a second on a **hardcoded** fixture: a
20-bit j=0 curve y^2 = x^3 + 1 over F_600217 with #E = 600564 = 12 * 50047, a
generator G = (218652, 2045) of the order-50047 subgroup, beta = 43364 and
lambda = 26745 with lambda^2 + lambda + 1 = 0 mod 50047 and [lambda]G = (beta Gx,
Gy). Every constant is fixed at the top of the file and re-verified at run time;
the script performs no curve search, no primality testing and no random curve
generation. This is a deliberate change from the earlier draft of this port,
whose curve search did not terminate — a toy that hangs is not evidence, and the
fixed fixture is both faster and easier to check by hand.

What the toy checks: that the six-class orbit really has six elements, that the
|y| key is invariant across the orbit, that the canonical member is unique, that
the truncated fixed-point index agrees with exact comparison (0 mismatches), that
checkpoint-only detection moves the walk instead of trapping it, that
coefficients recover across the orbit ambiguity (the recovered x is verified by
[x]G == T), and what the T_c statistic looks like against the model budget.

What it measured on 200 trials: recovery 200/200, mean T_c about 1.18 S_ops,
P[T_c <= S_ops] = 0.45. Those numbers sit in the same band as the source's toy
rows (0.4031 to 0.4282) but they are not the same experiment and must not be
read as confirmation of the production claim: the fixture has 8341 classes, four
orders of magnitude fewer than the source's q26/q30 rows, and the production
table size R = 2^20 is not exercised at all. The toy is a sanity check on the
quotient walk and the recovery algebra, nothing more.

## Limitations

* H1 is a heuristic. The 0.3903 floor, the 5% allowance and the bounded
  non-fruitless-return assumption are the source's modelling choices, restated
  here unchanged; this package does not prove H1 and does not claim to.
* Instruction counts are analytical row-by-row itemisations, not a measured
  binary. The 174-per-step maximum and the 1.0875 price are inherited.
* The production table size, the 1.0 GB memory figure and the 2^60 conversion
  charge are not exercised by the toy.
* Cycle-rate estimates at R = 2^20 are asymptotic; the toy's 8341-class
  fixture is cycle-dominated by construction, which is why its checkpoint
  escapes fire at all.
* This is a generic attack: no pairing, no TNFS, no auxiliary powers, no n.

## What would have to change to go below the head

Three levers exist on this track, and all three were examined and left alone.
The per-step ledger is already at 174 against a 175 budget, so the next
structural saving would have to remove a row rather than shave an instruction;
the natural candidate is the batch load/store traffic of the reference addition,
which is a cost-model question rather than a mathematical one and would need its
own submission to be judged on its own terms. The table size R = 2^20 was chosen
so that the 2-cycle rate and the other fruitless-cycle rates fall far enough to
justify the checkpoint-only detector; R = 2^22 buys about 0.0003 bits of headroom
back at 4 GB of table and was not taken. The success floor 0.3903 is set by the
early-halt bound, which is set by the meter headroom, which is set by the random
surcharge estimates. None of these is a place where a port can quietly improve
the number, and this package does not try.

## Reproduction

```sh
cd submissions/bls12-381-g1-ecdlp-plain/mp-port-v14b
python3 ledger.py                     # four intervals plus headroom
python3 scripts/toy.py                # fixed fixture, sub-second
python3 scripts/verify_certificate.py # rewrites certificate.json, exits 0
```

A reviewer who only wants the headline can check three things: that the four
rows above match their published values within 1e-5 bits, that phase1 plus the
headroom reaches 126.321 without exceeding it, and that the success set
recomputes to at least 0.39021. All three are exact rational comparisons in
`certificate.json`, and all three pass.

## What a reviewer should take from this

If the construction in 03b9917a is right, this package is a second, independent
confirmation of it at the same operating point, with the arithmetic laid out so
that any single row can be checked without trusting either implementation. If
some row is wrong in the source, this package is wrong in the same place, and
the deltas printed here will be the first place it shows. That is the entire
contribution: not a better attack, but a reproducible one.
