# Streamed signed BSGS on BLS12-381 G1 with batch affine conversion

This candidate claims the conservative upper bound **time_log2 = 1365639/10000 = 136.5639**, in the protected target-group-operation equivalents, with **success_probability >= 2/5** (exact deterministic coverage; threshold 0.39), **memory_log2_bytes = 145**, **preprocessing_log2 = 1365639/10000**, and **nonuniform_advice_log2_bytes = 0**. Zero advice bytes are used. These are submitted analytic bounds, not independently qualified results or an executed production attack. The fixed normalization is **C = 2000 scalar AArch64 instruction equivalents** per target-group equivalent, the protected BLS12-381 G1 price. All arithmetic, communication and control work is charged through scalar 64-bit instructions; no reference group operation is additionally charged.

Design provenance: this is a port to BLS12-381 G1 of the streamed signed baby-step giant-step construction published for secp256k1 in submission `f888bb9e-1cc3-4be1-bb0a-734722d78885` (which itself credits the earlier public note `a1821252`). The port changes the curve constants, the field-arithmetic prices for a 381-bit modulus with six 64-bit limbs, the record and packet widths, the search parameters and the coverage count for this subgroup order. No prior acceptance, score or cross-submission comparison is relied upon for validity; the construction, coverage proof, exact total `T` and complete ledger below stand alone.

## Target and algorithm

Use exactly the protected BLS12-381 field, G1 subgroup order, curve `y^2 = x^3 + 4`, generator P0 and canonical encoding, with a uniformly sampled full-production challenge T = [x]P0 (written Q below; P below means P0). In particular,

```
p = 1a0111ea397fe69a4b1ba7b6434bacd764774b84f38512bf6730d2a0f6b0f6241eabfffeb153ffffb9feffffffffaaab
r = 73eda753299d7d483339d80809a1d80553bda402fffe5bfeffffffff00000001
```

p has 381 bits and r has 255 bits (log2 r is about 254.857). The public profile is authoritative. No auxiliary powers, reduced-size challenge, scalar interval promise, extra advice or alternative computation price is assumed. Set

```
m = h = 102406909117623690224134270079834624000   (= 4096 * 25001686796294846246126530781209625)
L = 127                                           (2^126 < m < 2^127)
d = 2m - 1 = 204813818235247380448268540159669247999
B = 4096
D = -[d]P
```

m is the least multiple of B with 5*m*(2m-1) >= 2r.

Input validation. Decode Q canonically. JSON `null` is the infinity point. A finite Q must have both coordinates below p, satisfy the curve equation, and satisfy [r]Q = O. The last check is essential on this curve because the G1 cofactor is not 1: a point on the curve need not lie in G1, and such input is rejected. After validation Q lies in G1 = <P>, so every point generated below lies in G1. Compute D with charged scalar multiplication.

Construct two lists:

- baby records `(jP, j)`, for 0 <= j < m;
- giant records `(Q + iD, i)`, for 0 <= i < h.

Each sequence is generated by complete mixed Jacobian addition by its fixed affine increment, P or D. The baby sequence starts at infinity; the giant sequence starts at Q (infinity when Q is null). Collect B successive projective points, convert the block to affine with the exact batch-inversion procedure below, and write one record to each numbered leaf of the sequence's storage tree. m and h are divisible by B. The last update of a sequence may be performed and discarded; it is included in the budget.

A record has 24 64-bit words, or 192 bytes: one infinity tag, six canonical x limbs, six canonical y limbs, four scalar/index limbs, and seven padding words. A finite point's key is `(1, x)` (seven words); infinity's key is `(0, 0)` with zero coordinate words. The scalar/index is carried unchanged. No square roots, hashing or recovery of omitted coordinates are used.

Each tree lazily merges its leaves into a nondecreasing key stream. The central engine intersects the two sorted streams. It caches one head from each stream; if one key is smaller, it discards only that head and asks its stream for the next record. If keys are equal, it uses the two full y coordinates to identify

```
Q + iD = jP       or       Q + iD = -jP,
```

forms `a = id + j mod r` or `a = id - j mod r`, verifies [a]P = Q, and outputs a as the canonical 32-byte scalar. If both keys are infinity, j = 0 and a = id mod r. In particular, the identity target Q = O (scalar 0) gives the infinity giant record at i = 0, which matches the infinity baby record at j = 0, and the output is a = 0, as the profile requires. Exhausting either stream without a match returns failure. At most one final scalar verification is needed because an equal canonical key necessarily supplies a correct equality or negated equality. A y-coordinate disagreement with both choices is an implementation error, not a probabilistic false positive to be ignored.

## Exact success and ties

Baby keys are distinct. If jP = kP, then j = k in the stated range. If jP = -kP, then j + k is a multiple of r; since 0 <= j+k <= 2m-2 < r, this can only identify the same infinity record. Thus no finite baby key is duplicated.

Giant keys can repeat, and the algorithm does not assume otherwise. Internal merge nodes break equal-key ties by emitting the left child's head first, marking only that head consumed. The other head remains cached and is emitted later unless the search has already succeeded. Consequently no record is lost. At the central intersection, equal keys immediately provide a valid cross-list match; there is no reason to skip an equal-key run. Repeated giant keys therefore do not reduce success or require multiple verifications. If the heads differ, advancing only the smaller head is the usual exact sorted-list intersection rule and cannot discard a possible cross-list match.

For fixed i, an equal key exists exactly for the scalar residues

```
[id-(m-1), id+(m-1)] modulo r.
```

Successive integer intervals are adjacent and disjoint because d = 2m-1. Their union is the integer interval from -(m-1) through (h-1)d+(m-1), with precisely COV = h*d members. COV < r, so reduction modulo r is injective on this interval, including its wrap through zero. Exact arithmetic gives

```
COV      = 20974350070050476191779096203274388009425771397893117006380920108362917376000
r - COV  = 31461525105075714287668644304911577828264781102634520816222738591575663808513 > 0
5*COV-2r = 8371747751988410309386697283141937424510974 > 0.
```

The challenge scalar x is uniform on 0..r-1 (infinity included), and the algorithm succeeds exactly when x is in the covered set. The success probability is therefore exactly COV/r >= 2/5 > 0.39, with the integer check 100*COV >= 39*r implied by 5*COV >= 2*r. The construction is deterministic; fresh random coins, trials, restarts and amplification are unnecessary. It deliberately fails outside the covered set. No claim is made that the challenge scalar was sampled from a restricted interval.

The index arithmetic is finite and small relative to the table size: m, h, i and j fit two 64-bit words, d fits 128 bits, and id+j fits 256 bits. The greatest positive reconstructed integer is h*d-m < r. Negative reconstruction can occur only for i = 0 and is corrected by adding r. All comparisons, multi-limb counters and reconstruction work are charged below.

## Field arithmetic with 64-bit limbs

Field operands are canonical six-limb integers below p. A seventh limb holds carries where necessary. Modular addition or subtraction costs at most A = 512 instructions: six seven-limb passes at eight instructions per limb (336), plus sixteen fixed control instructions, cover loads, stores, carry/borrow propagation, comparison and conditional correction. Small multiples such as 2, 3, 4 and 8 are implemented with these charged additions.

p is a generic prime, so no special-form folding is used. Multiplication uses word-serial Montgomery multiplication (CIOS) with R = 2^384 and the precomputed public constant n' = -p^(-1) mod 2^64. For a, b < p one CIOS product computes a*b*R^(-1) mod p as follows: six outer rounds; each round accumulates a_i*b (six limb products), forms one quotient digit q = t_0*n' mod 2^64 (one product), adds q*p (six limb products) and shifts by one word. This is 78 MUL/UMULH pairs. Budget 40 instructions per pair for MUL, UMULH, the ADDS/ADCS carry chain, loads and stores, totaling 3120. Because p < R/4, the CIOS output is below 2p, so one conditional subtraction of p yields the canonical result; this subtraction, setup and output fit 512 instructions. One CIOS product therefore costs at most 3632 < 4096 instructions.

To keep every value canonical (not in Montgomery form), a field multiplication is defined as two CIOS products: first u = a*b*R^(-1) mod p, then u*(R^2 mod p)*R^(-1) = a*b mod p, with R^2 mod p a public constant. Thus a canonical-in, canonical-out multiplication costs at most **M = 8192 instructions**. Squaring uses the same bound. For reference, the protected cost model measures 383 instructions per optimized blst base-field multiplication; M is more than twenty times that.

For nonzero z, Fermat inversion z^(p-2) by left-to-right binary exponentiation uses at most 380 squarings and 380 multiplications (the exponent has 381 bits), 760 multiplications in total. With 64 control instructions for each of 381 exponent bits and fixed setup, it costs at most 760*8192 + 381*64 + 4096 = 6254400 < **I = 2^23** = 8388608 instructions. This is an analytic instruction bound, not a measured assembly result.

## Complete projective generation

Represent a finite affine point by `(X:Y:Z)` with x = X/Z^2 and y = Y/Z^3. Infinity is Z = 0. All coordinates remain canonical modulo p. For mixed addition of `(X:Y:Z)` and a finite fixed affine point `(u,v)`, first handle Z = 0 by returning `(u:v:1)`. Otherwise compute

```
ZZ = Z^2
U2 = u*ZZ
S2 = v*Z*ZZ
H  = U2-X
q  = S2-Y
```

If H = 0 and q != 0, return infinity. If H = q = 0, use the doubling procedure below. In all other cases compute

```
HH  = H^2
HHH = H*HH
V   = X*HH
X3  = q^2-HHH-2*V
Y3  = q*(V-X3)-Y*HHH
Z3  = Z*H
```

These formulas give exactly the group sum. For doubling, return infinity if Z = 0 or Y = 0; otherwise use the a = 0 formulas

```
AA = X^2
BB = Y^2
CC = BB^2
DD = 2*((X+BB)^2-AA-CC)
EE = 3*AA
FF = EE^2
X3 = FF-2*DD
Y3 = EE*(DD-X3)-8*CC
Z3 = 2*Y*Z
```

The displayed formulas are the `madd-2004-hmv` mixed-addition and `dbl-2009-l` doubling formulas from the [Explicit-Formulas Database, Jacobian coordinates with a = 0](https://www.hyperelliptic.org/EFD/g1p/auto-shortw-jacobian-0.html), with the exceptional-case branches specified here. They do not involve the curve constant b, so they apply unchanged to y^2 = x^3 + 4. The ordinary mixed branch uses eleven field multiplications/squares. The exceptional doubling branch uses at most the four initial multiplications plus seven doubling multiplications/squares. Each branch, including canonical zero tests, copies, scalar-index bookkeeping, storing the current point in the block, additions and negations, fits

```
JAC = 16*M + 32*A + 4096 = 151552 instructions.
```

P and D are nonidentity points of G1: d is nonzero modulo the prime r. The listed finite-increment procedure therefore covers both generated sequences. No probabilistic avoidance of exceptional denominators or points is used.

## Exact block normalization

For each block of B = 4096 projective points, set z_k = Z_k when Z_k != 0 and z_k = 1 otherwise. The zero-Z flags are retained. Form prefix products of all z_k, invert the final nonzero product once, and traverse backward: multiplying the running inverse by the preceding prefix gives z_k^(-1), and multiplying the running inverse by z_k prepares the next step. At most B prefix multiplications and 2B reverse multiplications suffice.

For each nonzero Z, compute Z^(-2), X*Z^(-2), Z^(-3), and Y*Z^(-3), costing four additional multiplications. For zero Z, emit the infinity record; substituting 1 ensures there is never a zero inversion. The entire block costs at most

```
B*JAC + 7*B*M + 4096*B + I
```

instructions. The 4096 instructions per point cover flags, prefix-array transfers, backward counters, canonical record construction and all normalization control. Since I/B = 2048, this is 151552 + 57344 + 4096 + 2048 = 215040 instructions per point, strictly below the adopted conservative allowance **E = 2^18 = 262144**. There are no partial blocks at the chosen production m and h. Point-block storage (three six-limb coordinates per point), original Z values, prefixes, flags and a single output staging record use less than 1 MiB; normalized records are written to their numbered leaves immediately during the reverse pass, so no second whole-block output array is retained; the whole central engine, code, scratch and state fit the separate 2^24-byte reserve.

## Distributed storage and initialization

Use two storage trees, one per list. Each is the full binary tree on m leaves obtained by splitting a contiguous leaf range [b,e) at its middle floor((b+e)/2) until single leaves remain. It has 2m-1 nodes, m-1 internal nodes and 2m-2 child edges. By induction, a range of at most 2^k leaves has depth at most k (both halves have at most 2^(k-1) leaves), so every leaf has depth at most L = 127 because m < 2^127. The two trees have 4m-2 < 4m nodes in total. A node is a scalar processor with at most 64 KiB local code, state, buffers and records. It has only local 64-bit pointers and three local word-transfer ports, for its parent and children; leaves ignore child ports. Each internal node stores its range split point (two words); a destination leaf index of at most 127 bits is routed down one level per edge by a two-word comparison with that split point, inside the per-crossing control charge below. The engine has a port to each root. Node state includes two cached child-head records (48 words), flags, local scratch and routing metadata; it fits the allowance. A single data request is served at a time along a dependency path, and processors suspend for events instead of spinning. All work of all participating processors is counted.

The trees are not a free global address space. Their topology metadata, code distribution, clears and initial state are charged. For each node, allow up to 8192 word clears at eight instructions each and up to 8192 word image copies/transfers at sixteen instructions each, with both sender and receiver charged. These are conservative whole-64-KiB bounds even though actual code and initialized state occupy less. Another 2^15 instructions per node cover port/path metadata, split points, counters, startup acknowledgements and local initialization control. Thus

```
8192*8 + 8192*16 + 2^15 = 229376 < INIT = 2^18
```

suffices per node. All initialization is bounded by 4m*INIT. Root code preparation is in the separate fixed reserve. Fixed programs are not assumed to arrive at the other nodes for free. No node's reserved capacity requires additional unreported retained data or randomness.

To write one 192-byte record, allow a 28-word command/data packet, including four command/address words, over every edge of its request/acknowledgement route. The route from the generating engine is its port to the root plus at most L = 127 tree edges, so at most 128 edges down and 128 back: at most 256 aggregate edge crossings. Per crossing, sixteen instructions per word cover both endpoint loads/stores, port transfers and addressing; another 64 cover control and the routing comparison. The bound is 256*(28*16+64) = 131072 instructions. **U = 3*2^16 = 196608** adds 65536 instructions for root/leaf work, packet setup and acknowledgements. Every baby and every giant record is written exactly once and charged U. There are no free remote accesses or uncharged table copies.

## Lazy sorting streams, including end markers

A leaf answers its first NEXT request with its single stored record, and its next request with END. Its END flag is then remembered. An internal node keeps one head slot per child, each marked EMPTY, RECORD or END. Initially both slots are EMPTY. To answer NEXT it fills EMPTY slots by issuing NEXT to the respective children. If both are END it returns END. If exactly one is END it emits the other's record. Otherwise it compares the two keys and emits the smaller; equal keys emit the left one. Only the emitted head becomes EMPTY. Refilling is deferred until the next parent request. A parent that receives END remembers it and never requests that child's stream again.

This is recursive merging of singleton streams. Induction on the tree proves that every record in a subtree is emitted exactly once, in nondecreasing key order. Cached unconsumed heads remain available, including across equal keys. The engine can abort immediately after a match. Its actual work is bounded by a complete drain of both streams, so cached lookahead on an aborted run cannot invalidate the budget.

For one tree, let n_e be the number of leaves below child edge e. That edge carries precisely n_e record responses on a complete drain, at most one END response, and at most n_e+1 corresponding NEXT requests. Each leaf has at most L ancestors, hence

```
sum_e n_e <= m*L
number of child edges = 2m-2
sum_e (n_e+1) < m*(L+2).
```

A NEXT packet needs at most four words; a record or END response is conservatively bounded by twenty-eight words. At sixteen instructions per word for BOTH endpoints and 64 control instructions per packet, a request-response pair costs at most

```
(4*16+64) + (28*16+64) = 640 instructions.
```

This includes all physical word transfers, endpoint loads/stores and local message handling. Reserve another 512 instructions per such pair for key comparisons, cached-head selection/copies, state updates and fixed-size local control, beyond those transfer charges. Keys have only seven 64-bit words, with x compared from its most significant limb; head records have twenty-four. A key comparison uses at most seven limb comparisons, while copying a head takes twenty-four loads and twenty-four stores. Both plus the fixed control fit this allowance. No internal loop scans a subtree or performs a remote array lookup. Child request handling and returning the selected response are already counted at their respective edges.

The central root's NEXT/response interaction and root-local bookkeeping do not add another tree level. A further 4096 instructions per root record cover them, leaf finalization, initial root state and the one root END event. Thus a complete sorted stream costs at most

```
m * [1152*(L+2) + 4096]
= m * 152704
< m * S, where S = 2^18.
```

The slack also covers fixed one-time events for nodes with no prior cached head. END messages are explicitly counted; no zero-cost sentinel oracle is used. Both trees together cost at most 2m*S. The separate central intersection makes fewer than 2m head-consumption iterations, each at most 8192 scalar instructions for key comparison, index/state movement and control. It is therefore bounded by m*2^14. NEXT transfers themselves were counted in the stream budget and are not charged again.

## Fixed work, memory and total bound

The fixed 2^40-instruction reserve covers input parsing and rejection of malformed input, the curve and [r]Q checks, computing D = -[d]P, preparing the engine's fixed code/constants (including n' and R^2 mod p), scalar reconstruction at a match, one independent [a]P verification, canonical output and fixed cleanup/control. For a simple independent implementation, complete affine addition fits 2^24 instructions using the inversion bound above and explicit infinity, opposite-point, doubling and y = 0 branches. Binary scalar multiplication by a scalar below 2^256 needs at most 512 such additions, 2^33 instructions; the three fixed scalar multiplications ([r]Q, [d]P and [a]P) fit well within 2^40. No inverse is taken on zero. All input-dependent giant construction, sorting and unsuccessful intersection work is in the variable ledger, not hidden in that reserve.

Let INIT = E = S = 2^18 and U = 3*2^16. The complete worst-case scalar instruction budget is

```
T = 2^40
    + 4m*INIT
    + m*(E+U+4096)                 # baby generation, normalization and writes
    + h*(E+U+4096)                 # giant generation, normalization and writes
    + 2m*S                         # both complete sorted streams
    + m*2^14                       # central intersection
  = 2^40 + m*2514944.
```

The extra 4096 per generated record covers outer block counters, leaf addressing and loop work beyond the internal arithmetic and transfer allowances. The exact components are:

Public profile constants and algorithm-design effort are the only excluded work, as permitted by the protected rules. ## Evidence and limitations

Heuristic assumptions: **none**. There is no random-walk mixing assumption, random oracle, birthday approximation, ideal hash table, empirical success extrapolation or uncharged precomputed table. The pairing transfer to GT allowed by the rules is not used. The cost claims are analytical scalar-instruction bounds rather than processor timing measurements. The distributed word-transfer implementation and its complete instruction allowance are explicit parts of the construction and remain reviewable assumptions of that accounting argument, rather than free parallel speedup.

The companion experiment (`experiment.py`, initial input `{"mode": "all", "m": 12, "h": 12, "block_size": 4}`) checks, at its executed scope only:

- exhaustive recovery in twelve odd-order additive toy groups (orders 17 to 257), including non-power-of-two tree sizes, where every covered scalar is recovered, every uncovered scalar fails, and a mutant that omits the minus sign is caught by the final verification;
- the middle-split lazy merge: output equals an independent sort, traversals equal the exact sum of leaf depths and are at most m*L, and end markers number 2(m-1);
- on the protected BLS12-381 G1 field and generator: [r]P = O, [r-1]P = -P, rejection of an on-curve point outside G1 by the [r]Q check, 108 mixed-addition and 18 doubling cases of the Jacobian formulas against an independent affine oracle under rescalings 1, 3 and p-1, mixed zero/nonzero-Z block normalization, and 17 targeted targets (including the identity target and both ends of the covered interval) with m = h = 12;
- every integer in the ledger above, the coverage inequalities, the minimality of m, and the exact score inequality in both directions.
