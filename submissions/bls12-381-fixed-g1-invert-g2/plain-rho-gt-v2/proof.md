# Fixed-G1 pairing inversion via plain distinguished-point rho in GT

Track: `bls12-381-fixed-g1-invert-g2`.

* Claimed score: **time_log2 = 127.80** (639/5) target-group-operation
  equivalents. Unit: the dense Fp12 multiplication at C = 20,000 scalar AArch64
  instruction equivalents.
* Success probability: at least 0.39 under the textbook random-mapping heuristic
  for rho, supported by experiments.

This is a deliberately **clean, heuristic-light** submission: a standard
distinguished-point Pollard rho for the GT discrete logarithm, with **no
automorphism/orbit quotient**, hence **no fruitless cycles**. Its only modelling
assumption is the random-mapping model for the rho collision time, which is
textbook and which I support with toy experiments. It supersedes my earlier
Frobenius-orbit attempts on this track, whose √12 speedup to ~126.3 relied on a
fruitless-cycle waste bound that I could not make rigorous. The Frobenius
speedup is discussed as future work in section 6.

## 1. Reduction

Input: nonidentity P in G1 (order r), z in GT. Q0 is the public G2 generator.

1. Validate P and z per the profile (on-curve, subgroup, z^r = 1).
2. If z = 1, output Q = infinity (valid exactly when z = 1).
3. Compute g = e(P, Q0) with the pinned map (`pairing(Q0, P)` in py_ecc order).
   P and Q0 have prime order r and the pairing is nondegenerate, so g != 1
   generates GT (prime order r).
4. Find a in [0, r) with z = g^a (section 2).
5. Output Q = [a]Q0. Then e(P, Q) = e(P, Q0)^a = g^a = z, and Q is in G2.
   Optionally recompute e(P, Q) and compare all 12 coefficients.

P is never replaced — the admissible route named in `rules.md`.

## 2. Discrete logarithm in GT by distinguished-point rho

GT is cyclic of prime order r, generated by g. We solve z = g^a with the
van Oorschot–Wiener parallel distinguished-point rho.

### 2.1 Walk

Precompute R = 2^20 adding entries M_j = g^{alpha_j} z^{beta_j} with random
alpha_j, beta_j in [0, r). A walk state is u = g^A z^B with exponents (A, B). One
step: j = H(u) (a multiplicative hash of u, 20 bits), u' = u·M_j (one dense Fp12
multiplication), A' = A + alpha_j, B' = B + beta_j mod r.

Because there is no orbit quotient, the step map is a plain R-adding walk on the
cyclic group GT. It has no fruitless cycles: the only cycle a trajectory can
enter is the rho tail at distance ~sqrt(r), which is exactly the collision the
algorithm is looking for. There is no automorphism folding, no look-ahead, no
cycle-escape, and no waste factor.

### 2.2 Parallel collision search, cheap restarts

Run w ≤ 2^40 walks from random starts (van Oorschot–Wiener). A point is
**distinguished** when 30 designated hash bits are zero (theta = 2^-30; chosen so
the distinguished-point table is small — see section 5). Store (256-bit
fingerprint of u, A, B), 96 bytes, keyed by fingerprint. On a fingerprint match,
confirm by recomputing u (false matches total ~2^-43) and solve
a = (A - A')/(B' - B) mod r when B != B' (B = B' has probability ~1/r). The walk
restarts after each distinguished point. Smaller theta means longer trajectories
(~1/theta = 2^30 steps) and a detection lag of at most 1/theta steps for the
final colliding pair; both are negligible against the ~2^127.7 step budget, and
the collision-step count and success probability (section 3) are unaffected by
theta.

**Restart (cheap).** A new walk starts at D·M_j for a random table index j, where
D is the just-recorded distinguished point: one dense Fp12 multiplication, with a
well-randomised (A, B) because D is pseudo-random and M_j injects fresh exponents.
This produces independent trajectories at one multiplication per restart. The
experiment confirms this restart preserves efficiency (mean work ~1.0·sqrt(πr/2)).

## 3. Steps and success probability

Model the R-adding walk as a random mapping on the r group elements. The number
of distinct points visited before a self-collision is ~sqrt(πr/2), and for T
total walk-points the collision probability is ~1 - exp(-T^2/(2r)). Let

    k0 = sqrt(2 r ln(1/0.61)),   log2 k0 = 127.420269

so that the random-mapping success at k0 steps is exactly 0.39. We budget
**1.25·k0 useful steps**; the random-mapping success is then
1 - 0.61^1.5625 = 0.538. The 25% margin also absorbs a walk up to ~25% less
efficient than a random mapping, and the detection lag.

### Experimental support (toy scale, Python 3.12, one core)

`experiment.py` runs this exact algorithm — R-adding distinguished-point rho,
parallel walks, cheap D·M_j restarts — in the prime-order-ell subgroup of F_q*
(a cyclic group of order ell, standing in for GT). Every group multiplication of
the walk and the restarts is counted.

| bits | seed | mean mults / sqrt(π ell/2) | success within 1.25 k0 |
| ---: | ---: | ---: | ---: |
| 26 | 1 | 0.984 | 0.567 |
| 26 | 2 | 1.033 | 0.500 |
| 26 | 3 | 1.021 | 0.500 |
| 26 | 4 | 1.053 | 0.467 |
| 28 | 5 | 1.060 | 0.450 |
| 30 | 5 | 1.039 | 0.533 |

The mean collision time is within a few percent of sqrt(πell/2), and the success
within the 1.25·k0 budget matches the random-mapping prediction 0.538 and stays
≥ 0.39 throughout. This is toy-scale evidence, not a production proof. Standard
support for R-adding walks behaving like random mappings: Teske (2001).

## 4. Cost accounting (dense Fp12 multiplication = 1 unit)

### Per step

* One dense Fp12 multiplication u·M_j: 1 unit (the reference operation).
* Other work, charged at the blst base-field rate where relevant:

| Item | Instructions |
| --- | ---: |
| Partition index H(u) (hash of a few limbs) | ~20 |
| Distinguished-point test | ~10 |
| Two 255-bit modular exponent additions (A, B) | ~160 |
| Table-entry load + state stores + control | ~100 |
| **Total** | **~290** |

Charged 300 instructions = 0.015 units. **Per-step s = 1.015 units.** There is
no canonicalisation and no waste factor.

### Steps

1.25·k0 useful steps. No fruitless-cycle waste factor.

### Additive work (all charged)

| Item | Bound (units) | Ratio to main |
| --- | --- | --- |
| Pairing g = e(P,Q0) | ≤ 2^14 | ~2^-113 |
| Table: 2^20 entries × 2 exponentiations | ≤ 2^31 | ~2^-96 |
| Restarts: steps·theta = 2^127.76·2^-30 = 2^97.76 × 1.015 units | ≤ 2^97.8 | ~2^-30 |
| Distinguished-point inserts: 2^97.76 × 2^13/20000 | ≤ 2^96.5 | ~2^-31.3 |
| Detection lag (final pair to next DP) | ≤ 2^30 | negligible |
| Output: a mod r, [a]Q0 in G2 (< 2^22 instr), verification pairing | ≤ 2^14 | ~2^-113 |

Total additive ≈ 2^107.9 units, ~2^-19.9 of the main term.

### Total

    W = 1.25 · 1.015 · k0 + additive
    log2(main) = 127.420269 + log2(1.25·1.015) = 127.420269 + 0.342997 = 127.763266
    log2(W)    = 127.763266 + log2(1 + 2^-19.9) ≈ 127.763267

Submitted bound **time_log2 = 127.80**, rounded up with margin above the additive
terms.

## 5. Memory, preprocessing, advice

Memory is dominated by the distinguished-point table. With theta = 2^-30 and the
useful-step budget T = 1.25·k0 (log2 T = 127.742197), the expected number of
stored records is T·theta = 2^97.742.

**Hard capacity bound.** Allocate a fixed table of **2^100 distinguished-point
slots** (96 bytes each). The record count is Binomial(≈ T, theta) with mean
2^97.742; by a Chernoff bound the probability it exceeds 2^100 (a factor 2^2.26
≈ 4.8 above the mean) before the collision is at most
exp(-(delta^2/3)·2^97.742) with delta ≈ 3.8, i.e. doubly-exponentially small.
So the 2^100-slot table is a hard storage bound that the run does not exceed
except with negligible probability, and it does not bind before the collision at
~2^97.742 records; the success analysis of section 3 (≥ 0.39 within 1.25·k0) is
therefore unchanged. In the negligible event the cap is reached without a
collision, the run restarts, at negligible amortised cost.

* Peak memory: 2^100 slots × 96 bytes = 2^106.585 bytes, times ~2 for hash-table
  load factor and indexing = 2^107.6, plus the 2^20-entry adding table (~2^26
  bytes), 2^40 walk states (~2^47 bytes) and code. Total ≤ **2^108 bytes**.
  memory_log2_bytes = 108 (reported only; memory has no scalar contribution or
  tie-break).
* Preprocessing (pairing + table) ≤ 2^31 units; preprocessing_log2 ≤ 32, included
  in W.
* Nonuniform advice: none (0 bytes). All constants are public.

The time bound of section 4 is independent of theta and of the memory cap: theta
affects only table size, restart count and detection lag, all negligible in W.

## 6. Heuristics, limitations, and the Frobenius speedup

* **Heuristic:** the R-adding walk behaves like a random mapping on the r group
  elements, within the 25% margin. Support: Teske (2001) and the toy ratio ~1.0.
  Not proven at production size. This is the single assumption; there is no
  fruitless-cycle rate to justify.
* **Frobenius speedup (not claimed here).** GT admits the order-12 Frobenius
  automorphism x → x^p = x^(p mod r), which could give a ~√12 (≈1.79-bit)
  speedup by walking on the orbit quotient (down to ~126.3). That requires
  handling fruitless cycles inherent to orbit walks, whose waste I could not bound
  rigorously (Brent detection's delay depends on the tail length, not the cycle
  length; the entry-rate bound covers only short patterns). The literature treats
  this overhead heuristically. I leave the rigorous orbit-walk bound, and the
  TNFS/SexTNFS route (~2^120–2^126 in those papers' own units, not converted to
  this cost model), as the directions to beat this clean bound.
* Analytic claim; no production-size execution.

References: Pollard (1978); van Oorschot–Wiener, "Parallel collision search with
cryptanalytic applications", J. Cryptology 1999; Teske, "On random walks for
Pollard's rho method", Math. Comp. 2001.
