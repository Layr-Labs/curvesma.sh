# Metered universal-hash signed GT baby-step/giant-step

This is a classical analytic accounting control for the exact protected profile, not a practical attack or a claim of novelty. The attack uses independent charged random bits for an explicitly sampled universal hash. It uses no auxiliary powers, searched advice, random oracle or heuristic. It returns a G2 point for the supplied G1 point. The claimed bound is W <= 2^141 dense-Fp12 reference equivalents, with C=20,000 scalar AArch64 instruction equivalents. Success is at least 0.4 over uniform production challenges and independent fresh hash coins. Peak memory is at most 2^139 bytes; preprocessing is at most 2^140 reference equivalents, included in W. Nonuniform advice is absent (the max(1,bytes) reporting convention gives log2=0).

## Algebra and complete algorithm

Use the protected prime order r and field modulus p, and the public generator Q0. The reduced pairing is bilinear and nondegenerate on these prime-order groups. For every allowed P != infinity, g=e(P,Q0) has order r: writing P=bP0 with nonzero b, nondegeneracy gives e(P0,Q0) order r and exponentiation by b preserves order. No computation of b is used. Thus each allowed z has a unique a in [0,r) with z=g^a. This is precisely the input domain, including identity.

## Signed baby table and exact coverage

Set m=2^126, D=2m-1 and k=2^127. For a GT value v let inv(v) be its multiplicative inverse and let c(v)=min(v,inv(v)) in lexicographic order on the complete canonical coefficient encoding. Keep a sign t in {+1,-1} such that c(v)=v^t. Break the identity tie with t=+1.

In this protected polynomial model inversion on GT is inexpensive and exact. The defining polynomial is even and irreducible of degree 12. Thus w^2 has degree 6 over Fp: w^2 satisfies Y^6-2Y^3+2, so its degree is at most 6, while adjoining its square root w has degree at most twice that degree and actually has degree 12; equality forces degree 6. The p^6 Frobenius fixes w^2 and sends w to -w, since w is not in Fp6. It therefore negates exactly the odd coefficients. Since GT has order r and embedding degree 12, p^6=-1 modulo r (order 12 gives a nontrivial element of order 2 modulo the prime r). Hence v^(p^6)=inv(v) on GT. Computing inv(v) costs at most six modular negations; selecting the lexicographic minimum and sign uses at most 72 word comparisons plus copies. Charge 2^14 scalar instructions per canonicalization, including all local loads, stores and control.

Generate the m records (c(g^j),j,s_j) for 0<=j<m, where s_j is the canonicalization sign. Generate g^j sequentially, starting from 1, and insert the records into the universal-hash table specified below. These keys are distinct: equality implies j=+j' or j=-j' modulo r, and 0<=j,j'<m, 2m-2<r forces j=j'. The sign and exponent fit in the existing 1024-byte record budget. Full-key equality is used throughout; no probabilistic fingerprint equality is used.

Compute h=g^(-D) by binary powering modulo r. Set v=z. For i=0,...,k-1, canonicalize v to obtain (c(v),t), and look up that key using the hash bucket and a full-key chain scan specified below. A hit at baby record (j,s_j) gives epsilon=t*s_j and a=iD+epsilon*j modulo r. Reconstruct the canonical residue a by one conditional addition of r if the signed value is negative; positive values are less than r. Return Q=[a]Q0 only after checking the exact e(P,Q)=z. If no hit is found, replace v by v*h and continue. At loop end report failure. All loops, failed challenges and routing-budget aborts are charged. The charged routing/hash work is metered as specified below, with no free restart or amplification.

A hit is equivalent to a=iD+j or a=iD-j modulo r for some 0<=j<m. Each giant step therefore covers the consecutive integer interval [iD-(m-1),iD+(m-1)] of exactly D=2m-1 elements. Adjacent intervals are disjoint and touch consecutively, so all k steps cover exactly kD=2^254-2^127 consecutive integers starting at -(m-1). Their residues modulo r remain distinct because kD<2^254<r. Thus the exact algebraic coverage probability for uniform z before hash-budget aborts is (2^254-2^127)/r for every fixed valid P. It is greater than 1/2: r<(15/16)*2^255 from its leading hexadecimal digits (0x73... < 0x78...), while kD>(15/16)*2^254 because 2^127<2^250. This is an exact counting argument, not an independence heuristic. The final success lower bound accounts additionally for routing/hash budget aborts below. The input P remains the supplied point. Identity z gives j=i=0 and Q=infinity. Every output is correct; uncovered inputs consume the bounded unsuccessful search and report failure.

## Explicit conservative scalar arithmetic

Here is a deliberately slow implementation sufficient for the bound; no measured blst multiplication is assumed to cost one. Use six 64-bit words for each residue. Implement Fp multiplication by 381 iterations of modular double-and-add, scanning the bits of one operand most-significant first. For each iteration double the accumulator modulo p and add either zero or the other operand modulo p. A modular addition takes six word adds with carry, six subtracts with borrow, a carry/borrow decision and a six-word selection. Allocate 256 scalar instructions for an addition, including source/destination accesses, loop/address control, and all carries. Both operands are canonical; their sum is <2p and fits six words because p<2^381, so one conditional subtraction suffices. Scanning a bit, selecting the operand and loop control take fewer than 128 additional instructions per bit. Therefore a field multiplication costs at most 381*(2*256+128)+1024 < 2^18 instructions. Field addition/subtraction each cost <=256; negation and equality have the same bound. This uses ordinary scalar word operations, not arbitrary-width unit costs. Stack and code storage fit below 2^20 bytes.

For Fp12 multiplication, use the polynomial representation specified in the target profile, not a conversion oracle. A schoolbook convolution has 144 coefficient multiplications and 144 coefficient additions. Reduce degrees 22 down to 12 using w^12=2w^6-2. Each of the eleven high coefficients contributes to two lower slots, via at most six modular additions/subtractions. Total is below 144*2^18+(144+66)*256 plus loop, indexing, copies and zeroing. Reserving a further 2^20 instructions covers that overhead: total <2^26 instructions per dense Fp12 multiplication. This is an upper bound for the actual algorithm, not a replacement reference price. Its normalized cost is strictly less than 2^26/20,000 <2^12 units.

Binary powers need fewer than 2L field multiplications for an L-bit nonnegative exponent; inversion in Fp uses exponent p-2 and costs <2^28 instructions. Fp2 arithmetic is two-component polynomial arithmetic and fits below 2^22 per multiplication. G2 scalar multiplication uses ordinary projective double-and-add and at most 510 point steps. A point step can alternatively use affine formulas with explicit Fp2 inversion; Fp2 inversion reduces to one Fp inversion and a constant number of Fp multiplications. Allow 2^40 instructions per point step, enormously above these formulas. All exceptional cases (identity, doubling, inverse points) are checked explicitly. G1 validation similarly uses affine formulas over Fp.

For pairing evaluation, evaluate the exact pinned optimal-ate definition using its field formulas. Its loop has fewer than 128 iterations; even a generic affine line computation with inversion, field evaluations, numerator/denominator updates and all exceptional checks is far below 2^40 instructions per iteration using the preceding polynomial arithmetic. The final exponent has fewer than 4572 bits, hence below 9144 Fp12 multiplications. Input parsing, group and GT checks, both pairing calls (initial g and final verification), exponentiation for h, G2 scalar multiplication, serialization, and any fixed initialization together fit below 2^64 scalar instructions. This also leaves more than 2^50 instructions for code and arithmetic setup. Constants come directly from the protected public profile; no construction of a lookup table is omitted. This deliberately coarse wrapper bound does not depend on a fast pairing implementation. The exact pinned pairing convention is essential; the algorithm does not substitute a Miller-loop value for its output.

## Explicit universal hashing, fixed storage and routing

Use B=2^128 buckets and m=2^126 fixed record slots. A bucket head is either empty or the index of a record; each record contains its complete key, exponent, sign and next index. No bucket has a fixed length cap. It is a linked chain of full-key records; equality is always checked exactly, not via a fingerprint. Head and next indices fit 128 bits; a 32-byte bucket entry and 1024-byte record have ample space. Assign slot j to baby j, so allocation needs no dynamic search. Insertion reads the old bucket head, writes the new record with next=old head, and writes the new head: at most three memory accesses. Baby keys were proved distinct; no duplicate check is needed on insertion.

Represent each key as its 4608 bits (72 canonical residue words). Independently sample a uniformly random binary matrix H of dimensions 128 by 4608, and let hash(x)=Hx over F2. It occupies 73,728 bytes. For any fixed distinct x,y, a nonzero differing bit makes each row product against x-y an unbiased independent bit, so Pr[hash(x)=hash(y)]=2^-128 exactly. The matrix is explicitly sampled once, not searched advice. It is independent of P,z and of all baby/giant keys, which are completely determined by P,z. This is a proven universal family, not an oracle hypothesis. Sampling all 589,824 independent bits and storing them costs below 2^30 scalar instruction equivalents, allowing 16 instructions per sampled bit; fresh random bits are charged.

For a query key, read its bucket head and scan the chain, comparing full 72-word keys, until a matching key or end. Condition on the complete challenge, but not H. Among m fixed distinct baby keys at most one equals the query. The expected number of inspected records is at most 1+(m-1)/B <= 5/4: the possible matching key contributes one and each other key collides with probability 1/B. No independence between collision events is needed. The sequence of query keys is fixed before H, so linearity of expectation applies to all k queries. For bounding aborts, consider the full unbounded search that performs all k queries even if it would have found an answer earlier. Early termination only reduces actual work. Neither adaptivity of chain order nor stopping at a matching key increases inspection count beyond the number of records in its bucket.

Keep the bounded local banks and explicit binary routing tree rather than assuming giant hardware addresses. The record pool uses 2^136 bytes and bucket array 2^133 bytes. Use local 2^30-byte banks; there are 2^106 record banks and 2^103 bucket banks, padded to 2^107 leaves, with tree depth 107. Each tree node has a local scalar processor, two child links and a parent link; requests carry a multiword logical page index and local offset. Local addresses fit 64 bits. A request follows the page-index bits and returns along the reverse path. Nodes are event-driven; inactive nodes do not poll. Sum every active processor's instructions and all transfers.

For each access, including full record retrieval/write, charge a nominal 2^20 instructions. This covers 109*(128*32+256)+2^17=605,440 instructions for transfer of the entire padded 1024-byte record, routing headers, round-trip control, local accesses and three-word addressing; bucket transfers are shorter but receive the same charge. It also leaves over 400,000 instructions for full-key comparison, signed exponent handling, local bookkeeping and meter debit. A record's next pointer is in the same retrieved record. No further memory access is hidden in chain traversal. Insertion's three accesses also cover generating/storing the entire new record and bucket index.

Hash plus inverse canonicalization costs at most 2^19 instructions per baby or giant key. Compute each matrix row product by AND/XOR over 72 words, then fold the 64-bit accumulator to one parity bit using six shift/XOR stages. Fewer than 128*(72*32+128)+2^14 <2^19 instructions suffice, including local matrix/key loads, loop control and canonicalization. Nothing uses arbitrary-width parity as one instruction.

Initialize all bucket entries and record slots locally, including every stored zero; four words per bucket and 128 per record require less than 2^136 instructions even at generous per-word loop charges. There are fewer than 2^108 tree nodes. Initialize at most 2^20 bytes of code/state/buffers per node at fewer than 2^30 instructions each. Tree and bank initialization, random sampling and controller setup together cost below 2^140 scalar instructions. All are charged to the nominal budget, not treated as free advice construction.

## Rigorous meter and success accounting

The nominal budget for all setup, randomness, hash/canonicalization, and table operations is capped at T=2^153 instructions. Before each bounded operation, debit its entire stated upper-bound charge. If it would exceed T, abort without executing it. Actual work for those operations is thus at most T even on a bad hash. The debit/control overhead is already included in each charge. No instruction-by-instruction free accounting oracle is assumed. If the metered algorithm aborts, the total nominal charge of its unbounded counterpart exceeds T.

Expected table accesses are at most 3m+(1+5/4)k=7.5*2^126, so expected access charge is below 2^149. Hash and canonicalization charge is (m+k)*2^19 <2^147. Initialization and coins cost below 2^140. Hence E[nominal unbounded cost] <2^149+2^147+2^140 <2^150, uniformly for every protected challenge. Markov's inequality gives Pr[budget abort] <1/8. This statement is over the fresh hash matrix and requires no probabilistic independence between queries.

Algebraic coverage is greater than (8/15)*(1-2^-127)>0.53 from the protected bound r<(15/16)*2^255. By a union bound, final success is greater than 0.53-1/8=0.405, in particular at least the claimed 0.4>0.39. No independence of coverage and abort events is needed; indeed the conditional abort bound holds for each challenge. Full-key equality and final pairing verification ensure that hash collisions can increase work or cause charged aborts, but cannot produce a false output. Outside coverage the algorithm fails, charging its arithmetic and all table operations. Every failure and every random coin is included.

## Total work, preprocessing and storage

The unmetered arithmetic consists of at most m+k=3*2^126 Fp12 multiplications. Using the explicit bitserial bound above, its cost is below 3*2^152 scalar instructions. The constant pairing/exponentiation/validation/output wrapper costs below 2^64. Everything else, including memory initialization and all hash/randomness work, is under the meter. Thus on every challenge and every coin outcome,
R < 3*2^152 + 2^153 + 2^64 < 2^155,
W=R/20,000 <2^141, since 20,000>2^14.
Preprocessing is at most m field multiplications plus the entire nominal budget and wrapper, less than 2^152+2^153+2^64<2^154 instructions, so below 2^140 equivalents; it is included in W and charged for this one target.

Record pool and bucket array total 2^136+2^133 bytes. All replicated node state is below 2^128 bytes. Matrix, keys, controller, field scratch and output use below 2^30 extra bytes. Peak is below 2^137 and hence below the claimed 2^139 bytes. The larger declared memory bound preserves slack. All hardware/storage is an analytic resource requirement, not a claim that this VM contains it. There is no nonuniform advice. Hash coins occupy the declared matrix storage, already included in memory and charged construction.

## Scope and verification

This package is proof-only and declares no computational experiments. No production attack was run and no full-size allocation was attempted. Its exact coverage, universal-hash collision proof, Markov bound and conservative accounting supply the evidence. It makes no empirical timing, novelty, practical feasibility, qualification or promotion claim. It uses the full production p and r and the exact supplied P. Exponential memory is a material limitation, disclosed rather than hidden as advice. Acceptance, if any, is the protected exploratory plausibility decision, not formal certification.
