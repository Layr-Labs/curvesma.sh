## Exact half-trace key and local cost

Use the native reference tower Fp2=Fp[u]/(u^2+1), Fp6=Fp2[v]/(v^3-u-1), Fp12=Fp6[w]/(w^2-v). Every element has a unique X=A+B*w with A,B in Fp6. The nontrivial Fp6 automorphism is bar(X)=A-B*w and equals p^6-Frobenius. The protected p,r satisfy p^6=-1 modulo r. Thus every GT element has bar(X)=X^(-1), including identity, and X*bar(X)=A^2-v*B^2=1.

Define the exact key J(X)=A, the first Fp6 half of the native representation. There is no need to compute a trace, negate B, select a sign or multiply by 2: A is already stored as six canonical base-field coordinates (36 words). It is half the trace, since X+bar(X)=2A. Copying this half needs at most 16*36+128=704 scalar instructions; reserve 1024, including initialized output bookkeeping. Preserve the entire raw X separately in local scratch for the dense update.

The fibers of J on GT are exactly {X,X^(-1)}. To prove this, suppose X=A+B*w and Y=A+C*w share J. Both have norm 1, so v*B^2=v*C^2. As v is nonzero and Fp6 is a field of odd characteristic, (B-C)(B+C)=0 implies C=B or C=-B. Hence Y=X or Y=bar(X)=X^(-1). Conversely inversion preserves A. For B=0 the two elements coincide; the proof still holds. This is an exact equality argument in the full production field, not a hash or statistical collision model. Every element generated and looked up belongs to GT because input validation establishes it and only GT operations follow.

Coordinates use canonical six-limb Montgomery residues with one fixed scale and basis. Equality of all 36 words is exactly equality of A. Multiplication remains a dense Fp12 reference operation on the full raw element. Input/output polynomial-to-tower conversion is fixed setup only. The half key does not need raw reconstruction or orientation recovery: the two scalar candidates in the centered algorithm below exhaust its proven two-element fiber.

The baby keys are distinct: equality means h^j=h^k or h^j=h^(-k); with j,k<m<r/2 only j=k (and the common zero exponent) permits this. For every a in this interval, one query matches its inverse-pair key and one tested scalar verifies. All verified outputs solve the actual supplied-P equation by bilinearity. ## Concrete finite dictionary

Use an ordinary preemptively split B-tree with minimum degree t=2^19 and maximum keys b=2t-1=2^20-1 per page. Every nonroot page has between t-1 and b keys; children are the ordered gaps between keys. The root may have fewer keys. Search compares the entire 36-word exact key and either returns its stored exponent or descends through its gap child. Leaf gaps report absence. There are no deletions.

Represent the sorted keys INSIDE each page by a local red-black tree over fixed-size records, with a separate descriptor for each external gap. Left/right/parent links are local indices, fitting 64 bits. Distinct gap sentinels carry their B-tree child descriptors; rotations preserve inorder gaps and therefore preserve B-tree semantics. A page has <=b records (384 MiB), <=b+1 descriptors (32 MiB), and bounded local scratch/code. For splitting, a temporary inorder copy of <=384 MiB also fits: 384+32+384 MiB plus <2 MiB control is <1 GiB. No enormous word-addressed global array is assumed.

Local red-black lookup has height <=2*log2(b+1)<=40. Insertion attaches a red key at its known external gap, then applies these standard cases while its parent is red: if the uncle is red, recolor parent/uncle black and grandparent red and continue there; otherwise rotate the inner configuration at the parent if needed, recolor the resulting parent black and grandparent red, then rotate at the grandparent. Make the root black. At most 40 iterations and two rotations suffice; rotations update a bounded number of local indices. This describes the balancing mechanism, not an oracle with an assumed expected height.

Before descending into a full B-tree child, split its 2t-1 keys around its median, giving two pages of t-1 keys and promoting the median into the nonfull parent. If the root is full, create a new root and split it first. Standard top-down insertion ensures every page receiving a promoted key is nonfull. Inorder-export the full page into local scratch, then rebuild each t-1=2^19-1 half as a perfect all-black binary search tree. This immediately satisfies the red-black invariant. Rebuild child-gap descriptors in the same inorder sequence. The parent's promoted key occupies the gap already located by the initial page search, so no second full key search is necessary; one comparison with the promoted median selects the next child. Serial operation preserves the saved gap position until insertion.

The B-tree invariants hold by these explicit median splits and gap-preserving rotations. With m<2^126 keys, a tree of seven or more edges would require at least 2*t^7-1>2^133 keys. Thus every search/insertion descends through at most SEVEN pages (at most six edges). All local comparisons are worst-case bounded; no probabilistic tree-balance premise is used.

## Binary routing and finite storage

Use the depth-108 binary fabric of the public deterministic routing control, with 2^108 leaves. Every controller has only two child directions and one parent direction. Each leaf supplies a 1-GiB locally addressed data bank plus bounded code/message scratch. An address is three 64-bit limbs containing leaf ID and local offset. Routing reads one destination bit per level and transfers a bounded packet to the selected neighbor, charging every hop. The total graph has <2^109 nodes/links. There is no high-fanout neighbor selector and no direct B-tree page-to-page communication edge.

B-tree pages occupy distinct leaves. At minimum occupancy their count is <=m/(t-1)+1<2^108. The B-tree root may remain in the coordinator's local bank when its content changes. Each child descriptor stores an ordinary three-limb destination and flags; it is a data address, not an additional physical link. Every page-to-page request travels through the binary fabric, up to 108 edges to the fabric root and at most 108 down, for <=216 hops. Replies use the same worst-case hop count. Sequential operation allows each page to retain its caller address in local scratch; no unbounded return stack must fit in a packet.

A forward packet contains at most 48 record words plus 16 header words, 64 words total. A reply contains at most 20 words, including header, status and exponent. Charge 16 scalar instructions per word per hop for all loads/stores, destination-bit extraction, neighbor selection, buffer clearing, route and acknowledgment control. A header alone supplies 256 instructions per hop; reading one of three address limbs, extracting a bit and bounded local route-state updates fit well below 128. Every transferred padding word is paid. All global address manipulation is multiword; local data and child-descriptor offsets fit ordinary 64-bit addressing.

For split-time bulk copies, a complete coordinator-to-leaf record read/write through the binary fabric costs at most 2*108*(16*16+64*16)+2048=278528<2^19 instructions. This charges request, record, acknowledgment and endpoint work. The looser 2^20 per-key split budget below covers this transfer together with local copies, descriptor writes and control. Other page-to-page messages are charged by their full <=216-hop length, not this special root path.

The material assumption is the same finite word/message interpretation as the public binary control: bounded scalar work per local link hop, with all processors' work summed. Physical distance, elapsed latency and network engineering are not extra objectives. This analytic claim does not provision exponential banks on this VM. If this explicit model is incompatible with the normative instruction measure, reject it rather than silently granting free remote addressing. The variant retains the earlier accepted binary topology throughout.

## Local instruction bounds and all split costs

A complete 36-word comparison costs <=16*36+128=704 instructions. A 48-word local record copy costs <=16*48+128=896. One page search uses <=40 comparisons (28160 instructions), <=128 extra instructions per visited red-black node for index arithmetic, gap/child reads and traversal (5120), and <=2048 fixed frame/descriptor/control instructions. Thus a query costs <=35328 instructions per page.

Across at most seven pages, add six forward and six return messages, each traversing at most 216 physical binary edges, plus 4096 coordinator instructions for key extraction, raw gamma preservation, center/counter arithmetic and loop control. One complete giant iteration excluding the separately charged dense multiplication is bounded by

 7*(40*704+40*128+2048)+6*216*(64*16+20*16)+4096 =1993216 <2^21.

Every failed query is charged this full bound, without averaging over favorable prefixes or targets. At most two terminal scalar candidates and output checks are fixed setup/finish work.

An ordinary insertion path, excluding bulk split work, uses <=2^16 instructions per visited page. Its 28160 comparison cost, 5120 traversal cost, <=40*128 recoloring/update work, two bounded rotations and <8192 additional page/gap/control instructions fit this cap. A promoted median occupies the saved gap, so no second full page search is needed. Across seven pages plus the same full binary paths and coordinator work the base is <=2204672 instructions. Allow an additional <2^20 instructions for child-fullness header checks/replies and ordinary control: up to six 16/20-word header exchanges at 216 hops cost 746496, within that reserve. Their combined path work is <2^22. Thus child-fullness information is not an uncharged remote read.

For a bulk split, allow 2^20 instructions per original key/associated gap. It covers inorder export, both perfect-tree rebuilds, local copies, gap/descriptor updates, routed remote record work (<2^19 on the coordinator path) and remaining control. There are at most 2^20 keys/gaps, so this part is <=2^40. Zeroing up to three 1-GiB banks, copying bounded code/control, assigning IDs and handling a root split costs <2^34 more. The whole split is therefore <=(65/64)*2^40 instructions. No physical B-tree neighbor links are constructed; its child pointers are routed addresses in the retained binary fabric.

Each split adds at least one live B-tree page, and there are no deletions. Since every nonroot page has >=t-1 keys, the number of splits is <=m/(t-1). The exact constants satisfy ((65/64)*2^40)/(2^19-1)<2^22. Hence summed split work is <2^22*m instructions. Fixed first-root allocation fits setup. Ordinary insertion paths add <2^22*m, yielding <=2^23*m non-reference instructions for the entire baby dictionary. This is aggregate cold work over every insertion and split, not a constant worst-case insertion assumption or expected-time estimate.
