# Deterministic full-range GT baby-step/giant-step

This is a classical analytic accounting control for the exact protected profile, not a practical attack or a claim of novelty. The attack uses no auxiliary powers, searched advice, random oracle, or heuristic. It returns a G2 point for the supplied G1 point. The claimed bound is W <= 2^145 dense-Fp12 reference equivalents, with C=20,000 scalar AArch64 instruction equivalents. Success is 1. Peak memory is at most 2^141 bytes; preprocessing is at most 2^144 reference equivalents, included in W. Nonuniform advice is absent (the max(1,bytes) reporting convention gives log2=0).

## Algebra and complete algorithm

Use the protected prime order r and field modulus p, and the public generator Q0. The reduced pairing is bilinear and nondegenerate on these prime-order groups. For every allowed P != infinity, g=e(P,Q0) has order r: writing P=bP0 with nonzero b, nondegeneracy gives e(P0,Q0) order r and exponentiation by b preserves order. No computation of b is used. Thus each allowed z has a unique a in [0,r) with z=g^a. This is precisely the input domain, including identity.

Set m=2^128. Since r<2^255, k=ceil(r/m)<=2^127. Form all m records (g^j,j) for 0<=j<m by sequential multiplication, starting at 1. Store elements in the protected polynomial coefficient representation with canonical residues. Sort the records lexicographically by the full canonical field-element encoding, using bottom-up mergesort and a second array. All baby powers are distinct, since m<r. Compute h=g^(-m) by binary powering modulo r. Initialize v=z. For i=0,...,k-1, binary-search the table for v. On a hit at j, set a=im+j, require a<r, construct Q=[a]Q0, verify e(P,Q)=z, and output Q. Otherwise update v=v*h. The loop uses at most k searches and k multiplications. The exponent exists: Euclidean division of its canonical a by m gives i<k and j<m, with z h^i=g^j. The first such hit is the correct a because a<r. If z=1, the j=0 record returns a=0 and Q=infinity; use the identity pairing convention. Success is exactly one for every valid input. No sampling or amplification is needed.

## Explicit conservative scalar arithmetic

Here is a deliberately slow implementation sufficient for the bound; no measured blst multiplication is assumed to cost one. Use six 64-bit words for each residue. Implement Fp multiplication by 381 iterations of modular double-and-add, scanning the bits of one operand. For each iteration double the accumulator modulo p and add either zero or the other operand modulo p. A modular addition takes six word adds with carry, six subtracts with borrow, a carry/borrow decision and a six-word selection. Allocate 256 scalar instructions for an addition, including source/destination accesses, loop/address control, and all carries. Both operands are canonical; their sum is <2p and fits six words because p<2^381, so one conditional subtraction suffices. Scanning a bit, selecting the operand and loop control take fewer than 128 additional instructions per bit. Therefore a field multiplication costs at most 381*(2*256+128)+1024 < 2^18 instructions. Field addition/subtraction each cost <=256; negation and equality have the same bound. This uses ordinary scalar word operations, not arbitrary-width unit costs. Stack and code storage fit below 2^20 bytes.

For Fp12 multiplication, use the polynomial representation specified in the target profile, not a conversion oracle. A schoolbook convolution has 144 coefficient multiplications and 144 coefficient additions. Reduce degrees 22 down to 12 using w^12=2w^6-2. Each of the eleven high coefficients contributes to two lower slots, via at most six modular additions/subtractions. Total is below 144*2^18+(144+66)*256 plus loop, indexing, copies and zeroing. Reserving a further 2^20 instructions covers that overhead: total <2^26 instructions per dense Fp12 multiplication. This is an upper bound for the actual algorithm, not a replacement reference price. Its normalized cost is strictly less than 2^26/20,000 <2^12 units.

Binary powers need fewer than 2L field multiplications for an L-bit nonnegative exponent; inversion in Fp uses exponent p-2 and costs <2^28 instructions. Fp2 arithmetic is two-component polynomial arithmetic and fits below 2^22 per multiplication. G2 scalar multiplication uses ordinary projective double-and-add and at most 510 point steps. A point step can alternatively use affine formulas with explicit Fp2 inversion; Fp2 inversion reduces to one Fp inversion and a constant number of Fp multiplications. Allow 2^40 instructions per point step, enormously above these formulas. All exceptional cases (identity, doubling, inverse points) are checked explicitly. G1 validation similarly uses affine formulas over Fp.

Pairing evaluation may use the direct reduced Tate pairing, normalized to the protected pairing if needed; to avoid relying on equality of conventions, instead evaluate the exact pinned optimal-ate definition using its field formulas. Its loop has fewer than 128 iterations; even a generic affine line computation with inversion, field evaluations, numerator/denominator updates and all exceptional checks is far below 2^40 instructions per iteration using the preceding polynomial arithmetic. The final exponent has fewer than 4572 bits, hence below 9144 Fp12 multiplications. Input parsing, group and GT checks, both pairing calls (initial g and final verification), exponentiation for h, G2 scalar multiplication, serialization, and any fixed initialization together fit below 2^64 scalar instructions. This also leaves more than 2^50 instructions for code and arithmetic setup. Constants come directly from the protected public profile; no construction of a lookup table is omitted. This deliberately coarse wrapper bound does not depend on a fast pairing implementation. The exact pinned pairing convention is essential; the algorithm does not substitute a Miller-loop value for its output.

## Full table work, including large addresses

Represent each record by 72 64-bit coefficient limbs and a 128-bit exponent padded to a 1024-byte record. Record size 1024 exceeds the required 592 bytes. Addresses for the entire computation fit 192 bits, so three-word addresses and counters suffice; arithmetic on these costs a fixed number of scalar word instructions. The abstract computation model permits the reported exponential storage; this is not a claim that this VM has that RAM. Every memory transfer is charged, as the rules require. A load/store at a three-word logical address can be understood as the usual addressed-memory instruction-equivalent model with multiword address formation charged; no whole large integer is processed as one word.

Comparing two keys scans at most 72 words. Copying a record transfers at most 128 words. Allocate 2^16 scalar instructions per merge comparison-plus-record-copy event including indexing, three-word address arithmetic, counters and branch control. A mergesort level performs at most m comparisons and at most m record copies; the 2^16 allocation covers both for each output record (use a separate copy event budget if the key comparison is skipped). There are exactly 128 levels. Hence sorting costs <=128*m*2^16 = 2^151 instructions. Table creation, allocation and initialization cost at most m*2^16 additional instructions besides field multiplications. Allocation means initializing the arrays and bookkeeping; memory transfers are not free and are included in these bounds.

Binary search takes <=129 key comparisons per giant step, each with <=2^16 instructions including all addresses and range arithmetic. Thus searches cost <=k*129*2^16 <2^151 instructions. Table lookup is deterministic over the full encoding, with no hash collisions, no probabilistic cost and no free dictionary oracle. Exponent reconstruction and bookkeeping fit within those budgets. Final output is constant size.

There are fewer than 2^129 sequential Fp12 multiplications in total for baby and giant steps. Their instruction cost is <2^155. Adding sorting, searches, table initialization, and the wrapper gives
R < 2^155 + 2^151 + 2^151 + 2^144 + 2^64 < 2^156.
Therefore W=R/20,000 < 2^142 < 2^145. The claim deliberately keeps three bits of additional slack and does not ask the reviewer to tighten the submitted score. Baby-table preparation including sorting costs <2^155/20,000 <2^141, so the stated preprocessing bound 2^144 is also conservative and is part of total W, not additional work amortized over other targets.

Two 1024-byte arrays of m records take 2^139 bytes. Code, input, output, field scratch, merge indices and bounded control storage fit below 2^30 bytes. Peak is below 2^140, hence below the claimed 2^141 bytes. No input-dependent retained randomness exists. Profile constants are public; no searched or external advice is used. Distributed parallelism is unnecessary and cannot reduce the summed-work claim.

## Scope and verification

This package is proof-only and declares no computational experiments. No production attack was run and no full-size allocation was attempted. Its deterministic algebraic proof and explicit conservative accounting supply the evidence. It makes no empirical timing, novelty, practical feasibility, qualification or promotion claim. It uses the full production p and r and the exact supplied P. Exponential memory is a material limitation, disclosed rather than hidden as advice. Acceptance, if any, is the protected exploratory plausibility decision, not formal certification.
