# Deterministic signed partial-range GT baby-step/giant-step

This is a classical analytic accounting control for the exact protected profile, not a practical attack or a claim of novelty. The attack uses no auxiliary powers, searched advice, random oracle, or heuristic. It returns a G2 point for the supplied G1 point. The claimed bound is W <= 2^143 dense-Fp12 reference equivalents, with C=20,000 scalar AArch64 instruction equivalents. Success is at least 1/2 over the protected uniform challenge distribution. Peak memory is at most 2^139 bytes; preprocessing is at most 2^142 reference equivalents, included in W. Nonuniform advice is absent (the max(1,bytes) reporting convention gives log2=0).

## Algebra and complete algorithm

Use the protected prime order r and field modulus p, and the public generator Q0. The reduced pairing is bilinear and nondegenerate on these prime-order groups. For every allowed P != infinity, g=e(P,Q0) has order r: writing P=bP0 with nonzero b, nondegeneracy gives e(P0,Q0) order r and exponentiation by b preserves order. No computation of b is used. Thus each allowed z has a unique a in [0,r) with z=g^a. This is precisely the input domain, including identity.

## Signed baby table and exact coverage

Set m=2^126, D=2m-1 and k=2^127. For a GT value v let inv(v) be its multiplicative inverse and let c(v)=min(v,inv(v)) in lexicographic order on the complete canonical coefficient encoding. Keep a sign t in {+1,-1} such that c(v)=v^t. Break the identity tie with t=+1.

In this protected polynomial model inversion on GT is inexpensive and exact. The defining polynomial is even and irreducible of degree 12. Thus w^2 has degree 6 over Fp: it lies in an extension of degree dividing 6, while adjoining its square root w has degree at most twice that degree and actually has degree 12. The p^6 Frobenius fixes w^2 and sends w to -w, since w is not in Fp6. It therefore negates exactly the odd coefficients. Since GT has order r and embedding degree 12, p^6=-1 modulo r (order 12 gives a nontrivial element of order 2 modulo the prime r). Hence v^(p^6)=inv(v) on GT. Computing inv(v) costs at most six modular negations; selecting the lexicographic minimum and sign uses at most 72 word comparisons plus copies. Charge 2^14 scalar instructions per canonicalization, including all local loads, stores and control.

Generate the m records (c(g^j),j,s_j) for 0<=j<m, where s_j is the canonicalization sign. Generate g^j sequentially, starting from 1, and sort the records by their full canonical keys. These keys are distinct: equality implies j=+j' or j=-j' modulo r, and 0<=j,j'<m, 2m-2<r forces j=j'. The sign and exponent fit in the existing 1024-byte record budget. No random hashing is used.

Compute h=g^(-D) by binary powering modulo r. Set v=z. For i=0,...,k-1, canonicalize v to obtain (c(v),t), and binary-search that key. A hit at baby record (j,s_j) gives epsilon=t*s_j and a=iD+epsilon*j modulo r. Reconstruct the canonical residue a by one conditional addition of r if the signed value is negative; positive values are less than r. Return Q=[a]Q0 only after checking the exact e(P,Q)=z. If no hit is found, replace v by v*h and continue. At loop end report failure. All loops and all failed challenges are included in the work bound; there is no free restart or amplification.

A hit is equivalent to a=iD+j or a=iD-j modulo r for some 0<=j<m. Each giant step therefore covers the consecutive integer interval [iD-(m-1),iD+(m-1)] of exactly D=2m-1 elements. Adjacent intervals are disjoint and touch consecutively, so all k steps cover exactly kD=2^254-2^127 consecutive integers starting at -(m-1). Their residues modulo r remain distinct because kD<2^254<r. Thus the exact success probability for uniform z is (2^254-2^127)/r for every fixed valid P. It is greater than 1/2: r<(15/16)*2^255 from its leading hexadecimal digits (0x73... < 0x78...), while kD>(15/16)*2^254 because 2^127<2^250. This is an exact counting argument, not an independence heuristic. The input P remains the supplied point. Identity z gives j=i=0 and Q=infinity. Every output is correct; uncovered inputs consume the bounded unsuccessful search and report failure.

## Explicit conservative scalar arithmetic

Here is a deliberately slow implementation sufficient for the bound; no measured blst multiplication is assumed to cost one. Use six 64-bit words for each residue. Implement Fp multiplication by 381 iterations of modular double-and-add, scanning the bits of one operand most-significant first. For each iteration double the accumulator modulo p and add either zero or the other operand modulo p. A modular addition takes six word adds with carry, six subtracts with borrow, a carry/borrow decision and a six-word selection. Allocate 256 scalar instructions for an addition, including source/destination accesses, loop/address control, and all carries. Both operands are canonical; their sum is <2p and fits six words because p<2^381, so one conditional subtraction suffices. Scanning a bit, selecting the operand and loop control take fewer than 128 additional instructions per bit. Therefore a field multiplication costs at most 381*(2*256+128)+1024 < 2^18 instructions. Field addition/subtraction each cost <=256; negation and equality have the same bound. This uses ordinary scalar word operations, not arbitrary-width unit costs. Stack and code storage fit below 2^20 bytes.

For Fp12 multiplication, use the polynomial representation specified in the target profile, not a conversion oracle. A schoolbook convolution has 144 coefficient multiplications and 144 coefficient additions. Reduce degrees 22 down to 12 using w^12=2w^6-2. Each of the eleven high coefficients contributes to two lower slots, via at most six modular additions/subtractions. Total is below 144*2^18+(144+66)*256 plus loop, indexing, copies and zeroing. Reserving a further 2^20 instructions covers that overhead: total <2^26 instructions per dense Fp12 multiplication. This is an upper bound for the actual algorithm, not a replacement reference price. Its normalized cost is strictly less than 2^26/20,000 <2^12 units.

Binary powers need fewer than 2L field multiplications for an L-bit nonnegative exponent; inversion in Fp uses exponent p-2 and costs <2^28 instructions. Fp2 arithmetic is two-component polynomial arithmetic and fits below 2^22 per multiplication. G2 scalar multiplication uses ordinary projective double-and-add and at most 510 point steps. A point step can alternatively use affine formulas with explicit Fp2 inversion; Fp2 inversion reduces to one Fp inversion and a constant number of Fp multiplications. Allow 2^40 instructions per point step, enormously above these formulas. All exceptional cases (identity, doubling, inverse points) are checked explicitly. G1 validation similarly uses affine formulas over Fp.

For pairing evaluation, evaluate the exact pinned optimal-ate definition using its field formulas. Its loop has fewer than 128 iterations; even a generic affine line computation with inversion, field evaluations, numerator/denominator updates and all exceptional checks is far below 2^40 instructions per iteration using the preceding polynomial arithmetic. The final exponent has fewer than 4572 bits, hence below 9144 Fp12 multiplications. Input parsing, group and GT checks, both pairing calls (initial g and final verification), exponentiation for h, G2 scalar multiplication, serialization, and any fixed initialization together fit below 2^64 scalar instructions. This also leaves more than 2^50 instructions for code and arithmetic setup. Constants come directly from the protected public profile; no construction of a lookup table is omitted. This deliberately coarse wrapper bound does not depend on a fast pairing implementation. The exact pinned pairing convention is essential; the algorithm does not substitute a Miller-loop value for its output.

## Full table work, including large addresses

Represent each record by 72 64-bit coefficient limbs and a 128-bit exponent padded to a 1024-byte record. Record size 1024 exceeds the required 592 bytes. Logical addresses and counters fit 192 bits, but no 192-bit hardware address is assumed. Use the following distributed binary memory tree. Each leaf holds at most 2^20 records, a 2^30-byte bank addressable by a local 64-bit processor. Across both arrays there are 2^107 leaves, attached to a binary tree of depth 107. For cost bounds below use 109 as a harmless upper bound on depth. Every internal node has a scalar processor, two child links and a parent link. Messages carry the logical page index and record offset. Each node reads the next path bit to route a request; the leaf accesses its local bank and returns a record along the reverse path. Processors are deterministic and event-driven, so no polling of inactive nodes is required. All processors' active instructions, initialization and transfers count. No uncharged parallel speedup is used: a controller can issue sequential requests.

A 1024-byte record is 128 words. Charge 16 scalar instructions for each word sent or received at an edge endpoint, plus 256 for header routing, control and offset computation per node visit. One full record routed over 109 edges, with both endpoints charged, costs at most 109*(128*32+256)<2^19 instructions. Requests and their headers add less than 2^17 instructions per access. Thus one record access costs less than 2^20 instructions. A mergesort event needs at most two record reads and one write; when implementing the merge, keep the two current input records buffered, so amortized per output record only one new input record is read and one output written, plus at most the two startup reads per run. Charge at most four record accesses per event, at a tighter per-access bound: 109*(4096+256)+2^17=605440. To avoid relying on that amortization for the numerical bound, use 2^22 instructions per merge output, including comparisons and all extra boundary/startup accesses. There are 126 levels and m records per level. Sorting costs <2^155 scalar instructions. Table initialization and tree setup cost <=m*2^22=2^148 instructions, including initialization of the record arrays and all node metadata.

Binary search takes at most 127 key comparisons per giant step. It fetches one table record per comparison and compares its 72 key words against the locally retained giant element. Charge 2^22 instructions per comparison including range arithmetic, all multiword logical addresses and routing. Hence searches cost <=k*127*2^22 <2^156 instructions. Exponent reconstruction and control fit within those budgets. Table lookup is deterministic over the full encoding, with no hash collisions, probabilistic cost, arbitrary-width instructions or free dictionary oracle. Final output is constant size.

There are at most m+k=3*2^126 sequential Fp12 multiplications for the baby and giant steps, including unsuccessful challenges. Their instruction cost is below 3*2^152. Canonicalization of each baby and giant element costs at most (m+k)*2^14<2^142 instructions, independently of whether the instance succeeds. Add sorting, lookup, initialization and the constant wrapper:
R < 3*2^152 + 2^155 + 2^156 + 2^148 + 2^142 + 2^64 < 2^157.
Since 20,000>2^14, W=R/20,000 <2^143. All signed exponent arithmetic and key comparisons fit the existing control budgets. Baby preprocessing costs less than (2^152+2^155+2^148+2^141)/20,000 <2^142 and is included once in total computation. Field arithmetic is local; all remote table and metadata transfers are explicitly charged.

The two arrays occupy 2^137 bytes. There are fewer than 2^108 routing nodes; their replicated code and buffers at 2^20 bytes each use below 2^128 bytes. Inputs, controller and arithmetic scratch use below 2^30 extra bytes. Total memory is below 2^138, and in particular below the claimed 2^139 bytes. Node initialization below 2^30 instructions each is within the table-initialization budget. Nonuniform advice and retained randomness are absent. The exponential distributed memory requirement is an analytic resource bound, not hardware present on this VM. All active processors and routed word transfers contribute to summed computation, with no elapsed-time speedup assumed.

## Scope and verification

This package is proof-only and declares no computational experiments. No production attack was run and no full-size allocation was attempted. Its algebraic coverage proof and explicit conservative accounting supply the evidence. It makes no empirical timing, novelty, practical feasibility, qualification or promotion claim. It uses the full production p and r and the exact supplied P. Exponential memory is a material limitation, disclosed rather than hidden as advice. Acceptance, if any, is the protected exploratory plausibility decision, not formal certification.
