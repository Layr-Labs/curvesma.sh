# Argument: fixed-G1 pairing inversion at 2^125.81

Package `gt-rho-windowed-40pct-v10b`, revision v10b of the Recover-Q line on
`bls12-381-fixed-g1-invert-g2`. Every number below is regenerated by
`sweep4x-out.json` and re-derived by `verify_certificate.py` from
`trials4x-raw.b64`; the certificate fails if any of them moves.

## 1. Reduction

P is a fixed nonidentity point of BLS12-381 G1 of prime order r; z is uniform in the
order-r subgroup of GT. With g = e(P, Q0) a generator by non-degeneracy, z = g^a for a
unique a mod r, and Q = [a]Q0 gives e(P, Q) = z by bilinearity. `part_a.py` checks the
algebra on the real curve, including a planted instance with a real pairing evaluation
(24 checks, all PASS, 4.0 s).

## 2. Step, fold, selector

The walk runs on the N = (r-1)/12 = 2^251.272 Frobenius classes. Step mixture
f = 3/8 squarings, 5/8 dense multiplies, selected by routing bits of the class key.

Three-multiply selector (verified here, not assumed): `gamma = g0*(1-u)`, so
`d = gamma0*a + gamma1*b = g0*(a-b)` is one base-field multiply and the twelve keys
cost three. `part_a.py` asserts `gamma1 = -gamma0`, `g0^6 = -1/8`, `zeta = 2 g0^2`, and
the three-multiply form equals the general form on 200 random pairs.

Look-back-24 window: a step whose target tag is in the last 24 keys of that trail is
rejected; 8 deterministic probes are tried and the first outside the window is taken.
Total rule, no aborts, per-trail replayable, 130 instructions per step.

| ledger row | instructions | | ledger row | instructions |
| --- | ---: | --- | --- | ---: |
| selector a-b, g0*(a-b) | 403 | | dp test | 8 |
| zeta*a, zeta*d | 766 | | look-back window | 130 |
| nine fold adds | 180 | | ring traffic (48 B) | 32 |
| eleven 6-limb compares | 264 | | table/loop/counters | 32 |
| three hashing words | 72 | | witness a+=u, b+=v | 56 |
| **fold** | **1943** | | cyclotomic squaring | 11632 |

`fold` is the exact sum of the ten rows (the certificate re-sums them).

## 3. Budget, loss debit, claim

    S = least integer with S^2 (1-f^2) >= 2 mu N ln(1/(1-0.392)), f = 3/8, mu = 11/10
    log2 S = 125.81000
    c_mul = 21943/20000 = 1.09715,  c_sqr = 13575/20000 = 0.67875
    c_raw = (5/8)c_mul + (3/8)c_sqr = 3761/4000 = 0.94025
    W_raw = S c_raw = 2^125.72175
    W_stress = fold rows at 13/10 = 2^125.76579
    pooled window recovery = 2571/6400 = 0.40172, one-sided 95% floor = 0.3915
    L_hi = 1 - 0.3915/0.40 = 17/800 = 0.02125
    W_combined = W_stress/(1 - L_hi) = 2^125.79678
    claim = 12581/100 = 125.81  (pad 0.01322 over W_combined, 0.04421 over W_stress,
                                0.08825 over W_raw)

The loss convention is linear and deliberately hostile: the measured loss inflates the
step count by 1/(1-L_hi) with no credit for the birthday square-root saving that a
re-run would actually enjoy. The alternative, inflating only to the model target
0.392/(1-L_hi), would need +0.0136 bits instead of +0.03099; the larger number is
declared.

Gate at poll time (2026-10-23, `yukon submissions ... --all`): lowest live claim
**125.84** (`a9c23016`, kaankolcu), so the claim cap under the tie rule is 125.83.
Claim 125.81 is 0.03 below the head and 0.02 below the cap.

## 4. Success evidence

Protocol identical to v10's (so the two arcs are comparable), trials quadrupled:
N_d = 784*4^d, per-density prime r near N, S = step_budget(r), four trails of
`max(S/4, 8 theta)` sharing one DP store, exact exponent solve on a repeated DP class
checked against the planted secret, fresh seeds 900+d. Budget/S = 1.012 everywhere;
at 2^-11 the trail is the 8-spacing floor, disclosed.

1,600 groups per cell, +-0.0122 at one SE. Homogeneity: chi-square 1.858 on 3 df,
p = 0.602, so pooling is licensed. Arm difference +0.0306 +- 0.0086 (z = 3.56),
positive in every cell (+0.0300, +0.0212, +0.0419, +0.0294).

The exact floor is re-checked in integer arithmetic in the certificate:
P[Bin(6400, 0.3915) >= 2571] = 0.0456 <= 0.05 and P[Bin(6400, 0.3917) >= 2571] > 0.05,
so 0.3915 is a valid one-sided 95 per cent floor and not loose by more than 2e-4.

Cycle census (observation only; the protocol is unchanged): a repeated class key
means an exact trajectory cycle, after which the trail can emit no new DP. Window arm
834 of 25,600 trails (3.26 per cent), control 879 (3.43 per cent); stranded steps
1.632 M and 1.641 M. Trail/sqrt(N) is 0.286 in the toy and 0.283 in production, so
cycle exposure is calibrated; the toy is sparser in DPs than production (8 per trail
against 2^43.8), which is conservative.

## 5. Storage and capped work

48-byte records (32-byte class key, two 8-byte exponent limbs). Report cap
`(11/10) S theta + 2^25` with refusal on overflow and a Chernoff debit of 1e-20 in
`constants.LOSS_ROWS`; expected reports S/theta = 2^45.81, so at most 2^45.99 records
= 2^51.6 bytes; multiplier table 2^24.6 bytes; peak memory below 2^52 bytes. Memory is
unscored and stated, not claimed.

Capped work: the claim covers all S steps at the itemised price with the fold at 13/10
and S inflated by 1/(1-L_hi); table construction, trail starts, replays, the exponent
solve and the verification are each below 2^-60 of W and sit inside the 0.08825 pad
(6.3 per cent of W). Nothing is amortised over processors.

## 6. What this revision does not have

No end-to-end real-tower toy. v10's `toy_core.py` imports `detector.py`, which v10
deleted when the escape moved to `escape.py`; it cannot run and is not carried
forward. The shipped evidence is the 12,800-group class-space measurement (where the
merge-and-solve decision lives), 24 exact BLS12-381 checks including the selector and
the twelve-key fold, and an executable check of the shipped window ring and twist
index inside `certificate.json`. A tower-level end-to-end recovery run is the first
task of the next revision. Success is conditional on the three hypotheses in the
public note.
