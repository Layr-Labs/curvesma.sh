# Concrete finite local-word storage implementation

This is an analytic scalar-instruction implementation,not a proposal for a new extended-address instruction. It replaces the unsupported97-bit bank latch from unpublished Toom21. It uses the ordinary finite word/message-storage construction explicitly described by published f00694ca-67df-4231-b803-8825a49ef896,with all implementation and construction costs charged here. Physical storage need not fit the review VM for an analytical challenge. All actual operands/pointers are64-bit;the global ID is only a pair of data words.

## Topology and ordinary address maps

A complete depth3 tree has fanouts2^29,2^34,2^34,exactly2^97 leaf processors and fewer than2^98 total processors. Each processor has the same scalar AArch64 instruction set. Every leaf has data RAM[2^40,2^41);code/private/page-table storage occupies at most1MiB below2^40. Each edge is one4096-byte shared mailbox page,ordinary coherent RAM mapped into BOTH endpoint processors' address spaces. The parent's page for child j is2^43+(j<<12);the child's corresponding parent page is2^42. No arithmetic is performed by this page. Highest child port end is2^43+2^46<2^47. Leaf RAM end2^41,parent port2^42,child ports2^43... are disjoint. Standard local page table mapping aliases the SAME physical mailbox words,not a virtual97-bit dereference. Logical processor labels/topology are finite combinatorial design,not secret or searched advice. Code replication,descriptors and mailbox initialization are paid below.

The mailbox halves are request2048 bytes and reply2048 bytes. Header4 words:IDlow,IDhigh,offset40,op/length. Payload at most130 words1040 bytes;header+payload1072 bytes leaves976 bytes for flags and control. Only initialized request/reply words are read. Root retains pending continuation locally. One RPC globally in flight;each node retains its parent continuation until child returns. This is a sequential depth-first message schedule,not a race or speculative lookup. Routing all97 bits takes exactly3 edges each way.

To compute child IDs from pair(lo,hi):level0 child=hi>>4 (29bits);level1 child=EXTR(hi,lo,34)&((1<<34)-1);level2 child=lo&((1<<34)-1). Thus each child index fits34bits. Port calculation LSL12+ADD2^43 is64-bit ordinary arithmetic. The high-word bound<2^33 follows from ID<2^97. Offsets are checked<2^40,oplength fixedpublic,then ADD2^40 produces local endpoint pointer. Two-limb ID formation uses native shifts,EXTR,AND,ADDS/ADC;root construction<=64 instructions with ample room for all fields. No ID requires multiplication of two97-bit operands.

## Message code and exact instruction budgets

Fixed lengths N={0,2,8,32,128,130};there are only six unrolled payload handlers. Every copied pair of words is two ordinary instructions: LDP x9,x10,[incoming,#8i];STP x9,x10,[outgoing,#8i]. Offsets through1072 fit AArch64 pair-immediate signed504 limit only after rebasing:use pointer base advanced by512 at fixed boundaries. For130 words,two fixed ADD instructions per source/destination boundary suffice;these are in the nonpayload ledger below. Headers use the same pair load/store form,not a bulk transfer. At the first/last endpoint local record loads/stores are separately counted,so none is hidden in transport. Count increments/fetch-increment operations execute leafLDP,ADDS/ADC,STP,charged in original endpoint budgets. No remote arithmetic primitive exists.

For a message crossing an edge,a pair store by sender and pair load by receiver costs2 instructions for2 words. In a forwarded chain the received pair immediately feeds the next pair store;only two data registers are needed. A READ sends header down3 edges and header+N data back3 edges;WRITE reverses data direction. Hence payload3N instructions and headers3*8=24. Both request and reply header words are explicitly copied on every edge. All padding actually transmitted is included in N;no N=130 padding beyond1040bytes is transmitted.

For EACH directed hop allow128 OTHER scalar instructions,total across sender+receiver,excluding payload/header copies:
12 continuation/register saves;16 header decode/type/length/offset validation;16 two-word bank extraction/child checks;16 local port/record address formation and dispatch;24 ready/commit/ack/barrier state;12 restores/return control;16 continuation scheduling/control handoff;16 spare including fixed payload base rebases. Sum128. All operations are fixed-word arithmetic,loads/stores,branches,barriers or exception/continuation dispatch. There is one active request/reply path. Inactive processors perform no algorithm instructions;this is serialized work counting,not a charge-free polling loop. Every ready check is performed at its scheduled handoff after the sender writes;no speculative busy polling or retries. The analytical schedule explicitly invokes the next local handler at that shared-message handoff,with its16 scheduling instructions charged. This is the standard bounded-word communication convention of f006;no latency/bandwidth/energy objective is substituted for instruction work. If such ordinary processors/shared-word links are disallowed by the protected model,the claim fails rather than silently recovering the bank latch. There is no extra assumption of arbitrary remote-memory address selection.

Thus six directed hops cost6*128+24=792 fixed;R(N)=3N+792. Root request construction64 replaces the32 budget already present in the old per-access ledger;add32. Leaf resident comparisons/copies/mutations are paid separately. Confirmation lengths and counts are capped in proof.md;all failed fingerprint cases use the same packets. Packet corruption/faults are outside the ordinary deterministic RAM machine model,as for resident loads/stores.

## Consecutive-record batch handlers

N128 uses exactly the same unrolled pair-copy sequence as N130 truncated by one final pair. It has no new transport primitive. Four payload records or sixteen metadata records make exactly128 words;header stays four words. The existing2048-byte request/reply halves suffice. The caller supplies one leaf ID and aligned local start offset;it does not request multiple addresses,sorting or vector arithmetic from a controller. READ copies1024 initialized contiguous bytes,WRITE stores1024 supplied bytes. All actual pair loads/stores are counted in R128=1176 plus resident endpoint budgets. The parent/child route is chosen once per bounded packet,not once per record. Scatter/count targets remain individual messages because they are not consecutive. Complete batch formation,boundary alignment and final initialized padding are proved and charged in proof.md.
