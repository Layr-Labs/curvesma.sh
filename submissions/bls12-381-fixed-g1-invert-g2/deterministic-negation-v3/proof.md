## Exact key and local cost

Use the native reference tower Fp2=Fp[u]/(u^2+1), Fp6=Fp2[v]/(v^3-u-1), Fp12=Fp6[w]/(w^2-v). Write X=A+B*w with A,B in Fp6. The nontrivial Fp6 automorphism sends X to bar(X)=A-B*w. It equals p^6-Frobenius, since this is a quadratic field extension. The protected integers satisfy p^6=-1 modulo r (checkable by six modular multiplications), so every order-r element satisfies bar(X)=X^(-1). This includes identity. Neither a subgroup reduction nor a replacement challenge point is being made.

All tower coordinates use canonical six-limb Montgomery residues. The scale and field basis are fixed and invertible. Define K(X) to be the lexicographic minimum of the full 72-word arrays for X and bar(X). Then K(X)=K(Y) if and only if Y=X or Y=X^(-1). This follows because the two-element sets are either disjoint or identical; selecting one member cannot identify distinct such sets. No hashing, lossy fingerprint or heuristic collision claim is present.

Compute bar(X) by negating exactly the six base-field coordinates in B, preserving A. For one canonical Montgomery residue t, use p-t if t is nonzero and zero otherwise. Six-limb subtraction, zero testing and conditional selection fit below 128 scalar instructions per coefficient, including loads and stores. Six such negations, a full 72-word comparison and full record movement use below 8192 instructions. Charge 8192 instructions for this local key computation, within the generation and giant local budgets below; it needs no dense multiplication or inverse exponentiation. Keep the raw X separately in local scratch so canonicalization does not change the iterated walk value. Copies and all zero cases are paid. Fixed conversion of the public inputs to/from the native tower is setup, not a per-sample operation.

## Centered BSGS algorithm

Validate P,z as in the protected profile, including nonidentity P and subgroup checks. The identity z=1 returns canonical G2 infinity after verification. Otherwise compute h=pairing(Q0,P), using the pinned G2-first library call. Nondegeneracy makes h a generator of GT for every allowed supplied P.

Let m=2^125, S=2m-1=2^126-1, H=ceil(r/S). The exact protected r satisfies r<2^129*S, so H<=2^129. Generate raw h^j for j=0,...,m-1 by repeated dense multiplication. Store 80-word (640-byte) initialized records: 72 words K(h^j), two words j, six zero padding words. Do not replace raw h^j by its key before multiplying by h. Sort all records by their complete keys with bottom-up merge sort, two full arrays and 125 passes. No two baby keys coincide: if h^j=h^(-k), then j+k=0 modulo r; with 0<=j,k<m<r/2 this requires j=k=0.

Let centers c_i=m-1+iS. Compute gamma=z*h^(-(m-1)) and D=h^(-S), using binary exponentiation modulo r in setup. For i=0,...,H-1, compute K(gamma) locally and binary-search the sorted array. On a match j, try x=(c_i+j) mod r and x=(c_i-j) mod r, verifying h^x=z. At least one is correct. For a verified scalar construct Q=[x]Q0, validate G2 membership and verify the full pairing(Q,P)=z before serializing the exact G2 output. The identity gamma matches j=0. If no key matches, update gamma=gamma*D and continue. All at most two terminal scalar/pairing attempts are charged in setup/finish.

## Deterministic success on the complete input distribution

For every integer i, the exponents c_i-j and c_i+j for 0<=j<m fill every integer in the interval [iS,(i+1)S-1]. The intervals are adjacent with no holes: the low endpoint is c_i-(m-1)=iS; the high endpoint is c_i+(m-1)=iS+2m-2=(i+1)S-1. Since H*S>=r, these intervals cover every a in [0,r). For z=h^a, at its interval gamma=h^(a-c_i)=h^(j) or h^(-j) for some baby j, so the exact inverse-orbit key is found. A match always implies one of the two tested exponents is a modulo r, even at a wraparound boundary. Thus h^x=z and bilinearity gives pairing([x]Q0,P)=z for the actual supplied P. Success is 1, not an estimate derived from toy experiments or a random walk model. No random coins are needed.

## Finite storage and transfer convention

The storage requirement is enormous and cannot be allocated on this VM. The challenge permits analytic arguments for exponentially large attacks. This is a finite abstract classical computation, not a claim that the current physical machine has the attack's storage. In particular, a 64-bit register is never assumed to hold a 140-bit address.

Each logical address has three 64-bit limbs. Realize storage as a binary tree of routing controllers and leaf banks. A leaf bank holds at most 2^30 bytes with ordinary 64-bit offsets. Both arrays together contain 1280*2^125 <2^136 bytes (and in particular <2^138); fewer than 2^108 leaf banks suffice after rounding. Choose a padded complete tree with 2^108 leaves and depth 108. Reserve code, controller state and messages separately below. Controllers route one bounded record or comparison request down and back along its three-limb address. Only a constant number of requests need be in flight, as the whole algorithm can be serialized. Work is summed over all controllers; distributed storage does not give free computation or a parallel speedup.

For one complete record move or a comparison of two remote records, charge T=2^19 scalar instructions. For a comparison between a root-resident query and one remote record, charge B=2^18. A message header is at most 16 words; a complete record plus header is at most 96 words. Each hop is charged 16 instructions per word for loads, stores, addressing, link/control and acknowledgments. A header path of depth 108 therefore costs 108*16*16=27648 instructions. A record path costs 108*96*16=165888. All messages are bounded and all routing work is included in these word costs. No physical-distance or elapsed-time discount is used.

A record read consists of a header request going down and a record coming up: 193536 instructions. A record write sends a record down and receives a header acknowledgment: another 193536. Together, reading a source and writing a destination cost 387072 instructions; 10000 additional endpoint instructions for local copying, address calculation and control leave 397072<524288=T. A comparison of two remote records can instead read both to the root (also 387072) and compare there, within the same T. Sorting may use this fully paid conservative path.

A giant-search comparison starts with its query already resident at the root. Send that complete query to the selected leaf, compare its full 72-word key locally, and return a result plus header (at most 17 words). The path work is 108*(96*16+17*16)=195264. Adding 10000 endpoint instructions gives 205264<262144=B. The leaf need not return its complete record merely to report order or equality. On the one successful match the exponent retrieval uses the separate T allowance within the giant budget. Sorting, however, is not charged the cheaper B for two operands that are both remote.

Initialization, clearing message buffers and endpoint comparison/copy work are covered by the 10000 endpoint reserve and separate tree construction allowance. Header and full-record costs are counted even for losing comparisons; no early-out savings are assumed. Leaf-resident data accesses stay within 64-bit offsets. Three-limb global addresses are routed explicitly.

This is a conventional finite word/message-storage model, not a measured device implementation. Its material limitation is physical realizability at this scale. The argument assumes links transmit a bounded word with bounded scalar work as above, with no additional distance-dependent energy or latency objective. Latency is not the score. If the normative instruction model disallows any such banked storage, this candidate should be rejected rather than silently treating addresses as single words. The claimed bound includes the concrete routing depth instead of asserting free memory switches.

## Complete work and exact cap certificate

Use T=2^19 instructions for a record move/two-remote-record comparison, and B=2^18 for a resident-query/remote-record comparison. Local canonicalization is <8192 instructions, below either. Generation costs m dense multiplications plus 4T*m instructions, including the exact key, zero-padding, writes and retained raw element. Each of 125 merge passes costs <=4T*m (one comparison, two moves and one extra T for run/address control per record). Hence generation and sorting are <=504T*m.

Binary search of the m=2^125 baby table needs at most 126 comparisons; conservatively charge 128B. A giant iteration has 134B instructions in total. Its remaining 6B=3T budget covers one index retrieval costing T, local key and raw-gamma preservation below B, three-limb midpoint/center/counter arithmetic, loop control and copying below B, with at least T spare. Every failed search, both key orientations and losing comparisons are paid. Raw gamma updates use one dense reference multiplication each. Setup pays the at most two terminal scalar verifications and output reconstruction.

Therefore

 Wmain <= m+H + [504*m*2^19 + 134*H*2^18]/20000.

Here m=2^125, H=ceil(r/(2^126-1)), with the complete protected r. The exact-integer total certificate, including the setup/tree/array initialization allowance below, is

 20000*(m+H)+504*m*2^19+134*H*2^18+2^140+2^129+2^100 < 20000*2^141.

No decimal floating-point value is needed for that inequality. As a diagnostic only, log2 of its left side divided by 20000 is about 140.239328; the submitted score is the more conservative rational 141/1. All main work is nonnegative, so all preprocessing is also below 2^141 and is included rather than amortized. The key and table have no random, hashing or mixing assumptions.

## Setup, representation, output, bank construction

Charge 2^100 scalar instructions for all fixed-size field conversions, canonical encoding validation, P and z subgroup tests, the initial pairing h, stride inversion, final scalar multiplication in G2, output subgroup test, final pairing and serialization, as well as code and constant construction. This extremely conservative bound is justified by elementary bit arithmetic: at most 381-bit base residues, at most 4572-bit field exponents, 12-coefficient polynomial arithmetic and standard projective or affine curve formulas. A 384-bit modular multiplication implemented by shift/add with one bit per byte uses fewer than 2^32 scalar instructions; exponentiation uses fewer than 2^14 such multiplications for the exponents here. Polynomial convolution uses 144 base products and fewer than 256 additions per extension multiplication. G2 uses quadratic arithmetic with u^2=-1. An affine inverse uses binary powering by p-2; a scalar multiplication has at most 510 additions/doublings. A Miller pairing has fewer than 128 loop iterations, each expressible with fewer than 2^16 base/extension operations, and final exponentiation fewer than 2^14 extension multiplications. Even multiplying all these loose upper bounds is below 2^100. Exceptional curve additions test infinity, opposite points and zero doubling denominator before division. These are fixed bounded computations, not exponentially repeated setup hidden under an asymptotic symbol.

For memory construction, initialize both complete arrays (at most 2^138 bytes) by word writes with at most 32 instructions per word, costing <2^140 instructions. Each of the fewer than 2^109 routing tree nodes receives at most 2^20 instructions of initialization, costing <2^129. Code replication at tree nodes is included in the storage/initialization allowance, not uncharged advice. Add all three budgets: (2^140+2^129+2^100)/20000 <2^127 reference equivalents. The exact total inequality above includes this allowance before comparison with 2^141. The submitted score is the upper cap 141 unchanged; it is not a decimal estimate of an exact optimum. Preprocessing including table generation and sorting is a subset of the fully charged total, so preprocessing_log2=141 is valid. It is never amortized across later targets.

Peak storage is bounded by the two arrays <2^138 bytes, routing nodes fewer than 2^109 each with <=2^20 bytes of code, message and scratch capacity (<2^129 bytes), and <2^30 bytes of coordinator code, arithmetic scratch and public constants. Their sum is below 2^139 and therefore below the declared 2^145 bytes. There are no searched embedded constants, precomputed answers or nonuniform advice. Randomness use is zero.
