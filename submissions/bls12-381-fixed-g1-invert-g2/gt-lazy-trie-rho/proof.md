# Frobenius-class rho in GT with lazily evaluated steps: a prefix-product trie, a 4,964-instruction key kernel and one full multiplication per six steps

**Claim.** For uniform nonidentity P in G1 and uniform z in GT the algorithm below recovers Q in G2 with
e(P,Q) = z with probability at least 0.39, using at most **2^124.205** dense-Fp12-multiplication equivalents
(C = 20,000 instructions), including setup (the multiplier table and the prefix-product trie), the two pairings,
walk starts and the fresh start of every trail, distinguished-point (DP) handling, fruitless-cycle escapes, the
DP detection delay, matching (sort, duplicate removal, replay of matched trails, pair checks), output and
verification. Peak memory is below 2^62 bytes; preprocessing (included) is at most 2^49.06 units; nonuniform
advice 0 bytes. The success bound rests on three disclosed heuristics, none of them proven: the usual
random-mapping heuristic for rho walks (H1), pseudorandom bits of the class key (H2), and whole-run concentration of
the run's counts (H1+, charged as a flat 0.01 of success, as in the parent 0b8665ae). The success probability is
computed in the ideal model in which the ChaCha20 stream that supplies the table and start scalars is an ideal
random source (also disclosed; no distributional bound on the realized scalars is claimed). No production-size run is claimed.

## 0a. Representation: which limbs the rule reads

As in the parent, an Fp value is held as the six-limb Montgomery vector x~ = x 2^384 mod p, fully reduced in [0, p),
and the rule is stated on these stored limbs: the twelve keys are the stored residues of section F2 (linear
operations commute with the Montgomery map, so stored keys are the Montgomery images of the integer keys and
their multiset is again Frobenius-invariant), K is their minimum as 381-bit integers, kappa the first index (in the
kernel's fixed order) attaining it. The rule on stored limbs is the integer rule composed with a fixed bijection
of Z/p, so every structural property used below carries over (the parent's section 0a). `lazy.s` and `root.s`
return exactly the stored a, b, B, a zeta, B zeta, K of the current element (part K and part C check this against
a big-integer reference, including keys from explicit Frobenius maps).

## 1. Reduction

Compute g = e(P, Q0) with the pinned convention pairing(Q0, P), where Q0 is the fixed G2 generator. P has prime
order r and the pairing is nondegenerate, so g != 1 generates GT (prime order r) and z = g^x for a unique x in
[0, r). Find x, output Q = [x]Q0 and check e(P, Q) = z; by bilinearity e(P, [x]Q0) = g^x = z. If z = 1 output
Q = infinity (the only valid answer then). The answer is for the supplied P.

Everything after this step sees only the pair (g, z). For uniform nonidentity P, g = e(P, Q0) is a uniform
generator of GT (P -> e(P, Q0) is a bijection from G1 \ {O} onto the generators), and z is uniform and independent
of P, exactly the distribution of (g, z) in the mirror track bls12-381-fixed-g2-invert-g1 (g = e(P0, Q) for uniform
nonidentity Q). The walk, its success analysis and its ledger therefore apply unchanged; only the output scalar
multiplication moves from G1 to G2 (its price is bounded in section 5).

## 2. Arithmetic facts (checked in `experiment.py`, parts A, K, C)

Tower: Fp2 = Fp[u]/(u^2+1), Fp12 = Fp2[w]/(w^6 - xi), xi = 1+u (blst's tower; with u = w^6 - 1 it is the
profile field). y = sum_{m<6} y_m w^m with y_m in Fp2.

**F1 Frobenius classes.** p has order 12 modulo r, p^6 = -1 and 1 + p^4 + p^8 = 0 (mod r), so y -> y^{p^k} is a
group of order 12 acting on GT and containing inversion. Every y != 1 lies in a class of exactly 12 elements;
N = (r-1)/12 classes, log2 N = 251.27213.

**F2 Keys (the parent's).** zeta = xi^{(p^2-1)/6} is a primitive sixth root of unity in Fp, d_1 = xi^{(p-1)/6}.
With c_1 = a + b u the w^1 coefficient of y and B = a Re(d_1) + b Im(d_1), the Re(w^1 coefficient) of y^{p^k} is
a zeta^j (k = 2j) and B zeta^j (k = 2j+1), j = 0..5; as zeta^j runs through 1, zeta, zeta - 1, -1, -zeta, 1 - zeta,
the twelve keys are a, a zeta, a zeta - a, -a, -a zeta, a - a zeta and the same for B. K = min of the keys is a
class invariant; kappa = argmin, and y^{p^kappa} is the same element for all 12 members of the class (the
canonical representative). The keys are distinct unless two coincide by a linear accident (at most 66/p per
element) or a or B is 0 (then a key p - 0 = p is formed; at most 2/p per element); both are charged as failure
(section 4).

**F5 Lazy key (new).** For x, Pi in Fp12, the w^1 coefficient of x * Pi is
`c_1(x Pi) = x_0 Pi_1 + x_1 Pi_0 + xi (x_2 Pi_5 + x_3 Pi_4 + x_4 Pi_3 + x_5 Pi_2) = sum_{k<6} x_k gamma_k`,
gamma_0 = Pi_1, gamma_1 = Pi_0, gamma_k = xi Pi_{7-k} (k = 2..5), because w^6 = xi and only the products
w^i w^j with i + j = 1 or 7 contribute to w^1. So a = Re c_1 and b = Im c_1 of the current element y * Pi_nu are
Fp-bilinear in (y, gamma(Pi_nu)): with the Karatsuba sums
`S0 = sum_k x_k.re g_k.re, S1 = sum_k x_k.im g_k.im, S2 = sum_k (x_k.re + x_k.im)(g_k.re + g_k.im)`
(all exact non-negative integers below 6p^2, 6p^2 and 24p^2), **a = S0 - S1** and **b = S2 - S0 - S1** modulo p. b
is exactly sum_k (x_k.re g_k.im + x_k.im g_k.re), a non-negative integer below 12p^2, and S0 - S1 + 6p^2 lies in
[0, 12p^2); both are below 2^768 and one Montgomery reduction gives r < 12p^2/2^384 + p < 2.2p, inside the q-table
subtraction of `gen.py` (r < 8p). Then B, a zeta, B zeta, the keys and K follow F2.

**F3 Cyclotomic squaring (escapes only).** The Granger-Scott map of the parent (`kernels/sqr.s`, 6,777).

**F4 Orders.** r - 1 = 2^32 * 3 * 11 * 19 * 10177 * 125527 * 859267 * 906349^2 * 2508409 * 2529403 * 52437899 *
254760293^2 (checked); ord_r(2) = (r-1)/16, so 2^t lies in <p> only for t a multiple of about 2^247.3.

## 3. Algorithm

Parameters: **R = 24** table multipliers, **trie depth L = 6**, DP density **theta = 2^-72**, M = 2^20 walks
round-robin on one processor (chunk K = 2^63 steps; proof-impl.md 0-i), report cap 2^55, restart cap 2^36.

**Table.** M_h = g^{a_h} z^{b_h} for h < 24 with fresh uniform a_h, b_h mod r from the sampler (0-iv), and the
twisted entries T[h][t] = M_h^{p^t}, t < 12: 288 entries (each with the 54 Karatsuba pre-sums of `mul.s`), and
the scalar tables a_h p^t, b_h p^t mod r (read only by replays).

**Trie.** A node nu at depth d <= 6 is a word ((h_1,t_1), ..., (h_d,t_d)) of table entries, with
Pi_nu = T[h_1][t_1] * ... * T[h_d][t_d]; the root is the empty word (Pi = 1). Nodes are stored in level order:
the children of node n are 288 n + 1 + 12 h + t. An internal node (depth 1..5) stores its 18-vector gamma(Pi_nu)
(gamma_k.re, gamma_k.im and their sum, k < 6) and the 54-vector `mul.s` entry of Pi_nu (for escapes): 3,456 bytes;
a leaf (depth 6) stores the `mul.s` entry of Pi_nu: 2,592 bytes. Internal nodes: sum_{d=1}^{5} 288^d = 2^40.855;
leaves 288^6 = 2^49.020; 2^60.3661 bytes in all. A node is built from its parent by one `mul.s` call
Pi_child = Pi_parent * T[h][t] and its pre-sums and gamma (16,068 instructions, charged 20,000 = one unit).

**Walk state.** Two base buffers (the current explicit base y with its six Karatsuba pre-sums
x_k.re + x_k.im, and the previous base), the current node and its depth, a ring of three K slots (the current K and
the two before), the previous step's node and buffer index (for escapes), the checkpoint K, the step count mod 64,
the 2-word stuck-walk counter and the trail's start pair (alpha0, beta0). It carries no running exponents.

**One iteration** (pre-debit charge first, proof-impl.md 0-i):

```
1  if node = root: (K, kappa) <- root.s(y)            [also writes the six pre-sums of y]
   else:           (K, kappa) <- lazy.s(y, pre-sums, gamma(Pi_node))    [K of the element y * Pi_node]
2  if bits 64..135 of K are 0 (distinguished): F <- bits 136..247 of K; append (F, alpha0, beta0) to the report
   log; the trail ends: fresh start y <- g^alpha0 z^beta0 from a new start pair, node <- root, histories reset
3  2-cycle and checkpoint tests on K (section 3.3); on a hit: escape, then next iteration
4  h <- floor(24 K_0 / 2^64), t <- (12 - kappa) mod 12, node <- child(node, h, t)
5  if depth(node) = 6: y_prev <- y, y <- mul.s(y, entry(Pi_node)) (the flush), node <- root
```

A replay runs the same iteration from (alpha0, beta0) and additionally adds (a_h p^t, b_h p^t) to its exponent
pair on every step and doubles it at an escape's squaring, as in the parent; it stops at the trail's distinguished
class and returns p^kappa (alpha, beta) there.

**3.1 The step is a map on classes, and the lazy walk is the eager walk.** The current element is
y * Pi_node exactly (an invariant: it holds at a start, at an escape and after a flush, where node = root, and a
step multiplies Pi_node by T[h][t] on the right). By F5 the key computed in step 1 is the key of that element, so
(K, kappa) and therefore h, t, the DP test and the fingerprint are those of the current element; the next
element is (y Pi_node) T[h][t] = (y^ M_h)^{p^{-kappa}}, y^ the canonical representative, which lies in the class
[y^ M_h]. So the step depends only on the class, and the sequence of elements (not only of classes) is exactly
that of the parent's multiply-only walk run with this table. The declared run of part C takes 240 production steps (47 root, 193
lazy, 32 flushes, one escape) with every key from the emulated `root.s`/`lazy.s` and every flush and escape from
the emulated `mul.s`/`sqr.s`, and asserts at every step that y * Pi_node equals the eager walk's element and that
(K, kappa) equals the reference; it also checks the exponent invariant at the end.

**3.2 Collision.** As in the parent: every report is appended to the log until the cap; after the walk phase the
log is heapsorted, duplicates dropped, and every pair inside a run of equal F is replayed and checked, under a hard
budget of 2^16 pairs. Two records with equal F are the same class up to a false match of probability 2^-112 per
pair of distinct classes under H2 (at most (2^55)^2/2 x 2^-112 = 2^-3 false pairs in expectation for 2^55 records;
each costs at most two replays inside the pair budget). The replays give canonical
pairs with alpha^1 + x beta^1 = alpha^2 + x beta^2 mod r, so x = (alpha^1 - alpha^2)/(beta^2 - beta^1) unless
beta^1 = beta^2 (about 1/r). Output Q = [x]Q0 after checking g^x = z.

**3.3 Fruitless cycles at R = 24.** A closed walk of the class graph is *useless* if the canonical exponent pair
returns unchanged. After l steps the pair is Lambda (alpha^_0, beta^_0) + tau with Lambda = 2^s p^m (s squarings, m a
sum of twists) and tau = sum_h c_h (a_h, b_h), c_h in Z[p]. Because (alpha^_0, beta^_0) is uniform and independent of
the table, the walk is useless (up to probability about 1/r) only if Lambda = 1 and every c_h = 0. An escape's
squaring cannot lie in a useless walk (Lambda = 2^s p^m = 1 needs s >= 2^247, F4). For multiply steps: the l classes
of a closed walk that starts at a first visit are themselves first visits until it closes, so under H2 (section 6) their indices are uniform on 24 and their frames p^e independent uniform on the 12
powers of p (each step's twist is (12 - kappa) mod 12 with kappa a class bit), and c_h is the sum of the frames of
index h's occurrences. The rates below are the model rates for a closed walk starting at a first visit. For coefficients far below r, c_h = 0 mod r exactly when this sum of 12th roots of unity
vanishes in Z[zeta_12]. So the probability P_l that the l steps from a given step form a useless walk is at most
E[prod_h g(n_h)] over the multinomial counts n_h of the 24 indices, with g(0) = 1, g(1) = 0 and g(n) = q(n), the
exact probability that n independent uniform 12th roots of unity sum to 0 (computed exactly for n <= 12 in part
F: q(2) = 1/12, q(3) = 1/72, q(4) = 0.0191, ..., q(12) = 0.00195), and g(n) = Q(12) = 0.00195, the largest point
probability of a 12-term sum, for n > 12 (adding independent terms cannot raise a point probability). Part F
evaluates the bound exactly for l <= 288 and, beyond, by Poissonisation (P_l <= e sqrt(l) (E_Pois(l/24) g)^24,
monotone on doubling segments), weighted by the probability exp(-theta l) that a closed walk of length l holds no
distinguished class (H2). Results: **P_2 <= 1/288** (same index twice, opposite twist; the only l = 2 term the bound keeps), sum_{l=3}^{64} P_l =
6.17e-5 (P_3 = 2^-15.34, P_4 = 2^-14.76, P_8 = 2^-25.94, P_64 = 2^-108.88), and useless walks longer than 64 at
a rate **below 2^-105.6 per step** (charged as 2^-104).

* **Detection and escapes (the parent's rules, on K).** The K of the step before last is remembered; if it equals
  the current K, the two classes form a 2-cycle: the walk makes explicit the representative of the class with the
  smaller K (the current element y * Pi_node, or the previous element, which is Pi of the previous node times the
  base it was computed from: y, or y_prev if a flush came between; one `mul.s` call with that node's entry, or no
  call when that node is the root) and replaces it by its square (`sqr.s`), node
  <- root, and resets the two-step history and the checkpoint; a replay doubles its pair there. A checkpoint K is
  stored every 64 steps and compared at every step; a repeat means a cycle of length at most 64, which is traversed
  once more to its minimum-K class, which is then squared the same way. Both choices depend only on the cycle, so
  merged trails stay merged. Every walk whose stuck-walk counter reaches 20/theta = 20 * 2^72 steps is restarted
  (0-iii); the counter is reset at every walk start, restart, report and fresh start, and not at escapes.
* **Charge.** A 2-cycle wastes the step that re-enters the cycle and the detecting step (2 steps) and one escape
  (24,000 instructions, 1.2 units = 3.4432 steps at c): (2 + 3.4432)/288 = 0.018900 step-equivalents per step. A cycle of
  length 3 <= l <= 64 wastes at most 64 + l steps before its detection, its traversal of l steps at the largest
  step price (19,554, 2.8054 c each) and one escape: sum_l P_l (64 + l + 2.8054 l + 3.4432) = 0.005014. The ledger
  charges **eps = 1.25 x 0.023914 = 0.029892** on the step count; the extra 0.25 x 0.023914 is margin, and that the
  realized waste of the run stays within eps is part of H1+ (section 3.4) (the toy censuses read pre-collision 2-cycle rates of 0.00334 to 0.00346 per step at R = 24, model 0.00347,
  and checkpoint escapes at 2.1e-5 to 3.5e-5 per step against the bound 6.17e-5; evidence.md).
  Useless walks longer than 64 with no distinguished class are left to the stuck-walk rule at the charged rate
  2^-104: below 2^21.73 expected restarts over the run's at most 2^125.73 iterations (0-iii).

**3.4 Caps and the work cap.** As in the parent: setup (at most 2^49.06 units), the walk phase, and the stopping
phase (matching, output, verification, halting; the stopping allowance R_stop < 2^106.04 units, section 5). The
walk phase has the budget B_walk = W_cap C - 2^49.06 C - R_stop C instructions (W_cap = 2^124.205, W_cap C rounded
down) and meters its own charged work in the 192-bit meter under the pre-debit rule (proof-impl.md 0-i) with the
prices of section 5: before each charged action the meter is compared with L = B_walk - A_max (A_max = 2^25) and the
action runs only if the meter is below L. So every run does at most 2^49.06 C + B_walk + R_stop C <= W_cap C
instructions, a deterministic inequality `experiment.py` checks on integers. The step price is fixed per step type
and known before the step: root 1,731, lazy 5,134, lazy with flush 19,554 (the step whose child is a leaf).

*No price-drift heuristic.* A block is the run of iterations from a root iteration to the next return to the root
(a flush, an escape or a fresh start). Its iterations are charged 1,731 (the first), 5,134 (the second to fifth) and
19,554 (the sixth, the only one whose child can be a leaf), so a block of k <= 6 iterations is charged at most
1,731 + (k-1) 5,134 < k c C for k < 6 and exactly 6 c C for k = 6, whether or not its last iteration ended in a
report or an escape (the escape and the fresh start are charged on top). Hence the charged step work of n
iterations is at most n c whatever the walk does. Three quantities are kept apart: first visits (productive
progress), executed iterations, and escape work. The ledger's S (1 + eps) is a count of step units, one unit being
c C instructions: each iteration costs at most one unit and each escape costs esc = 24,000/(c C) = 3.4432 units.
The eps of section 3.3 is the expected cost in these units of the useless closed walks, re-entry, traversal and the
escape that leaves them, per first visit (section 3.3 prices a 2-cycle at 2 + 3.4432 units). Escapes are not part of
the walk-phase non-step work below; their whole cost sits inside the eps term, and eps
charges each one at its full price. A first visit whose image is a structural return (below) is itself one of the steps a closure wastes (for a
2-cycle, the re-entering step of the 2 + 3.4432 units), so it is paid inside eps. Writing P for the first visits
whose images are not structural returns, the count H1 uses, the meter at the P-th such visit is at most
c (P + waste in units) plus non-step work, and S (1 + eps) is never read as a number of executed iterations
(structural first visits are about S/288 + 6.17e-5 S < 0.0036 S, inside the eps S = 0.0299 S they are charged
in). Reports, fresh starts and restarts
are the non-step work, charged separately.

*Iteration maximum.* Counting also the action that ends a block, every block of k iterations is charged at least
k c C: a block ended by a flush is charged exactly 6 c C; one ended by an escape at least 1,731 + (k-1) 5,134 + 24,000
>= k c C (k <= 6); one ended by a report at least 1,731 + (k-1) 5,134 + 4,000 plus its fresh start, charged its fixed
allowance of 2^10.1 units (proof-impl.md 0-i; its two 255-bit exponentiations alone exceed 2^21 instructions)
(`experiment.py` asserts all three for every k). So a run has at most n_max = B_walk/(c C) + 6M < **2^125.73
iterations** (the last, incomplete block of each walk adds at most 6).

*H1 at first visits, and structural returns.* An iteration is a **first visit** if its class has not been visited
earlier in the run, by any walk. The image of a first visit can land in the trail's own recent classes by the
walk's structure rather than by chance: a 2-cycle (the same index twice with opposite twists) returns to the class
two steps back with probability 1/288, and a useless closed walk of length l <= 64 returns at the rate P_l of section
3.3. The carve-out is defined by position only: an image that equals one of the last 64 classes the walk
visited since its latest start, restart, fresh start or escape is a **structural return**. It closes a cycle of
length at most 64 inside one trail, so it can never be the two-trail collision the run needs; the 2-step check
or the checkpoint compare (stored every 64 steps, compared at every step) finds it within 64 + l steps, an escape
leaves it, and its whole cost is charged in eps at the rates P_l that part F computes for exactly these closures
(section 3.3). 64 is the checkpoint period: it is the longest closure the checks are sure to catch, so it is
the longest one carved out. Closures longer than 64, and returns to classes before the latest escape, are not
carved out; they stay under H1 and the stuck-walk rule. H1 (section 6) models everything else: the image of a
first visit that is not a structural return, and the output of a walk start, fresh start, restart or escape, behaves
as a class of the random mapping with the conservative N', so the first S such first-visit images contain no class
collision with probability exp(-S (S - 1)/(2N')) (section 4). Before the first collision every iteration is a first
visit or lies inside a useless closed walk that an escape or the stuck-walk rule leaves.

*H1+ (whole-run concentration; disclosed, not proven).* The run's counts stay within the margins built into the
ledger: the waste of useless closed walks within eps per first visit (eps is 1.25 times the model mean), the
reports within their cap, the stuck-walk restarts within theirs, and the restarted or stuck colliding trails at
their model rates. As in the parent 0b8665ae, the failure of this concentration is charged as a flat 0.01 of
success (section 4). The 0.01 is an allowance fixed in advance, not a computed bound, and no martingale or tail
bound is claimed for it. The toy censuses (evidence.md) are consistent
with it; they do not prove it.

*Caps.* Reports D <= 2^55 (one-word counter; reaching it fails the run). A first visit is distinguished with
probability theta (H2), so the expected number of reports at the iteration maximum is below 2^53.73, a factor 2.41
below the cap. At most 2^16 matcher pairs (expected false pairs 2^-3, overflow probability at most 2^-19 by
Markov). At most 2^36 stuck-walk restarts (below 2^25.65 expected at the model rates, proof-impl.md 0-iii).
Reaching the report or the restart cap is inside H1+; the pair budget is charged on its own (section 4). The
ledger's step count is S (1 + eps) + (M + 2^36) 20/theta, the detection window and restart allowance being below
2^112.33 steps.

## 4. Success probability

**H1 (random mapping).** The class sequence behaves like iterates of a random mapping on N classes in which two
distinct classes have the same image with probability (1 - sum q^2)/N, q the multiplier-index probabilities. As in
the parent: for two classes with different indices the image equation has about one solution among N classes; for
the same index about 11/12 of one (the twist adds 11 nontrivial chances). We use the conservative sum q^2 = 1/R =
1/24 (first-order value 1/(12R) = 1/288), the Brent-Pollard factor R/(R-1) of an R-adding walk:
**N' = N/(1 - 1/24), log2 N' = 251.33353.** Part E samples 15,000 classes at q = 67, R = 24 in the declared run and reads N times
the pair-collision rate 0.9816 +- 0.0342 against 0.9583 (conservative) and 0.9965 (exact); a 20,000-class run read
0.9751 +- 0.0257. H1 does not depend on how the keys are computed: section 3.1 shows the lazy walk visits exactly the
elements of the eager multiply-only walk.

Under H1 (section 3.4) the probability that the first S first-visit images contain no class collision is
exp(-S (S - 1)/(2N')), within a factor 1 + 2^-125 of exp(-S^2/(2N')), which the floor absorbs. With
P_model = 0.4002: **S = sqrt(2 N' ln(1/0.5998)) = 2^125.68269.** Losses, each computed in part D:

* H1+ failing (section 3.4): a flat 0.01.
* The restart cap's worst case as steps: 2^36 x 20/theta < 2^112.33 steps, a fraction f below 9.507e-5 of S. With
  x = S^2/N' = 1.0223 the model success is P(S) = 1 - exp(-x/2) and P'(S) S = x exp(-x/2) = 0.6132. The function
  x exp(-x/2) increases for x < 2, so on [S(1 - f), S] it stays at most 0.6132, and losing a fraction f of the S
  steps costs at most 0.6132 f/(1 - f) < f of success;
  charging f itself is conservative.
* Detection failure on either of the two colliding trails. A trail is lost if its stuck-walk counter reaches
  20/theta iterations before a distinguished class. Under H1+ (its clause on colliding trails, applied to
  the waste inside each colliding trail's window) those iterations hold at least a = 20/(1 + eps)
  first visits, each distinguished with probability theta (H2). The trail holding the collision point is hit in
  proportion to its length, so its length is size-biased (Gamma(2, theta)); for the hitting trail, its own prefix
  and the remainder of the trail it merges into are each exponential at rate theta. Either way the probability
  of no distinguished class within the window is (1 + a) e^-a = 7.521e-8, so 1.505e-7 for both (part D computes it).
* A collision inside a single trail. Trails have geometric lengths with mean 1/theta, so the within-trail pairs
  among the first S first visits are at most S/theta + M/theta^2 in expectation, and under H1 the chance that
  any of them collides is below (S/theta + M/theta^2)/N' = 2^-53.65 (part D asserts it). The ledger charges 1e-6.
* The pair budget exceeded: Markov, 2^-3/2^16 = 2^-19.
* The sampler's exhaustion allowance 2^-71.99, a key tie or a zero key (at most 70/p per keyed element over at most
  2^125.73, below 2^-240) and beta^1 = beta^2 (2^-255).

The sum is below 0.010099: **success at least 0.4002 - 0.010099 = 0.390101, floored to 0.39010**, 0.00010 above
the required 0.39 (part D asserts the floored value). The fresh starts of the trails (one per 2^72 steps) are uniform
classes, which collide at rate 1/N >= 1/N', so counting them as iterates is conservative.

Toy support (evidence.md: censuses of this package's complete walk at R = 24, s = 0 with trails, replay and the
matcher in toy fields q = 67, 163, 211): the fraction of runs whose first useful collision falls within
S(0.3910)(1 + eps), counted in the ledger's step units, is 0.410 to 0.427 per field (pooled 0.4206 +- 0.0053 over
8,725 runs; an earlier census of 17,350 runs reads 0.4319 +- 0.0038 at S(0.4005)(1 + eps)), and the mean T_c/sqrt(N) is
1.23 to 1.27 against the model's 1.2803. The toy derives its class bits from a hash of the canonical representative (a toy key in F_q has too
few bits); the production rule's own bits of K are tested in the real GT by part G. They support H1 at their sizes; they do not measure
production success. Census 2 runs at S(0.3910), which is below S(0.4002), and the fraction can only grow
with S, so its 0.4206 is also a lower reading for the toy fraction at S(0.4002), above the 0.4002 the model uses.

## 5. Cost (units of one dense Fp12 multiplication = 20,000 instructions)

Counts are executed scalar AArch64 instructions as the cost model counts them. The four kernels are straight-line
programs (general-purpose registers only, no branch but the final ret, no call), so the executed count equals the
emitted count on every call; `kernels/emu.py` interprets the subset and counts every executed instruction (ldp/stp
count one), and `experiment.py` part K regenerates all four in memory and runs them against a big-integer
reference on real GT elements:

| kernel | executed instructions | what it computes |
| --- | ---: | --- |
| `lazy.s` (`gen_lazy.py`) | **4,964** | from (y, its pre-sums, gamma(Pi)): 18 products, 2 + 3 Montgomery reductions, a, b, B, a zeta, B zeta of y Pi, the 12 stored keys, K and kappa |
| `root.s` (`gen_lazy.py`) | **1,561** | the six pre-sums of y, then B, a zeta, B zeta (3 products, 3 reductions), the keys, K and kappa |
| `mul.s` (`gen.py`, parent) | **14,402** | y * Pi for a stored entry with its 54 pre-sums (flush, escapes, trie construction) |
| `sqr.s` (`gen.py`, parent) | **6,777** | Granger-Scott cyclotomic squaring (escapes) |

`lazy.s` by category (from the generator): products 3,146 (22 products of 143), Montgomery reductions 780 and
their final subtractions 100 (5 reductions), loads/stores 462, Karatsuba combinations 240, keys and minimum 227
(eleven 6-limb compares with 6 + 1 selects, two 6-limb subtractions with add-back select, six 6-limb negations p - v),
prologue/epilogue and addressing 9.

**Every step** (both kinds), analytic, 170 instructions: K reads and h = umulh(K_0, 24) 3; DP test 4; kappa and the
twist 5; child index 5; depth and flush test 3; node or leaf address 5; previous node for escapes 2; 2-cycle and
checkpoint comparisons, history ring and checkpoint store test 60; loop control and the kernel call 17; margin 53;
192-bit meter 8; 2-word stuck-walk counter 5 (`experiment.py` lists the items). **Flush** 14,420: `mul.s` 14,402,
call 8, buffer swap and node reset 3, margin 7.

| step | instructions | units |
| --- | ---: | ---: |
| root step (node = root) | 1,561 + 170 = **1,731** | 0.08655 |
| lazy step | 4,964 + 170 = **5,134** | 0.2567 |
| lazy step whose child is a leaf (with the flush) | 5,134 + 14,420 = **19,554** | 0.9777 |
| block of six steps | 1,731 + 4 x 5,134 + 19,554 = **41,821** | **c = 41,821/120,000 per step** |

**Escape** (2-cycle or checkpoint): 24,000 instructions (choose the smaller key 14, address 4, `mul.s` + call 14,410
(none at the root), `sqr.s` + call 6,785, resets 20, meter 8, margin 2,759); a checkpoint escape adds its traversal of
at most 64 steps at 19,554 and 65 x 64 of bookkeeping (1,279,616 < A_max = 2^25).

**Setup** (preprocessing, at most 2^49.06 units): pairing g (<= 2^14), z^r = 1 (<= 510), the table (24 multipliers
x (two exponentiations <= 1,021 units + 11 Frobenius maps), 48 sampler draws at 14.848 units, the scalar tables
2 x 288 products mod r at 800 instructions and 288 x 54 pre-sums at 200), **the trie**: 2^40.855 + 2^49.020 nodes at
one unit each (copy of the parent's raw coordinates 72, `mul.s` 14,410 with call, 42 pre-sums at 20, gamma 480, stores and control 266: 16,068 <= 20,000) plus
the operating system's zero-fill of its 2^60.3661 bytes (0.1875 instructions per byte, 2^43.4 units), the M = 2^20
walk starts (<= 2^10.1 units each) and the counters and constant pools: below 2^49.054 units in all.

**Unchanged from the parent** (proof-impl.md): 4,000 instructions per report (at most 2^55, 2^52.68 units); a fresh
start after every report and at every walk start or restart, at most 2^10.1 units plus 40 of meter bookkeeping
(2^65.10 units for the at most 2^55 + 2^36 + 2^20); switches 600 instructions (at most n_max/2^63 + 2^20 + 2^36 + 1,
2^57.65 units); the stopping allowance: heapsort of 2^55 records (7,188 instructions per record), dedup, at most 2^16
pairs of two replays (each below (2 x 20/theta + 3) x 2^26 instructions, 2^89.03 units), the check g^x = z (at
most 510), [x]Q0 in G2 (at most 2^11, below), the verification pairing (at most 2^14), halting: below 2^106.04 units.
The G2 multiplication: left-to-right double-and-add over the 255-bit x in Jacobian coordinates on the twist
(a = 0), at most 255 doublings (2 Fp2 multiplications + 5 squarings) and 255 mixed additions with the affine Q0
(7 multiplications + 4 squarings), then one Fp2 inversion (one Fp inversion, at most 2 x 381 Fp products by
exponentiation) to return affine coordinates. With Karatsuba (3 Fp products per Fp2 multiplication, 2 per
squaring) that is at most 255 x (16 + 29) + 800 < 12,300 Fp products; at a generous 600 instructions per Fp
product with its share of reductions, additions and control (`mul.s` spends 267 per product) the total is below
7.4 x 10^6 instructions, 369 units, so 2^11 units leaves a factor 5.5. The replay bound uses that one iteration repeats at most one step (at most
19,554 instructions plus 64 for the exponent update) and one escape (at most 1,279,616), below 2 x 2^25.

**Ledger** (`experiment.py` part D, 60-digit decimal arithmetic):

`W = c S (1 + eps) + c (2^20 + 2^36) 20/theta + 2^106.035 (non-walk: setup, reports, fresh starts, restarts, stopping allowance) + 2^57.67 (switches)`

with c = 41,821/120,000, log2 S = 125.68269, eps = 0.029892, (2^20 + 2^36) 20/theta = 2^112.322: **log2 W = 124.20458**.
Submitted bound: **time_log2 = 124.205** (the least thousandth at or above it; `experiment.py` checks
W <= 2^124.205 exactly on integers, and that the walk-phase threshold covers c (S(1+eps) + window) plus the walk's
non-step work, with 0.028% to spare).

Sensitivities (part D): eps without the 1.25 factor: -0.0084 bits; +100 instructions on every step: +0.0206 bits;
a lazy kernel twice as expensive: +0.56 bits (still below the parent's 125.111).

**Memory:** report log 2^55 x 80 bytes = 2^61.322; trie 2^60.3661 (leaves 288^6 x 2,592 bytes = 2^60.36, internal
nodes 2^52.6); table, scalar tables, walk states (2^20 x 4 KB) and replay states below 2^33: **below 2^61.93 bytes**
(< 2^62). Each array is addressed by one 64-bit register (every byte offset < 2^63). Memory is reported, not scored.

## 6. Heuristics and limitations

* Three heuristics, none proven, and the ideal-source model for the ChaCha20 sampler. H1: the class walk, with
  structural returns to the trail's own last 64 classes carved out (fruitless closures, charged in eps and left by
  an escape, never counted as collisions; section 3.4), behaves as a random mapping on classes with the
  conservative R/(R-1) correction, so the first S first-visit images collide with probability
  1 - exp(-S (S - 1)/(2N')). H2: bits 0..247 of K are a random function of the class (next item). H1+: the run's
  counts (waste within eps, reports and restarts within their caps, colliding trails at their model rates)
  concentrate as the model says, and the failure of that is charged as a flat 0.01 of success. H1, H2 and H1+ are
  the parent's heuristics; the carve-out of structural returns is written out here. They are standard in rho
  analyses (Teske 2001; van Oorschot-Wiener 1999; Duursma-Gaudry-Morain 1999; Bos-Kleinjung-Lenstra 2010) and
  supported here by toy and production-field runs, not proved. Lazy evaluation adds no heuristic: it computes the
  same walk (section 3.1).
* H2 for K's bits, stated precisely: the map class -> bits 0..247 of K is modelled as a random function (each class
  value uniform, values of distinct classes independent). The frame kappa is not a class function (it is the index
  of the member reached, which depends on the predecessor element); as in the parent, the frame of the element
  arriving at a fresh class is modelled as uniform on 0..11 and independent of the history. Part G tests the 248
  bits only; kappa enters the tests through part C's step-by-step walk and the cycle rates of part E and the censuses. This is a model, not a distributional fact: the 248 bits
  take at most N + 1 < 2^251.28 values, so no statement about their joint distribution over GT is claimed; the rule
  uses h (essentially the top 5 bits of the low word), 72 DP bits and 112 fingerprint bits, 248 in all. Support:
  K is the minimum of the twelve stored keys, i.e. of six values min(v, p - v) of nonzero Fp-linear functions of the
  element composed with the Montgomery map, so K < p/2 and its density on [0, p/2) varies only on scale p, far above
  the 2^248 range of the bits read; part G tests the bits on 3,000 production classes (chi-square of h 21.7 on 23
  degrees of freedom, of 8 DP-field bits 237.2 on 255, of 8 fingerprint bits 225.8 on 255; largest |z| of the 248 bit
  frequencies 2.67) and part C's walk statistics. The toy censuses use a hash in place of these bits.
* R = 24 is small for an adding walk; the conservative correction 1/(1-1/R) (0.0307 bits on S) and the recomputed
  fruitless-cycle charge (0.0425 bits) are both in the ledger; P_model = 0.4002 leaves 0.00010 above 0.39 after the H1+
  budget and the computed losses (the toy censuses read above the model at this point). Larger R makes the trie (12R)^6 too large for memory below 2^62.
* Scope of the prices: kernel counts are executed counts from the shipped emulator; the every-step 170, the escape
  24,000, the flush overhead, the node price, the 4,000 per report, the heapsort level price and the replay bound are
  analytic bounds. The kernels are checked on real GT elements and edge values (`kernels/check_lazy.py`), not compiled
  and run on hardware. The trie (2^60.37 bytes) and the log (2^61.322 bytes) are RAM-model arrays; memory is unscored
  and no physical machine maps that much.
* This is a generic square-root attack (no index calculus in Fp12); a valid upper bound, not a security estimate.
