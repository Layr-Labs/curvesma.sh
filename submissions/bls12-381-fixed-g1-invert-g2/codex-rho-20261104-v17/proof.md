# Bounded32-adding rho: heuristic time bound136, local memory

This classical cold attack claims at most2^136 dense-Fp12 reference equivalents at fixed C=20000, with algorithmic success at least0.49 under the two explicitly stated supported heuristics below. Peak memory is below2^30 bytes; preprocessing below2^136 equivalents is included; nonuniform advice is zero. It uses the full protected BLS12-381 groups and the exact supplied P. This is a heuristic exploratory claim, not an unconditional theorem, a practical break or a production execution. No reviewer-confidence number is used as success probability.

## Concrete algorithm

Validate input and compute h=e(P,Q0) with the pinned pairing(Q0,P), including final exponentiation and the protected generator Q0. Since P is nonidentity and r is prime, h generates GT. If z=1 return infinity. Otherwise write z=h^a for the unknown a. A recovered exponent is only an intermediate; output Q=[a]Q0 after exact e(P,Q)=z and subgroup verification.

The implementation uses actual scalar SHA-256, never an external hash oracle. Let INIT,SCAL,WALK be the distinct16-byte ASCII tags FAPI-RHO-INIT-v1,FAPI-RHO-SCAL-v1,FAPI-RHO-WALK-v1. Encode P as its two canonical48-byte coordinates and z as its twelve canonical48-byte polynomial coefficients. Set seed=SHA256(INIT||P_bytes||z_bytes). Generate scalar candidates from SHA256(SCAL||seed||counter_be64), using a globally incremented counter and masking to255 bits. Accept a candidate if<r. Allow at most1024 attempts per scalar; on exhaustion return failure/infinity. This consumes no external randomness: the actual algorithm is deterministic on its uniformly sampled challenge. Hash-based initialization is part of heuristic H1, not a hidden source of independent coins.

Generate independent-in-the-idealized-analysis pairs(u_j,v_j),j=0,...,31, and store M_j=h^u_j*z^v_j with their coefficients. Generate alpha0 similarly and start(X,A,B)=(h^alpha0,alpha0,0). Every step computes j as the low five bits of SHA256(WALK||seed||X_bytes), then replaces X by X*M_j,A by A+u_j mod r,B by B+v_j mod r. X_bytes is an injective576-byte encoding of its twelve canonical Montgomery tower coefficients, in fixed coefficient order and limb-byte order. The walk message is16+32+576=624 bytes. The index depends on X, not on A or B, so this is a deterministic function on GT and maintains X=h^A*z^B.

Run Floyd cycle finding: initialize slow and fast to the same initial state. For t=1,...,S, S=8*ceil(sqrt(r)), advance slow once and fast twice, then compare all twelve coefficients exactly. At a match compute D=B_fast-B_slow mod r. If D=0 return failure. Otherwise compute a=(A_slow-A_fast)/D mod r,verify h^a=z,construct and verify Q and return it. If the cutoff expires return infinity. No restart,parallelism,distinguished-point database or large memory is used. Sampling failures,zero denominators and cutoff failures are charged in full.

## Explicit heuristics and their scope

H1: For the average-case success analysis over the specified independently uniform P and z, the domain-separated SHA-256 computations may be modeled as independent random functions on their distinct input domains. This gives uniform initialization scalars after rejection and random partition labels on previously unvisited group elements. This is a computational pseudorandomness idealization of a fully implemented and charged hash, not a supplied free oracle. The actual fixed SHA function is not mathematically proved to satisfy it at production scale.

H2: In this idealized32-adding walk on the protected prime-order group, the mean index tau of the first repeated group element is at most4*sqrt(r), averaged over initialization tables,starting values and partition. This finite production bound is an extrapolation, not a theorem imported from another group or an observed BLS runtime.

Relevant support: Bos et al., section3.1 and Table1, describe adding walks,Floyd recovery and their heuristic collision model; their sampled32-bit-group32-adding mean is1.015 times the random birthday prediction. They explicitly note that the rigorous result for the original squaring walk does not immediately transfer to adding walks. The balanced32-partition estimate is approximately1.273*sqrt(r); H2 permits more than triple that mean. These are reasons for plausibility, not proof of H2 at255 bits. Source: https://www.joppebos.com/files/noan112.pdf . The original adding-walk work is Teske2001, DOI10.1090/S0025-5718-00-01213-8. No numeric production claim is attributed to an unread theorem. The optional finite experiment measures this implementation only in small prime-field subgroups; it cannot certify production mixing or H1/H2. Unknown representation/hash correlations,rare long cycles and the enormous extrapolation remain material uncertainties. If either heuristic is unsupported or refuted, the production success claim fails.

## Success calculation under H1/H2

Under H1, a255-bit candidate is accepted with probability r/2^255>1/2. There are65 scalars, so the chance of exhausting a1024-attempt sampler is less than65*2^-1024<2^-1000. Conditioned on no sampling failure, all accepted scalars are uniform and independent: the accepted value is independent of the rejection count. Starting X is uniform. H2 and Markov's inequality give P(tau<=S)>=1/2. For every deterministic function with tail length mu and cycle length lambda, Floyd meets at a positive multiple of lambda no greater than mu+lambda=tau, so a repeat by S implies a meeting by the stated cutoff. This is not a birthday heuristic substituted without disclosure; the quantitative uncertainty is precisely H2.

The denominator calculation needs no separate uniform-relation heuristic. Condition on P,z,all M_j,the starting group value and partition. If z=h^a, each choice of v_j determines exactly one u_j for a fixed M_j, so the v_j remain independent uniform scalars. The trajectory depends only on these group values and partition, not the coefficient representation. At a Floyd meeting time t<=S<r, the coefficient difference B_fast-B_slow is a sum of v_j with coefficients equal to the nonnegative counts of jump j between trajectory positions t and2t. Their sum is t,positive and<r; thus at least one count is nonzero mod r. This linear form in independent uniform v_j is uniform mod r and is zero with probability1/r, even conditioned on that trajectory and meeting. If nonzero, the maintained equality gives the unique a, and bilinearity proves the returned G2 point solves the supplied-P problem.

Consequently success under the declared heuristic model is at least(1-2^-1000)*(1/2)*(1-1/r)>0.49. Identity targets succeed deterministically. The actual distribution includes uniform P,z and no fresh algorithm coins, with H1 providing the stated modeling bridge. This success lower bound is conditional on the disclosed heuristics; it is not claimed proved for fixed SHA-256.
