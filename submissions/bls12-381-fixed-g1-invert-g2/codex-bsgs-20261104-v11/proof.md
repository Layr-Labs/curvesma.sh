# Six-limb deterministic prefix BSGS: bound 131

This is an analytical classical upper bound for the full protected BLS12-381 fixed-G1 pairing inversion target. It is not a practical break or measured runtime. The first claim requests score 131 unchanged: total cold computation below 2^131 dense-Fp12 reference equivalents with fixed C=20000. Success is exactly L/r>0.39, where m=39*2^121 and L=m*(2m-1). Preprocessing below 2^131 equivalents is included in that total. Peak memory is below 2^145 bytes; nonuniform advice is zero bytes. All successful and failed executions are charged. There are no auxiliary powers, quantum steps, target amortization or parallel elapsed-time discounts.

## Target, algorithm and success

Use the protected prime order r and standard G2 generator Q0. For the supplied nonidentity P, compute h=e(P,Q0) using the pinned pairing(Q0,P), including final exponentiation. Nondegeneracy makes h order r for every allowed P. Write z=h^a for the unique a in [0,r). The answer must be the G2 point [a]Q0 for this exact P; neither a scalar nor a different P suffices.

Set m=39*2^121 and s=2m-1. Use the orbit key K(t)=min(t,t^-1) in a consistent full-coefficient order and retain its sign sigma(t) in {+1,-1}, so K(t)=t^sigma(t). Break the identity tie with sign +1. The following paragraph proves the inversion implementation is exact and charges it below. Construct the m baby records (K(h^j),j,sigma(h^j)), 0<=j<m, with successive products by h. Deliver the full records to the leaves of the explicit merge tree below. Its sorted output stream populates the balanced distributed search tree; no unimplemented wide-address table is used.

The protected constants satisfy p^6=-1 mod r (direct modular exponentiation verifies this). In the tower below, the p^6 automorphism fixes Fp6 and sends w to -w. Thus for every t=A+B*w in GT, t^-1=t^(p^6)=A-B*w. This applies to h, all babies and every giant because they lie in GT. No inverse is computed by exponentiation inside the loop; conjugation performs six field negations and copies six unchanged coefficients. The choice of canonical orbit key and its sign is exact. For j,k<m, equality of baby keys implies j=+k or j=-k mod r. Since 2m<r, only j=k is possible; identity is handled explicitly. There are no duplicate baby keys from different j.

Set the giant center c_i=i*s+(m-1) for i=0,...,m-1. Compute v_0=z*h^(-(m-1)) and update v by multiplication by h^(-s) between searches. At each i form K(v) and sigma(v), then search the balanced distributed search tree by exact full keys. On a match j with stored sigma_j, set a=c_i+sigma(v)*sigma_j*j. Verify h^a=z, construct Q=[a]Q0, verify membership and the exact protected pairing e(P,Q)=z, then encode Q. If all m searches fail, return infinity. Identity targets succeed immediately. All setup exponents, validation and final verification are charged separately.

A match means sigma(v)*(a_true-c_i)=sigma_j*j mod r; multiplying by sigma(v) gives the reconstruction formula. The candidate lies in [i*s,(i+1)*s-1], because j<=m-1. These m intervals are adjacent and disjoint and cover exactly [0,L), L=m*(2m-1). Every a_true in this prefix has the required signed residual and is found; no a_true outside it can match because L<r and the reconstructed candidate is inside the prefix. Infinity on failure cannot accidentally satisfy an outside nonidentity target. Hence success is exactly L/r, with all failures charged in full.

The hexadecimal order has leading byte 0x73, so 115*2^248<r<116*2^248. Here L=3042*2^242-39*2^121. This is less than r, and 100L>39r: use 39r<289536*2^242 while 100L=304200*2^242-3900*2^121, whose positive margin exceeds zero. Thus success is rigorously greater than 0.39 (approximately 0.410005), over uniform z for every allowed P. No random-walk heuristic, random coins, amplification or success-conditioned cost is used. No guarantee is claimed for adversarial targets outside the searched prefix.

## Tower extension arithmetic and exact basis conversion

Use Fp2=Fp[u]/(u^2+1), Fp6=Fp2[v]/(v^3-(u+1)), and Fp12=Fp6[w]/(w^2-v). This is the protected polynomial field under v=w^2 and u=w^6-1: w^12=(u+1)^2=2u=2w^6-2. No field or pairing is changed. Given polynomial coefficients c0,...,c11, convert for each k=0,...,5 the pair c_k+c_(k+6)*w^6 to (c_k+c_(k+6))+c_(k+6)*u, and place even k coefficients in the Fp6 constant part and odd k in its w part. This uses six base additions. Inverse conversion uses six subtractions. Both are bijective linear maps and are charged in setup. Store all twelve canonical Montgomery tower coefficients as an exact full key. Sorting may use any consistent order of these keys; equality is invariant under the bijection. The final verification still uses the exact protected pinned pairing and original polynomial target.

Fp2 multiplication uses three base products. For a=a0+a1*u and b=b0+b1*u set t0=a0*b0, t1=a1*b1, output c0=t0-t1 and c1=(a0+a1)*(b0+b1)-t0-t1. This is three base products and five base additions/subtractions.

For Fp6, write a=a0+a1*v+a2*v^2 and b=b0+b1*v+b2*v^2 with Fp2 coefficients. Set t0=a0*b0,t1=a1*b1,t2=a2*b2 and cross values s_ij=(a_i+a_j)*(b_i+b_j)-t_i-t_j for ij=01,02,12. With xi=u+1, output c0=t0+xi*s12, c1=s01+xi*t2, c2=s02+t1. This uses six Fp2 products and fifteen Fp2 additions/subtractions. Multiplication by xi is (x0+x1*u)*(1+u)=(x0-x1)+(x0+x1)*u, two base additions. There are two such xi multiplications. Thus each Fp6 product uses eighteen base products and at most 6*5+15*2+2*2=64 base additions/subtractions.

For Fp12 write A=a+b*w and B=c+d*w. Compute t0=a*c,t1=b*d,t2=(a+b)*(c+d). Output (t0+v*t1)+(t2-t0-t1)*w. This is three Fp6 products. The two input Fp6 sums and two output Fp6 subtractions use 24 base additions. Multiplication by v maps (x0,x1,x2) to (xi*x2,x0,x1), using two base additions; the constant output addition adds six. Total is 54 base products and 3*64+24+2+6=224 base additions/subtractions.

Allow 32 additional local field copies, for 256 lower-order field operations in total. Each displayed sum/product writes its result directly into a fixed temporary slot; t_i and s_ij are read by pointer. The v permutation changes coefficient references. A twelve-coefficient final copy and alias handling fit within 32 copies, and alternate local buffers avoid copying the previous group value. No tower accumulator array is zeroed. The scalar kernel's temporary work is already included in its 512-instruction bound.

Arithmetic costs 54*512+256*128=60416 instructions. Allocate 8192 more for extension-level fixed-slot argument/control and BSGS counter bookkeeping: even 24 per one of the 310 field operations is 7440, leaving 752 for the bounded outer control; much of caller work is already included in kernel allowances. Thus a dense product/loop step is at most 68608. Canonical orbit preparation needs six field copies and six negations (1536), a full local-key comparison (512), and selection/sign handling, below 4096. Charge 72704 instructions for every baby or giant orbit step. The original value remains available for its next fixed-base multiplication. No inversion by exponentiation occurs in the loop.

## Explicit processors, links and local memory

The rejection of 1181f6e1-3b78-4950-ba02-061253159c3c correctly identified that a multiword pointer does not implement a wide-address load. This algorithm uses a different data structure: a binary merge tree followed by a binary search tree, with all accesses implemented through adjacent-node messages. No processor loads from an address beyond its ordinary local 64-bit address space. No free global memory instruction or routing oracle is assumed.

Use a balanced merge tree with m leaves and height at most 127, and a balanced binary search tree with m key nodes, height at most 127. Each is connected through fixed parent/child links. Fewer than 4m processors including the coordinator suffice for both trees together. Each processor uses at most 16384 bytes of local code, state and buffers. Neighbors share bounded queue windows at ordinary local addresses; forwarding is an explicit load from the incoming adjacent queue and store into the outgoing adjacent queue. The physical topology consists only of these fixed local links. Its design/fabrication is not computation; constructing all routing/interval metadata, initializing queues and distributing code is charged below.

A full record is at most 640 meaningful bytes: 576 for the twelve canonical Montgomery tower coefficients, 32 for j, and 32 for sign/tag/metadata. A packet adds up to four header words, so a full transfer is at most 84 words. A small request, acknowledgment or result packet has at most eight words. A result can return the low two words of j (j<2^127) and a packed sign/status word; the high two index words are known zero and restored by the coordinator. Headers still fit within eight total words.

A full local relay uses 84 unrolled LDR/STR pairs (168 instructions) plus 32 for fixed link/window selection, route/state flags, event/wait handshakes and control, at most 200. A small relay uses at most 16 loads/stores plus 32, at most 48. Each node receives only the scheduled request and response; no contending operations or polling loops are hidden. Idle nodes sleep until the addressed event. Event/wait instructions and queue flags are in the 32 allowance. The coordinator is serial; all processors' executed instructions count, while idle elapsed time does not. Environmental interrupts, wire latency and OS scheduling noise are not an algorithmic speed claim.

Queue offsets and all key/head offsets are small local constants. A full local key comparison scans 72 words with unrolled pairs of LDR plus CMP and conditional branch: at most 288 instructions plus 224 fixed/control, charged 512. Copying 80 meaningful record words locally uses 160 unrolled load/store instructions. The per-node code can fit within 4096 bytes: the unrolled key comparison is 1152 bytes, full packet relay 672, head copy 640, and small relay 64, leaving over 1500 for fixed protocol, branching and startup. Three pairs of full queue windows use at most 4032 bytes, two merge heads use 1280, and code/labels/stack fit comfortably in each 16384-byte allocation. No node stores an entire exponentially large run.

The queue protocol permits one outstanding request on each activated path. A child response also acknowledges that its parent's request was consumed; the parent does not reuse that request buffer prematurely. Flags are cleared before the next scheduled activation. No separate uncharged packet acknowledgment is required. A relay's explicit read/write is the software transfer across the adjacent shared page; every intermediate node executes its counted copy. Reverse-path small packets and all local coordination are counted below.

## Place babies and merge lazily with bounded state

During generation, the coordinator delivers baby j to merge leaf j by routing its rank through the merge tree's stored subtree intervals. Rank and interval labels have at most 128 bits and are processed with bounded word comparisons/shifts; they never serve as memory pointers. A full packet descends and a small acknowledgment returns. At most 128 hops at 200+48 instructions, plus 1024 for local setup, rank counters and final leaf storage, give 32768 instructions per baby placement. This includes copying into the leaf's local record slot.

Each leaf supplies its record once on GETNEXT and then EOF. Each internal merge node holds at most one head record from each child. On GETNEXT it fills missing heads, compares their full keys, emits the smaller, and marks that child's head missing for next time. If one child has ended, it emits from the other; EOF is explicit and distinct from the GT identity. The cached heads prevent rereading/resending a record before it is popped. This is ordinary two-way streaming mergesort, not a free sorting primitive.

For each record emitted by one node allow 1024 instructions: a small GETNEXT path step (48), a full response (200), a local comparison (512), copying a new head into its local slot (160), and another 104 for node state, sign/index retention and control. Requests/refills executed by children are charged on those child emissions, not omitted. Charging every node emission even where a comparison or head copy is unnecessary is conservative. A record participates at most once at each tree level, including the root emission to the coordinator: at most 128m record emissions. Each edge carries EOF at most once, fewer than 2m more emissions. Charging EOF the same 1024 gives total merge work at most 130m*1024=133120m instructions. There is no m-sized hidden head array at a node.

## Build and query a distributed search tree

Consume the sorted root stream in increasing rank k=0,...,m-1. The preallocated balanced search tree assigns node intervals [l,u) and midpoint floor((l+u)/2). Route the record by rank to its unique midpoint node, using local interval labels and child links. The node stores the full canonical key, j and sign. Comparisons during construction use rank labels, not key order, and the sorted stream ensures the binary-search-tree invariant. Full down packets and small acknowledgments over at most 128 hops plus 1024 local rank/store/control cost another 32768 instructions per record, including coordinator receipt of the merge output. No materialized run larger than local buffers is required.

A giant query sends K(v) down the resulting search tree. Each node compares the full query to its local full key, then returns a match, a missing-child failure, or forwards to its chosen child. The result returns on the active parent path. Charge 1024 instructions per visited level: local comparison at most 512, full relay 200, reverse small result 48, and 264 for branch/link selection, local query state and remaining control. All are ordinary local addresses. At most 128 levels give 131072 instructions per giant query, including a not-found result. The coordinator retains sigma(v), restores j from the bounded result, reconstructs a, and performs the charged final verification only on a match. Exactly the same signed-interval success proof applies; changing storage does not change which exponents match.

## Initialize every processor and charge all memory

There are fewer than 4m nodes in the two trees. Allocate up to 4096 instructions per node in aggregate, or 16384m instructions, for code distribution, labels/intervals, queue flags and startup. More explicitly, distribute each at-most-4096-byte node image in at most seven 80-word payloads. At most 1400 instructions copy/forward each image at the source end of a parent/child edge, and at most 1400 receive/install it. There are fewer than 4m edges across the trees, so this costs at most 11200m. Another 512 per node (2048m) covers fixed-size interval arithmetic, node labels, queue flags, startup and local instruction-cache synchronization. Total 13248m is below 16384m. Nodes do not zero unused data buffers: a ready flag is initialized before use, and the full head/key is written before it is read. Every actual data write was charged in placement/merge/build. No large uninitialized buffer is read as a key.

The code distribution is a tree broadcast, once per edge, not an uncharged global copy or a path from the root repeated for every image. Startup labels use only small fixed arrays and at-most-128-bit arithmetic per node. The topology and generic code are algorithm design, but populating every node's state and code is paid. The arithmetic library is only on the coordinator, whose fixed setup is separately charged. The chosen neighbor-local queue machine needs no global physical address map or wide RAM extension.

At fewer than 4m nodes of 16384 bytes, aggregate node storage is below 2^143 bytes. This includes all distributed code, queues, merge heads, baby records and search keys. Coordinator library, constants, input, arithmetic buffers and output are fixed and fit well within the remaining margin to the declared peak 2^145 bytes. Both trees coexist, so peak is not a per-processor or single-phase memory claim. No nonuniform advice is used. This is enormous theoretical hardware, not a production execution claim; the rules permit analytic attacks without constructing it.

## Fixed setup, output and exact total

Charge another 2^90 scalar instructions for canonical decoding, membership tests, public scalar/field constants, Montgomery and tower conversions, both pinned pairings, stride/offset powers, final G2 scalar multiplication, output and independent verification. These are not free oracles. For adequacy, a base inverse by p-2 uses fewer than 768 field products, an Fp12 inverse by p^12-2 fewer than 9216 dense products, and a subgroup check/scalar multiplication fewer than 512 complete point steps. Fp2 inverse is (a-bu)/(a^2+b^2); complete affine G1/G2 operations check infinity, equal/opposite points and y=0 before division. Even the very loose 2^52 instructions per complete G2 step fits all such bounded work inside 2^90. A pinned 64-bit Miller loop and less-than-4608-bit final exponent need fewer than 2^20 extension operations; allowing 2^58 per operation including inversion gives less than 2^78 per pairing. Two pairings plus all other fixed work fit comfortably in the stated 2^90. The exact supplied P and protected pairing are used in final verification.

- populate the search tree: 32768m;

The score is a conservative analytical logarithmic bound, not a measured runtime. Preprocessing is a subset of total work and below 2^131 equivalents. Peak memory is below 2^145 bytes, advice zero, and success exactly L/r>0.39 as proved above.
