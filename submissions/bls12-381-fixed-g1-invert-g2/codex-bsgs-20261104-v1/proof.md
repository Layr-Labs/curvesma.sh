# Deterministic FAPI-1 via explicitly charged polynomial BSGS

This is a classical analytic upper bound, not a practical pairing break, a timing measurement, or a claim of novelty. The declared total work is at most 2^158 dense-Fp12 reference equivalents, with success probability one. The sole score is the rational integer 158. Peak storage is below 2^145 bytes. Preprocessing is below 2^158 reference equivalents and is included in total work. Nonuniform advice is zero bytes. ## Supplied-point reduction and complete algorithm

Use exactly the protected BLS12-381 profile, prime subgroup order r, standard Q0 and supplied nonidentity P. Decode all inputs canonically and perform the prescribed membership checks. Compute h=e(P,Q0) with the pinned pairing convention, i.e. pairing(Q0,P). Nondegeneracy and prime order imply h has order r for every allowed P. Never substitute a solver-chosen P. Write z=h^a for the unique a in [0,r). The objective is the G2 point [a]Q0, not the exponent alone.

Set m=ceil(sqrt(r)) by integer arithmetic. Since r<2^256, m<=2^128. Make m records (h^j,j), j=0,...,m-1, starting from the identity and multiplying by h. Represent each group element by all twelve canonical polynomial coefficients in the protected basis. Sort records lexicographically by their full representation using bottom-up mergesort with a second array. No hashes or probabilistic equality are used. Compute d=h^(-m), using h^(r-1) for its inverse and binary exponentiation for the stride. Start v=z. For i=0,...,ceil(r/m)-1, binary-search the sorted array for v. On a match j, set a=i*m+j and check a<r. If so, verify h^a=z and return Q=[a]Q0 after independently verifying e(P,Q)=z and membership. Otherwise continue. Between searches update v=v*d. The identity target may be handled immediately by returning infinity after input checks.

For the unique actual a, Euclidean division a=i*m+j has i<ceil(r/m) and 0<=j<m. At this i, v=z*h^(-i*m)=h^j. No earlier accepted false answer can occur because equality h^a=z and a<r identifies the unique exponent. The final block is included. A wraparound match with i*m+j>=r is ignored; the correct decomposition still exists. Hence success is exactly one over the full independently uniform P and z distributions, including z=1. There are no random algorithm coins, retries or unproved collision heuristics.

## Bit arithmetic schedule

The cost is instructions, not unit-cost arbitrary integers. A deliberately slow implementation suffices. Store each residue as 384 bytes containing its bits, least significant first. One carry position and loop state fit in fixed additional words. Maintain canonical residues throughout. To compute modular addition of two canonical residues, perform a 384-position ripple-carry addition, retain the carry, subtract p with borrow over 385 positions, and select the subtraction exactly when the unreduced sum is at least p. The sum is less than 2p, so one conditional subtraction suffices. Subtraction uses an analogous borrow pass and conditional addition of p. Comparison scans the bits; copying scans the bytes.

Charge 64 scalar AArch64 instructions per position per pass. This includes byte loads, stores, carry/borrow logic, shifts, tests, branch and address increments. The actual arithmetic in a position needs fewer than 16 such instructions, leaving margin for loop control and conditional selection. Sixteen passes of length at most 385, plus initialization and return, fit below 2^19 instructions. Thus every modular add/subtract, full comparison or copy of one field residue is bounded by 2^19 instructions. Bits beyond the 381-bit modulus are zero; using 384 positions is an upper bound. No hardware division instruction or large-integer oracle is required.

For multiplication modulo p, set A=0 and B=x. For each of the 384 bits of y, conditionally replace A by A+B mod p, then double B mod p. There are at most 768 modular additions and a scan of y. Even bounding each iteration by eight complete 2^19-instruction operations and including initialization, the total is below 2^31 instructions. This generous bound includes all temporary copies, branching, loop indices and parameter loads. Squaring is multiplication. Nonzero inversion by exponent p-2 uses fewer than 768 modular products and hence less than 2^41 instructions, with lower-order loop overhead included in the ample slack. Zero tests precede every division.

## Dense polynomial extension arithmetic

Use Fp[w]/(w^12-2*w^6+2) directly, so no basis conversion is needed. A dense product uses 144 base products to form coefficients 0 through 22 and at most 144 accumulator additions. Reduce coefficients from degree 22 down to 12 using w^k=2*w^(k-6)-2*w^(k-12). Each reduction needs only a constant number of field additions and subtractions; processing in descending degree also handles terms temporarily created above degree 11. Multiplication by two uses addition, not a costly generic multiply. Fewer than 1024 base operations cover every convolution product, accumulator, reduction, zeroing, and twelve-coefficient output copy. At 2^31 instructions per base operation this is below 2^41 instructions, including fixed-size loop overhead. We charge the looser 2^42 instructions per full GT multiplication together with its BSGS loop update and scalar-counter bookkeeping. Group products use this implementation, never both this charge and a reference multiplication charge.

Fp12 addition/subtraction and equality are coefficientwise. To invert a nonzero element, binary exponentiation to p^12-2 takes fewer than 9216 dense products because p^12<2^4608. Its cost is below 2^56 instructions using the above conservative step bound, including control. All BSGS elements are powers of a nonzero h, so no inverse of zero is taken. No extension arithmetic heuristic or smoothness assumption enters the algorithm.

## Records, sorting, lookup and address work

A GT element occupies 12*384=4608 bytes in this intentionally inefficient representation. An exponent uses 256 bits; store 32 bytes, or 256 bytes if convenient. A record, including tags, alignment and logical location metadata, fits in 8192 bytes. Compare all coefficients lexicographically; an equality comparison is exact. Charge 2^24 instructions per complete record compare or copy, including all metadata, loop control, addressing and transfers. Scanning at most 8192 bytes, even at 128 scalar instructions per byte, is below 2^20, leaving a further factor sixteen. No probabilistic expected constant-time table is assumed.

The tables are theoretical large storage, as in the earlier BSGS accounting control. Logical byte addresses have fewer than 145 bits and are explicitly represented in three 64-bit words. Index arithmetic, carries and comparisons are charged in the record allowance. This does not assume the array fits a 64-bit host address space. Memory work is total logical accesses and transfers in the published instruction-equivalent model, not interconnect latency. The physical construction of such a storage machine is not claimed. The explicit multiword representation prevents accidental treating a 128-bit index as a single hardware register.

Bottom-up mergesort uses at most 128 passes and at most m comparisons and 2m copies per pass (generously allowing copying between both arrays each pass). Binary search needs at most 129 comparisons per giant. Initialization and residual bookkeeping fit within m extra record operations and low-order constants. Combining all comparisons and copies is less than 2^139 record operations. At 2^24 instructions each this contributes less than 2^163 instructions. Record construction is charged both its field arithmetic and its record copy; neither is omitted. An integer square-root and scalar products use fixed 256-bit arithmetic and are covered by setup or per-step allowances.

## Setup, output and exact pairing

Allocate a separate 2^90-instruction allowance for all fixed setup and finish work: canonical parsing, subgroup checks, sqrt(r), public-constant loading, the two pinned pairings, inverses, exponentiations for the stride and verification, G2 scalar multiplication, encoding and final comparison. This allowance is not amortized across targets. The following elementary bounds explain its adequacy rather than treating a pairing as free.

A subgroup check or scalar multiplication needs fewer than 512 complete point operations. Affine G1 formulas use base arithmetic and inversion. For Fp2, (a+bu)^-1=(a-bu)/(a^2+b^2), u^2=-1; multiplication uses four base products and a bounded number of sums. Complete G2 addition/doubling uses fewer than 1024 base multiplications/additions and inversions, so even charging the inversion bound 2^41 to every one gives below 2^52 instructions per point step. Infinity, equal points, inverse pairs and y=0 are checked before division. Fewer than 2^12 such steps cover membership checks, reconstruction and other point work, well below 2^90.

Compute the exact protected optimal-ate map with the pinned 64-bit loop count and final exponent (p^12-1)/r. A Miller iteration contains bounded line-function arithmetic and point updates, each expressible with fewer than 2^10 extension operations even using affine coordinates. For inverses, exponentiate to p^12-2 as above; thus one extension arithmetic operation, generously including an inverse, costs below 2^58 instructions. The loop, exceptional cases and exponentiation to the less-than-4608-bit final exponent fit below 2^20 such operations per pairing. This gives below 2^78 instructions per pairing. Two pairings, input checks, output and all remaining fixed exponents fit far below 2^90. This uses the supplied P in both pairings. No alternative pairing or unnormalized Miller value is substituted.
