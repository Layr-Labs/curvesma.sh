# Explicit banked-storage realization

The full variant table is larger than one ordinary commodity virtual mapping. This analytic implementation therefore specifies its storage interface rather than treating a multiword/arbitrary-size address as one unpriced access. It uses only64-bit arithmetic,ordinary scalar loads/stores andbounded barriers to a RAM bank-selection register. The backing bank decoder supplies storage only,no group operation,lookup oracle,randomness orother computation. All address calculation,data construction,selection andtransfers are charged. This is a proposed classical memory realization,not hardware installed on the VM or a practical availability claim. A reviewer must assess its admissibility under the challenge's instruction-equivalent model;the assumption is not hidden as free hardware work.

For each of the three components,split a47-bit j into high10-bit bank number andlow37-bit local index. Each physical bank stores2^37 base indices times12 variants times640 bytes:
 12*640*2^37=15*2^46 <2^50 bytes.
There are1024 banks per component,3072 total. Reserve a bank window of2^50 bytes andan ordinary shared region below2^50. Shared code,stack,constants,raw-state buffers,canonical scratch,prefix records andfingerprint tables are never bank switched. Map the selected bank at the window;its offset is(12*j_low+e)*640. The complete record always fits inside its bank,so no operand orcoefficient straddles a window boundary.

Use a fixed shared memory-mapped selector carrying b*1024+(j>>37),a12-bit value. Window memory is configured noncacheable at cold setup so bank changes cannot expose stale cached aliases;the shared region may use normal memory. Before selecting another bank,the preceding reference/scalar accesses complete. A conservative selection sequence is a full barrier,selector STR,andfull barrier,with all scalar address/control instructions included. The three reference multiplications read their ordinary native576-byte jump operands from the window;the scalar updates read the two plain32-byte coefficients before switching bank. Current/next raw states andoutputs remain in shared RAM,so there is no uncharged inter-bank transfer of live state orprocessor migration.

For one factor,the following operations fit24 scalar instructions,with initialized window/selector pointers in the shared context:
 load cached j ande;shift j right37 for bank;add component*1024;
 load selector pointer;barrier;STR bank;barrier;
 mask low37 j;form12*j_low byshift/add;add e;
 form x640 byshift9 plusshift7;add fixed window base;
 pass record pointer to the ordinary reference/scalar routines.
All integers fit64 bits,the largest local byte offset is<2^50,andcomponent bank id<3072. Extra pointer materialization andcontrol fit the24 allowance. The reference/scalar caller interfaces themselves are already charged separately in scalar-audit.md,so they are not smuggled through this allowance. No store is assumed to perform a group computation;it merely enables a storage bank.

The scalar instruction metric is not elapsed time. RAM/bus stalls orlarge capacities do not reduce computation across processors;there is one sequential controller here andevery actual load/store is counted. No speculative free network,DMA search,OS page fault loop oruncounted secondary algorithm is assumed. The bank decoder is the finite addressing organization of the RAM,analogous to an ordinary memory controller;its only algorithm-visible state is the explicitly written bank id. Cold setup configures the memory attributes/selectors andwrites every table entry through the same charged protocol. Unused bank padding is included in peak capacity andis never read as advice.

Full allocated bank capacity is3072*2^50=3*2^60 bytes,not merely the payload3*12*640*2^47. Shared fingerprint tables use(72*2^32+2)*40<2^44 bytes. All code,selector metadata,Frobenius constants,two960-byte working records,1023 saved records,scratch andframes fit comfortably below2^45 shared bytes. Therefore complete peak<3*2^60+2^45<2^62<2^63. The reported2^63 bound includes capacity slack andpadding. No array is amortized over other targets andno nonuniform advice is imported.

This realization is an analytic instruction/storage claim only. It does not say that the current VM,an ordinary userspace process,or existing commodity RAM can execute a production attack of this size. The repository explicitly permits analytic bounds without exponentially large execution. Structural local verification requires only the normal shared verifier;candidate files never execute on the host orwith credentials. If this bank-selection realization is outside the permitted machine model,the cost claim must be rejected rather than silently repriced orpresented as qualified.
