# Deterministic full-range GT baby-step/giant-step

This is a classical analytic accounting control for the exact protected profile, not a practical attack or a claim of novelty. The attack uses no auxiliary powers, searched advice, random oracle, or heuristic. It returns a G2 point for the supplied G1 point. The claimed bound is W <= 2^145 dense-Fp12 reference equivalents, with C=20,000 scalar AArch64 instruction equivalents. Success is 1. Peak memory is at most 2^141 bytes; preprocessing is at most 2^144 reference equivalents, included in W. Nonuniform advice is absent (the max(1,bytes) reporting convention gives log2=0).

## Algebra and complete algorithm

Use the protected prime order r and field modulus p, and the public generator Q0. The reduced pairing is bilinear and nondegenerate on these prime-order groups. For every allowed P != infinity, g=e(P,Q0) has order r: writing P=bP0 with nonzero b, nondegeneracy gives e(P0,Q0) order r and exponentiation by b preserves order. No computation of b is used. Thus each allowed z has a unique a in [0,r) with z=g^a. This is precisely the input domain, including identity.

Set m=2^128. Since r<2^255, k=ceil(r/m)<=2^127. Form all m records (g^j,j) for 0<=j<m by sequential multiplication, starting at 1. Store elements in the protected polynomial coefficient representation with canonical residues. Sort the records lexicographically by the full canonical field-element encoding, using bottom-up mergesort and a second array. All baby powers are distinct, since m<r. Compute h=g^(-m) by binary powering modulo r. Initialize v=z. For i=0,...,k-1, binary-search the table for v. On a hit at j, set a=im+j, require a<r, construct Q=[a]Q0, verify e(P,Q)=z, and output Q. Otherwise update v=v*h. The loop uses at most k searches and k multiplications. The exponent exists: Euclidean division of its canonical a by m gives i<k and j<m, with z h^i=g^j. The first such hit is the correct a because a<r. If z=1, the j=0 record returns a=0 and Q=infinity; use the identity pairing convention. Success is exactly one for every valid input. No sampling or amplification is needed.

## Explicit conservative scalar arithmetic

Here is a deliberately slow implementation sufficient for the bound; no measured blst multiplication is assumed to cost one. Use six 64-bit words for each residue. Implement Fp multiplication by 381 iterations of modular double-and-add, scanning the bits of one operand most-significant first. For each iteration double the accumulator modulo p and add either zero or the other operand modulo p. A modular addition takes six word adds with carry, six subtracts with borrow, a carry/borrow decision and a six-word selection. Allocate 256 scalar instructions for an addition, including source/destination accesses, loop/address control, and all carries. Both operands are canonical; their sum is <2p and fits six words because p<2^381, so one conditional subtraction suffices. Scanning a bit, selecting the operand and loop control take fewer than 128 additional instructions per bit. Therefore a field multiplication costs at most 381*(2*256+128)+1024 < 2^18 instructions. Field addition/subtraction each cost <=256; negation and equality have the same bound. This uses ordinary scalar word operations, not arbitrary-width unit costs. Stack and code storage fit below 2^20 bytes.

For Fp12 multiplication, use the polynomial representation specified in the target profile, not a conversion oracle. A schoolbook convolution has 144 coefficient multiplications and 144 coefficient additions. Reduce degrees 22 down to 12 using w^12=2w^6-2. Each of the eleven high coefficients contributes to two lower slots, via at most six modular additions/subtractions. Total is below 144*2^18+(144+66)*256 plus loop, indexing, copies and zeroing. Reserving a further 2^20 instructions covers that overhead: total <2^26 instructions per dense Fp12 multiplication. This is an upper bound for the actual algorithm, not a replacement reference price. Its normalized cost is strictly less than 2^26/20,000 <2^12 units.

Binary powers need fewer than 2L field multiplications for an L-bit nonnegative exponent; inversion in Fp uses exponent p-2 and costs <2^28 instructions. Fp2 arithmetic is two-component polynomial arithmetic and fits below 2^22 per multiplication. G2 scalar multiplication uses ordinary projective double-and-add and at most 510 point steps. A point step can alternatively use affine formulas with explicit Fp2 inversion; Fp2 inversion reduces to one Fp inversion and a constant number of Fp multiplications. Allow 2^40 instructions per point step, enormously above these formulas. All exceptional cases (identity, doubling, inverse points) are checked explicitly. G1 validation similarly uses affine formulas over Fp.

For pairing evaluation, evaluate the exact pinned optimal-ate definition using its field formulas. Its loop has fewer than 128 iterations; even a generic affine line computation with inversion, field evaluations, numerator/denominator updates and all exceptional checks is far below 2^40 instructions per iteration using the preceding polynomial arithmetic. The final exponent has fewer than 4572 bits, hence below 9144 Fp12 multiplications. Input parsing, group and GT checks, both pairing calls (initial g and final verification), exponentiation for h, G2 scalar multiplication, serialization, and any fixed initialization together fit below 2^64 scalar instructions. This also leaves more than 2^50 instructions for code and arithmetic setup. Constants come directly from the protected public profile; no construction of a lookup table is omitted. This deliberately coarse wrapper bound does not depend on a fast pairing implementation. The exact pinned pairing convention is essential; the algorithm does not substitute a Miller-loop value for its output.

## Full table work, including large addresses

Represent each record by 72 64-bit coefficient limbs and a 128-bit exponent padded to a 1024-byte record. Record size 1024 exceeds the required 592 bytes. Logical addresses and counters fit 192 bits, but no 192-bit hardware address is assumed. Use the following distributed binary memory tree. Each leaf holds at most 2^20 records, a 2^30-byte bank addressable by a local 64-bit processor. Across both arrays there are 2^109 leaves, attached to a binary tree of depth 109. Every internal node has a scalar processor, two child links and a parent link. Messages carry the logical page index and record offset. Each node reads the next path bit to route a request; the leaf accesses its local bank and returns a record along the reverse path. Processors are deterministic and event-driven, so no polling of inactive nodes is required. All processors' active instructions, initialization and transfers count. No uncharged parallel speedup is used: a controller can issue sequential requests.

A 1024-byte record is 128 words. Charge 16 scalar instructions for each word sent or received at an edge endpoint, plus 256 for header routing, control and offset computation per node visit. One full record routed over 109 edges, with both endpoints charged, costs at most 109*(128*32+256)<2^19 instructions. Requests and their headers add less than 2^17 instructions per access. Thus one record access costs less than 2^20 instructions. A mergesort event needs at most two record reads and one write; when implementing the merge, keep the two current input records buffered, so amortized per output record only one new input record is read and one output written, plus at most the two startup reads per run. Charge at most four record accesses per event, at a tighter per-access bound: 109*(4096+256)+2^17=605440. To avoid relying on that amortization for the numerical bound, use 2^22 instructions per merge output, including comparisons and all extra boundary/startup accesses. There are 128 levels and m records per level. Sorting costs <=2^157 scalar instructions. Table initialization and tree setup cost <=m*2^22=2^150 instructions, including initialization of the record arrays and all node metadata.

Binary search takes at most 129 key comparisons per giant step. It fetches one table record per comparison and compares its 72 key words against the locally retained giant element. Charge 2^22 instructions per comparison including range arithmetic, all multiword logical addresses and routing. Hence searches cost <=k*129*2^22 <2^157 instructions. Exponent reconstruction and control fit within those budgets. Table lookup is deterministic over the full encoding, with no hash collisions, probabilistic cost, arbitrary-width instructions or free dictionary oracle. Final output is constant size.

There are fewer than 2^129 sequential Fp12 multiplications in total for baby and giant steps. Their instruction cost is <2^155. Adding sorting, searches, table initialization and the wrapper gives
R < 2^155 + 2^157 + 2^157 + 2^150 + 2^64 < 2^159.
Since 20,000>2^14, W=R/20,000 < 2^145. Baby-table preparation including sorting costs <(2^154+2^157+2^150)/20,000 <2^144, so the stated preprocessing bound is conservative and is part of total W, not additional work amortized over other targets. Every array access performed by field arithmetic occurs in a processor's local bounded workspace; routing is needed only for table and tree data, already charged above.

The two arrays use 2^139 bytes. Allocate at most 2^20 bytes of code, routing state and buffers per tree node, including leaves. There are fewer than 2^110 tree nodes, so all replicated state is below 2^130 bytes. Local bank addressing fits 64 bits. Inputs, outputs, controller and field scratch use less than 2^30 additional bytes. Total peak is below 2^140 and thus below the claimed 2^141 bytes. Tree construction initializes fewer than 2^110 nodes; even charging 2^30 instructions per node is below the table-initialization budget 2^150. Communication is abstract scalar word-transfer work, not a claim about physical propagation speed or network throughput. The rules score summed computation and transfers, not elapsed time, and the bound includes each tree hop. No unbounded physical processor address space is assumed. No retained randomness or searched advice exists. The distributed construction requires exponential hardware resources and is purely analytic; it is not asserted to run on this VM. This does not omit its resource costs: every component is included in the reported memory and summed work.

## Scope and verification

This package is proof-only and declares no computational experiments. No production attack was run and no full-size allocation was attempted. Its deterministic algebraic proof and explicit conservative accounting supply the evidence. It makes no empirical timing, novelty, practical feasibility, qualification or promotion claim. It uses the full production p and r and the exact supplied P. Exponential memory is a material limitation, disclosed rather than hidden as advice. Acceptance, if any, is the protected exploratory plausibility decision, not formal certification.
