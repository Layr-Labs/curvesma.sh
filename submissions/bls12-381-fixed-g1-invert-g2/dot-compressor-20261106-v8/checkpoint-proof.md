# Exact checkpoint keys and charged pipeline

Use q=126, R=ceil(sqrt(r)), L=ceil(25767*R/25000), s=ceil(L/126), K=L+s. Save index zero and, after each equality search, indices s,2s,...,126s. Stop on the first equality, denominator zero or not, and fail if K transitions finish without one. There are at most 127 saved keys. At every search saved indices strictly precede the current index.

For a deterministic trajectory with tail mu and cycle lambda, first repeat tau=mu+lambda<=L implies a=ceil(mu/s)*s is a saved index with mu<=a<=mu+s-1. Its repeat a+lambda<=tau+s-1<K is detected, unless an earlier equality already terminated. This proves detection for any deterministic map, including the actual compressed-hash map; no random-mapping theorem is assumed.

## Injective key

Use the injective b||sign encoding in compression-proof.md and the 37-word aligned integer buffer d_0,...,d_36 in compressor-audit.md. Those 37 unsigned 64-bit words are the integer value of all 289 encoding bytes, padded at the high end with zero bits. The fixed-length 37-word representation is injective on encodings; the encoding is injective on the norm-one GT subgroup. Thus key equality is exactly group equality for every permitted group state. No probabilistic fingerprint or compressed polynomial value is used for checkpoint equality. Order the 37 words lexicographically in the fixed order d_0,...,d_36. Any total unsigned word order suffices for binary search; numerical integer order is unnecessary.

Keep complete 576-byte group elements and 64-byte coefficient pairs in checkpoint records as before, and additionally store the 296-byte key. Pad each saved record to 1024 bytes. Jump-table records stay exactly 640 bytes and their number remains 2^40. At most 127 checkpoint records, current/next state, aligned buffers, code and all scratch still fit below the unchanged 2^50-byte peak bound. This adds no external advice.

## Pipeline, no duplicate encoding work

During fixed setup compute the initial state's sign and aligned d buffer, and save index zero's state, coefficients and key. Charge this single initial preparation to the unchanged 2^90 fixed allowance.

For each transition: (1) evaluate U(d) and the WALK hash using the current prepared buffer, giving the same table index as before; (2) multiply by the jump element and update both coefficients; (3) compute the new state's sign and aligned d buffer, retaining it for the next transition; (4) search the saved keys for this new buffer and process the equality or checkpoint save. At the next transition no sign or aligned-buffer preparation is repeated. There is exactly one sign computation and one buffer preparation per transition, plus the one fixed initialization. Hence moving these operations across the transition boundary does not add any cost or alter any walk label. The previous per-transition sign allowance 128 and the SHA preparation allowance 2048 remain unchanged. On the final or failed step the same full budget is charged even if the next hash will not be needed.

The buffer preparation bound below 512 and remaining SHA/padding formatting below 512 remain as audited in compressor-audit.md. The SHA 2048 preparation budget contains both, though they now occur on opposite sides of a multiplication. No memory object is reencoded during a comparison. Save a checkpoint by copying its 576-byte state, two coefficients and 296-byte key exactly once. There are 117 eight-byte words in 936 bytes; a fully unrolled LDR/STR pair per word uses 234 instructions, with fixed immediate offsets below 1024. The unchanged 512 copying allowance includes pointer setup/control and padding initialization. Record padding is never part of key comparisons.

## Worst-case comparison and search cost

Completely unroll a comparator over the37 aligned key words. For each consecutive pair, use LDP for two current words, LDP for two saved words, then CMP/B.ne for the first pair and CMP/B.ne for the second pair: six scalar instructions per two words. There are18 pairs and one remaining word, whose LDR/LDR/CMP/B.ne costs four, for108+4=112 instructions worst case. A mismatch branches before inspecting further words; flags determine unsigned order. LDP reads two ordinary64-bit registers and is one scalar AArch64 instruction; no vector or128-bit arithmetic is used. The buffers are8-byte aligned and all paired offsets are at most272 bytes, within scalar LDP immediate range. The final word is at288. Allow96 additional instructions for caller BL, return, key/record pointer lookup, lo/hi/m, selection of the next interval, control and any preserved-register pair. This is at most208; charge224 per comparison including its binary-search iteration, retaining16 slack. The bound holds even when36 leading words agree.

Ordinary half-open binary search among at most 127 immutable saved keys requires at most seven comparisons, hence at most 1568 instructions. An unsuccessful search also yields insertion position. Sorted pointers are shifted on insertion, without changing saved records; charge all at most 127*126 pointer moves plus fixed insertion work below 2^30 to the existing 2^90 fixed budget.

Other outer allowances remain: 512 both four-limb scalar updates, 256 index/address work, 512 counters/saving control, 512 complete checkpoint copy, 256 equality/dispatch, 1024 spills/control. The bound r<2^255 prevents fifth-limb sum overflow.

## Correct relation and complete cost

The key only observes the group state and public counters, never jump coefficients. Given M_j, every v_j remains uniform independently because each v_j determines exactly one u_j with M_j=h^u_j*z^v_j. At any detected equality current minus anchor length d obeys 0<d<=K<r. The difference in B coefficients is sum n_j*v_j, with nonnegative counts summing to d. Some n_j is nonzero modulo r, so the denominator is uniform modulo r conditional on the entire observed trajectory. It vanishes with probability exactly 1/r. Otherwise a=(A_anchor-A_current)/(B_current-B_anchor) gives h^a=z by the invariant. Construct Q=[a]Q0 and verify the exact supplied-P pairing and subgroup.
