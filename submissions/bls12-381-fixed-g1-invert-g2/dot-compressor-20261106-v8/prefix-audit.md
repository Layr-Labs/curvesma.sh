# Standard SHA-256 block and full scalar schedule

Use standard SHA-256 from FIPS180-4 sections4.1.2 and6.2, with all arithmetic modulo2^32. The primary specification is https://csrc.nist.gov/files/pubs/fips/180-4/final/docs/fips180-4.pdf . Scalar W-register AArch64 operations implement these32-bit arithmetic words without extra masks. Arm's instruction reference at https://documentation-service.arm.com/static/6245c734b059dc5ff9a8bdab defines EOR Wd,Wn,Wm with an optional ROR or LSR operand and ordinary scalar loads/adds. No SIMD or crypto extension is used. This is an analytic instruction audit, not a measured trace.

Initialization seed is SHA256(INIT||P_bytes||z_bytes), exactly32 bytes. SCAL and UKEY messages use this seed, the original distinct16-byte tags and an8-byte big-endian counter. Scalar candidates are the lower255 bits of a256-bit digest. Key candidates are the lower61 bits. Rejection limits and uniformity under the sole ideal-hash heuristic remain unchanged. These scalar messages have56 data bytes and at most two64-byte blocks including padding; fixed setup still pays at most2^52 attempts below2^16 instructions each, inside2^90.

The walk message is WALK(16)||seed(32)||zero16(16)||U(M)(40), exactly104 bytes and832 bits. Prefix64 bytes is compressed once in charged setup. Each transition copies its32-byte chaining state and compresses the remaining40-byte payload with0x80,15 zero bytes and8-byte big-endian832-bit length. This is the exact standard padded message, not a different hash. The40-bit table label is extracted from its standard32-byte digest.

For Sigma1(e), use ROR t,e,#6; EOR t,t,e,ROR #11; EOR t,t,e,ROR #25, in W registers. Sigma0(a) uses2,13,22. Small sigma0 uses ROR7, EOR with ROR18, EOR with LSR3. Small sigma1 uses ROR17, EOR with ROR19, EOR with LSR10. Each function costs three instructions and has the specified SHA-256 semantics.

Prepare the64-word schedule in a256-byte aligned stack frame. For each of48 expanded words: four LDR predecessor words, two three-instruction small sigmas, three ADD W modulo2^32, one STR W. Exactly14 scalar instructions per expanded word. All48 iterations are fully unrolled; offsets are fixed immediates below256. There is no runtime counter, dynamic addressing helper or subroutine call in the schedule.

A round uses two three-instruction large sigmas(6), Ch as XOR/AND/XOR(3), Maj as ORR/AND/AND/ORR(4), two LDR for schedule word and round constant(2), four ADD for T1, one for T2 and two for new E/A(7). Total22. Logical state-register names rotate by compile-time permutation; new A and E overwrite old H and D only after last use. Six other states remain in place. Charge24 per round, giving two instructions slack per round. All64 rounds are completely unrolled, so no uncharged loop branch, increment or runtime register shuffle occurs.

Eight state registers, five reusable temporaries, two loaded words and three base/output pointers fit within18 general-purpose registers. Expansion precedes rounds and reuses them. A platform reserving x18 can use one callee-saved pair, whose save/restore is paid in the fixed block allowance; otherwise caller-saved registers suffice. No per-round spills or calls are needed.

Parsing and storing16 initial input words with LDR/REV/STR costs48. Initializing eight working states costs8. Eight feed-forward LDR/ADD/STR triples cost24. Sum80. Prologue, stack allocation, one saved pair if needed, pointers, epilogue and return fit in the remaining48 of a128 fixed block allowance.
