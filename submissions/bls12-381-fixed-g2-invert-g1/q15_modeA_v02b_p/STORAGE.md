# Storage and Addressing

Every object is partitioned into abstract 64-bit owner address spaces (`< 2^64` bytes = `16.00 EiB` per owner) with every cross-owner byte transfer explicitly priced in `KERNELS.md`. *(Hardware modeling caveat: physical ARMv8.0-A MMUs cap VA/PA at 48 bits [52-bit from ARMv8.2-A]; direct `ldrh`/`strh` addressing over `8.50–10.32 EiB` owners operates under the abstract 64-bit flat-RAM instruction-count model of this benchmark.)*

## 1. Relation Collection (`Arch2-Prod-ZeroSlice-Buf64K-B2-U16-Streamed`, Pure Product `qa <= s_c R2_a` & `qb <= R2_b`, `W_tile = 448 = 7 * 64`, `W_SB = 16`, `P_min = 2^32`, `P_m4s = 2^52.0`, `P_m4 = 2^57.5`, `P_lo = P_f = 2^58.0`, `P_g = 2^63.5`)

- **Canonical `a` packing & exact `2^56` power-of-2 bank stride (`K_a = 1`, `W_SB = 16`, `rec = 64b` with 2 zero guard bits `58..59`):** Continuous 8D ellipsoid volume (`A^2 = 321,500, r_ab = 0.83`) gives `V_a = 2^55.8744 < 0.92 * 2^56` canonical `a`-orbits; `N_a^tbl = 4 V_a = 2^57.8744`. Canonical `a`-entries are partitioned into `3` contiguous static 2-adic classes `c(a) in {0, 1, 2}` with ONE constant `g`-side threshold `T_g[c] = (299, 287, 275)` bits (ZERO `Q_CM(a)` radial shells, ZERO `bgo` norm predictor).
- **Column-slab owner RAM (`28` independent slab owners, `2^63.087 B < 2^64 B` each):** Each of `28` slab owners owns `16` consecutive columns and allocates `uint16_t S_g[16][4][2^56]` (`8.00 EiB`) + single-column `uint16_t S_f[4][1][2^56]` (`0.50 EiB`) + `64 KiB` Band-2 receive buffer = **`2^63.087 B = 8.50 EiB < 16.00 EiB`**.
- **Sequential Incrementing-Pointer `64 KiB`-Buffered Band-2 (`1` Prime Orbit per Build/Replay Owner, `~2^56.05` Owners -> `28` Slab Owners):** Each Band-2 `g`-side prime orbit owns its own dedicated build/replay owner (`<= 14.981 EiB` peak build `2^63.905 B`, `<= 7.491 EiB` max resident `2^62.905 B` + `416 B` row-step state, ZERO cross-owner build transfers). Each row runs `rev_b2_row_k0_step4` (`33/4 = 8.25` Ir/prime/row + `<= 1.354` outer-chord reset `<= 10.0` Ir/prime/row) into `rev_sb_probe_fast` + `rev_b2_emit_1` (`15` ops) + `rev_b2_recv_apply_1` (`6` ops) + `0.004` flush = `21.004 <= 22.0` Ir/hit + `28` row-end partial drains.
- **1-Prime-Per-Owner Local Flat-Array Build (`<= 2^63.905 B < 2^64 B` peak build):** Band-1a `<= 14.981 EiB`, Band-1b `<= 7.667 EiB`, Band-2 `<= 14.981 EiB` peak / `<= 7.491 EiB` resident; total replay `a`-table storage **`2^118.349 B < 2^120 B`**.
- **Distributed `2,048`-Owner Product Trees (`P_f = 2^70.79` + `P_g = 2^71.19` + Retained `g`-Batch Candidate Tree):** Partitioned across `2,048` 64-bit owners at **`0.1932 * 2^64 B = 3.091 EiB << 16.00 EiB`** per owner, with ALL THREE `L - 11` local subtrees `<= 1.053 EiB < 2^62 B` asserted live in `audit_cm.py`.

## 2. Linear Algebra Storage — Complete Owner Map Across ALL Phases (All `< 2^64 B = 16.00 EiB`, Conservative `nl_cap = 0.00278`, `sw_cap = 0.00568`, `nonunit_ub = 0.25`, `W_max = 4,096` Guard)

Each Block Wiedemann bundle runs `4` 256-bit vectors (`128 B/slot`) over `N_sw = sw_cap * U' = 0.00568 * 2^62.8277 = 2^55.3678` structured-Gaussian slots and `N = nl_cap * U' = 0.00278 * 2^62.8277 = 2^54.3370` logical columns (`nonunit_ub = 0.25`, mean row size `<= 64 + 201 * 8.25 + 7 = 1,729.25 B`):

- **Dense-vector owner (`1` owner, sequential Krylov -> Horner reuse):** `2 * N_sw * 128 B = 2^63.368 B = 10.323 EiB < 16.00 EiB` during Krylov (`2.581 EiB` reused sequentially for 1-vector Horner via `lsr #2`).
- **Dedicated row-sharded projection owners (`16` owners, holding `Z + Y=[S,BZ] + X` simultaneously):** `2^63.359 B = 10.263 EiB < 16.00 EiB` per owner (asserted live).
- **Krylov sequence owners (`2,048` owners):** `L_bm = 2^47.3539`, `2^63.354 B = 10.224 EiB < 16.00 EiB` per owner (asserted live).
- **PM-Basis generator owners (`2^22` owners + `1` owner for final `F(z)`):** Coeff arrays + 3-plane x 4-prime NTT workspace = **`2^63.108 B = 8.623 EiB < 16.00 EiB`** per owner; final `F(z)` = `2^59.354 B = 0.639 EiB` (asserted live).
- **Mutable filtering owner map (variable-size byte pools prior to finalizing the `16` read-only matrix shards):**
  - **Purge (`2,048` hash-partitioned owners, `<= 5.866 EiB <= 8.0 EiB < 16.00 EiB` each):** Bounded at `<= 40` raw incidences * `16 B` + `128 B` SM + `64 B` header times `1.25x` load factor `= 1,040 B/rel` across deterministically capped `N_rels <= n_rels_upper = 2^63.530` -> **`2^62.552 B = 5.866 EiB`** per owner (asserted live).
  - **Merge (`8,192 = 2^13` hash-partitioned variable-size byte-pool owners, `<= 5.498 EiB <= 8.0 EiB < 16.00 EiB` each):** Sized conservatively against pre-merge peak `nrows_tot <= n_rels_upper`, with aggregate mean payload across live rows + popped `merge_stack` pivots `<= 1,729.25 B` (`64 + 201 * 8.25 + 7`, `nonunit_ub = 0.25`) + `128 B` SM + `32 B` descriptor + `201 * 10 B` incidences = `3,899.25 B/obj` -> **`2^62.459 B = 5.498 EiB`** per owner (asserted live).
- **Read-only sparse-matrix shard owners (`n_mat_owners = 16` byte-balanced owners, deterministic `W_max = 4,096` guard):** `64 B` 24-bucket header + `d_i` 8B column offsets + `ceil(nu_i / 8)` 8B magnitude words -> average `<= 1,729.25 B/row` -> **`2^62.124 B = 4.358 EiB << 16.00 EiB`** per owner incl. `+ (64 + 4096 * 9)` max-row bytes (asserted live).
- **Explicit aggregate priced cross-owner burst streaming:** `w_row_avg = 8 + 201 + 201 * 0.25 / 8 + 7/8 = 216.156` words -> `1.125 * w_row_avg + 47.125 = 290.301 <= 291.0 = c_stream_mat_1vec` Ir/row (1-vec Horner) and `72.575 <= 73.0 = c_stream_mat` Ir/vec-row (4-vec Krylov), asserted live in `audit_cm.py`.
