# Storage and Addressing

Every object is partitioned into abstract 64-bit owner address spaces (`< 2^64` bytes = `16.00 EiB` per owner) with every cross-owner byte transfer explicitly priced in `KERNELS.md`. *(Hardware modeling caveat: physical ARMv8.0-A MMUs cap VA/PA at 48 bits [52-bit from ARMv8.2-A]; direct `ldrh`/`strh` addressing over `8.50–10.32 EiB` owners operates under the abstract 64-bit flat-RAM instruction-count model of this benchmark.)*

## 1. Relation Collection (`Arch2-Prod-ZeroSlice-Buf64K-B2-U16-Streamed`, Pure Product `qa <= s_c R2_a` & `qb <= R2_b`, `W_tile = 448 = 7 * 64`, `W_SB = 16`, `P_min = 2^32`, `P_m4s = 2^52.0`, `P_m4 = 2^57.5`, `P_lo = P_f = 2^58.0`, `P_g = 2^63.5`)

Canonical `a`-entries are partitioned strictly into `3` contiguous static 2-adic classes `c(a) in {0, 1, 2}` (each padded to a multiple of 64 entries) with ONE constant `g`-side threshold `T_g[c] = (299, 287, 275)` bits (ZERO `Q_CM(a)` radial shells, ZERO `bgo` norm predictor!). Band-1b packs `a_slot = (m << 56) | oid` (`58`b) and Band-2 packs `rec = (r << 60) | (m << 56) | oid` (guard bits `58..59 == 00`) on the prime-shard owner.
- **Column-slab owner RAM (`28` independent slab owners, `2^63.087 B < 2^64 B` each) & sequential 1-column `S_f` reuse:** Each of the `28` slab owners (`448 / 16 = 28`) owns `16` consecutive columns `[16*S, 16*S+15]` and allocates `uint16_t S_g[16][4][2^56]` (`2^63.0` B = `8.00 EiB`, indexed directly by `62b` `(u << 58) | (m' << 56) | oid`) plus a single-column `uint16_t S_f[4][1][2^56]` (`2^59.0` B = `0.50 EiB`) plus a `64 KiB`-aligned Band-2 receive buffer = **`2^63.087 B < 2^64 B`** (`8.50 EiB < 16.00 EiB`). Out-of-chord padded columns `[L_b, 448)` accumulate harmlessly inside the allocated `S_g` array (priced via `cand_bd = 1 + 16/L_b`), while `rev_scan_zero_u64` scans active columns `t < L_b` (and resets padded columns inside the `(1 + 16/189.0)` scan factor). Because the `f`-side has **ZERO Band-2** (`P_f = 2^58.0 = P_lo`), after Band-2 `g`-side finishes on the slab, the slab processes its active columns sequentially on the `f`-side, scanning `(S_g[u], S_f)` via `rev_scan_zero_u64` + blunt `1,000`-Ir cold handler (`S_f >= 118` bits = `472` quarter-bits).
- **Sequential Incrementing-Pointer `64 KiB`-Buffered Band-2 (`~2^54.28` Prime-Shard Owners -> `28` Slab Owners):** Band-2 replay tables total `2^118.28 B`, partitioned across `~2^54.28` read-only prime-shard owners (`< 2^64 B` each). Under sequential single-threaded row execution across the prime-shard owners (processed one owner at a time, so only one emitter is active at any instant — ZERO multi-producer race or tearing), each of the `28` slab owners maintains a `64 KiB`-aligned `64 KiB` (`4,096`-record, `16 B/record`) receive buffer `[buf_base[S], buf_base[S] + 65536)` with live write cursor `x_wr[S]` stored in a `28 * 8 B = 224 B` cursor table `x_tx_tbl[0..27]` owned by the row controller and passed to the active prime-shard. Total Band-2 hit cost = `15.0 + 6.0 + 0.004 = 21.004 <= 22.0 = C_HIT_HI` Ir/hit (`+0.996` Ir/hit slack).

## 2. Linear Algebra Storage — Complete Owner Map Across ALL Phases (All `< 2^64 B = 16.00 EiB`, 64B 24-Bucket Header with `W_max = 4,096` Guard, Aggregate `u16`-Burst Streaming)

Each Block Wiedemann bundle runs `4` 256-bit vectors (`128 B/slot`) over `N_sw = sw_cap * U' = 0.00568 * 2^62.8277 = 2^55.3678` structured-Gaussian slots (`1.477x` above the `2^25` conditioned zero-column-loss ladder mean `0.0038453`) and `N = nl_cap * U' = 0.00278 * 2^62.8277 = 2^54.3370` logical columns (`1.482x` above `0.0018755`):

- **Dense-vector owner (`1` owner, sequential Krylov -> Horner reuse):** During Krylov, double-buffered 4-vector state uses **`2 * N_sw * 128 B = 2^63.368 B = 10.323 EiB < 16.00 EiB`**, leaving **`5.68 EiB` (`35.5%`)** free for code, row-stream L1/DRAM ring buffer, and scratch. After Krylov finishes and `PM-Basis` computes the generator on separate owners, the dense-vector owner frees the 4-vector buffers and reuses the same address space sequentially for 1-vector Horner evaluation (`2 * N_sw * 32 B = 2^61.368 B = 2.581 EiB << 16.00 EiB`, using explicit `add x7, x6, x7, lsr #2` in `unit_run_1vec4_z12` / `gen_run1_1v_z12` to address `32 B/slot` directly from the unchanged `128*j` shard offsets!).
- **Dedicated row-sharded projection owners (`16` owners, holding `Z` AND `Y = [S, BZ]` AND `X` simultaneously at `<= 10.263 EiB < 16.00 EiB` each!):** Partition rows `[0, N)` evenly across `16` owners (`N/16` rows per owner), storing BOTH **`Z`** (`124 * 32 B * N / 16 = 4.895 EiB`/owner) AND **`Y = [S, BZ]`** (`128 * 32 B * N / 16 = 5.053 EiB`/owner, computed once via a single SpMV pass before Krylov) AND **`X`** (`16 B * N = 0.316 EiB`) simultaneously = **`2^63.359 B = 10.263 EiB < 16.00 EiB`** per owner (asserted LIVE in `audit_cm.py`!).
  - During **Krylov**, streaming each step's `4` dense output vectors (`4.5` Ir/vec-row) to the projection owners is charged inside `c_xproj = 70.0` Ir/vec-row (`4.5` stream + `65.5` `X`-MAC), writing sequence blocks `S_k = X B^k Y` directly to the `2,048` Krylov sequence owners.
  - During **1-vector Horner** (matching `hx_z12.py:159` verbatim!), the projection owners stream **`Y = [S, BZ]`** (`128` columns, `4.5 * n = 576` Ir/row over the full `d = ceil(D/n) + 1 + ceil(D/(128*n))` degree, explicitly charged inside `la_u`) into the dense-vector owner!
  - During **final kernel reconstruction** (`hx_z12.py:164`: `w = [S, BZ]*... + Z * F_0[4:]`, 1 single pass), the projection owners stream **`Z`** (`124` columns, negligible `< 2^65` Ir) to form the final kernel vector!
- **Krylov sequence owners (`2,048` owners, `<= 10.224 EiB < 16.00 EiB` each):** The sequence `S_0..S_{L_bm - 1}` (`L_bm = 2^47.3539`, `m * n * 32 B` per block -> `2^74.354 B` total) is partitioned by step index `k` across **`2,048` sequence owners** at **`2^63.354 B = 10.224 EiB < 16.00 EiB`** per owner (asserted LIVE in `audit_cm.py`).
