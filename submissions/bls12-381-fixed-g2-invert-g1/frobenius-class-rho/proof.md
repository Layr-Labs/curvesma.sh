# bls12-381-fixed-g2-invert-g1: Pollard rho in GT on Frobenius classes

Claim: total work at most 2^126.19 dense-Fp12-multiplication equivalents (C = 20,000), success probability at least 0.39 over uniform nonidentity Q, uniform z in GT and fresh coins, peak memory at most 2^53.7 bytes. Heuristics: random-mapping behaviour of the class walk (H1), independence of the walk's choices on distinct classes, which the fruitless-cycle count uses (H2), and random-function behaviour of the key mix that gives the jump index and the distinguished test (H3). All are named in section 6.

## 1. Reduction

Let r be the subgroup order, p the field modulus, P0 the G1 generator. Given (Q, z):
1. If z = 1 return P = infinity (valid exactly for z = 1). This has probability 1/r and costs nothing.
2. Compute g = e(P0, Q) with one reduced pairing. Q is not infinity and the pairing is non-degenerate on G1 x G2, so g != 1 and g generates GT (prime order r).
3. Find x with g^x = z (the DLP in GT, section 2 to 5).
4. Return P = [x]P0. By bilinearity e(P, Q) = g^x = z, for this exact Q.

## 2. Frobenius classes of GT

GT has prime order r and r divides Phi_12(p) = p^4 - p^2 + 1. Checked numerically: the multiplicative order of p modulo r is exactly 12, p^6 = -1 mod r, and p^4 - p^2 + 1 = 0 mod r. For y = g^e in GT, y^p = g^(ep), so Frobenius acts on exponents as multiplication by p mod r. The group H = {+-p^i : i = 0..5} has 12 elements (p^(i+6) = -p^i) and y^(p^6) = y^(-1) is Fp12 conjugation. For e != 0, p^i e = e mod r forces r | p^i - 1, impossible for 0 < i < 12. So every nonidentity class has exactly 12 elements and the number of classes is N' = (r-1)/12 + 1, log2 N' = 251.2721 (log2 r = 254.8571). A collision of two class members gives, with c1 = g^a1 z^b1 = c2 = g^a2 z^b2, the equation a1 + x b1 = a2 + x b2 mod r, so x = (a1 - a2)/(b2 - b1) when b1 != b2. The exponents b are close to uniform mod r, so b1 = b2 has probability about 1/r and such a collision is discarded.

## 3. Walk with conjugated jump tables

Work in the tower Fp2[w]/(w^6 - xi), xi = 1 + u. This is the profile's basis: w^6 = 1 + u, and coefficients convert by x_j = d_j + d_(j+6), y_j = d_(j+6), six additions. Write y = sum c_j w^j. Then y^(p^i) has coefficients conj^i(c_j) * gamma(i,j), with gamma(i,j) = xi^(j (p^i - 1)/6) in Fp2 (checked numerically against direct exponentiation), and y^(p^6) negates the odd coefficients.

Class key. Let v_i = Re(gamma(i,1) conj^i(c_1)) for i = 0..5 (v_0 = Re(c_1)). The 12 images y^(+-p^i) have keys v_i and p - v_i (for v_i = 0 take 0), and the key of the class is the least of the 12, K. The key depends only on the class. The six values are not independent: xi^((p^2-1)/6) = 2^((p-1)/6) = zeta lies in Fp (checked numerically), so v_2 = zeta v_0 and v_4 = zeta^2 v_0, and gamma(3,1) = gamma(1,1) gamma(2,1) gives v_3 = zeta v_1 and v_5 = zeta^2 v_1. The 12 keys are the orbits of two values A = v_0 and B = v_1 under six multipliers +-zeta^m, so only six Fp multiplications give all keys (ten are charged). Ties between distinct images have probability below 2^-370 per step (at most 66 pairs, each equal with probability about 1/p when A and B are uniform) and are broken by the index (i, sign).

Walk. Fix s = 2^20 random exponent pairs (a_j, b_j) and M_j = g^(a_j) z^(b_j). Store for every j and every lam in H the dense element M_j^(1/lam) and the pair (a_j, b_j)/lam mod r. The state is y with known exponents, y = g^a z^b. One step:
1. Compute the 12 keys, the least key K and the lam attaining it; j is bits 44 to 63 of the mix m1 of K defined below.
2. y' = y * M_j^(1/lam) (one dense Fp12 multiplication); (a, b) += (a_j, b_j)/lam mod r.
Then y'^lam = c * M_j, where c = y^lam is the canonical image. The class sequence is that of the standard class walk: the next class is [c * M_j], j taken from the canonical key. The canonical image c is never built during a step.

Distinguished points and the jump index: a charged mix. The index and the distinguished test are taken from a fixed mix of the six 64-bit limbs k_0..k_5 of K, not from raw key bits, because the structure above ties the key bits to each other. Let s := 0; for i = 0..5: s := (s xor k_i) * 0x9E3779B97F4A7C15 mod 2^64, then s := s xor (s >> 32). Let fin be the splitmix64 finalizer. Set m1 = fin(s) and m2 = fin(s + 0x9E3779B97F4A7C15 mod 2^64). The jump index is j = bits 44 to 63 of m1. A class is distinguished when m2 = 0 and bits 28 to 43 of m1 are zero, 80 bits in all (theta = 2^-80), a different field from the index bits. The mix is about 60 instructions and is charged 150 in the per-step ledger below. H3: on the keys that occur, (m1, m2) behaves as a random function of K, so index and distinguished test are independent and uniform and distinct classes have independent choices. This is a heuristic about a fixed 64-bit mix; no claim about raw key bits is made. Leaving Montgomery form costs one more Fp multiplication per step, inside the charge below. At a distinguished point, build the full image c = y^lam (at most 5 Fp2 constant multiplications), scale (a, b) by lam, hash c to 256 bits and insert (hash, a, b), 96 bytes, into one global store. A repeated hash with a different b yields x. A found x is checked by g^x = z before use.

Fruitless cycles. The map F from a class to its successor is a function of the class. A trail that enters a cycle of F never leaves it, so the rule below makes every walker leave a cycle through the same point, and the exit is an operation that no table step can undo.

Detection (fixed period alpha = 64). Each trail counts its own steps t = 0, 1, 2, ... At every step, before anything else, the walker tests its distinguished-point condition. Then: if a checkpoint key C is set and the current key equals C, a cycle is detected; else if t is a multiple of 64, it sets C := current key and W := current key; else if C is set it sets W := min(W, current key). The window of comparisons after a checkpoint is 64 steps (the equality test comes before the checkpoint is overwritten). If a trail is inside a cycle of length L <= 64, the first checkpoint after it entered lies on the cycle (at most 63 steps after entry), and the cycle returns to that point L <= 64 steps later, inside the window. So every cycle of length at most 64 is detected, and a detection is a true repeat of a class (keys of distinct classes agree with probability below 2^-370 per comparison). When detected, the trail sits at the checkpoint class and W is the least key over the whole cycle, because the window then covers exactly the L members.

Escape by squaring (a function of the cycle only). The walker keeps stepping along the cycle, with detection off, until its key equals W (at most L - 1 steps; if the checkpoint class has key W, zero). At that member m* (the least-key class of the cycle) it makes no table step. It squares its state instead: y := y^2, (a, b) := (2a, 2b) mod r, a cyclotomic squaring in GT costing at most one dense multiplication, then clears C and W. Since y^lam = c(m*), the new state satisfies (y^2)^lam = c(m*)^2, so it lies in the class Z = [c(m*)^2], which depends on m* alone. The next step is an ordinary step from Z. What depends on the walker is the detection time (the phase of t mod 64) and the entry point into the cycle; neither affects where the trail leaves. Let F' be F with the escape edge m* -> Z for the least-key class m* of every cycle of length at most 64; every walker follows F' exactly. Two trails that have met are at the same class, so they follow the same F' orbit: either both reach the same distinguished point on it, or both enter the same F-cycle, both pass every member of it (each walker travels a whole turn before it can detect, and the distinguished test runs at every step, so a cycle that holds a distinguished point stops both trails there), and both leave from the same m* to the same Z. They stay merged. A later cycle on the orbit is handled in the same way, since the walker keeps no memory except C, W and t.

Why the escape is not undone. An escape by a table step (index j + 1) fails: the next ordinary step from the class reached undoes it with probability 1/(12 s), because a step from [c M_(j+1)] repeats the inverse index with that probability. Then the cycle is re-formed, the same minimum is chosen again, and the walker loops until its cap. A fraction 1/(12 s) of all escapes is undone this way, which at the event rate 2^-23.585 per step is one trapped trail per about 2^47.2 steps, so about 2^78 trails would run to the 2^84 cap over the run. Squaring has no such inverse among the table steps. A step from Z lands in [c(m*)^2 * M_(j')] for the index j' of Z, and a return to any class of the cycle, [c * w] with w a product of table elements, needs c^2 * (product of table elements and conjugates) = (c * w)^h for some h in H, that is (2 - h) e + (a combination of table values) = 0 mod r, where e is the exponent of c to base g. The coefficient 2 - h is nonzero mod r because 2 is not in H = {+-p^i} (checked numerically: 2 differs from all twelve elements, and 2^k is in H for no k below 5,000), and e is a uniform exponent chosen by the walk before the escape. So the relation holds only by a coincidence of probability about 1/r for each of the at most 12 L (class, image) pairs, with no identity in the table values that could make it hold systematically. Z is also not in the class of m*, since c^2 = c^h would need h = 2. Under H1 the trail from Z then behaves as a fresh trail: it meets one of the at most 64 classes of the cycle within its at most 2^84 steps with probability at most 64 * 2^84 / N' = 2^-161.3. A cycle through the escape edge is the same event. Over the whole run there are at most 2^102.2 events, so the expected number of escapes that fall back into their cycle is at most 2^102.2 * 2^-161.3 = 2^-59.1, and each costs at most 2^84 steps before the cap drops the trail: at most 2^25 steps in expectation, which is 2^-100 of T and is ignored in the ledger with the other terms below 2^-80.

Rates of cycle events. A 2-cycle needs the successor of X to have the same jump index (probability 1/s) and the canonicalising element at the successor to equal inversion (probability 1/12: multiplying A by one of the six multipliers permutes the six orbit values of A cyclically, and likewise for B, so for A and B uniform the image holding the least key is uniform over the 12); other canonicalising elements close the cycle only by a coincidence of probability about 1/r. So the 2-cycle rate is rho_2 = 1/(12 s) = 2^-23.585 per step. A cycle of length L >= 3 closes with probability above about 1/r only when its exponent relation holds as an identity in the table values, which forces every distinct jump index in it to occur at least twice: at most floor(L/2) distinct indices, so at most L - floor(L/2) = ceil(L/2) forced coincidences. The number of index patterns is at most the number of set partitions of the L positions, below L!, and each pattern is realised with probability s^-L times s^(number of distinct indices), so rho_L <= L! s^-ceil(L/2) (the 12 conjugation choices only lower it, since their probability is at most 1). Summing gives rho_3 + ... + rho_64 <= 2^-35.09 = 2^-11.51 rho_2, and for 65 <= L <= 2048 the same count gives at most 2^-351 per step in total (its terms are decreasing from L = 65 to L near 1,000 and below 2^-900 at L = 2048). Cycles longer than 2048, and any other cycle longer than 64, need a trail to revisit one of its own classes. Under H1 a trail of l steps has a repeated class with probability at most l^2/(2N'), so over all trails of at most 2^84 steps the probability that any trail is trapped in an undetected cycle is at most T * 2^84 / (2N') = 2^-42.6, and such a trail costs at most 2^84 steps before the cap drops it (2^-84 of T in expectation). A trapped trail never produces a wrong collision; it only restarts. The total rate of cycle events is rho <= 2^-23.585 (1 + 2^-11.5) = 2^-23.5845.

Cost per event, derived: from entry to the first checkpoint at most 63 steps, then L steps to the repeat, then at most L - 1 steps to m*, then the escape step (the squaring costs at most one dense multiplication, no more than a step, and the key work was done at the step before), a total of 63 + L + (L - 1) + 1 <= 191 steps for L <= 64, of which the first L were fresh class visits. I charge 192 steps per event, the escape included, at the full step price. The waste per productive step is at most 192 rho = 2^-16 (1 + 2^-11.5) = 2^-15.9995, charged as a factor (1 + 2^-15), about twice the derived waste. The window test, the minimum and the checkpoint compare add about 50 instructions per step, inside the 8,000 charge. This follows Bos, Kaihara, Kleinjung, Lenstra, Montgomery (2010) and Bernstein, Lange, Schwabe (2011). A trail without distinguished point after 2^84 steps (16 times the mean trail length 2^80, probability e^-16) is dropped.

Starting points. Each trail begins at y = g^a z^b with fresh uniform (a, b), by a double exponentiation of at most 500 dense multiplications.

## 4. Success probability

Run until T steps have completed, with T = 1.05 k + 2^104, then finish all trails in flight (at most P 2^84 steps for P <= 2^20 processors, at most 2^104). The run is a fixed budget that halts, not an expected runtime. Here k = sqrt(-2 ln(0.61) N') = sqrt(0.98859 N'), log2 k = 125.6278. T counts productive steps, the fresh class visits; the cycle waste of section 3 is charged on top in section 5.

Class visits of distinct trails behave as independent uniform draws on N' classes up to a first collision (a collision lies within one trail with probability about 2^84/k, negligible). Two trails that meet share all later points, so both reach the same distinguished point: van Oorschot and Wiener (1999). The birthday bound is applied with the effective class count

    N_eff = N' (1 + 1/16) (1 + 2^-15),  log2 N_eff = 251.3596,

which folds in the additive-walk penalty (1 + 1/16, next paragraph) and the cycle waste (1 + 2^-15, section 3; the waste is also charged as steps in section 5, so this reading is the conservative one). With T = 1.05 k + 2^104 productive visits,

    P >= 1 - exp(-T^2/(2 N_eff)) = 1 - exp(-0.51289) = 0.4012 >= 0.39,

a margin of 0.011 in probability and 1.019 in the number of visits. Reading T as the whole step budget instead, there are T/(1 + 2^-15) productive visits and the exponent is 0.51287; the bound is the same to four digits.

Walk randomness on the quotient. This is the standard heuristic for additive walks and I state it as such (H1). Teske (2001) analyses r-adding walks with r >= 16 and finds the collision time within a few percent of the random-walk value; Bernstein, Lange and Schwabe (2011, on the correct use of the negation map) give the additive-walk collision penalty about sqrt(1 + 1/r) for an r-entry table. For Teske's minimum r = 16 that penalty is sqrt(1 + 1/16) = 1.0308, which is what N_eff charges; at our s = 2^20 the penalty would be 1 + 2^-21, so the r = 16 value is a conservative stand-in. Bos, Kaihara, Kleinjung, Lenstra, Montgomery (2010) and Duursma, Gaudry, Morain (1999) cover walks on classes under negation and endomorphisms, with the fruitless-cycle treatment used in section 3. The 1.05 factor in T is 1.9 percent above the 1.0309 needed, an explicit margin on top of the penalty. A collision of two class members is useful when the exponents b differ, which fails with probability about 1/r. Cycle losses (2^-16 of the steps) are charged separately in section 5. Trails dropped at the 2^84 cap are 2 e^-16 of the collisions, inside the margin. A random self-collision of a trail (an undetected cycle of length above 64) has total probability at most T 2^84 / (2 N') = 2^-42.6 over the run, and costs at most 2^84 steps. Success at least 0.39 follows from the birthday bound when H1 and H2 hold.

## 6. Heuristics and limits

1. H1: random-mapping behaviour of the class walk on the quotient (Teske, Bernstein-Lange-Schwabe, Bos et al.), charged as the r = 16 penalty sqrt(1 + 1/16) = 1.0308 plus the 1.05 factor in T; no proof is claimed.
2. H2: the jump indices and conjugation choices of distinct classes are independent and uniform. The fruitless-cycle counts (L! s^-ceil(L/2) for 3 <= L <= 2048, the return bound after an escape, the self-collision bound for longer cycles) rest on it. H3: the key mix of section 3 behaves as a random function of the key; it replaces any claim about raw key bits.
3. Cycles longer than 2048 are not counted structurally; their effect is bounded only by the self-collision bound, 2^-42.6 trails over the run, each costing at most 2^84 steps. A trapped trail restarts and cannot give a wrong answer.
4. The key and hash ties have negligible probability (below 2^-370 per step).
5. Per-step instruction counts are analytic, based on blst's 383 instructions per Fp mult; the 8,000 charge exceeds the estimate by about 40%.
6. Toy-scale evidence only (experiment.py at its declared inputs: order 60,000, 20 recovery trials, seed 1, about 1.2 s; a group of order 59,929 with an order-12 automorphism, a 16-entry table for the recovery and ratio runs): the same walk (least of 12 images as key, index and distinguished test from a mix of the key, period-64 detection, squaring escape) recovered x in 20 of 20 runs with none wrong; 12 of 12 pairs of trails started at one class with different counter phases (on a 4-entry table in a group of about 8 x 10^6 classes, 38 cycle events) ended at the same distinguished point, none apart, none dropped; escapes that fell back into their cycle were 0 of 80 for squaring against 11 of 80 for the earlier table-step escape (2-entry table); and the number of distinct classes visited until two different trails first met was 1.064 (95% half-width 0.097, 100 runs) times sqrt(pi N'/2), against 1.069 (half-width 0.101) for an ideal random mapping run through the same procedure, which is above 1 at this size because trails are short and end at distinguished points (the walk's value in executed steps is 1.267, inflated further because a 64-step detection period is comparable to sqrt(N') = 90). These are toy-scale measurements. They check the scheme, not production costs.
