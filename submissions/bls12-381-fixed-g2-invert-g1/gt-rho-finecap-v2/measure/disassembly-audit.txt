3. Static vs dynamic reconciliation
-----------------------------------
Summing the composition of section 2 with each symbol body counted once gives
  144 + 3 x 2,860 + 3 x 88 + 15 x 36 + 90 = 9,618, plus the 1-instruction exported wrapper = 9,619.
The dynamic Callgrind count is 9,803 per call. The gap is 184 instructions (1.88%): one `ret` for
every executed call (181 executed call sites per squaring) plus the few instructions around them.
The static sum cannot see them because a symbol body is counted once while its `ret` executes per
call; and the two shared assembly entry points __mul_by_1_mont_384 and __redc_tail_mont_384 are
entered mid-body from several callers, so a per-symbol sum is a lower bound on their executed
share. The two figures therefore agree to within 1.9%, and the dynamic count - exact to the
instruction, identical at n = 1, n = 65 and all five slice offsets - is the number the ledger
charges. The static audit's role is to confirm the order of magnitude and the straight-line
property, not to set the price.

4. What the ledger charges
--------------------------
results.tsv gives I(n=1) = 9,823 and I(n=65) = 637,215, so the marginal per call is
(I_65 - I_1)/64 = (637,215 - 9,823)/64 = 9,803.0, exactly, at every offset and every routine.
That marginal is the like-for-like counterpart of the cost model's "executed instructions,
including call and loop work" convention, which is why the same harness reproduces the model's
two reference counts exactly: blst_fp_mul = (24,915 - 403)/64 = 383.0 and
blst_fp12_mul = (1,494,761 - 23,017)/64 = 22,996.0.
The earlier revision's ledger charged the whole marginal, 9,803 instructions, for the routine,
with no deduction for the harness loop (about 5 instructions per iteration, which its walk
loop's own 30 instructions of loop control in its 270-instruction every-step row also covered;
its squaring step therefore carried that control twice, which can only overstate the cost). Its
squaring step was 9,803 + 270 = 10,073 instructions = 0.50365 units of 20,000. This package
charges the kernels/sqr.s count instead, 6,767 + 226 = 6,993 (proof.md section 5).

5. Which limbs the routine returns
----------------------------------
This section is an argument from the blst source, not a measurement: the harness image could
not be rebuilt for this revision, so the limb equality below was not run.
The walk reads its decision bits from the stored Montgomery limbs of a GT element. Every
primitive that the call tree above executes returns a fully reduced residue in [0, p):
  * the double-width reduction tail, build/elf/mul_mont_384-armv8.S, __redc_tail_mont_384
    (lines 1336-1372): accumulate the upper half, subtract the modulus (subs/sbcs, last
    sbcs with the carry word), then csel ..., lo selects the difference unless it borrowed;
  * the end of __mul_mont_384 (same file, lines 457-824, the subs/sbcs block and the
    csel ..., lo group ending at line 818): the same conditional subtraction after the final
    accumulation;
  * __add_mod_384 (add_mod_384-armv8.S, label at line 42, falling through to
    __add_mod_384_ab_are_loaded at line 50) and __sub_mod_384 (same file, label at line 530): add and
    conditionally subtract the modulus (a trial subtraction and csel ..., lo), or subtract and add the
    modulus back under a borrow mask, so the result is again in [0, p); __add_mod_384x384 (line 40
    of mul_mont_384-armv8.S) and __sub_mod_384x384 (line 122) do the same for the upper half of a
    double-width value, keeping it below p * 2^384;
Every operand that enters those sequences is itself in [0, p) (inputs are stored values;
double-width values are kept below p * 2^384 by the x384 add/sub routines), so a single
conditional subtraction gives the unique representative in [0, p). A field element therefore
has exactly one stored limb vector x * 2^384 mod p. blst_fp12_cyclotomic_sqr(a) and
blst_fp12_mul(a, a) both return the element a^2 for a in the cyclotomic subgroup (the
Granger-Scott map of src/fp12_tower.c lines 630-660 and the dense product agree there), each
coordinate fully reduced, so their output limbs are identical.
