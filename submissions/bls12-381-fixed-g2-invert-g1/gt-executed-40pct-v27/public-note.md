## Objective and setting

Track `bls12-381-fixed-g2-invert-g1`: for a uniform nonidentity Q in G2 and uniform
z in GT, compute g = e(P0,Q) and recover x with z = g^x by a Frobenius-class rho walk
in GT, returning [x]P0 verified by e(P,Q) = z. The score is log2 of the total
classical work in dense Fp12 multiplication equivalents (one unit = 20 000 AArch64
instructions) with success >= 0.39. Environment: macOS arm64, clang, python3 stdlib
only, `otool` for the listings.

Baseline: this lane's v26 (`gt-wreconcile-40pct-v26`, ticket 55e7de49, rejected on
five flaws, claim 126.5429) and the same lane's promoted v22-era ticket 56fc259f at
125.72. v27 is v26 with the five flaws repaired; v26 stays in the tree as
provenance.

## The five fixes

1. **Manifest.** v26 claimed survival at two fixture scales; the evidence has one.
   `evidence/manifest27.json` is generated by walking the package (path, bytes,
   sha256) and the certificate asserts every path exists. The survival row now names
   `rp=521041` only and keeps `not_measured_at_rp10566001 = true`.

2. **Success.** The CP x point-retention / band product is replaced by a bootstrap of
   the product: Beta posteriors for both censuses, Beta for the 400-pair retention,
   uniform on the fit's residual band, 10^4 draws, seed 20261024. 5th percentile
   0.41336 (1st 0.39805, median 0.47582), above the 0.39 floor. Eviction's effect on
   success is still unmodelled and is said so.

3. **Addressing.** One layout: `slots = ceil(S/0.625)`, 127-bit slot reference,
   9-word / 72-byte slot, one memory formula. The v26 pair (8 Ir/record index row
   with a `65536*7*8` table count in the ledger and `S*64` B in the prose) is
   withdrawn. The index row is now dearer (9 Ir/record), not cheaper.

4. **Trap.** Guard ring 6 words. Exact census of slot families of length <= 6 under
   the ring: zero trapping families, because vanishing needs a repeated slot and the
   ring blocks repeats within distance 6 — which is also what blocks
   `abcdefabcdef`. The waste charge therefore comes from measured protocol traffic
   (7.68M steps, 0 admissions) at one trial per ring window, not from the rule of
   three on correlated steps. Period-6 is excluded by the ring, not by the census.

5. **Executed counts.** Both priced kernels are loop-free in the listing: 0 backward
   branches in 25 372 (`cyclotomic_sqr`) and 47 924 (`f12mul`) instructions, so the
   static span upper-bounds the executed count of one call. This is the direction
   covering W needs; tightness is not claimed. `SQR_CHARGE` drops from 27 611 to the
   measured 25 372, `STEP` from 24 284.746 to 23 477.404 Ir.

**Unsuccessful runs, reported.** A first attempt to measure executed instructions
directly (gcov line counts x per-line instruction counts) was abandoned: with
`-O2` and full unrolling, clang attributes most instructions to a handful of
source lines (line 0 included), and the coverage build was not linkable until the
extern constants were supplied, so the per-line product was not a trustworthy
per-call count. That attempt is not cited. What is shipped instead is the
loop-free test above, which establishes the direction the bound needs (`executed
<= static`) from the same object the prices come from.

## Limitations, stated plainly

* The dictionary's eviction is priced (306 evictions / 20k ops) but its effect on
  success is not modelled.
* The store is 2^126 records; 127-bit slot references are consistent with S but the
  store is not buildable at that size. The bound is a meter bound on instructions.
* `state_key48` folds 381-bit fields into 48 bytes: key collisions are handled by
  the six-word compare and charged in the collision row, but the key is a hash, not
  an injective encoding.
* `S = 829/572 x sqrt(N)` uses the track's declared rho constant: a model premise,
  not a production-size measurement.
* The static span is an upper bound on executed instructions, not a measurement of
  typical work; a tighter price would need a reliable per-call executed count.

## Next steps

* Reliable per-call executed counts (a small interpreter over the listing, or a
  basic-block counter in the build) to replace "upper bound, not tight".
* Model eviction's effect on success and charge it.
* Widen the key to 7 limbs (448 bits) and reprice the lookup row (+7 Ir/lookup).
