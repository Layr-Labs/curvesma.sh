# Directed quadrature refinement (inherited)

Inherited from f1929991 (bernardo-lima12, GPT-6 Astra in Codex) and e3940d11 (Claude Opus 5.5 in Claude Code) and used unchanged by the descent and retention models. The descent integration mesh is 384 cells instead of 48 and the Dickman table spacing 1/1024 instead of 1/128; PLAN16 and BOOT16 multiply every iA by eight, so the physical endpoint nA = 69 + iA (n - 69)/mesh is unchanged; TRUNC = 0; retention and descent share the global mesh. e3940d11 re-optimised eight plan entries at the refined quadrature: (100,g) iA 192 -> 168; (110,f) 216 -> 192; (120,f) 240 -> 216; (140,f) n 101 -> 100; (140,g) iA 336 -> 312; (165,g) n 129 -> 128; (195,g) n 160 -> 159; (210,g) n 168 -> 166. This package keeps that plan.

**Validity.** The model integrates rho((m - sum(t) + alpha)/69) prod(dt/t) / (jA! jB!). Each old mesh interval splits into eight whose logarithmic measures sum exactly to the old one; subcells of a wholly feasible cell stay feasible, cells crossing sum(t) = m are discarded, and there is no truncation cutoff. Left endpoints give a lower rho value (rho decreases), moving them right only raises it, and the finer rho table moves the upper-rounded argument toward the true one; the upper bracket is treated consistently. So the refined integrals bound the same model, with no change of heuristic. Only convolution rows through the requested kA are computed (a jA row depends on rows 0..jA only), which leaves every requested sum unchanged; eight probes (kA = 0, 1, 4, 15 on both rho grids) matched the full-row calculation exactly in binary64. This speeds the evidence only and is not charged as a faster kernel.

**Limitations.** rho coefficients are generated with 200-digit Decimal arithmetic and evaluated in binary64; the table brackets the computed series, which is numerical evidence, not an interval certificate for every real rho value. The probability model and its extrapolation remain H1-H5; the decimal precision is accounting precision conditional on the model.
